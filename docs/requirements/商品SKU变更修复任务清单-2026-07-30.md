## 八、验收标准汇总

### 8.1 功能验收

| 功能点 | 验收条件 |
|-------|---------|
| 双库存源统一 | 管理员改库存后，购物车、C端详情、下单流程看到的库存数完全一致 |
| 改库存写流水 | `inventory_flow` 表有 `ADJUST_IN`/`ADJUST_OUT` 记录，含 adminId |
| 停售通知 | 停售 SKU 后，所有待支付订单用户收到小程序订阅消息 |
| 改价通知 | 改价后，所有待支付订单用户收到小程序订阅消息 |
| 事务保护 | updateSku/deleteSku 中途失败时数据全部回滚 |
| is_hidden 判定 | 商品 hide 后购物车标记 invalid |
| 批次一致性 | 校验脚本识别 batch_info 与 inventory_real_time 差异 |

### 8.2 数据一致性验收

| 指标 | 目标值 |
|------|-------|
| `product_sku.stock` 与 `inventory_real_time.available_qty + locked_qty` 差异 | 0 |
| `batch_info.quantity` 汇总与 `inventory_real_time` 差异 | 0 |
| `inventory_flow` 流水覆盖场景 | 管理员调整/下单预占/取消释放/出库扣减 4 类全覆盖 |

### 8.3 性能验收

| 指标 | 目标值 |
|------|-------|
| 购物车列表响应时间（10 SKU） | < 500ms |
| updateSku 响应时间（含事务） | < 1s |
| 消息推送延迟（10 个用户） | < 3s |

### 8.4 兼容性验收

| 场景 | 验收条件 |
|------|---------|
| inventory_real_time 记录不存在 | adjustStock 自动创建，不抛 404 |
| Redis 故障 | 缓存失效不回滚事务（已有 try-catch 保护） |
| 微信订阅消息未授权 | 消息写入 user_message 表，用户可在消息中心查看 |
| 待支付订单数 > 100 | 消息推送分批执行，不阻塞主流程 |

## 九、风险与注意事项

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| `isProductInvalid` 改为异步后调用点遗漏 `await` | 永远返回 Promise 对象（truthy）→ 商品永远 valid | 全局搜索调用点，单元测试覆盖 |
| `adjustStock` 改造支持外部事务影响范围大 | inventoryService 所有方法需同步改造 | 单独 PR 提交，完整回归测试 |
| 订阅消息模板审核周期长 | 阻塞 MP-P1-01 实施 | 提前在微信公众平台申请，并行实施后端任务 |
| 大量待支付订单的消息推送性能 | 推送 > 100 用户时阻塞 API | 改为异步队列（bull/bullmq）或分批推送 |

### 9.2 业务风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 双库存源切换期间数据不一致 | 切换瞬间可能产生差异 | 选择低峰期切换；切换前执行 BE-P2-01 一致性校验 |
| 停售通知引发用户大量取消订单 | 短期订单取消率上升 | 通知文案优化，提供替代商品推荐 |
| 价格变更通知引发用户投诉 | 用户认为"涨价欺诈" | 文案明确"您可按原价完成支付" |

### 9.3 部署风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 数据库迁移失败 | inventory_real_time 字段变更失败 | 提前备份；分阶段迁移（先双写后切读） |
| 消息推送服务故障 | 用户收不到通知 | user_message 表保留消息记录，用户可在消息中心查看 |
| 事务回滚导致缓存与 DB 不一致 | 缓存仍为旧值 | 事务提交后再失效缓存（BE-P1-02 已规划） |

### 10.3 回滚预案

| 场景 | 回滚方案 |
|------|---------|
| 双库存源切换后出现严重问题 | 通过 feature flag 切回使用 product_sku.stock；保留旧逻辑代码 1 个迭代 |
| 消息推送引发用户大量投诉 | 关闭消息推送开关（环境变量 `ENABLE_SKU_OFFLINE_NOTIFY=false`） |
| 事务保护导致死锁 | 回滚事务包裹，改用乐观锁 |
