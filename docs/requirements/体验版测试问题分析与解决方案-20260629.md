## 问题根本原因分析

### 问题1、2、3、6：双重弹窗问题

**问题现象**：游客模式下点击手机号、邮箱、填写邀请码、性别编辑等卡片时，出现两个相同的"请先登录后再编辑资料"弹窗，需要点击两次"取消"才能关闭。

**根本原因**：

1. **事件冒泡与重复触发**：`InfoMiniCard` 组件的外层 `view` 绑定了 `@tap="onTap"`，该方法会触发 `$emit('tap')`。但在某些情况下，点击事件可能被触发两次（可能是组件嵌套或事件冒泡导致）。

2. **登录检查逻辑不一致**：在 `mine.vue` 中，`ensureLoggedIn()` 方法会调用 `uni.showModal()` 弹出登录提示。当点击事件被触发两次时，`ensureLoggedIn()` 也被调用两次，导致两个弹窗。

3. **代码位置**：`src/pages/mine/mine.vue:858-869`
   ```javascript
   ensureLoggedIn() {
     if (this.isUserLoggedIn && !this.guestMode) return true
     uni.showModal({
       title: '提示',
       content: '请先登录后再编辑资料',
       confirmText: '去登录',
       success: (res) => {
         if (res.confirm) this.goLogin()
       },
     })
     return false
   },
   ```

4. **对比正常功能**：在线客服（`onOnlineService`）和用户昵称编辑（`onEditNickname`）使用了不同的检查方式，避免了重复弹窗：
   - 在线客服使用自定义的 `serviceChatModalVisible` 控制弹窗，有 `v-if` 条件渲染保护
   - 用户昵称编辑同样调用 `ensureLoggedIn()`，但由于昵称编辑按钮的 DOM 结构不同，可能避免了事件重复触发

### 问题4、5：双重跳转问题

**问题现象**：游客模式下点击日常提醒或收货地址卡片，进入页面后需要点击两次返回按钮才能回到"我的"Tab 页。

**根本原因**：

1. **登录状态检查逻辑错误**：在 `mine.vue` 中，`onDailyReminders()` 和 `onManageAddress()` 的登录检查条件不正确：

   ```javascript
   // src/pages/mine/mine.vue:597-602
   onDailyReminders() {
     if (!this.isUserLoggedIn && !this.guestMode) {
       this.goLogin()
       return
     }
     uni.navigateTo({ url: '/subpk-reminder/list' })
   },
   
   // src/pages/mine/mine.vue:604-609
   onManageAddress() {
     if (!this.isUserLoggedIn && !this.guestMode) {
       this.goLogin()
       return
     }
     uni.navigateTo({ url: '/subpk-address/list' })
   },
   ```

2. **逻辑分析**：
   - 游客模式下：`isUserLoggedIn = false`，`guestMode = true`
   - 条件 `!this.isUserLoggedIn && !this.guestMode` = `!false && !true` = `true && false` = `false`
   - 条件不满足，所以不会调用 `goLogin()`，而是直接执行 `uni.navigateTo()`
   - 用户被允许进入日常提醒/收货地址页面

3. **二级页面的 onShow 再次触发跳转**：日常提醒和收货地址页面的 `onShow` 生命周期中调用了 `redirectToLoginIfNeeded()`，但该函数在当前实现中恒返回 `false`（浏览已放开），所以页面不会被拦截。

4. **双重跳转的真正原因**：
   - 日常提醒页面的 `onShow` 生命周期会调用 `loadReminders()`，该方法可能触发了某些数据加载或状态变化
   - 由于 `redirectToLoginIfNeeded()` 返回 `false`，页面不会被拦截
   - 但在某些情况下，可能存在 `navigateTo` 被调用两次的情况，导致页面栈中有两个相同的页面

### 问题7：收货地址页面添加按钮未拦截

**问题现象**：游客模式下进入收货地址页面后，点击"添加收货地址"按钮直接进入了新增地址页面，而没有弹出登录提示。

**根本原因**：

1. **登录检查缺失**：在 `subpk-address/list.vue` 的 `onAdd()` 方法中，没有进行登录状态检查：

   ```javascript
   // src/subpk-address/list.vue:261-264
   onAdd() {
     uni.navigateTo({
       url: buildAddressEditUrl({
         from: this.from,
         orderId: this.orderId || undefined,
       }),
     })
   },
   ```

2. **对比其他功能**：日常提醒页面的 `onAdd()` 方法有登录检查：

   ```javascript
   // src/subpk-reminder/list.vue:158-170
   onAdd() {
     if (!isLoggedIn()) {
       uni.showModal({
         title: '提示',
         content: '请先登录后再添加提醒',
         confirmText: '去登录',
         success: (res) => {
           if (res.confirm) navigateToLoginPage()
         },
       })
       return
     }
     // ...
   },
   ```

## 解决方案

### 方案1：修复双重弹窗问题

**目标**：确保登录提示弹窗只弹出一次

**修改文件**：`src/pages/mine/mine.vue`

**修改内容**：

1. 在 `data()` 中添加一个锁标志，防止重复弹窗：

   ```javascript
   data() {
     return {
       // ... 其他数据
       authModalVisible: false,
     }
   },
   ```

2. 修改 `ensureLoggedIn()` 方法，添加锁机制：

   ```javascript
   ensureLoggedIn() {
     if (this.isUserLoggedIn && !this.guestMode) return true
     if (this.authModalVisible) return false
     this.authModalVisible = true
     uni.showModal({
       title: '提示',
       content: '请先登录后再编辑资料',
       confirmText: '去登录',
       success: (res) => {
         this.authModalVisible = false
         if (res.confirm) this.goLogin()
       },
       fail: () => {
         this.authModalVisible = false
       },
     })
     return false
   },
   ```

### 方案2：修复双重跳转问题

**目标**：统一登录检查逻辑，确保游客模式下无法进入需要登录的页面

**修改文件**：`src/pages/mine/mine.vue`

**修改内容**：

1. 修改 `onDailyReminders()` 方法：

   ```javascript
   onDailyReminders() {
     if (!this.isUserLoggedIn || this.guestMode) {
       this.ensureLoggedIn()
       return
     }
     uni.navigateTo({ url: '/subpk-reminder/list' })
   },
   ```

2. 修改 `onManageAddress()` 方法：

   ```javascript
   onManageAddress() {
     if (!this.isUserLoggedIn || this.guestMode) {
       this.ensureLoggedIn()
       return
     }
     uni.navigateTo({ url: '/subpk-address/list' })
   },
   ```

**逻辑变更说明**：
- 原条件：`!this.isUserLoggedIn && !this.guestMode`（仅在未登录且非游客时跳转登录）
- 新条件：`!this.isUserLoggedIn || this.guestMode`（未登录或游客模式时都拦截）
- 使用 `ensureLoggedIn()` 统一处理登录提示，保持用户体验一致性

### 方案3：修复收货地址添加按钮未拦截问题

**目标**：游客模式下点击"添加收货地址"时弹出登录提示

**修改文件**：`src/subpk-address/list.vue`

**修改内容**：

1. 在 `import` 语句中添加 `isLoggedIn` 和 `navigateToLoginPage`：

   ```javascript
   import { getItem, setItem, isLoggedIn } from '@/utils/storage'
   import { redirectToLoginIfNeeded, navigateToLoginPage } from '@/utils/guest'
   ```

2. 修改 `onAdd()` 方法，添加登录检查：

   ```javascript
   onAdd() {
     if (!isLoggedIn()) {
       uni.showModal({
         title: '提示',
         content: '请先登录后再新增地址',
         confirmText: '去登录',
         success: (res) => {
           if (res.confirm) navigateToLoginPage()
         },
       })
       return
     }
     uni.navigateTo({
       url: buildAddressEditUrl({
         from: this.from,
         orderId: this.orderId || undefined,
       }),
     })
   },
   ```

3. 同样修改 `onEdit()` 方法，添加登录检查：

   ```javascript
   onEdit(addr) {
     if (!isLoggedIn()) {
       uni.showModal({
         title: '提示',
         content: '请先登录后再编辑地址',
         confirmText: '去登录',
         success: (res) => {
           if (res.confirm) navigateToLoginPage()
         },
       })
       return
     }
     uni.navigateTo({
       url: buildAddressEditUrl({
         from: this.from,
         id: addr.id,
         orderId: this.orderId || undefined,

     })

   ```

### 方案4：统一登录检查模式（推荐）

**目标**：在整个小程序中统一游客模式的登录检查逻辑，避免类似问题再次出现

**修改文件**：`src/utils/guest.js`

**修改内容**：

1. 修改 `requireAuthForAction()` 方法，添加防重复调用机制：

   ```javascript
   let authModalPending = false
   
   export function requireAuthForAction(actionHint = '') {
     if (canPerformWriteActions()) return true
     if (authModalPending) return false
     authModalPending = true
     const suffix = actionHint ? `后再${actionHint}` : ''
     uni.showModal({
       title: '提示',
       content: `请先登录${suffix}`,
       confirmText: '去登录',
       cancelText: '取消',
       success: (res) => {
         authModalPending = false
         if (res.confirm) {
           navigateToLoginPage()
         }
       },
       fail: () => {
         authModalPending = false
       },
     })
     return false
   }
   ```

2. 在 `mine.vue` 中使用 `requireAuthForAction()` 替代 `ensureLoggedIn()`：

   ```javascript
   import { requireAuthForAction } from '@/utils/guest'
   
   // 替换所有 ensureLoggedIn() 调用
   onEditPhone() {
     if (!requireAuthForAction('编辑资料')) return
     // ...
   },
   
   onEditEmail() {
     if (!requireAuthForAction('编辑资料')) return
     // ...
   },
   
   onFillInviterCode() {
     if (!requireAuthForAction('填写邀请码')) return
     // ...
   },
   
   onEditGender() {
     if (!requireAuthForAction('编辑资料')) return
     // ...
   },
   
   onDailyReminders() {
     if (!requireAuthForAction('查看日常提醒')) return
     // ...
   },
   
   onManageAddress() {
     if (!requireAuthForAction('管理收货地址')) return
     // ...
   },
   ```

## 代码质量改进建议

### 1. 统一登录检查 API

建议在 `src/utils/guest.js` 中提供统一的登录检查方法，所有页面和组件都使用这个方法进行登录状态检查，避免重复代码和逻辑不一致。

### 2. 添加防重复弹窗机制

在所有使用 `uni.showModal()` 的地方添加防重复调用机制，防止因事件重复触发导致的多重弹窗问题。

### 3. 游客模式下的按钮禁用状态

建议在游客模式下，将所有需要登录的操作按钮设置为禁用状态（`disabled`），并添加视觉提示（如灰色背景、禁用样式），让用户直观地知道这些功能需要登录后才能使用。

### 4. 二级页面的路由守卫

建议为所有二级页面添加路由守卫，在页面加载时检查登录状态，如果用户未登录且不是游客模式，自动跳转到登录页。
