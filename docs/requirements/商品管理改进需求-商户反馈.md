## 2. 需求详情

### 2.1 PM-02：商品级original_price改为SKU派生值

#### 2.1.1 问题描述

当前商品编辑页面上方有「商品原价」输入框，商户需手动填入数值。商户认为：
- 该值是对应在商品卡片上显示的划线价
- 普遍情况下会显示标价和划线价
- 因此该值应当直接使用下方SKU规格中的某个SKU的对应值
- 默认或未填写时，应选用第一个SKU内的值

#### 2.1.2 当前实现分析

**后端**：
- `product.original_price` 为独立字段，由Admin直接写入（见 [adminProductService.js](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/services/adminProductService.js#L135)）
- C端商品列表/详情页格式化时，优先使用SKU的`original_price`，若为空则回退到`product.original_price`（见 [productHelpers.js](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/utils/productHelpers.js#L89-L96)）

**前端**：
- Admin Web 的 [Edit.vue](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-admin-web/src/views/product/Edit.vue#L57) 中 `form.original_price` 作为独立字段提交

#### 2.1.3 改进方案

**方案一（推荐）**：商品级`original_price`改为只读派生值

| 端 | 改动 |
|----|------|
| **Admin Web** | 移除「商品原价」输入框，改为显示派生的划线价（优先使用卡片显示规格，未指定时用第一个SKU），标注「由SKU规格派生」 |
| **后端** | 保存商品时，自动从SKU派生商品级`original_price`（优先使用`card_display_sku_id`指定的SKU，未指定时用第一个SKU），不再接受手动输入 |
| **C端** | 保持现有逻辑不变（优先使用SKU级，回退到商品级） |

**派生规则**：

```
1. 如果 product.card_display_sku_id 已设置且对应SKU存在且在售：
   - product.original_price = 指定SKU的 original_price

2. 否则（未设置或指定SKU无效）：
   - 从所有在售SKU中选取第一个有效的SKU（status !== 0 && stock > 0）
   - 如果存在在售SKU：
     - product.original_price = 该SKU的 original_price
   - 如果不存在在售SKU：
     - product.original_price = min(sku.original_price for sku in product.skus if sku.original_price > 0)
```

> **说明**：派生规则与PM-05的卡片价格计算逻辑保持一致，优先使用商户指定的显示规格SKU。未指定时使用第一个SKU的`original_price`，无在售SKU时取所有SKU中最小的`original_price`作为兜底。

#### 2.1.4 技术改动

**后端**：
- 修改 `adminProductService.js` 的 `createProduct` 和 `updateProduct` 函数，不再接受`original_price`参数
- 在保存商品后，自动从SKU派生`original_price`并更新，派生规则参考 §2.1.3
- 派生逻辑需与PM-05的`card_display_sku_id`字段协同工作：若指定了卡片显示规格，则使用该SKU的`original_price`；否则使用第一个SKU的`original_price`

**Admin Web**：
- 修改 `Edit.vue`，移除`form.original_price`输入框
- 在商品信息区域显示派生的划线价，标注为「由SKU规格派生」
- 派生值的显示需根据PM-05的「卡片显示规格」选择结果动态更新

### 2.2 PM-03：商品提交时校验至少拥有一个SKU

#### 2.2.1 问题描述

商户认为商品必须至少拥有一个规格（无论是否在售），否则商品无法正常销售。当前系统未对此进行校验。

#### 2.2.2 当前实现分析

当前创建商品流程（[Edit.vue](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-admin-web/src/views/product/Edit.vue#L283-L287)）：
```
保存商品基本信息 → 再添加SKU
```

无强制校验，允许商品没有SKU的情况下保存。

#### 2.2.3 改进方案

**方案**：在商品提交时强制校验

| 端 | 校验逻辑 |
|----|----------|
| **Admin Web** | 保存商品前校验`skus.length >= 1`，否则提示「请至少添加一个规格」 |
| **后端** | 保存商品时校验关联SKU数量，否则返回错误码 |

**校验时机**：
- 创建商品时：必须至少有一个SKU
- 更新商品时：必须至少保留一个SKU

#### 2.2.4 技术改动

**后端**：
- 在 `adminProductService.js` 的 `updateProduct` 函数中增加SKU数量校验
- 新增错误码：`PRODUCT_REQUIRES_AT_LEAST_ONE_SKU`（建议码：40060）

**Admin Web**：
- 修改 `Edit.vue` 的 `handleSave` 函数，增加SKU数量校验
- 修改删除SKU逻辑，确保至少保留一个SKU

### 2.4 PM-05：商品卡片价格显示规格可选

#### 2.4.1 问题描述

商户希望可以自由选择在商品卡片（商城标签页的商品展示区中显示的商品卡片）上显示哪一个规格下的价格内容：
- 默认情况下，或未选定规格时，选择商品的第一个规格下的相关价格显示在商品卡片上
- 商户可手动指定某一个SKU规格作为商品卡片价格的展示来源
- 需要保留和兼容其他没有选定规格的商品的显示

#### 2.4.2 当前实现分析

**后端**：
- 当前 [productHelpers.js](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/utils/productHelpers.js#L83-L111) 的 `formatProductListItem` 函数计算商品卡片价格时：
  - 取所有活跃SKU价格的最小值作为 `price`（第87-88行）
  - 取所有活跃SKU中最小的 `original_price` 作为商品级划线价（第89-96行）
- `Product` 模型中无「卡片显示SKU」相关字段

**前端**：
- Admin Web 的商品编辑页面中无「卡片显示规格」选择控件
- 商品卡片预览组件（`ProductCardPreview.vue`）使用父组件传递的价格数据

#### 2.4.3 改进方案

**方案**：新增 `card_display_sku_id` 字段，支持商户指定卡片显示规格

| 端 | 改动 |
|----|------|
| **后端 Model** | 在 `Product` 模型中新增 `card_display_sku_id` 字段（可空） |
| **后端 Service** | 修改 `formatProductListItem` 函数，优先使用指定SKU的价格；未指定时使用第一个SKU的价格 |
| **Admin Web** | 在商品编辑页面添加「卡片显示规格」下拉选择框，列出所有SKU供商户选择 |
| **C端** | C端API响应不变，由后端统一处理价格计算逻辑 |

**价格计算规则**（修改 `formatProductListItem`）：

```
1. 如果 product.card_display_sku_id 已设置且对应SKU存在且在售：
   - price = 指定SKU的 price
   - original_price = 指定SKU的 original_price

2. 否则（未设置或指定SKU无效）：
   - 从所有在售SKU中选取第一个有效的SKU（按 sku_id ASC 排序，status !== 0 && stock > 0）
   - 如果存在在售SKU：
     - price = 该SKU的 price
     - original_price = 该SKU的 original_price
   - 如果不存在在售SKU：
     - 使用原有逻辑（取所有SKU的最低价/最小划线价）保持兼容性
```

> **「第一个SKU」定义**：按 `sku_id` 升序排列后的第一个SKU，即创建时间最早的SKU规格。

> **边缘情况处理**：当商户选定的显示规格SKU被删除或设置为非在售状态时，`formatProductListItem` 在查询时自动回退到第一个有效SKU的价格，不自动修改 `card_display_sku_id` 字段。建议在Admin Web端删除SKU或修改SKU状态时，若该SKU是当前选定的卡片显示规格，给出提示并询问是否更换为其他规格。

> **与PM-02的关联**：PM-02的商品级`original_price`派生规则需同步更新，当 `card_display_sku_id` 存在时，派生值取自指定SKU的`original_price`；否则取第一个SKU的`original_price`。

#### 2.4.4 技术改动

**后端 Model**：
- 修改 `Product.js`，新增 `card_display_sku_id` 字段（`INTEGER`, `NULLABLE`, `COMMENT '商品卡片显示规格ID'`）

**后端 Service**：
- 修改 `productHelpers.js` 的 `formatProductListItem` 函数，按新规则计算价格
- 修改 `adminProductService.js` 的 `createProduct` 和 `updateProduct` 函数，支持 `card_display_sku_id` 参数

**Admin Web**：
- 修改 `Edit.vue`，添加「卡片显示规格」下拉选择框
- 下拉选项：列出所有SKU的规格名称（如"500g/原味"），并添加「默认（第一个规格）」选项
- 修改商品卡片预览组件的数据来源，使用当前选定的显示规格价格
- 删除SKU或修改SKU状态时，若该SKU是当前选定的卡片显示规格，弹出提示询问是否更换为其他规格或设为默认

**数据库迁移**：
```sql
ALTER TABLE products ADD COLUMN card_display_sku_id INTEGER NULL COMMENT '商品卡片显示规格ID' AFTER is_hidden;
```
