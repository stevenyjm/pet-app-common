> 以下为本次评审依据的规范准则速查，详细规则见规范母版。

### A. 必备字段

| 字段类别 | 字段名（强制） | 类型与约束 | 说明 |
|----------|---------------|------------|------|
| 主键 | `{实体}_code` | `VARCHAR(n) PRIMARY KEY`，禁止 `BIGINT AUTO_INCREMENT` | 业务主键 |

### B. 业务主键编码规则

| 实体 | 编码格式 | 字段类型建议 |
|------|----------|--------------|
| 用户 `user_code` | `U00000001`（前缀 `U` + 8 位数字） | `VARCHAR(16)` |
| 其他实体 | **在实际确定数据库表字段时，由用户询问决策** | 按需预留余量 |

> 本模块涉及的实体编码（待用户决策）：
> - 会话编码 `conversation_code`：建议 `VARCHAR(32)`
> - 会话消息编码 `message_code`：建议 `VARCHAR(32)`
> - 消息模板编码 `template_code`：旧表已存在 `VARCHAR(64)`，沿用
> - 预设广播编码 `broadcast_code`：建议 `VARCHAR(32)`
> - 任务执行日志编码 `log_code`：建议 `VARCHAR(32)`

### C. 其他已决策规则

| 规则 | 决策结果 |
|------|----------|
| 时间字段维护方式 | 后端主动推送（移除 DB 自动维护） |
| CONSTRAINT 约束 | 全量移除（引用完整性由后端校验） |
| 字段表源前缀 | 仅易混淆字段加前缀（`status`→`{entity}_status`、`type`→`{entity}_type`、`content`→`{entity}_content`、`name`→`{entity}_name`）；通用字段不加 |
| `is_deleted` 索引 | 移除单列索引；联合索引中 TINYINT 不作首列 |
| COMMENT | 表级与字段级 COMMENT 均不可省略；枚举字段标注取值映射 |
| TEXT/JSON 类型 | 避免使用；短文本用 VARCHAR(n)，数组用子表，结构化对象用扁平字段或子表；若触发分表须先向用户确认 |

#### 建表语句

```sql
CREATE TABLE IF NOT EXISTS `service_conversation` (
  `conversation_id` BIGINT NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `merchant_id` INT NOT NULL DEFAULT 1 COMMENT '一期固定单商户',
  `active_order_id` BIGINT DEFAULT NULL COMMENT '当前咨询订单',
  `active_product_id` BIGINT DEFAULT NULL COMMENT '商品咨询上下文',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '1=open 2=closed',
  `last_message_at` DATETIME DEFAULT NULL,
  `last_message_preview` VARCHAR(200) DEFAULT NULL,
  `unread_admin` INT NOT NULL DEFAULT 0,
  `unread_user` INT NOT NULL DEFAULT 0,

  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`conversation_id`),
  UNIQUE KEY `uk_user_merchant` (`user_id`, `merchant_id`),
  KEY `idx_merchant_last_message` (`merchant_id`, `last_message_at`),
  KEY `idx_active_order` (`active_order_id`),
  CONSTRAINT `fk_service_conv_user` FOREIGN KEY (`user_id`) REFERENCES `user_account` (`user_id`),
  CONSTRAINT `fk_service_conv_order` FOREIGN KEY (`active_order_id`) REFERENCES `order_main` (`order_id`),
  CONSTRAINT `fk_service_conv_product` FOREIGN KEY (`active_product_id`) REFERENCES `product` (`product_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 备注说明

- `conversation_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则
- `user_id` / `active_order_id` / `active_product_id` 为外键 ID 引用，主键改造后需同步改为对应业务编码（`user_code` / `order_code` / `product_code`）
- `status` 字段名易混淆（联表查询时无法区分表源），违反 D2 字段表源前缀规则
- `created_at` / `updated_at` 命名不符 D3 时间字段命名（应为 `create_time` / `last_modified_time`）
- 时间字段使用 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，违反 D3 维护方式规则（应后端推送）
- 3 处 `CONSTRAINT` 外键约束违反 D5，需移除（引用完整性由后端校验）
- 无表级 `COMMENT`
- `unread_admin` / `unread_user` 命名风格不统一（snake_case 下 admin/user 作为后缀可读性可接受，但需保持一致）

CREATE TABLE IF NOT EXISTS `cron_task_execution_log` (

  KEY `idx_task_code_start` (`task_code`, `start_time`),

  KEY `idx_triggered_by_admin` (`triggered_by_admin_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='定时任务执行日志（仅追加流水表，§8.10 豁免 is_deleted；§8.8 豁免 result_summary / error_message）';
