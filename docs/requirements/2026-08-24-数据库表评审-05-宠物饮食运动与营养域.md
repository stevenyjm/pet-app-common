## 开头：评审与决策参考的规范准则

> 以下为本次评审依据的规范准则速查，详细规则见规范母版。

### A. 必备字段

| 字段类别 | 字段名（强制） | 类型与约束 | 说明 |
|----------|---------------|------------|------|
| 主键 | `{实体}_code` | `VARCHAR(n) PRIMARY KEY`，禁止 `BIGINT AUTO_INCREMENT` | 业务主键 |
| 创建时间 | `create_time` | `DATETIME NOT NULL`（无 `DEFAULT CURRENT_TIMESTAMP`，后端推送） | 创建时间 |
| 最后修改时间 | `last_modified_time` | `DATETIME NOT NULL`（无 `DEFAULT`/`ON UPDATE`，后端推送） | 最后修改时间 |
| 逻辑删除标记 | `is_deleted` | `TINYINT NOT NULL DEFAULT 0` | 0-未删除，1-已删除 |

### B. 业务主键编码规则

| 实体 | 编码格式 | 字段类型建议 |
|------|----------|--------------|
| 宠物 `pet_code` | `UP0001`（前缀 `UP` + 4 位数字） | `VARCHAR(16)` |
| 用户 `user_code` | `U00000001`（前缀 `U` + 8 位数字） | `VARCHAR(16)` |
| 其他实体（session/item/template/breed/tag/req/plan/factor/dim 等） | **在实际确定数据库表字段时，由用户询问决策** | 建议 `VARCHAR(32)`，按需预留余量 |

> 注：`pet_code` 外键引用统一为 `VARCHAR(16)`；本模块其他实体主键（如 `meal_session_code`、`template_code`、`breed_code`、`factor_code` 等）建议 `VARCHAR(32)`，编码生成方案待用户决策。

### C. 其他已决策规则

| 规则 | 决策结果 |
|------|----------|
| 时间字段维护方式 | 后端主动推送（移除 DB 自动维护） |
| CONSTRAINT 约束 | 全量移除（引用完整性由后端校验） |
| 字段表源前缀 | 仅易混淆字段加前缀（`status`→`{entity}_status`、`name`→`{entity}_name`、`type`→`{entity}_type`、`period`→`meal_period`、`category`→`tag_category`）；通用字段（`phone`/`email`/`avatar_url`/`create_time`/`sort_order`/`notes`/`unit` 等）不加 |
| `is_deleted` 索引 | 移除单列索引；联合索引中 TINYINT 不作首列 |
| COMMENT | 表级与字段级 COMMENT 均不可省略；枚举字段标注取值映射 |
| TEXT/JSON 类型 | 避免使用；短文本用 VARCHAR(n)，数组用子表，结构化对象用扁平字段或子表；若触发分表须先向用户确认 |
| `status` 字段语义 | `status` 仅表示业务状态枚举（启用/停用、草稿/进行中等），不可替代 `is_deleted` 参与逻辑删除判定 |

### D. 豁免表清单（宠物饮食运动与营养域）

| 表名 | 豁免项 | 豁免理由 |
|------|--------|----------|
| （无） | - | 本模块无豁免表，所有表均须包含 `is_deleted` |

> 本模块所有表均须包含主键 + `create_time` + `last_modified_time` + `is_deleted`。

### E. 本模块特有评审要点

1. **TEXT/JSON 集中分布**：`pet_meal_session.nutrition_reference`（TEXT）、`pet_meal_item.nutrition_json`（JSON）、`pet_meal_template_item.nutrition_json`（JSON）、`pet_exercise_session.ext_json`（JSON）、`pet_breed_dict.temperament_tags`（JSON）/`description`（TEXT）、`pet_nutritional_requirement`（3 个 JSON + 2 个 TEXT）、`pet_exercise_plan.recommended_activities`（JSON）以及多表 `extra_json`（TEXT）均需按 D6 规则改造，给出子表/扁平化替代方案。
2. **GENERATED 列与唯一索引**：`pet_meal_template` / `pet_exercise_template` 使用 `GENERATED ALWAYS AS ... STORED` 列配合唯一索引实现"删除后重建同名模板"，依赖 `status` 字段（1-正常 0-软删）语义；`status` 与 `is_deleted` 语义重复，须改造为基于 `is_deleted` 的方案。
3. **字典表主键既有业务码**：`pet_breed_dict.breed_code`、`pet_breed_tag_dict.tag_code`、`pet_nutrition_factor.factor_code`、`pet_nutrition_factor_dimension.dim_code` 已有业务编码且原为 `UNIQUE`，可直接提升为主键。
4. **主键命名不规范**：`pet_meal_template_meal.id`、`pet_nutrition_factor.id`、`pet_nutrition_factor_dimension.id`、`pet_nutrition_factor_value.id` 使用裸 `id` 命名，须改为业务主键。
5. **纯关联表联合主键**：`pet_nutrition_factor_value` 为因子×维度矩阵单元格值表，属纯关联表，可考虑联合主键 `(factor_code, dim_code)`。
6. **跨模块外键引用**：`pet_meal_formula_item.formula_id` 引用的配方表不在本模块、`sku_id` 引用 `product_sku`，须待对应模块主键改造后对齐。

## 表 1：pet_meal_session（宠物用餐记录主表）

### 第一部分：当前数据表（旧表）

#### 字段介绍

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| session_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| pet_id | BIGINT | NOT NULL | 宠物ID（关联 pet.pet_id） |
| record_date | DATE | NOT NULL | 记录日期（冗余，便于按宠按日查询） |
| period | VARCHAR(16) | NOT NULL | 时段：早上/下午/晚上 |
| meal_time | TIME | NULL | 用餐时间 HH:mm |
| post_meal_status | VARCHAR(32) | NULL | 餐后状态 |
| nutrition_reference | TEXT | NULL | 营养参考（自由文本） |
| remark | VARCHAR(500) | NULL | 备注 |
| sort_order | TINYINT | NOT NULL, DEFAULT 0 | 排序 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 最后更新时间 |
| is_deleted | TINYINT | NOT NULL, DEFAULT 0 | 逻辑删除：0-未删除，1-已删除 |

#### 建表语句

```sql
CREATE TABLE IF NOT EXISTS `pet_meal_session` (
  `session_id` BIGINT NOT NULL AUTO_INCREMENT,
  `pet_id` BIGINT NOT NULL COMMENT '宠物ID（Schema v51，替代原 pet_meal_session_pet 关联表）',
  `record_date` DATE NOT NULL COMMENT '冗余，便于按宠按日查询（Schema v23）',
  `period` VARCHAR(16) NOT NULL COMMENT '早上/下午/晚上',
  `meal_time` TIME DEFAULT NULL,
  `post_meal_status` VARCHAR(32) DEFAULT NULL,
  `nutrition_reference` TEXT,
  `remark` VARCHAR(500) DEFAULT NULL,
  `sort_order` TINYINT NOT NULL DEFAULT 0,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`session_id`),
  KEY `idx_meal_record_date` (`record_date`),
  KEY `idx_meal_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_meal_session_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 备注说明

- `session_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则
- `pet_id` 外键引用需改为 `pet_code VARCHAR(16)`
- 1 处 `CONSTRAINT` 外键约束（含 `ON DELETE CASCADE`），违反 D5（应移除，级联逻辑由后端实现）
- `nutrition_reference` 使用 `TEXT` 类型，违反 D6（建议改 `VARCHAR(n)`；若为结构化快照建议子表）
- `period` 字段名易混淆（联表时无法区分表源），违反 D2 字段表源前缀规则
- `created_at` / `updated_at` 命名不符 D3 时间字段命名（应为 `create_time` / `last_modified_time`）
- 时间字段使用 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，违反 D3 维护方式规则（应后端推送）
- 无表级 `COMMENT`
- `meal_time` / `post_meal_status` / `nutrition_reference` / `remark` / `sort_order` 等字段缺失 `COMMENT`
