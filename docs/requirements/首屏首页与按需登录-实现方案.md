## 1. 文档目的

在**不改变现有业务功能结构**的前提下，完成以下改造：

1. **冷启动首屏**由「登录/注册页」改为**「首页」Tab**（`pages/index/index`）。
2. **浏览与写操作分离**：未登录用户可浏览 Tab 与只读二级页；在**提交订单、购物车去结算、支付/取消/售后/确认收货**等关键动作时，统一引导**注册/登录**。
3. 与微信平台「先体验、后登录」的产品规范对齐，降低审核与投诉风险。

本文档为**实现方案**，不含代码提交；开发完成后需同步更新 §7 所列关联文档与测试清单。

## 2. 现状摘要

### 2.1 冷启动路由（当前）

| 场景 | 当前行为 | 问题 |
|------|----------|------|
| 纯新用户冷启动 | `pages.json` 首项为 `login` → 首屏只见登录 UI | 不符合「进入即可体验业务内容」 |
| 已选游客预览 | 登录页 `onSkip` → 首页 Tab | 需额外一步；首屏仍是登录页 |
| 已登录老用户 | 登录页 `onLoad` → 静默登录成功 → 宠物 Tab | 首屏闪登录页或依赖登录页中转 |
| 未登录非游客进 Tab | `guardTabPageShow` → `reLaunch` 登录页 | 与「首页首屏 + 按需登录」冲突 |

### 2.2 鉴权与 Mock 数据（当前）

| 能力 | 实现位置 | 现状 |
|------|----------|------|
| 浏览放行 | `canBrowseWithoutLogin()` = 已登录 **或** `zzp_guest_mode` | 未点「暂不登录」的用户无法浏览 |
| 写操作拦截 | `requireAuthForAction(actionHint)` | 提交订单 ✅；再来一单/评价/客服 ✅ |
| 订单交易动作 | `services/trade.js` → `handleOrderAction` | 支付/取消/售后/确认收货 **未** 统一鉴权 🟡 |
| 购物车结算 | `cart.vue` → `onCheckout` | 可直接进结算页，仅提交时拦截 🟡 |
| Mock 数据短路 | 各 `services/*` 中 `isGuestPreview()` | 仅显式游客标记触发，需与「未登录浏览」对齐 |

### 2.3 关键代码锚点

```
src/pages.json                          # pages[0] 启动页顺序
src/pages/login/login.vue               # onLoad 冷启动中转逻辑
src/pages/index/index.vue               # 首页 Tab
src/utils/guest.js                      # canBrowse / redirect / requireAuth
src/utils/tabPageGuard.js               # Tab onShow 鉴权
src/services/trade.js                   # 订单操作统一入口
src/pages/cart/cart.vue                 # 去结算
src/pages/order/checkout.vue            # 提交订单
```

## 3. 目标态设计

### 3.1 用户身份模型（改造后）

| 状态 | 判定 | 浏览 | 写操作 / 交易 |
|------|------|------|----------------|
| **未登录浏览** | `!isLoggedIn()` | ✅ 全站只读 + Mock/本地数据 | ❌ 引导登录 |
| **游客模式**（可选保留） | `isGuestPreview()` | 同未登录浏览 | ❌ 引导登录；UI 展示「游客模式」横幅 |
| **已登录** | `isLoggedIn() && !isGuestMode()` | ✅ API + Mock 回退 | ✅ |

说明：

- **首屏放开后**，未登录用户**无需**先点「暂不登录，先看看」即可浏览；`enterGuestMode()` / 「暂不登录」入口**保留**在登录页与「我的」等位置，用于显式进入「游客模式」提示（P1，非阻塞 P0）。
- **Mock 数据触发条件**统一为 **`!isLoggedIn()`**（见 §4.3），不再依赖是否写入 `zzp_guest_mode`。

### 3.2 冷启动路由（目标）

```
冷启动
  └─ pages[0] = pages/index/index（首页 Tab）
       ├─ attemptSilentWechatLogin()（App.onLaunch，不阻塞渲染）
       │    ├─ 老用户静默成功 → 保持首页（或产品可选：switchTab 宠物 Tab，见 §4.1 备注）
       │    └─ 失败 / 新用户 → 保持首页，展示 Mock 内容
       └─ 用户主动点击「去登录」或触发 requireAuthForAction → navigateTo 登录页
```

**不再**在冷启动时经过 `login.vue` 做路由中转。

### 3.3 按需登录拦截点（目标）

采用**统一函数** `requireAuthForAction(actionHint)`，在动作触发时：

1. Toast：`请先登录后再{actionHint}`（或 Modal，见 §4.5.1）
2. 约 400ms 后 `navigateTo('/pages/login/login')`
3. 可选（P1）：写入 `STORAGE_KEYS.POST_LOGIN_RETURN_URL` 供登录成功后回跳

| 动作 | actionHint 建议 | 优先级 |
|------|-----------------|--------|
| 购物车「去结算」 | `结算` | P0 |
| 结算页「提交订单」 | `提交订单` | P0 ✅ 已有 |
| 订单「立即付款」 | `支付` | P0 |
| 订单「取消订单」 | `取消订单` | P0 |
| 订单「申请售后」 | `申请售后` | P0 |
| 订单「查看进度」（售后） | `查看售后进度` | P0 |
| 订单「确认收货」 | `确认收货` | P0 |
| 订单「查看物流」 | `查看物流` | P1（涉及订单隐私，建议纳入） |
| 订单「再来一单」 | `再来一单` | P0 ✅ 已有 |
| 订单「评价」 | `评价` | P0 ✅ 已有 |
| 订单「联系客服」 | `联系客服` | P0 ✅ 已有 |
| 在线客服发消息 | `联系客服` | P0 ✅ 已有 |

**仍允许未登录的操作**（不拦截）：

- 浏览首页/商城/宠物/订单/我的 Tab
- 查看商品详情、资讯详情
- 加入购物车（本地 Mock 购物车，与现游客逻辑一致）
- 编辑本地 Mock 宠物/地址（预览体验，不产生云端写请求）

## 4. 详细实现方案

### 4.1 启动页调整（P0）

#### 4.1.1 修改 `src/pages.json`

将 `pages/index/index` 调整为 **`pages` 数组第一项**；`pages/login/login` 与 `pages/login/qr-confirm` 仍注册，但后移即可。

**改造前（节选）：**

```json
"pages": [
  { "path": "pages/login/login", ... },
  { "path": "pages/login/qr-confirm", ... },
  { "path": "pages/index/index", ... },
  ...
]
```

**改造后（节选）：**

```json
"pages": [
  { "path": "pages/index/index", ... },
  { "path": "pages/login/login", ... },
  { "path": "pages/login/qr-confirm", ... },
  ...
]
```

#### 4.1.2 调整 `login.vue` 的 `onLoad`

| 项 | 动作 |
|----|------|
| 删除 | 冷启动向首页/宠物 Tab 的 `switchTab` 中转（`isGuestPreview` / `navigateToPetTabAfterAuth` 分支） |
| 保留 | `attemptSilentWechatLogin()` 可保留（用户**主动打开**登录页时尝试恢复会话） |
| 新增 | 若已登录且非游客：登录成功后 `navigateBack` 或 `switchTab` 回来源页（P1）；P0 可简化为 `switchTab` 首页或关闭登录页 |

#### 4.1.3 调整 `App.vue` / 首页 `index.vue`

| 文件 | 动作 |
|------|------|
| `App.vue` | 保持 `onLaunch` 内 `attemptSilentWechatLogin()`；**不要** `reLaunch` 登录页 |
| `index.vue` `onLoad` | 移除 `canBrowseWithoutLogin()` 门闩，**始终**执行 `loadHomeNews()` / `loadHomeCover()` |
| `index.vue` `onShow` | 见 §4.2，不再因未登录踢回登录页 |

**产品可选（P2）**：老用户静默登录成功后自动 `switchTab` 至宠物 Tab——与「首屏=首页」冲突，**默认不做**，若商户要求再开配置项。

### 4.2 浏览鉴权放开（P0）

#### 4.2.1 修改 `src/utils/guest.js`

**方案（推荐，改动最小）：**

```javascript
/** 是否允许当前用户浏览（首屏放开后：恒 true；写操作仍用 requireAuthForAction） */
export function canBrowseWithoutLogin() {
  return true
}

/** 是否应使用 Mock / 本地数据（未登录即 true） */
export function shouldUseLocalMock() {
  return !isLoggedIn()
}

/** 是否处于游客预览（仅控制 UI 横幅，不再控制能否浏览） */
export function isGuestPreview() {
  return isGuestMode() && !isLoggedIn()
}
```

**`redirectToLoginIfNeeded()` 改造：**

- **P0**：改为**恒返回 `false`**（不再 `reLaunch` 登录页），或标记 `@deprecated` 并在调用处删除。
- 二级页原 `onShow` 中的 `redirectToLoginIfNeeded()` 调用：**删除或替换为 no-op**，避免从商品详情等页踢回登录。

**`guardTabPageShow(callback)` 改造（`tabPageGuard.js`）：**

```javascript
export function guardTabPageShow(callback) {
  if (typeof callback === 'function') callback()
  return true
}
```

#### 4.2.2 需检查的 Tab / 二级页

| 页面 | 当前 | 目标 |
|------|------|------|
| 5 个 Tab 页 | `guardTabPageShow` 可能踢登录 | 仅加载数据，不踢 |

| `news/detail`、`news/list` | 同上 | 删除 |
| `cart/cart` | 同上 | 删除；结算见 §4.5 |
| `order/checkout` | 同上 | 删除 onShow 跳转；提交时鉴权 |
| `order/detail` | 同上 | 删除；操作按钮见 §4.5 |
| `message/index` | 同上 | 删除或保留只读 Mock（建议删除跳转） |

**仍保留登录门禁的页面（P0）**——在 `onShow` 或操作前调用 `requireAuthForAction()`：

| 页面 | 原因 |

#### 4.4.0.2 微信平台合规审查

**依据**：微信开放社区 [确保小程序良好的使用](https://developers.weixin.qq.com/community/develop/doc/000ee86d9a8a401fd88160f0766809)、《微信小程序平台运营规范》§15 用户隐私与数据规范——核心要求是**先可浏览、非必要不收集信息、需登录时说明原因、用户拒绝后仍可继续浏览**。

| 审查项 | 产品拟定稿 | 结论 |
|--------|------------|------|
| 是否暗示用户已正式登录 | 「游客用户」+「游客模式」标题 | ✅ 未冒充真实账号 |
| 是否使用技术术语（Mock、本地、云端、同步等） | 拟定稿无此类词汇 | ✅ 比现网旧文案更友好 |
| 是否说明登录后可获得更多能力 | 「登录后可体验完整内容」 | ✅ 方向正确 |
| 措辞是否准确、无歧义 | 「游客模式**预览**」中「模式」与「预览」语义重叠 | 🟡 非违规，但略啰嗦，普通用户可能疑惑「预览什么」 |
| 「完整内容」是否严谨 | 未登录实际可浏览大部分页面，不仅「部分内容」 | 🟡 不会构成虚假宣传，但「完整内容」偏抽象；电商场景下「全部功能」或「下单并保存资料」更易理解 |
| 是否强迫登录才能浏览 | 横幅仅提示 +「去登录」按钮，不阻断滚动浏览 | ✅ 符合「拒绝后仍可浏览」精神（需与 §4.2 首屏放开一并落地） |

**审查结论**：产品拟定稿**整体符合**微信平台相关规定，无必须修改的违规表述；建议在定稿中做**轻量润色**（去冗余、用日常用语），降低误解，**无需**引入 Mock、云端、鉴权等专业词。

#### 4.4.0.3 推荐定稿（采用）

在保留「游客用户 / 游客模式」的前提下，推荐以下用户可见文案（**已实现于 `guest.js` · `mine.vue`**）：

| 场景 | 推荐文案 | 说明 |
|------|----------|------|
| 我的 · 昵称 | **游客用户** | 与产品拟定一致；一眼可知非本人真实昵称 |
| 我的 · 卡片标题 | **游客模式** | 与微信社区「提供游客模式」表述一致 |
| 我的 · 卡片说明 | **你还未登录，可先浏览；登录后可下单并保存资料** | 与 `GUEST_MODE_HINT` / bio 一致 |
| 我的 · 个人介绍默认文案 | **你还未登录，可先浏览；登录后可下单并保存资料** | 口语化、分句清晰；点明「可先逛」与「登录后能做什么」 |
| 登录页 · 跳过后 Toast | **已进入游客模式** | 与卡片标题统一 |
| 设置页 · 退出按钮 | **退出游客模式** | 动作与状态名称一致 |

**未采用的拟定句及原因**：

- 「当前为游客模式**预览**」→ 去掉「预览」，避免与「游客模式」重复。  
- 「体验**完整内容**」→ 改为「**使用全部功能**」，避免用户理解成「还有隐藏页面没展示」。

#### 4.4.0.4 文案禁用清单（用户可见层）

以下词汇**不得**出现在游客模式相关 UI 中：

| 禁用 | 原因 |
|------|------|
| Mock、本地数据、云端、同步、鉴权 | 开发术语，用户难以理解 |
| 预览用户 | 易与「预览模式」旧称混淆，且不如「游客用户」直观 |
| 测试 / 假数据 / 演示 | 可能削弱产品信任感 |
| 绑定手机号才能浏览 | 违反平台「浏览不应强制收集信息」红线 |

### 4.5 写操作鉴权增强（P0）

#### 4.5.1 增强 `requireAuthForAction`（可选 P1）

P0 保持现有 Toast + 跳转；P1 可升级为 Modal，文案示例：

> **需要登录**

按钮：「去登录」/「暂不」—— 用户选「暂不」时**不跳转**，符合微信「拒绝后仍可浏览」。

#### 4.5.2 购物车 · 去结算（P0）

**文件**：`src/pages/cart/cart.vue` → `onCheckout()`

在 `navigateTo` 结算页**之前**增加：

```javascript
if (!requireAuthForAction('结算')) return
```

#### 4.5.3 结算页 · 提交订单（P0）

**文件**：`src/pages/order/checkout.vue` → `onSubmit()`

已有 `requireAuthForAction('提交订单')` ✅；与 `onCheckout` 形成双保险，保留即可。

#### 4.5.4 订单操作统一鉴权（P0）

**文件**：`src/services/trade.js` → `handleOrderAction()`

在 `switch (label)` **各 case 入口**（或提取 `ensureOrderActionAuth(label)`）增加鉴权：

```javascript
const ORDER_AUTH_HINTS = {
  '取消订单': '取消订单',
  '立即付款': '支付',
  '申请售后': '申请售后',
  '查看进度': '查看售后进度',
  '确认收货': '确认收货',
  '查看物流': '查看物流',
}

export async function handleOrderAction(label, order, handlers = {}) {
  const hint = ORDER_AUTH_HINTS[label]
  if (hint && !requireAuthForAction(hint)) return false
  // ... 原有 switch
}
```

**注意**：`再来一单`、`评价`、`联系客服` 已在 case 内或子函数鉴权，避免重复 Toast。

**`payOrder` / `confirmCancelOrder` 等底层函数**：可不重复鉴权，以 `handleOrderAction` 为唯一入口；若订单详情页有绕过 `handleOrderAction` 的调用，需一并排查。

#### 4.5.5 订单详情自动支付（P0）

**文件**：`src/pages/order/detail.vue`

`onLoad` 参数 `action=pay` 时自动触发 `onAction('立即付款')`——将随 `handleOrderAction` 鉴权生效；确认无直连 `payOrder()` 路径。

### 4.6 `request.js` 401 处理（P1）

**文件**：`src/utils/request.js` → `handleUnauthorized()`

| 现状 | 目标 |
|------|------|
