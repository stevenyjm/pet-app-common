## 二、Redis Key 命名规范

### 2.1 命名格式

```
pet:seq:{entity_type}:{date_str}
```

### 2.2 命名规则

| 段 | 说明 | 示例 |
|----|------|------|
| `pet` | 项目固定前缀 | `pet` |
| `seq` | 序列号功能域 | `seq` |
| `{entity_type}` | 实体类型（小写 + 下划线） | `user`、`login_log`、`feedback` |
| `{date_str}` | 北京时间日期（yyyyMMdd） | `20260826` |

### 2.3 当前支持的实体

| 实体类型 | Key 示例 | 编码格式 | 示例编码 |
|----------|----------|----------|----------|
| `user` | `pet:seq:user:20260826` | U + yyyyMMdd + 4位流水号 | U202608260001 |
| `login_log` | `pet:seq:login_log:20260826` | LL + yyyyMMdd + 4位流水号 | LL202608260001 |
| `feedback` | `pet:seq:feedback:20260826` | FB + yyyyMMdd + 4位流水号 | FB202608260001 |

### 2.4 TTL 策略

- **TTL**：48 小时（172800 秒）
- **理由**：确保跨日边界安全（午夜前创建的 key 在次日仍有效），48 小时后自动清理过期 key
- **首次创建时设置 TTL**：使用 Redis `INCR` 返回值为 1 时触发 `EXPIRE`

### 2.5 操作命令

| 操作 | 命令 | 说明 |
|------|------|------|
| 获取下一个序号 | `INCR pet:seq:{entity}:{date}` | 原子自增，返回新值 |
| 设置 TTL | `EXPIRE pet:seq:{entity}:{date} 172800` | 仅首次创建时设置 |
| 查询当前序号 | `GET pet:seq:{entity}:{date}` | 不自增，仅读取 |
| 查询 TTL | `TTL pet:seq:{entity}:{date}` | 查看剩余过期时间 |

## 三、Redis 故障降级方案

### 3.1 降级触发条件

- Redis 连接失败（`checkRedisConnection` 返回 `connected: false`）
- Redis 未配置（`REDIS_HOST` 环境变量未设置）
- Redis 命令执行超时

### 3.2 降级路径：DB 行锁计数表

当 Redis 不可用时，自动切换到 MySQL `seq_counter` 表 + `SELECT ... FOR UPDATE` 行锁方案：

```
请求 generateCode(entity_type)
    ↓
尝试 Redis INCR
    ├── 成功 → 返回序号 ✅
    └── 失败（Redis 不可用）
        ↓
开启 DB 事务
    ├── SELECT ... FOR UPDATE（行锁）
    ├── findOrCreate（counter_code）
    ├── current_seq + 1
    ├── UPDATE current_seq
    └── 提交事务 → 返回序号 ✅
        ↓
异步尝试同步 DB → Redis（不阻塞主流程）
```

### 3.3 懒同步机制

Redis 恢复后，DB 降级期间产生的序号会异步同步回 Redis：

1. 每次从 DB 降级路径获取序号后，触发异步 `syncDBToRedis`
2. 比较 Redis 当前值与 DB 值，若 DB 值 > Redis 值，则 `SET` 覆盖
3. 同步失败不影响主流程（catch 静默处理）

### 3.4 双重故障

当 Redis 和 DB 均不可用时：
- 抛出 `Error`，拒绝服务
- 上层调用方应捕获异常并返回 HTTP 500

### 3.5 降级方案特性

| 特性 | 说明 |
|------|------|
| 数据一致性 | Redis 和 DB 计数器可能有短暂不一致，但 DB 降级路径使用行锁保证不重复 |
| 性能 | Redis 主路径：~1ms；DB 降级路径：~10-50ms（行锁开销） |
| 恢复 | Redis 恢复后自动通过懒同步追上最新序号 |
| 并发安全 | Redis INCR 原子操作；DB 使用 `FOR UPDATE` 行锁 |

## 四、降级计数表 seq_counter

### 4.1 字段信息

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| counter_code | VARCHAR(64) | PK | 计数器编码（格式：{entity_type}_{date_str}，如 user_20260826） |
| entity_type | VARCHAR(32) | NOT NULL | 实体类型（user/login_log/feedback 等） |
| date_str | VARCHAR(8) | NOT NULL | 日期字符串（yyyyMMdd，如 20260826） |
| current_seq | INT | NOT NULL, DEFAULT 0 | 当前已分配的最大序号 |
| create_time | DATETIME | NOT NULL | 创建时间（北京时间 UTC+8，格式 yyyy-MM-dd HH:mm:ss） |
| last_modified_time | DATETIME | NOT NULL | 最后修改时间（北京时间 UTC+8，格式 yyyy-MM-dd HH:mm:ss） |
| is_deleted | TINYINT | NOT NULL, DEFAULT 0 | 逻辑删除：0-未删除，1-已逻辑删除 |

### 4.2 建表语句

```sql
CREATE TABLE IF NOT EXISTS `seq_counter` (
  `counter_code` VARCHAR(64) NOT NULL COMMENT '计数器编码（格式：{entity_type}_{date_str}，如 user_20260826）',
  `entity_type` VARCHAR(32) NOT NULL COMMENT '实体类型（user/login_log/feedback 等）',
  `date_str` VARCHAR(8) NOT NULL COMMENT '日期字符串（yyyyMMdd，如 20260826）',
  `current_seq` INT NOT NULL DEFAULT 0 COMMENT '当前已分配的最大序号',
  `create_time` DATETIME NOT NULL COMMENT '创建时间（北京时间 UTC+8，格式 yyyy-MM-dd HH:mm:ss）',
  `last_modified_time` DATETIME NOT NULL COMMENT '最后修改时间（北京时间 UTC+8，格式 yyyy-MM-dd HH:mm:ss）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`counter_code`),
  KEY `idx_entity_date` (`entity_type`, `date_str`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='序列号计数器（Redis 降级方案，仅 Redis 不可写时使用）';
```

## 五、代码实现

### 5.1 文件清单

| 文件 | 说明 |
|------|------|
| `pet-app-backend/utils/seqGenerator.js` | 序列号生成器核心（Redis 主路径 + DB 降级） |
| `pet-app-backend/models/SeqCounter.js` | 降级计数表 Sequelize Model |

| `pet-app-backend/scripts/verify-db.js` | 已添加 `seq_counter` 校验项 |

### 5.2 API

```javascript
const { generateCode } = require('../utils/seqGenerator');

// 生成用户编码
const userCode = await generateCode('user');        // 如 "U202608260001"

// 生成登录日志编码
const loginLogCode = await generateCode('login_log'); // 如 "LL202608260001"

// 生成反馈编码
const feedbackCode = await generateCode('feedback');  // 如 "FB202608260001"
```

### 5.3 扩展新实体

如需支持新的序列号实体，在 `seqGenerator.js` 的 `ENTITY_CONFIG` 中添加配置：

```javascript
const ENTITY_CONFIG = {
  user: { prefix: 'U', padding: 4 },
  login_log: { prefix: 'LL', padding: 4 },
  feedback: { prefix: 'FB', padding: 4 },
  // 新增实体：
  // order: { prefix: 'ORD', padding: 4 },
};
```

## 六、环境配置

### 6.1 Redis 连接（.env）

```bash
# 启用 Redis（配置 REDIS_HOST 即自动启用）
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
# REDIS_PASSWORD=
# REDIS_DB=0
```

### 6.2 降级行为

- `REDIS_HOST` 未配置时：Redis 路径跳过，直接使用 DB 降级路径
- `REDIS_HOST` 已配置但连接失败：自动降级到 DB 路径，异步尝试恢复 Redis 连接
