## 1. 需求背景与目标

### 1.1 背景

当前宠物档案（`pet` 表）的填写存在如下不足：

1. **宠物性别非必填**：`gender` 字段允许为空（默认 `0` 即"未知"），导致大量宠物档案性别缺失，影响后续营养推荐、健康提示等业务场景的性别差异化逻辑。
2. **宠物名称字数过长**：`name` 字段类型 `VARCHAR(64)`，前端 `maxlength="32"`，允许过长的昵称导致 UI 截断、列表错位。
3. **品种字段为单文本框**：`breed` 字段为单个 `VARCHAR(64)` 文本框，用户自由输入，存在拼写不一、无法结构化筛选、无法统计品种分布等问题。

### 1.2 目标

- 宠物性别在「添加宠物引导卡片」与「编辑宠物档案」两个入口均设为必填，提交时校验。
- 宠物名称字数上限统一为 10 字，前端 maxlength 与后端校验保持一致。
- 宠物品种改为「主类别 + 品种类别 + 品种补充描述」三段式结构化填写，输出格式如 `小型犬 - 柯基`、`小型犬 - 串串 - 柯基+边牧`。

### 2.2 宠物名称字数上限 10 字

| 子项 | 说明 |
|------|------|
| 添加宠物引导卡片 | `maxlength="10"`，输入实时计数 |
| 编辑宠物档案 | `maxlength="10"`，输入实时计数，提交时校验 |
| 后端 | `name` 长度校验为 1~10 字符（trim 后非空） |

### 2.3 宠物品种填写优化

#### 2.3.1 字段结构

```
主类别 - 品种类别 - 品种补充描述
```

输出示例：

- `小型犬 - 柯基`
- `小型犬 - 串串 - 柯基+边牧`
- `小型犬 - 其他 - 柯基混血`

#### 2.3.2 品种类别（单选，默认勾选"从下拉列表中选择"）

| 选项 | 显示控件 | 品种补充描述 |
|------|---------|-------------|
| 从下拉列表中选择 | 品种下拉框（具体品种名） | 不显示 |
| 其他 | 文本输入框 | 限 16 字 |
| 串串 | 搜索多选弹窗 | 至少勾选 1 项，自动拼接为 `品种1+品种2+品种3` |

#### 2.3.3 双向填写流程

- **分支一（先大类后品种）**：主类别 → 品种类别 → 品种/描述 → 提交
- **分支二（先品种后大类）**：品种类别 → 品种（自动锁定主类别）/ 描述 → 主类别 → 提交
- 主类别始终必填；"串串"模式下选主类别不剔除已选品种，跨主类别品种全部保留

#### 2.3.4 校验规则

| 条件 | 提示 |
|------|------|
| 主类别为空 | 请选择主类别 |
| 品种类别为"从下拉列表中选择"且未选品种 | 请选择品种 |
| 品种类别为"其他"且描述为空 | 请输入品种补充描述 |
| 品种类别为"其他"且描述超 16 字 | 输入时实时截断 |
| 品种类别为"串串"且未勾选 | 请至少勾选一个品种 |

## 4. 实现方案

### 4.1 数据库变更方案

#### 4.1.1 `pet` 表字段调整

| 字段 | 变更类型 | 类型 | 约束 | 说明 |
|------|---------|------|------|------|
| name | 调整长度 | VARCHAR(16) | NOT NULL | 名称字数上限 10 字（预留余量 16） |
| breed | 保留为冗余 | VARCHAR(96) | NULL | 后端组装为可读字符串，兼容旧前端 |
| gender | 调整约束 | TINYINT | NOT NULL, DEFAULT 1 | 必填，默认 1（雄性），消除 0=未知语义 |
| breed_main_category | 新增 | VARCHAR(16) | NULL | 主类别：小型犬/中型犬/大型犬/巨型犬 |
| breed_category | 新增 | VARCHAR(32) | NULL | 品种类别：具体品种名 / 其他 / 串串 |
| breed_description | 新增 | VARCHAR(64) | NULL | 品种补充描述（其他/串串时填写） |

> 说明：
> - `breed` 字段保留为冗余字段，由后端在 create/update 时按 `"主类别 - 品种类别"` 或 `"主类别 - 品种类别 - 描述"` 拼装，便于旧接口读取与列表展示。
> - `gender` 默认值改为 `1`，并在服务层强制校验 ∈ {1, 2}，从语义上消除"未知"。
> - 三个新字段允许 NULL，便于存量数据平滑迁移（迁移期间 NULL 表示"未填写结构化品种"）。

#### 4.1.3 迁移 SQL（ALTER TABLE）

```sql
-- 1. name 字段缩短（先清理超长数据，再改类型）
UPDATE `pet` SET `name` = LEFT(`name`, 10) WHERE CHAR_LENGTH(`name`) > 10 AND `is_deleted` = 0;
ALTER TABLE `pet` MODIFY COLUMN `name` VARCHAR(16) NOT NULL COMMENT '宠物名称（上限 10 字，预留 16）';

-- 2. breed 字段扩容（用于冗余可读字符串）
ALTER TABLE `pet` MODIFY COLUMN `breed` VARCHAR(96) DEFAULT NULL COMMENT '品种（冗余可读字符串：主类别 - 品种类别 [- 描述]）';

-- 3. gender 字段约束收紧（先将 0 值更新为 1，再改约束）
UPDATE `pet` SET `gender` = 1 WHERE `gender` = 0 OR `gender` IS NULL;
ALTER TABLE `pet` MODIFY COLUMN `gender` TINYINT NOT NULL DEFAULT 1 COMMENT '性别：1-雄性，2-雌性（必填，不再支持 0=未知）';

-- 4. 新增品种三段式字段
ALTER TABLE `pet`
  ADD COLUMN `breed_main_category` VARCHAR(16) DEFAULT NULL COMMENT '品种主类别：小型犬/中型犬/大型犬/巨型犬' AFTER `breed`,
  ADD COLUMN `breed_category` VARCHAR(32) DEFAULT NULL COMMENT '品种类别：具体品种名/其他/串串' AFTER `breed_main_category`,
  ADD COLUMN `breed_description` VARCHAR(64) DEFAULT NULL COMMENT '品种补充描述：其他时为自定义文本（限16字），串串时为 品种1+品种2+...' AFTER `breed_category`;

-- 5. 存量数据回填（尝试从 breed 文本反解析）
-- 注：存量 breed 为自由文本，无法 100% 准确反解析，仅做尽力而为的回填
-- 详细回填策略见 §4.1.4

-- 6. 新增品种主类别索引（用于按主类别统计/筛选）
ALTER TABLE `pet` ADD KEY `idx_breed_main_category` (`breed_main_category`);
```

#### 4.1.4 存量数据迁移策略

由于存量 `breed` 字段为自由文本，无法精确反解析为三段式结构。迁移策略如下：

1. **阶段一（迁移脚本执行时）**：所有存量记录的 `breed_main_category`/`breed_category`/`breed_description` 保持 NULL，`breed` 字段保留原文本。
2. **阶段二（用户下次编辑时）**：用户编辑宠物档案时，前端检测到 `breed_main_category` 为 NULL 且 `breed` 非空，进入"品种补录"模式：
   - 显示原 `breed` 文本作为参考
   - 强制用户重新选择主类别 + 品种类别 + 补充描述
   - 提交后写入三个新字段，并同步更新 `breed` 冗余字段
3. **阶段三（兜底统计）**：对长期不活跃用户的记录，可由后端定期脚本尝试关键字匹配（如 `breed` 包含"柯基"→ 推断为中型犬/柯基犬），但不强制覆盖，仅填充 NULL。

### 4.2 后端接口变更方案

#### 4.2.1 请求体字段变更

`POST /pets` 与 `PUT /pets/{pet_id}` 请求体新增字段：

| 字段 | 类型 | 必填 | 校验 | 说明 |
|------|------|------|------|------|
| name | string | 是 | 1~10 字符（trim 后） | 宠物名称 |
| gender | integer | 是 | ∈ {1, 2} | 性别（必填） |
| breed_main_category | string | 是 | ∈ {小型犬, 中型犬, 大型犬, 巨型犬} | 品种主类别 |
| breed_category | string | 是 | 具体品种名 或 "其他" 或 "串串" | 品种类别 |

| breed | string | 否 | - | 不再由前端传入，由后端组装（若传入则忽略，以后端组装为准） |

> 旧字段 `breed` 仍在响应中返回（冗余可读字符串），便于兼容旧前端展示。

#### 4.2.2 服务层校验逻辑

```javascript
// petService.createPet / updatePet 新增校验
function validatePetBreedFields(body) {
  const { breed_main_category, breed_category, breed_description } = body;

  // 主类别必填且枚举合法
  const VALID_MAIN = ['小型犬', '中型犬', '大型犬', '巨型犬'];
  if (!breed_main_category) {
    throw new AppError('请选择主类别', codes.INVALID_PARAMS, 400);
  }
  if (!VALID_MAIN.includes(breed_main_category)) {
    throw new AppError('主类别值无效', codes.INVALID_PARAMS, 400);
  }

  // 品种类别必填
  if (!breed_category) {
    throw new AppError('请选择品种类别', codes.INVALID_PARAMS, 400);
  }

  // 品种类别为"其他"或"串串"时，补充描述必填
  if (breed_category === '其他') {
    if (!breed_description || breed_description.trim().length === 0) {
      throw new AppError('请输入品种补充描述', codes.INVALID_PARAMS, 400);
    }
    if (breed_description.length > 16) {
      throw new AppError('品种补充描述上限 16 字', codes.INVALID_PARAMS, 400);
    }
  } else if (breed_category === '串串') {
    if (!breed_description) {
      throw new AppError('请至少勾选一个品种', codes.INVALID_PARAMS, 400);
    }
    // 校验格式：品种1+品种2+...
    if (!/^[^+]+(\+[^+]+)+$/.test(breed_description) && !/^[^+]+$/.test(breed_description)) {
      throw new AppError('品种补充描述格式无效', codes.INVALID_PARAMS, 400);
    }
  } else {
    // 具体品种名：校验是否在主类别对应的品种列表中
    const BREED_DATA = {
      '小型犬': ['吉娃娃','博美犬','贵宾犬','泰迪','约克夏梗','法国斗牛犬','巴哥犬','马尔济斯犬','雪纳瑞'],
      '中型犬': ['柯基犬','柴犬','边境牧羊犬','可卡犬','萨摩耶','中华田园犬'],
      '大型犬': ['金毛寻回犬','拉布拉多寻回犬','德国牧羊犬','哈士奇','罗威纳犬'],
      '巨型犬': ['大丹犬','阿拉斯加雪橇犬','圣伯纳犬']
    };
    const validBreeds = BREED_DATA[breed_main_category] || [];
    if (!validBreeds.includes(breed_category)) {
      throw new AppError('品种类别与主类别不匹配', codes.INVALID_PARAMS, 400);
    }
  }
}

// 组装冗余 breed 字段
function buildBreedString(body) {
  const { breed_main_category, breed_category, breed_description } = body;
  if (breed_category === '其他' || breed_category === '串串') {
    return `${breed_main_category} - ${breed_category} - ${breed_description}`;
  }
  return `${breed_main_category} - ${breed_category}`;
}
```

```javascript
    gender: form.gender,  // 必传
    breed_main_category: form.breedMainCategory,
    breed_category: form.breedCategory,
  };
  if (form.breedCategory === '其他' || form.breedCategory === '串串') {
    payload.breed_description = form.breedDescription;
  }
  if (form.birthday) payload.birthday = form.birthday;
  if (form.avatarUrl) payload.avatar_url = form.avatarUrl;
  return payload;
}
```

## 8. 兼容性与风险

### 8.1 兼容性

| 场景 | 兼容方案 |
|------|---------|
| 旧版小程序前端访问新后端 | 旧前端读 `breed` 冗余字段仍可正常展示；旧前端发起的 create/update 请求若不包含新字段，后端返回 400 错误并提示升级 |
| 新版小程序前端访问旧后端 | 不存在（强制后端先发布，前端再发布） |
| 存量宠物档案 | `breed_main_category` 等三字段为 NULL，用户编辑时强制补录（§4.1.4） |
| `gender=0` 的存量数据 | 迁移脚本统一更新为 1（雄性），用户可后续编辑修正 |

### 8.2 风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 存量 `breed` 文本无法精确反解析为三段式 | 中 | 阶段二强制用户补录，不自动覆盖 |
| `gender=0` 数据被统一改为 1 可能有误 | 低 | 仅作为默认值，用户可在编辑时修正 |
| name 长度缩短导致超长名称被截断 | 低 | 迁移前先 UPDATE 截断，不直接改字段类型 |
| 跨主类别串串品种语义争议 | 低 | 当前需求允许保留，不做剔除 |
| 旧前端发起请求被 400 拒绝 | 中 | 发布前公告；过渡期可短暂开放"breed 字段兼容"开关（不建议） |
