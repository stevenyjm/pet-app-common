## 二、根因分析

### 数据流追踪

```
权限配置弹窗数据流：
  前端 RolePermissions.vue
    ├── groups（权限分组）← GET /admin/admin-permissions ← PERMISSION_MODULES（代码常量，非DB）
    └── checkedSet（已勾选）← GET /admin/admin-roles/:id/permissions ← admin_role_permission 表

信息注册台卡片数据流：
  前端 registration/Index.vue
    └── visibleCards ← ALL_CARDS.filter(card => authStore.hasPermission(card.permission))
      └── authStore.permissions ← GET /admin/permissions ← ALL_PERMISSIONS（超管）或 admin_role_permission（非超管）
```

### 根因 1：后端服务未重启（主要原因）

`adminPermissions.js` 代码已正确修改：
- ✅ `PERMISSION_MODULES` 已删除 `content` 模块
- ✅ `registration` 已迁入 `article:view/edit` + 新增 `registration:nutrition_dict_manage`
- ✅ `workbench` 已迁入 `cms:view/edit` + `shop_config:view/edit`
- ✅ `ALL_PERMISSIONS = Object.values(ADMIN_PERMISSIONS)` 已包含新权限码

但 Node.js 模块在进程启动时加载，运行中的后端进程仍持有旧版本的 `adminPermissions.js`，导致：
- `GET /admin/admin-permissions` 返回旧的 `PERMISSION_MODULES`（含 content 模块）
- `GET /admin/permissions`（超管）返回旧的 `ALL_PERMISSIONS`（不含 `registration:nutrition_dict_manage`）

→ **影响**：超级管理员看到的权限矩阵和卡片均为旧结构。

### 根因 2：`normalizePermissionCode` 与 `stripDeprecatedPermissionCodes` 顺序颠倒（代码 Bug）

在 `controllers/adminPermissionController.js` 中，非超管角色的权限查询路径存在逻辑缺陷：

**`getCurrentPermissions`（第 73-89 行）**：
```js
// 非超管：先查关联表
const records = await AdminRolePermission.findAll({ ... });
permissions = stripDeprecatedPermissionCodes(records.map(r => r.permission_code));
// ❌ 直接剔除：product:nutrition_dict ∈ DEPRECATED_PERMISSION_CODES → 被删除
// ❌ 未做 normalize：product:nutrition_dict → registration:nutrition_dict_manage 的映射未执行
//   结果：旧码被剔除，但新码未注入 → 权限丢失
```

**`getRolePermissions`（第 139-145 行）**：存在同样问题。

**对比**：`updateRolePermissions`（第 206-214 行）的写入路径是正确的：
```js
const normalized = normalizePermissionCode(code);  // ✅ 先 normalize
if (validSet.has(code) || normalizedValid.has(normalized)) {
  validIncoming.push(normalized);  // ✅ 写入的是规范化后的新码
}
```

→ **影响**：即便重启后端，已有 `product:nutrition_dict` 权限的非超管角色（如 operations）在查询时：
1. 旧码 `product:nutrition_dict` 被 `stripDeprecatedPermissionCodes` 剔除
2. 新码 `registration:nutrition_dict_manage` 未被注入
3. 前端 `checkedSet` 中缺少该权限 → 卡片/菜单不可见

### 根因 3：前端缓存的权限数据可能过期

`authStore` 将权限列表缓存到 `localStorage`（key: `pet_admin_permissions`），后端重启后如果前端未主动刷新，可能继续使用旧缓存。

→ **影响**：即使后端已修复，首次打开仍可能看到旧数据，需刷新页面或重新登录。

## 三、修复方案

### 3.1 修复一：调整 `getCurrentPermissions` 和 `getRolePermissions` 的 normalize-then-strip 顺序

**修改文件**：`pet-app-backend/controllers/adminPermissionController.js`

**`getCurrentPermissions`（第 78-79 行）**：

修改前：
```js
permissions = stripDeprecatedPermissionCodes(records.map(r => r.permission_code));
```

修改后：
```js
// 先 normalize（旧码 → 新码，如 product:nutrition_dict → registration:nutrition_dict_manage）
// 再 strip（剔除弃用码，已规范化的新码不会被误删）
permissions = stripDeprecatedPermissionCodes(
  records.map(r => normalizePermissionCode(r.permission_code))
);
```

**`getRolePermissions`（第 145 行）**：

修改前：
```js
permissions = stripDeprecatedPermissionCodes(records.map(r => r.permission_code));
```

修改后：
```js
permissions = stripDeprecatedPermissionCodes(
  records.map(r => normalizePermissionCode(r.permission_code))
);
```

**原理**：
1. `normalizePermissionCode` 将 `product:nutrition_dict` 映射为 `registration:nutrition_dict_manage`
2. 规范化后的 `registration:nutrition_dict_manage` 不在 `DEPRECATED_PERMISSION_CODES` 集合中
3. `stripDeprecatedPermissionCodes` 不会误删
4. 同时兼容其他历史别名（如 `log:view` → `audit_log:view`）

### 3.2 修复二：后端服务重启

代码修改提交后，需重启后端 Node.js 进程以加载新的 `adminPermissions.js`：

```bash
# 在 pet-app-backend 目录下
npm run dev  # 或 pm2 restart / node 直接重启
```

**重启后验证**：
```bash
# 验证 1：权限分组结构（应无 content 模块）
curl GET /admin/admin-permissions | jq '.groups[].module'
# 期望：dashboard, order, product, inventory, user, pet, registration, workbench, task_platform, system
# 不应出现：content

# 验证 2：超管权限列表（应包含 registration:nutrition_dict_manage）
curl GET /admin/permissions | jq '.permissions | contains(["registration:nutrition_dict_manage"])'
# 期望：true
```

### 3.3 修复三：前端刷新与权限缓存清理

后端重启后，前端需确保加载新权限数据：

1. **强制刷新页面**（Ctrl+Shift+R 或 Cmd+Shift+R）
2. 或**退出重新登录**（清空 localStorage 缓存）
3. 如果仍有问题，手动清除 localStorage 中 `pet_admin_permissions` 键

### 3.4 修复四（可选）：数据库层面历史数据清理

当前 `admin_role_permission` 表中可能存在历史弃用码（`batch:view`、`reminder_tag:view`、`reminder_tag:edit`、`product:nutrition_dict`），虽然代码层已做 normalize+strip 处理，但建议在下次有 MySQL 环境时执行一次清理：

```sql
-- 清理历史弃用权限码
DELETE FROM admin_role_permission 
WHERE permission_code IN ('batch:view', 'reminder_tag:view', 'reminder_tag:edit');

-- product:nutrition_dict 迁移为 registration:nutrition_dict_manage
UPDATE admin_role_permission 
SET permission_code = 'registration:nutrition_dict_manage' 
WHERE permission_code = 'product:nutrition_dict';
```
