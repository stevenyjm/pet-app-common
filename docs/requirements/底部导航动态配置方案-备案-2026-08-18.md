## 一、备案目的

本文档完整记录底部导航动态配置方案的三端架构、核心代码文件清单和关键设计决策。当前项目已确认采用**静态化方案**（详见 [实施总纲](./底部导航静态化方案实施总纲-2026-08-18.md)），动态配置方案不再使用。

若未来商户需要恢复"底部导航自助配置"能力，可参考本文档重新实现。

## 二、原动态配置架构概览

### 2.1 三端数据流

```
商户管理端 Dock.vue
  → PUT /admin/mini-app-config/dock/draft
  → POST /admin/mini-app-config/dock/publish
后端 miniAppConfigService.js
  → 存入 mini_app_config 表（草稿/发布分离，版本自增，发布历史，回滚）
  → Redis 缓存 + DB fallback
C 端 GET /api/v1/mini-app-config/public?keys=dock
  → pet-app stores/dockConfig.js
    → 三级兜底：remote → cache（storage TTL）→ bundled default
  → pet-app utils/tabBarConfig.js
    → buildVisibleTabList() 从 storage 读取配置
  → pet-app custom-tab-bar/index.js
    → setData 渲染图标/文案/背景
```

### 2.2 核心机制

| 机制 | 实现位置 | 说明 |
|------|---------|------|
| 草稿/发布分离 | 后端 `miniAppConfigService.js` | draft (version=0) / published (version≥1) / archived 三态 |
| 版本号自增 | 后端 `publishDock()` | 每次发布 version+1，旧版本归档 |
| 发布历史 | 后端 `getArchivedRows()` | 保留最近 N 条历史，支持回滚 |
| 回滚 | 后端 `rollbackDock()` | 回滚到指定历史版本 |
| Redis 缓存 | 后端 `miniAppConfigService.js` | published 配置走 Redis 缓存 |
| Storage TTL | C 端 `dockConfig.js` | `MINI_APP_CONFIG_CACHE_TTL_MS` 过期清理 |
| 三级兜底 | C 端 `dockConfig.js` | remote → cache → bundled default |
| 配置校验 | 后端 `miniAppConfigValidator.js` | 基于 JSON Schema 校验 |
| 电商导航开关 | C 端 `tabBarConfig.js` | mall/order 的 enabled 同开同关 |

### 2.3 已知缺陷（静态化方案已根除）

| 缺陷 | 根因 | 影响 |
|------|------|------|
| custom-tab-bar 绕过 Pinia store 直读 storage | `tabBarConfig.js` 未调用 `getEffectiveDockConfig()` | storage 被清空时图标回退静态资源 |
| C 端拉取策略过度活跃 | `App.vue` onShow 每次调用 `refreshDockConfigFromRemote()` | 与"跟随版本"诉求不符，资源浪费 |
| 两套默认值未对齐 | `DEFAULT_TAB_LIST` 与 `dock.theme.default.json` 独立硬编码 | 商户撤回时样式不一致 |

## 四、恢复指南

若未来需要恢复动态配置方案，按以下步骤操作：

1. **后端恢复**：从 git 历史中恢复 dock 相关文件（schema、default config、validator、service 函数、路由、控制器），在 `miniAppConfigRegistry.js` 重新注册 dock
2. **管理端恢复**：从 git 历史中恢复 Dock.vue、DockPreviewPanel.vue、dockConfigMerge.ts、dockEcommerceNav.ts，恢复路由和 API 函数
3. **小程序恢复**：从 git 历史中恢复 dockConfig.js store、dockConfigMerge.js、dock.theme.default.json，恢复 App.vue 中的 bootstrap/refresh 调用，恢复 tabBarConfig.js 的 storage 读取逻辑
4. **修复已知缺陷**：恢复后需同步修复三个已知缺陷（custom-tab-bar 改读 Pinia store、App.onShow 改为 stale 阈值、DEFAULT_TAB_LIST 与 bundled default 对齐），详见 [调整分析文档](./底部导航(dock)配置实现方案调整分析-2026-08-18.md) §五

## 五、V3 升级计划（归档）

原计划在动态配置基础上升级到 dock.v3.json，新增 `iconSize` 和 `showLabel` 字段。该计划随静态化方案确认而终止。如未来恢复动态配置，需同步实施 V3 升级：

| 新增字段 | 类型 | 约束 | 说明 |
|---------|------|------|------|
| `slots[].iconSize` | integer | minimum 40, maximum 120, rpx | 图标尺寸 |
| `slots[].showLabel` | boolean | - | 是否显示文案 |
| `slots[].pageName` | string | showLabel=false 时允许空字符串 | 文案内容约束放宽 |

详见 [调整分析文档](./底部导航(dock)配置实现方案调整分析-2026-08-18.md) §5.1。
