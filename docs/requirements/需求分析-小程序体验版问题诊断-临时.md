#### 根因分析

**现象解释**: "压缩中，请稍后"提示来源于：
- `uni.chooseImage()` 参数 `sizeType: ['compressed']` 触发微信小程序内置压缩
- 压缩过程由微信底层处理，前端无法直接控制时长

**可能原因**:

| 原因分类 | 具体分析 | 验证方法 |
|---------|---------|---------|
| **API调用失败** | 后端 `/storage/upload` 接口返回错误，但前端仅捕获并显示"上传失败"，用户可能未注意到 toast 提示的短暂显示 | 检查网络请求日志，查看 uploadFile 返回状态码和响应体 |
| **图片URL问题** | 后端返回的 `url` 或 `public_url` 字段为空、格式错误、或包含特殊字符（如空格/反引号）导致渲染失败 | 在 uploadAvatar 返回后打印 url 值，检查是否为有效 URL |
| **状态更新失败** | 用户头像场景：`updateProfileFields()` 调用失败或返回数据未包含 avatarUrl<br>宠物头像场景：用户未点击「保存档案」按钮，form.avatarUrl 仅停留在临时状态 | 检查 updateProfileFields 的返回值，确认是否包含 avatar_url 字段 |
| **图片缓存问题** | 微信小程序对 image 组件有缓存机制，即使 URL 更新，仍显示旧图片 | 强制刷新页面或使用唯一查询参数 `url + '?t=' + timestamp` |
| **权限问题** | 体验版可能缺少正式版的某些权限配置，导致上传失败但无明确错误提示 | 在真机调试模式查看完整错误堆栈 |

### 2.2 手机号绑定问题

#### 问题描述
用户在「我的」页面点击手机号卡片进行绑定：
1. 弹出模态框"将使用微信授权获取手机号"
2. 点击「确定」后，模态框关闭
3. **再次弹出相同的模态框**
4. 再次点击「确定」后，模ual框关闭

  ```javascript
  async onGetPhoneNumber(e) {
    this.phoneAuthVisible = false
    const phoneCode = e.detail?.code
    if (!phoneCode) {
      uni.showToast({ title: '未授权手机号', icon: 'none' })
      return
    }
    try {
      uni.showLoading({ title: '绑定中…', mask: true })
      await loginWithWechat({ phoneCode })
      await this.loadProfile()
      uni.showToast({ title: '手机号已绑定', icon: 'success' })
    } catch (err) {
      uni.showToast({ title: err.message || '绑定失败', icon: 'none' })
    } finally {
      uni.hideLoading()
    }
  }
  ```

  - 函数: `wechatLogin(data)` → POST `/auth/wechat/login`

#### 根因分析

**现象解释**: 模态框弹出两次的原因：

| 可能原因 | 分析详情 |
|---------|---------|
| **微信授权流程设计** | 微信小程序 `open-type="getPhoneNumber"` 的标准流程为：<br>1. 用户点击 → 微信弹出官方授权弹窗<br>2. 用户同意 → 微信返回加密code<br>3. 前端调用后端解密<br><br>但代码中先显示自定义模态框，确认后才显示授权按钮，按钮点击又触发微信官方弹窗。这导致两次弹窗：自定义框 + 微信官方框 |
| **按钮触发时机** | 当 `phoneAuthVisible = true` 时，隐藏的授权按钮立即显示。微信可能在按钮渲染时自动触发授权流程（某些版本行为） |
| **事件监听问题** | 可能存在多次事件绑定或 `@getphonenumber` 被触发两次 |

**手机号未更新的可能原因**:

| 原因分类 | 具体分析 |
|---------|---------|
| **API调用失败** | `loginWithWechat({ phoneCode })` 调用后端失败，但错误被 catch 捕获，仅显示 toast 提示，用户可能未注意 |
| **phoneCode无效** | 微信返回的 `e.detail.code` 为空或无效，触发"未授权手机号"提示 |
| **后端解密失败** | 后端接收到 code 但无法解密出真实手机号（code过期、小程序配置错误、secret错误） |
| **数据未同步** | `loadProfile()` 未从后端获取最新用户信息，或返回数据未包含 phone 字段 |
| **权限配置问题** | 体验版可能缺少微信手机号授权的必要配置（需在微信公众平台配置） |

#### 关键代码问题

**当前流程设计存在冗余**：
```
用户点击手机号卡片 
→ uni.showModal 自定义提示（第1次弹窗）
→ 用户确认 
→ phoneAuthVisible = true，显示隐藏按钮
→ 微信自动或用户点击触发 getPhoneNumber 
→ 微信官方授权弹窗（第2次弹窗）
→ 用户同意 → 微信返回 code
→ 调用后端 API
```

**优化方案**: 应直接触发微信授权，无需自定义模态框作为前置确认：
```
用户点击手机号卡片
→ 直接显示带有 open-type="getPhoneNumber" 的按钮（或使用 button 包裹卡片）
→ 微信官方授权弹窗（仅1次）
→ 用户同意 → 微信返回 code
→ 调用后端 API
```

> **🔴 根因确认**: 从日志中发现关键错误：

#### 权限配置要求

微信小程序获取手机号需要在微信公众平台进行以下配置：

| 配置项 | 位置 | 说明 |
|-------|------|------|
| **开通能力** | 开发管理 → 接口设置 → 「获取用户手机号」 | 需申请开通，审核通过后生效 |
| **添加体验成员** | 管理 → 成员管理 → 体验成员 | 测试账号必须是体验成员列表中的成员 |
| **实名认证** | 个人小程序账号 | 体验成员需已完成微信实名认证 |
| **类目资质** | 开发管理 → 类目设置 | 部分类目需要提供相关资质证明 |
| **主体认证** | 设置 → 主体设置 | 企业主体小程序权限更完整 |

#### 获取手机号权限申请步骤

1. **登录微信公众平台**: https://mp.weixin.qq.com
2. **进入接口设置**: 开发管理 → 接口设置
3. **找到「获取用户手机号」**: 点击「申请开通」
4. **填写申请理由**: 说明小程序需要手机号的原因
5. **等待审核**: 审核通常 1-3 个工作日
6. **配置权限范围**: 审核通过后，在「接口设置」中配置调用限制

### 2.4 章节目录跳转失效

#### 问题描述
用户在「用户协议」/「隐私政策」/「商家资质」页面：
1. 页面顶部显示章节目录卡片
2. 点击某个章节条目
3. 页面未滚动到对应章节位置
4. 内容停留在当前位置

#### 代码定位

- **信息页面**: [src/pages/info/index.vue](file:///c:\Users\22188\Desktop\宠物生鲜电商开发项目\pet-app\src\pages\info\index.vue)
  - 章节目录渲染: line 40-53
  - 跳转方法: `scrollToSection(idx)` (line 309-336)

- **scroll-view配置**: line 18-27
  ```vue
  <scroll-view
    class="content-scroll"
    scroll-y
    :show-scrollbar="false"
    :scroll-into-view="scrollIntoView"
    :scroll-top="scrollTop"
    scroll-with-animation
    @scroll="onScroll"
  >
  ```

- **章节结构**: line 65-82
  ```vue
  <view
    v-for="(sec, idx) in page.sections"
    :id="'section-' + idx"
    :key="'sec-' + idx"
    class="section"
  >
  ```

#### 根因分析

**scroll-into-view 失效的常见原因**:

| 原因分类 | 具体分析 |
|---------|---------|
| **ID格式问题** | 微信小程序 `scroll-into-view` 要求：<br>1. ID不能以数字开头（如 `id="section-0"` 可能无效）<br>2. ID需为纯小写字母或驼峰格式<br>当前使用 `'section-' + idx`，可能不符合规范 |
| **scroll-top与scroll-into-view冲突** | 同时设置两个属性可能导致冲突，微信小程序优先处理其中一个 |
| **时机问题** | `nextTick` 后立即查询节点位置，但小程序渲染可能尚未完成 |
| **嵌套结构问题** | `scroll-view` 内部的 `view-legal` 可能影响滚动定位 |
| **Vue响应式更新** | `scrollIntoView.value = ''` 后立即 `nextTick`，再设置新值，可能被合并为一次更新导致无效 |

**关键代码问题分析**:

```javascript
function scrollToSection(idx) {
  const targetId = 'section-' + idx
  scrollIntoView.value = ''  // 先清空
  activeSection.value = idx

  nextTick(() => {
    // 使用 createSelectorQuery 计算精确位置
    query.exec((res) => {
      // ...
      scrollTop.value = targetScroll  // 设置 scrollTop
    })
  })
}
```

**问题点**:
1. 设置 `scrollIntoView.value = ''` 但未在新值生效前设置目标值
2. 同时操作 `scrollIntoView` 和 `scrollTop` 可能冲突
3. 小程序 `scroll-into-view` 可能不支持动态 ID 更新

#### 诊断建议

**方案A: 修改ID格式（推荐）**

将章节 ID 改为符合小程序规范的格式：
```vue
<!-- 修改前 -->
<view :id="'section-' + idx" class="section">

<!-- 修改后 -->
<view :id="'sec' + idx" class="section">
<!-- 或 -->
<view :id="'section' + (idx + 1)" class="section">
```

并在跳转方法中同步更新：
```javascript
function scrollToSection(idx) {
  scrollIntoView.value = 'sec' + idx
  activeSection.value = idx
}
```

**方案B: 仅使用 scrollTop**

移除 `scroll-into-view`，完全依赖 `scrollTop` 精确控制：
```javascript
function scrollToSection(idx) {
  const targetId = 'section-' + idx
  
  const query = uni.createSelectorQuery()
  query.select('.content-scroll').boundingClientRect()
  query.select('#' + targetId).boundingClientRect()
  query.exec((res) => {
    const scrollRect = res[0]
    const targetRect = res[1]
    if (!scrollRect || !targetRect) return
    
    // 计算目标位置
    const targetScroll = currentScrollTop + targetRect.top - scrollRect.top - 24
    scrollTop.value = Math.max(0, targetScroll)
  })
}
```

**方案C: 增加渲染延迟**

在 `nextTick` 后增加延迟，确保小程序渲染完成：
```javascript
function scrollToSection(idx) {
  scrollIntoView.value = ''
  nextTick(() => {
    setTimeout(() => {
      scrollIntoView.value = 'sec' + idx
      activeSection.value = idx
    }, 50)  // 增加50ms延迟
  })
}
```

#### 功能可行性评估

**可行性**: ✅ 高

章节跳转是小程序常见功能，主要问题是：
- 当前实现方式与微信小程序 scroll-view 规范不匹配
- 需调整 ID 格式或改用纯 scrollTop 方案

**推荐方案**: 采用方案A（修改ID格式）+ 方案B（scrollTop备选），确保兼容性。
