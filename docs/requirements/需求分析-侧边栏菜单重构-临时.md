# 侧边栏菜单重构需求分析

## 一、现状分析

### 1.1 当前菜单结构

根据 `src/router/index.ts` 路由配置，当前侧边栏共包含 **17 个一级菜单选项**：

### 1.2 问题诊断

**菜单过载问题**：
- 17 个一级菜单选项导致侧边栏过长，需要滚动才能查看全部
- 相关功能分散展示，用户难以快速定位同类业务
- 视觉层级扁平，缺乏清晰的业务分组

**用户体验痛点**：
- 高频操作（如订单相关）与低频操作（如配置类）同等权重展示
- 缺乏业务逻辑关联，增加心智负担

## 二、需求合理性分析

### 2.1 业务逻辑合理性

商户提出的「订单管理」「待发货」「售后管理」归为「订单」分组的需求，具有明确的业务逻辑支撑：

```
订单生命周期：
┌─────────────────────────────────────────────────────────────────┐
│                        订单流程                                   │
├─────────────┬─────────────┬─────────────┬───────────────────────┤
│  订单管理    │   待发货    │   售后管理   │                       │
│ (全部订单)   │ (待处理)    │ (售后申请)   │                       │
└─────────────┴─────────────┴─────────────┴───────────────────────┘

   查看订单      执行发货        处理售后
   管理订单      跟踪物流        退款退货
```

**合理性评分：★★★★★（完全合理）**

## 三、技术可行性分析

### 3.1 现有实现机制

当前 `AdminLayout.vue` 的菜单渲染逻辑：

```typescript
const menuRoutes = computed(() => {
  const layoutRoute = router.getRoutes().find((item) => item.path === '/')
  return (layoutRoute?.children ?? []).filter((item) => !item.meta?.hidden)
})
```

当前仅支持一级菜单渲染，使用 `el-menu-item` 组件，**不支持嵌套子菜单**。

### 3.2 技术改造方案

**方案 A：路由配置改造（推荐）**

通过修改路由配置，添加 `children` 层级，实现菜单嵌套：

```typescript
// 修改前 - 扁平结构
{
  path: 'orders',
  name: 'OrderList',
  component: () => import('@/views/order/List.vue'),
  meta: { title: '订单管理', icon: 'List' },
},
{
  path: 'shipments',
  name: 'Shipments',
  component: () => import('@/views/shipment/Index.vue'),
  meta: { title: '待发货', icon: 'Box' },
},

// 修改后 - 嵌套结构
{
  path: 'orders',
  name: 'OrderGroup',
  component: AdminLayout, // 占位组件或重定向
  meta: { title: '订单', icon: 'List' },
  children: [
    {
      path: '',
      name: 'OrderList',
      component: () => import('@/views/order/List.vue'),
      meta: { title: '订单管理' },
    },
    {
      path: '/shipments',
      name: 'Shipments',
      component: () => import('@/views/shipment/Index.vue'),
      meta: { title: '待发货' },
    },
    {
      path: '/after-sales',
      name: 'AfterSales',
      component: () => import('@/views/after-sales/Index.vue'),
      meta: { title: '售后管理' },
    },
  ],
},
```

**方案 B：布局组件改造**

修改 `AdminLayout.vue`，支持解析自定义菜单配置（非路由驱动）：

```typescript
// 新增菜单配置数据
const menuConfig = [
  {
    title: '订单',
    icon: 'List',
    children: [
      { path: '/orders', title: '订单管理' },
      { path: '/shipments', title: '待发货' },
      { path: '/after-sales', title: '售后管理' },
    ],
  },
  // ...
]
```

### 3.3 技术可行性评估

| 评估维度 | 方案 A（路由驱动） | 方案 B（配置驱动） |
|---------|-------------------|-------------------|
| 改动范围 | 路由配置 + 布局组件 | 布局组件 + 新配置文件 |
| 兼容性 | 高（保持路由机制） | 中（需同步维护两份配置） |
| 扩展性 | 中（受路由结构限制） | 高（灵活配置） |
| 实现复杂度 | 低 | 中 |
| 推荐指数 | ★★★★★ | ★★★☆☆ |

## 四、推荐解决方案

### 4.1 推荐分组方案

```

├── 仪表盘                    ← 独立一级菜单（高频入口）
├── 订单 ▼                    ← 新增分组
│   ├── 订单管理

```

### 4.2 关键技术要点

**1. 路由配置修改**

需要为分组菜单添加父级路由，并调整子路由路径：

- 父级路由设置 `component: AdminLayout` 或重定向到首个子菜单
- 子路由路径保持原有路径不变，避免影响已有链接

**2. 布局组件改造**

修改 `AdminLayout.vue`，支持 `el-sub-menu` 嵌套：

```typescript
// 新增菜单分组判断逻辑
const groupedMenus = computed(() => {
  // 将路由按分组规则组织
})
```

**3. 高亮匹配优化**

需要更新 `activeMenu` 逻辑，确保子菜单选中时父级菜单高亮：

```typescript
const activeMenu = computed(() => {
  const active = route.meta.activeMenu
  if (typeof active === 'string') {
    // 判断是否为子菜单，返回父级路径
    const parentPath = getParentPath(active)
    return parentPath || active
  }
  return route.path
})
```

**4. 折叠状态处理**

当前侧边栏支持折叠（64px），折叠状态下子菜单应显示为 tooltip 形式。

## 五、潜在风险与注意事项

### 5.1 风险评估

| 风险项 | 风险等级 | 影响范围 | 应对措施 |
|-------|:-------:|---------|---------|
| 路由路径变化 | 中 | 外部链接、书签 | 保持子路由路径不变 |
| 菜单高亮异常 | 低 | 用户体验 | 完善 `activeMenu` 逻辑 |
| 折叠状态适配 | 低 | 用户体验 | 测试折叠/展开切换 |
| 仪表盘快捷入口 | 低 | 用户体验 | 保持现有快捷按钮不变 |

### 5.2 兼容性考虑

- **Dashboard 快捷入口**：当前仪表盘有「待发货」「售后管理」快捷按钮，点击后应正确导航到子菜单对应的页面
- **外链引用**：确保现有书签、分享链接仍然有效
- **权限控制**：分组菜单的显示/隐藏应遵循现有权限逻辑

**可行性**：★★★★☆ —— 技术实现方案成熟，风险可控

**优先级**：高 —— 直接改善商户日常操作体验
