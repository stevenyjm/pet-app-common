## 1. 需求背景

当前商户管理端将"商品分类管理""商品管理""资讯管理""营养字典""消息广播"分散在不同导航分组中，且"广播"仅支持即时发送、缺少预设模板库，"宠物营养因子"维度的矩阵式配置完全缺失。为统一"信息注册"入口、沉淀可复用的配置资产，新增左侧导航一级菜单**「信息注册台」**，作为聚合式落地页，内置若干模块卡片，将既有分散模块分离/迁移至此，并新增"预设广播消息""宠物营养因子矩阵"两个全新模块。

同时强化两条数据约束：
1. **商品 SKU 营养信息中的"额外营养素"**：管理员录入/编辑时不再允许自定义，必须取自"营养配置表"已有项。
2. **小程序端餐食记录"额外营养素"**：用户编辑时不再允许自定义，必须取自"营养配置表"已有项（前端 `FoodNutritionForm.vue` 已限制从字典选取，本次需在**后端校验层硬化**，防御绕过前端的提交）。

所有非查询（新增/编辑/软删除）操作均需计入管理员操作日志（`admin_audit_log`）。

## 2. 需求范围

### 2.1 In Scope（本次范围）

- **管理端 · 信息注册台**：新增一级导航 + 落地页（含模块卡片）。
- **管理端 · 商品注册模块**：从原"商品分类管理""商品管理"分离/迁移而来；保留商品分类、商品、商品规格的新增/编辑/软删除能力；商品 SKU 营养信息支持录入/编辑；额外营养素强制取自营养配置表。
- **管理端 · 资讯注册模块**：从原"资讯管理"分离/迁移而来；保留资讯预设的新增/编辑/软删除能力。
- **管理端 · 营养配置表模块**：原"营养字典"功能迁移并更名；管理员可新增/编辑/软删除。
- **管理端 · 预设广播消息模块（全新）**：管理员预设若干条广播消息模板，支持新增/编辑/软删除。
- **管理端 · 宠物营养因子矩阵模块（全新）**：行=营养因子（指标维度，当前为一列）、列=宠物维度（幼年期/成长期/月经期/肥胖/怀孕…，可新增/编辑/软删除）、值=百分比（可编辑）。
- **后端**：新增/调整上述模块所需 Model、迁移脚本、Controller、Route；补齐/新增管理员 CRUD 接口；硬化营养素来源校验（SKU 营养信息与 C 端餐食记录提交）；所有非查询操作接入审计日志。
- **小程序前端**：C 端餐食记录提交时，后端硬化"额外营养素必须来自营养配置表"校验后的字段对齐与异常提示（前端 UI 已限制从字典选取，预计改动极小）。
- **小程序工作台联动（追加 · 依赖小程序工作台 Phase 1）**：商品/分类/资讯软删时增加工作台发布状态检查 + 二次确认 + 同步下架 + 禁止再次发布（详见 §5.4/§5.5 及 `2026-08-21-需求-小程序工作台.md` §5.8）。

### 2.2 Out of Scope（本次不做）

- 信息注册台落地页之外的全局信息架构（订单、进销存、用户服务、宠物、系统、小程序配置等分组）保持不变。
- 既有的"消息广播"即时发送流程（`/messages/broadcast`、`adminBroadcastService`）本次不删不改；预设广播消息与即时广播的关系见 §5.6 决策。
- 商品/SKU/资讯/营养字典的既有业务字段（除 `is_deleted` 补齐外）不做无谓重构。
- C 端资讯浏览、商品选购、餐食记录 UI 主流程不变（仅后端校验硬化 + 必要异常文案对齐）。
- 历史已发出的广播消息、既有 `admin_message_job` 数据保留不动。

## 5. 解决方案

### 5.1 总体策略

1. **文档先行**：先定 API 规范（Phase 1），再后端实现，再前端对接，最后联调（遵循 `multi-project.md` §2）。
2. **迁移优先、新增并行**：商品/资讯/营养字典三模块以后端能力复用为主，重心在管理端 UI 迁移与约束硬化；预设广播、营养因子矩阵为全新建设，后端先行。
3. **最小破坏**：保留既有表名/接口路径/权限码，仅前端文案与导航调整，避免角色矩阵与缓存震荡。
4. **审计全覆盖**：所有写操作统一走 `writeAdminAudit`。

### 5.2 管理端导航重构（D1/D2）

- 新增一级菜单「信息注册台」，路由 `/registration`，落地页 `views/registration/Index.vue`，权限码 `registration:view`。
- 落地页以卡片网格展示 5 个模块卡片，点击进入子页面：
  - 商品注册 → `/registration/product`（聚合页：分类 + 商品 + 商品编辑入口）
  - 资讯注册 → `/registration/article`（列表 + 编辑）
  - 营养配置表 → `/registration/nutrition-config`
  - 预设广播消息 → `/registration/preset-broadcast`
  - 宠物营养因子矩阵 → `/registration/nutrition-matrix`
- 旧菜单项（商品管理/商品分类/营养字典/资讯管理）从分组移除；旧路由保留为 hidden 或 redirect 到新路径，避免书签失效（D2 取 B 的折中：路由 redirect 一版后删除）。
- 权限码保留：`product:view`、`product:category`、`product:nutrition_dict`、`article:view`、`article:edit`，新增 `registration:view` 作为落地页入口权限。

### 5.3 营养字典 → 营养配置表（D3/D4/D5）

- 表名 `nutrition_extra_dict` 不变，接口路径 `/nutrition-extra-dict`（管理端）/`/nutrition-extra-dict`（C 端只读）不变。
- 迁移脚本补 `is_deleted TINYINT NOT NULL DEFAULT 0`；`updated_at` 已存在。
- `nutritionExtraDictService.deleteDict` 收敛为软删（`UPDATE is_deleted=1`）；查询默认带 `is_deleted=0`。
- 新增"额外营养素来源校验"工具 `utils/nutritionSourceValidator.js`（或复用 `nutritionValidator.js`）：传入 `extra[]`，校验每个 `code` 命中启用且未删除的字典项。
- 接入点：
  - 后端 SKU 营养信息保存（`adminProductService.createSku`/`updateSku`）：校验 `nutrition_json.extra[].code`。
  - 后端 C 端餐食记录/餐次项提交（`petService` 餐食相关 Service）：校验 `extra[].code`。

### 5.4 商品注册模块（D9/D10）

- 复用 `adminProductService` 全部既有能力，不新增后端接口。
- 管理端新建聚合页 `/registration/product`，内含"分类管理"与"商品列表"两区，编辑入口复用既有 `product/Edit.vue`、`product/Categories.vue`（可原地迁移或新建包装组件）。
- 补/确认：`adminProductService` 中 `category_id` 存在性校验（若缺则补）。
- 前端按商品分类/类型控制是否展示"营养信息"录入区（非食品类隐藏）。
- SKU 营养信息中"额外营养素"下拉源切到营养配置表（管理端已是对全量字典，需确认 `status=1 AND is_deleted=0` 过滤）。
- **小程序工作台联动（A2/A3，Phase 1 追加任务 L-RG-59/60）**：`softDeleteProduct` / `softDeleteCategory` 增加工作台发布状态检查——若商品/分类已在工作台 `workbench_draft`（`module_type='product_publish'` 且 `publish_status=1`）中发布，返回 40901/40903 状态码触发前端二次确认；带 `force_workbench_offline=true` 重新请求后执行软删 + 同步下架 + 写入 `workbench_item_blocklist` 禁止再次发布。详见 `2026-08-21-需求-小程序工作台.md` §5.8。

### 5.5 资讯注册模块

- 复用 `adminArticleService` 全部能力。
- 管理端 `/registration/article` 列表 + 编辑页，由 `article/List.vue`、`article/Edit.vue` 迁移而来。
- **小程序工作台联动（A2 扩展，Phase 1 追加任务 L-RG-61）**：`softDeleteArticle` 增加工作台发布状态检查——若资讯已在工作台 `workbench_draft`（`module_type='article_publish'` 且 `publish_status=1`）中发布，返回 40904 状态码触发前端二次确认；带 `force_workbench_offline=true` 重新请求后执行软删 + 同步下架 + 写入 `workbench_item_blocklist` 禁止再次发布（W7 扩展，与商品/分类联动逻辑一致）。详见 `2026-08-21-需求-小程序工作台.md` §5.8.3。

### 5.6 预设广播消息模块（全新，D6）

- 新增 Model `PresetBroadcastMessage`（表 `preset_broadcast_message`，字段见 §8.1）。
- 新增 Service `adminPresetBroadcastService.js`：`listPresetMessages`/`createPresetMessage`/`updatePresetMessage`/`softDeletePresetMessage`，均接审计。
- 新增 Controller + Route（`/admin/preset-broadcast`）。
- 管理端新建页面 `/registration/preset-broadcast`：列表 + 新增/编辑/软删表单。
- 与即时广播解耦：本期不自动联动发送；预留"选用预设填充发送表单"为二期增强。

### 5.7 宠物营养因子矩阵模块（全新，D7/D8）

- 新增 3 张表（见 §8.2/8.3/8.4）：
  - `pet_nutrition_factor`（行：营养因子）
  - `pet_nutrition_factor_dimension`（列：宠物维度）
  - `pet_nutrition_factor_value`（单元格值）
- 新增 Service `adminNutritionMatrixService.js`：
  - `listFactors`/`createFactor`/`updateFactor`/`softDeleteFactor`
  - `listDimensions`/`createDimension`/`updateDimension`/`softDeleteDimension`
  - `getMatrix`（返回因子×维度×值的二维结构）/`upsertFactorValue`（批量或单个编辑值）
  - 软删因子/维度时联动软删关联 `value` 行。
- 新增 Controller + Route（`/admin/nutrition-matrix/...`）。
- 管理端新建页面 `/registration/nutrition-matrix`：可编辑表格（行=因子、列=维度、单元格输入百分比），支持新增/编辑/软删行与列。

### 5.8 审计日志接入

- 全新模块（预设广播、矩阵）写操作均调用 `writeAdminAudit`，`resource_type` 示例：`preset_broadcast`、`nutrition_factor`、`nutrition_factor_dimension`、`nutrition_factor_value`。
- 既有模块（营养字典）补齐审计（若缺）。
- `detail` 记录关键字段变更（如 `before`/`after`）。

## 10. 风险与注意事项

1. **`nutrition_extra_dict.is_deleted` 迁移风险**：既有 `deleteDict` 若为硬删，收敛为软删后需确认无其他调用方依赖"删除即消失"语义；C 端字典查询须保持 `status=1 AND is_deleted=0` 双过滤。
2. **额外营养素来源校验的性能**：餐食记录提交可能含多条 `extra`，校验需一次性 `findAll` 字典码集合做 Set 比对，避免逐条查询。
3. **矩阵联动软删**：软删因子/维度时，需在同一事务内软删关联 `value` 行，避免出现孤儿值。
4. **导航迁移的向前兼容**：旧路由 redirect 一版后再删除，避免用户书签/外部链接 404。
5. **预设广播与即时广播的边界**：本期明确解耦，避免误将"预设"理解为"自动发送"。
6. **矩阵"行因子可 CRUD"为倾向方案（D7）**，若评审确认行因子固定，则删除 `pet_nutrition_factor` 表的写接口，仅保留值与维度管理。
