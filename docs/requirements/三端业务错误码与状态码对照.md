# 三端业务错误码与状态码对照

> **版本**：v1.0.1 · 2026-06-15  
> **维护责任**：后端 `pet-app-backend` 为**业务错误码权威源**；本文档为三端（小程序 C 端 · Web 管理端 · 后端 API）**同步对照与规划**总表。  
> **实现锚点**：`utils/businessCodes.js`（业务代码须引用常量，禁止硬编码数字） · `AppError(message, code, httpStatus)` · 响应 `{ code, message, data }`  
> **关联文档**：[项目开发说明-后端.md](../pet-app-backend/docs/项目开发说明-后端.md) §5.19 · [项目开发说明-Web前端.md](../pet-app-admin-web/docs/项目开发说明-Web前端.md) §5.6 · [项目开发说明-小程序前端.md](../pet-app/docs/项目开发说明-小程序前端.md) §5.16

## 1. 术语区分

| 类型 | 字段/位置 | 用途 | 三端约定 |
|------|-----------|------|----------|
| **业务错误码** | 响应 body `code` | API 成功/失败语义；`0` 表示成功 | **以 body `code` 为准**做分支与 Toast |
| **HTTP 状态码** | 响应行 `status` | 传输层分类（401/403/404/422/500 等） | 可与 body `code` **不一致**（如客服 **40051** 常对应 HTTP 404） |
| **领域状态码** | 业务实体字段 | 订单/售后/认证/反馈等**生命周期** | 与错误码分离；用于筛选、Tag、门禁，**勿与 body `code` 混用 |

## 2. 响应 Envelope

### 2.1 成功

```json
{ "code": 0, "message": "success", "data": { } }
```

HTTP 通常为 **200**（少数接口 message 为 `"ok"`，语义相同）。

### 2.2 失败

```json
{ "code": 40001, "message": "具体原因", "data": null }
```

- **前端/Web 优先展示 `message`**，再按 `code` 做分支（401 刷新、403 跳转等）。
- 禁止维护「码 → 固定中文」全量静态表覆盖后端 `message`（多义码见 §4）。

## 4. 多义业务错误码（重要）

以下码**跨模块复用同一数字**，含义由 **请求路径 + `message`** 决定。

### 4.1 `40001` — 通用参数/确认类错误

| 场景 | 典型触发 | 小程序 | Web |
|------|----------|--------|-----|
| 微信登录 | `code` 无效/过期 | `getAuthErrorMessage` 静态文案 | — |
| 用户资料 | 禁写字段、空更新体 | — | — |
| 宠物档案 | 缺 `adoption_date`、日期范围非法 | **`getPetCertErrorMessage` 优先 `message`** | — |
| Admin 二次确认 | CMS/广播/Dock 缺 `confirmed: true` | — | Toast `message` |
| 上传/存储 | 文件类型、key 为空 | `getStorageErrorMessage` | Toast `message` |
| 在线客服 | `after_id`/`before_id` 无效、参数组合非法 | 前端应避免 `after_id=0` 轮询 | — |
| 关于我们 CMS | `content_json` 校验失败 | — | Toast `message` |

**三端约定**

- 除登录模块外，**优先展示后端 `message`**；静态码表仅作 `message` 为空时的兜底。
- **方案 D（待实施）**：将 `adoption_date` 等宠物参数从 `40001` 拆至 **40043–40046**（见 §8.2），减少与微信 `code` 语义混淆。

### 4.2 `40301` — 无权访问

| 场景 | 典型触发 | 小程序 | Web |
|------|----------|--------|-----|
| 宠物权限 | 非所属用户访问 `/pets/{id}` | Toast / 码表 | 一般不触发 |
| Admin 路由隔离 | C 端 JWT 误调 `/admin/*` | — | 跳转 `/403` |
| 管理员账号 | 账号已禁用 | — | 跳转 `/403` 或 Toast |
| 存储 | 无权操作他人资源 | `getStorageErrorMessage` | — |

**Web 约定**：对 `40301` 统一跳转 403 页，无需区分场景。

### 4.3 `40101` — 未登录 / 鉴权失败（隐式多义）

| 场景 | 典型触发 | 说明 |
|------|----------|------|
| C 端 | accessToken 缺失/失效 | `request.js` / Web `http.ts` 触发 refresh |
| Admin 登录 | 账号或密码错误 | **与「未登录」同码**；登录页应 Toast 后端 `message` |

### 4.4 `50000` — 系统繁忙（隐式多义）

| 场景 | 典型 HTTP | 说明 |
|------|-----------|------|
| 扫码 poll 限流 | **429** | 文案「请求过于频繁」 |
| 微信配置缺失 | **500** | 非 mock 环境缺 `APP_ID`/`SECRET` |

文档 §5.19 记 HTTP **500** 为典型值；实现以**实际响应 HTTP** 为准，body `code` 均为 **50000**。

| 段 | 用途 | 规则 |

| **40301–40309** | 权限 | 01 多义；02 家庭组；03 通用 |

| **50000–50009** | 系统/依赖故障 | 00 繁忙；01 内部/邮件；02 存储/支付 |

### 9.2 新增错误码流程（三端同步）

1. 在 `utils/businessCodes.js` 增加常量（后端 PR）。
2. 更新本文档 §7 对应小节 + 后端 §5.19。
3. 小程序：`constants/error-codes.js` + 对应 `get*ErrorMessage`（C 端专属码）。
4. Web：§5.6 Admin 子表或 `error-codes.ts`（仅 Admin 相关码）。
5. 补充 `scripts/verify-*` 断言。

### 9.3 三端 UX 策略对照

| 维度 | 小程序 C 端 | Web 管理端 | 后端 |
|------|-------------|------------|------|
| 码表 | `constants/error-codes.js` 分模块 | 默认 Toast `message`；可选 Admin 子集 | `businessCodes.js` 权威 |
| 401/refresh | `request.js` 自动 refresh | `api/http.ts` refresh 队列 | `authService` / `adminAuthService` |
| 403 | Toast 或跳登录 | **`40301` → `/403`** | middleware |
| 多义码 | 分模块 Helper；**优先 message** | **禁止**静态全表 | 文档 §4 + 具体 message |
| 40412 等「预期空」 | 静默，不 Toast | — | 业务约定 |
