## 1. 背景说明

Web 商户管理端新增用户详情页面（`/users/:id`）和邀请码快速预览功能，需要后端在用户列表接口中返回邀请码相关字段。

当前状态：

- 前端已完成类型定义、页面 UI 和路由配置，等待后端扩展接口

## 2. 需要后端配合的接口

### 2.1 `GET /admin/users` - 用户列表接口

**扩展需求**：在列表响应中返回邀请码相关字段。

#### 当前列表响应字段

```
user_id、nickname、avatar_url、phone（脱敏）、phone_full（完整号，供 Tooltip）、
status、gender、create_time、last_login_time、is_online、pet_count、order_count
```

#### 需要新增的响应字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `invite_code` | string \| null | 用户自己的邀请码（注册时生成，只读） |
| `invited_by_code` | string \| null | 用户填写的他人邀请码 |
| `inviter_user_id` | number \| null | 邀请人用户 ID |
| `invited_at` | string \| null | 填写邀请码时间（ISO 8601 格式） |
| `email` | string \| null | 邮箱（已脱敏或 null） |

#### 建议的数据来源

根据后端 Schema v14（`user_profile` 表）：

```sql
SELECT
  u.user_id,
  u.nickname,
  u.avatar_url,
  u.phone,
  u.phone_full,
  u.status,
  u.gender,
  u.create_time,
  u.last_login_time,
  u.is_online,
  u.pet_count,
  u.order_count,
  p.invite_code,         -- 新增
  p.invited_by_code,     -- 新增（需关联查询或存储）
  p.inviter_user_id,     -- 新增
  p.invited_at,          -- 新增
  p.email                -- 新增
FROM user_account u
LEFT JOIN user_profile p ON u.user_id = p.user_id
-- WHERE ...
```

> **注意**：`invited_by_code` 字段在后端 Schema 中未直接存储，需要通过 `inviter_user_id` 反向关联查询邀请人的 `invite_code`。
