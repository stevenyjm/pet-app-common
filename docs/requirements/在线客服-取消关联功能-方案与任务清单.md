## 1. 文档目的

在联系客服（`pages/service/chat`）已交付的基础上，针对 **「从『我的』等通用入口进入时，顶部仍展示历史关联订单/商品卡片」** 的体验问题，固化产品确认结论，给出 **「取消关联」** 的完整技术方案，并拆分为 **后端** 与 **小程序前端** 可执行任务清单，作为开发与验收依据。

## 2. 产品确认结论（2026-06-14）

| # | 确认项 | 结论 | 方案落点 |
|---|--------|------|----------|
| D1 | 总体方案 | **方案 C（混合）**：卡片提供「取消关联」；**不**在「我的」无参进入时自动清空旧上下文 | §4.1 · §4.3 |
| D2 | 「我的」入口行为 | 从「我的 Tab → 在线客服」无参进入时，**保留**会话已有 `active_order_id` / `active_product_id`，由用户主动取消 | §4.3 |

## 3. 背景与问题

### 3.1 会话模型（现状，不变）

- 每 C 端用户 ↔ 单商户：**一条主会话**（`service_conversation`）。
- 活跃上下文字段：`active_order_id`、`active_product_id`；发送消息时 `related_order_id` 默认等于当前 `active_order_id`。
- `POST /service/conversations/open`：**有参则更新**活跃上下文；**无参则保留**已有上下文。

### 3.2 用户痛点

| 场景 | 现状 | 问题 |
|------|------|------|
| 曾在订单/商品页咨询 | 会话持久保存 `active_order_id` / `active_product_id` | 合理 |
| 从「我的 → 在线客服」无参进入 | 顶部仍展示旧订单/商品卡片 | 用户意图多为**通用咨询**，旧卡片易误导 |
| 用户希望转为普通咨询 | 订单卡片仅有「切换」，商品卡片无操作 | **缺少「取消关联」能力** |

### 3.3 为何不能仅前端隐藏

| 风险 | 说明 |
|------|------|
| 状态不一致 | 刷新或再次 `open` 后卡片复现 |
| 消息上下文错误 | 用户发消息仍携带旧 `related_order_id` |
| 商户侧误导 | Admin 侧栏仍展示旧活跃订单 |

**结论**：必须在后端持久层清空活跃上下文，前端同步更新 UI。

## 4. 技术方案

### 4.1 方案 C 落地说明

```
┌─ 有参入口（订单/商品页「联系客服」）──────────────────┐
│  open(body: order_id / product_id) → 绑定/更新上下文   │
│  顶部展示对应卡片；用户可「切换订单」或「取消关联」      │
└────────────────────────────────────────────────────────┘

┌─ 无参入口（「我的 → 在线客服」等）──────────────────────┐
│  open(body: {}) → 不修改已有上下文（D2）                 │
│  若存在旧上下文 → 仍展示卡片 + 提供「取消关联」（D1）   │
└────────────────────────────────────────────────────────┘

┌─ 用户点击「取消关联」───────────────────────────────────┐
│  DELETE …/active-context → 清空 order + product（D4）  │
│  顶部卡片消失；后续消息 related_order_id = null         │
│  历史消息 related_order_id 不变                          │
└────────────────────────────────────────────────────────┘
```

### 4.2 清空语义

| 字段 | 取消关联后 |
|------|------------|
| `active_order_id` | `NULL` |
| `active_product_id` | `NULL` |
| `active_order` / `active_product` 响应摘要 | `null` |
| 新发送消息的 `related_order_id` | `NULL`（普通咨询） |
| 已有历史消息 | **不修改**（保留当时上下文） |
| Admin 侧栏活跃订单/商品 | 随 `current` 接口返回为空 |

### 4.3 入口行为矩阵（实现后）

| 入口 | URL / body | 是否自动绑定 | 是否自动清空 | 顶部卡片 |
|------|------------|--------------|--------------|----------|
| 订单详情/列表「联系客服」 | `?orderId=` | ✅ 绑定该订单 | ❌ | 展示订单卡片 |
| 商品详情「客服」 | `?productId=` | ✅ 绑定该商品 | ❌ | 展示商品卡片（无订单时） |
| 我的 Tab「在线客服」 | 无参 | ❌ | ❌（D2） | 有旧上下文则展示，可手动取消 |
| 消息中心「查看会话」 | 无参 | ❌ | ❌ | 同上 |

### 4.4 与现有能力关系

| 现有能力 | 关系 |
|----------|------|
| 「切换咨询订单」+ `OrderPicker` | **保留**；与「取消关联」互补（切换 vs 清空） |
| `PUT …/active-order` | **保留**；用于切换到另一订单，非清空 |
| `PUT …/active-product` | **保留**；用于切换商品（本期 UI 未暴露切换商品，接口不动） |

## 5. 交互与 UI 规范（小程序）

### 5.1 展示位置

关联卡片位于 **商户信息条下方、对话区上方**（与现布局一致）：

- `ServiceOrderCard`：`v-if="activeOrder"`
- `ServiceProductCard`：`v-if="activeProduct && !activeOrder"`（订单优先于商品，与现逻辑一致）
- 取消关联后两者均为空，卡片区域不渲染

### 5.2 按钮形态（D3 · D5）

| 元素 | 规范 |
|------|------|
| 位置 | 卡片右侧区域（与「切换」并列或替代其外侧）；**独立点击热区**，不与卡片跳转详情冲突 |
| 形态 | **图标 + 文字**：如 `✕` + 「取消关联」 |
| 样式建议 | 字号 22–24rpx；颜色 `#8a8a8a`；图标与文字间距 4–8rpx；`@tap.stop` 阻止冒泡 |
| 订单卡片 | 保留「切换」；「取消关联」置于「切换」右侧或卡片最右 |
| 商品卡片 | 新增「取消关联」（原无操作按钮） |

### 5.3 反馈

| 事件 | 反馈 |
|------|------|
| 点击「取消关联」 | 无二次确认（D6） |
| 请求中 | 按钮区域可 `disabled` 或轻量 loading，防重复提交 |
| 成功 | Toast：`已取消关联`（或 `已转为普通咨询`，二选一，实现时统一） |
| 失败 | Toast：沿用 `getServiceErrorMessage`；卡片保持展示 |

### 5.4 「我的」页卡片摘要联动

`buildServiceChatEntrySummary` 在 `activeOrder` 存在时会加 `订单 {orderNo} ·` 前缀。取消关联后：

- 用户返回「我的」Tab → `onShow` 已调用 `fetchCurrentServiceConversation` → 摘要应不再带订单前缀（**依赖后端清空后 current 响应正确**）。

## 6. 接口设计（后端）

### 6.1 新增接口（推荐）

| 方法 | 路径 | 说明 |
|------|------|------|
| **DELETE** | `/service/conversations/{id}/active-context` | 清空当前会话全部活跃上下文 |

**请求**

- Header：`Authorization: Bearer {user_jwt}`
- Path：`conversation_id` 须属于当前用户
- Body：无

**成功响应** `200`

```json
{
  "code": 0,
  "data": {
    "conversation": {
      "conversation_id": "123",
      "active_order_id": null,
      "active_product_id": null,
      "active_order": null,
      "active_product": null,
      "unread_user": 0,
      "last_message_preview": "...",
      "last_message_at": "..."
    }
  }
}
```

**错误码（沿用现有段，建议）**

| code | 场景 |
|------|------|
| 40051 | 会话不存在或不属于当前用户 |
| 40052 | 会话已关闭（若业务禁止在 closed 会话操作） |

**幂等**：已是空上下文时再次调用，仍返回 `200` 且 `active_*` 为 `null`（推荐幂等成功，避免前端状态漂移）。

### 6.2 备选方案（不采用，仅记录）

扩展 `PUT …/active-order` 支持 `order_id: null` —— 需分别清 order/product 两次，不符合 D4「一次清空全部」，故 **不采用**。

### 6.3 Admin 端

| 端 | 改动 |
|----|------|
| `pet-app-admin-web` | **无需改代码**；侧栏读会话详情中的 `active_order` / `active_product`，后端清空后自然为空 |
| 可选 P2 | 商户侧增加「用户已取消关联」类审计提示 —— 本期不做 |
