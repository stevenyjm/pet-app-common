## 一、需求背景

### 1.1 问题描述

商户管理端左侧导航中**「进销存」分组菜单不显示**。经排查，根因如下：

1. **后端 `GET /admin/permissions` 接口缺失**：前端登录后调用 `getCurrentAdminPermissions()` 请求 `GET /admin/permissions`，但后端 `routes/admin/index.js` 注册的 32 条路由中无此路由，导致 404，`authStore.permissions` 为空数组。
2. **进销存路由独带 `meta.permission` 约束**：`router/index.ts` 中进销存分组的 17 条路由均配了 `meta.permission`（如 `inventory:dashboard`），而其他分组（订单/商品/用户服务/宠物/内容）无此约束。当权限列表为空时，`AdminLayout.vue` 的 `hasRoutePermission()` 将进销存全部过滤。

### 1.2 需求目标

在修复上述问题（方案 A：新增 `/admin/permissions` 接口）的基础上，进一步完善商户管理端账号体系：

1. **超权账户（super_admin）**：固定账户名和密码，拥有全部操作权限，可新建/删除管理员账户并调整其权限。
2. **全操作审计**：超权账户和管理员账户的每个操作（登录/登出/读写数据/管理员管理等）都需关联"操作执行者"并记录。
3. **操作记录查询**：超权账户可查看操作记录及历史记录，支持按操作者追责定位。

## 三、需求细化

### 3.1 超权账户（super_admin）

#### 3.1.1 账户定义

| 属性 | 规则 |
|------|------|
| 角色编码 | `super_admin`（已存在于 `admin_role` 表） |
| 账户名 | 固定为 `admin`（通过 `ADMIN_SEED_USERNAME` 环境变量配置） |
| 初始密码 | 固定为 `admin123`（通过 `ADMIN_SEED_PASSWORD` 环境变量配置，默认值改为 `admin123`） |
| 权限范围 | 拥有 `ROLE_PERMISSION_MATRIX.super_admin` 即 `ALL_PERMISSIONS` 全部权限 + 隐式 `*` 通配 |
| 不可删除 | 超权账户不可被删除、不可被禁用（`status` 不可设为 0） |
| 不可降级 | 超权账户的 `role_id` 不可被修改为非 super_admin 角色 |
| 密码修改 | 超权账户可自行修改密码，新密码需满足复杂度要求 |
| 密码复杂度 | 至少 6 位，至少包含数字、字母、符号中的两种类型 |

#### 3.1.2 超权账户专属能力

| 能力 | 说明 |
|------|------|
| 新建管理员 | 创建管理员账号，指定用户名/初始密码/角色 |
| 删除管理员 | 逻辑删除（设 `status=0`），不进行物理删除；超权账户自身除外 |
| 禁用/启用管理员 | 切换 `status`（"删除"与"禁用"均为逻辑操作，统一通过 `status` 字段表达） |
| 重置管理员密码 | 由超权账户设置新密码 |
| 分配/调整角色 | 修改管理员的 `role_id` |
| 强制下线管理员 | 使指定管理员的所有设备登出（吊销全部 refresh_token） |
| 查看全部操作日志 | 不受 `admin_user_id` 限制，可按任意操作者筛选 |
| 查看管理员列表 | 查看所有管理员账号信息（脱敏） |

### 3.2 管理员账户（普通管理员）

| 属性 | 规则 |
|------|------|
| 创建方式 | 仅超权账户可创建 |
| 角色分配 | 创建时指定角色，后续可由超权账户调整 |
| 权限来源 | 继承所属角色的权限集合（`admin_role_permission` 表） |
| 登录 | 用户名 + 密码登录 |
| 密码修改 | 可自行修改密码，新密码需满足复杂度要求（至少 6 位，至少包含数字、字母、符号中的两种类型） |
| 操作范围 | 受 `requirePermission` 中间件约束 |
| 审计范围 | 可查看自己的操作日志（见 3.4）；无权修改或删除任何操作日志 |

### 3.3 全操作审计

#### 3.3.1 审计范围

**所有**管理端操作必须记录审计日志，包括但不限于：

| 操作类别 | action 示例 | resource_type 示例 | 说明 |
|----------|-------------|---------------------|------|
| 认证 | `admin_login` / `admin_logout` / `admin_token_refresh` | `auth` | 登录/登出/刷新令牌 |
| 管理员管理 | `admin_create` / `admin_delete` / `admin_disable` / `admin_enable` / `admin_reset_password` / `admin_assign_role` / `admin_force_logout` | `admin_user` | 超权账户管理操作（含强制下线） |
| 订单 | `order_update` / `order_ship` / `order_hide` | `order` | 订单读写操作 |
| 商品 | `product_create` / `product_update` / `product_delete` | `product` | 商品读写操作 |
| 库存 | `inventory_inbound` / `inventory_outbound` / `inventory_adjust` | `inventory` | 库存操作 |
| 批次 | `batch_create` / `batch_update` / `batch_delete` | `batch` | 批次操作 |
| 采购 | `purchase_create` / `purchase_update` | `purchase_order` | 采购操作 |
| 退款 | `refund_approve` / `refund_reject` / `refund_submit` | `refund` | 售后退款 |
| 配置 | `shop_config_update` / `mini_app_config_update` | `config` | 配置变更 |
| 审计日志 | `audit_log_export`（如需导出功能） | `audit_log` | 审计日志自身操作 |

#### 3.3.2 审计日志字段规范

复用现有 `admin_audit_log` 表结构，每条日志包含：

| 字段 | 来源 | 说明 |
|------|------|------|
| `admin_user_id` | `req.admin.adminId` | 操作执行者 ID（FK → admin_user.admin_id） |
| `action` | 调用方传入 | 操作类型标识 |
| `resource_type` | 调用方传入 | 资源模块标识 |
| `resource_id` | 调用方传入 | 被操作资源 ID |
| `detail_json` | 调用方传入 | 操作详情 JSON（变更前后值、参数摘要等） |
| `ip_address` | `req.admin.ipAddress`（中间件已提取） | 操作者 IP |
| `create_time` | `new Date()` | 操作时间 |

#### 3.3.3 审计写入机制

- **已有机制**：`writeAdminAudit()` 工具函数，已在进销存模块的 Controller 中调用。
- **需补充**：在认证流程（登录/登出）和管理员管理接口中补充审计写入。
- **容错策略**：审计日志写入失败不阻塞主业务（已有策略，打 warning 日志即可）。

### 3.4 操作记录查询

#### 3.4.1 查询入口

- **现有入口**：进销存分组下的「操作日志」页面（`/inventory/operation-logs`）。
- **调整方案**：将操作日志页面提升为**独立菜单**（归入「系统管理」分组），使审计功能覆盖全模块。
- **可见性规则**：
  - **超权账户**：可查看全部操作日志，可按任意操作者筛选。
  - **普通管理员**：仅可查看自己的操作日志（后端按 `req.admin.adminId` 强制过滤 `admin_user_id`）。
- **不可变性**：无论超权账户还是普通管理员账户，均**无权修改或删除**操作日志。后端不提供 UPDATE/DELETE 接口。

#### 3.4.2 查询能力

| 查询维度 | 支持情况 | 说明 |
|----------|----------|------|
| 按操作者筛选 | **需新增** | 后端已支持 `admin_user_id` 参数，前端需新增操作者下拉选择 |
| 按模块筛选 | ✅ 已有 | `module` 参数（inventory/batch/expiry/outbound/transfer/purchase/supplier/finance/product） |
| 按 action 筛选 | ✅ 已有 | `action` 参数 |
| 按关键词搜索 | ✅ 已有 | `keyword` 参数（模糊搜索 action/resource_type/resource_id） |
| 按日期范围 | ✅ 已有 | `date_from` / `date_to` |
| 分页 | ✅ 已有 | `page` / `page_size` |

#### 3.4.3 追责定位能力

- 日志列表展示「操作人」列（已有，关联 `admin_user.username`）。
- 支持点击某条日志查看详情（`detail_json` 完整内容）。
- 支持按操作者筛选，查看某管理员的所有操作历史。

**结论：技术可行性高。核心基础设施（表/Model/中间件/工具函数/前端逻辑）均已存在，本方案主要是"补齐缺失接口 + 补充审计覆盖 + 新增管理员管理页面"。**

### 4.2 安全性分析

| 风险点 | 等级 | 缓解措施 |
|--------|------|----------|
| 超权账户默认密码 `admin123` 泄露 | 高 | 部署时建议修改 `ADMIN_SEED_PASSWORD` 为更强密码；首次登录后建议强制改密（二期） |
| 管理员管理接口被越权调用 | 高 | 所有管理员管理接口加 `requireRole('super_admin')` 中间件 |
| 审计日志被篡改/删除 | 中 | 审计日志表不支持 UPDATE/DELETE（后端不提供修改/删除接口，任何角色均无权操作）；数据库层面可考虑只追加（二期） |
| 密码明文传输 | 低 | 已使用 HTTPS（部署层）+ bcrypt 哈希存储 |
| 超权账户被删除 | 高 | 后端硬编码保护：`admin` 用户不可删除/禁用/降级 |
| 操作日志量过大 | 中 | `admin_audit_log` 已有 `(admin_user_id, create_time)` 复合索引；可定期归档（二期） |

### 4.3 性能分析

| 关注点 | 分析 |
|--------|------|
| 权限查询频率 | 每次请求经过 `requirePermission` 会查 DB 获取角色权限。当前未做缓存，但管理员操作量远小于 C 端，可接受。二期可加 Redis 缓存。 |
| 审计日志写入 | `writeAdminAudit()` 为异步写入，不阻塞主流程。已有容错策略。 |
| 审计日志查询 | 已有复合索引 `idx_admin_time(admin_user_id, create_time)`，分页查询性能可控。 |
| 管理员列表查询 | 管理员数量有限（通常 < 50），无性能压力。 |

## 五、实施方案

### 5.1 后端变更

#### 5.1.1 新增 `GET /admin/permissions` 接口（方案 A 核心）

**文件**：新建 `routes/admin/permissionRoutes.js`

**逻辑**：
- 路由 `GET /`，挂载 `adminAuthMiddleware`
- 从 `req.admin.adminId` 获取管理员 ID
- 调用已有的 `getAdminPermissions(adminId)` 函数
- 返回 `{ permissions: string[] }`（snake_case）
- 超权账户返回 `ALL_PERMISSIONS` 数组（含全部权限标识）
- 前端 `hasPermission()` 收到权限列表后，进销存菜单自动显示

**注册路由**：在 `routes/admin/index.js` 添加：
```javascript
const permissionRoutes = require('./permissionRoutes');
router.use('/permissions', permissionRoutes);
```

#### 5.1.2 新增管理员管理 CRUD 接口

**文件**：新建 `controllers/adminUserController.js` + `routes/admin/adminUserRoutes.js`

**接口清单**：

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| `GET` | `/admin/admin-users` | `requireRole('super_admin')` | 管理员列表（分页，脱敏） |
| `POST` | `/admin/admin-users` | `requireRole('super_admin')` | 新建管理员 |
| `DELETE` | `/admin/admin-users/:id` | `requireRole('super_admin')` | 逻辑删除管理员（设 `status=0`，不物理删除；超权账户除外） |
| `PATCH` | `/admin/admin-users/:id/status` | `requireRole('super_admin')` | 禁用/启用管理员 |
| `PATCH` | `/admin/admin-users/:id/password` | `requireRole('super_admin')` | 重置管理员密码 |
| `PATCH` | `/admin/admin-users/:id/role` | `requireRole('super_admin')` | 分配/调整角色 |
| `POST` | `/admin/admin-users/:id/force-logout` | `requireRole('super_admin')` | 强制下线指定管理员（吊销全部 refresh_token，使其所有设备登出；超权账户不可被强制下线） |
| `PATCH` | `/admin/admin-users/me/password` | `adminAuthMiddleware` | 修改自己的密码（所有管理员可用） |

**业务规则**：
- 新建管理员：用户名唯一校验、密码复杂度校验（至少 6 位，至少包含数字、字母、符号中的两种类型）、`role_id` 必须指向 `is_active=true` 的角色
- 删除管理员：采用**逻辑删除**（设 `status=0`），不进行物理删除，保留审计日志 FK 完整性；不可删除 `admin`（超权账户）
- 超权账户保护：不可修改 `admin` 的 `role_id`、不可禁用 `admin`、不可逻辑删除 `admin`
- 每个操作均写审计日志（`admin_create`/`admin_delete`/`admin_disable`/`admin_enable`/`admin_reset_password`/`admin_assign_role`/`admin_force_logout`）
- 强制下线：调用已有的 `revokeAllAdminRefreshTokens(adminId)` 工具函数，吊销该管理员的所有 refresh_token，使其所有设备立即登出；不可对超权账户（`admin`）执行强制下线操作；`admin_force_logout` 审计日志的 `detail_json` 中记录被下线的管理员用户名/ID 及吊销的令牌数量
- 操作日志不可变性：后端不提供操作日志的 UPDATE/DELETE 接口，任何角色（含超权账户）均无权修改或删除操作日志

## 八、补充说明与缺漏补全

### 8.1 审计日志的 `admin_user_id` FK 约束问题

**现有约束**：`admin_audit_log.admin_user_id` 带 FK + `allowNull=false`，必须指向存在的 `admin_user.admin_id`。

**影响**：
- 登录失败时若用户名不存在，无法确定 `admin_user_id`。当前 `writeAdminAudit()` 会降级为 `resolveDefaultAdminUserId()`（取最早的 status=1 管理员），并在 `detail_json` 中标注 `executedBy: 'system'`。
- 删除管理员时，因采用逻辑删除（`status=0`），不物理删除 `admin_user` 记录，FK 完整性不受影响。

**结论**：本方案统一采用逻辑删除，审计日志 FK 约束问题已规避，无需额外处理。

### 8.2 超权账户密码安全

**当前状态**：初始密码固定为 `admin123`（通过 `ADMIN_SEED_PASSWORD` 环境变量配置，默认值为 `admin123`）。

**建议**：
- 部署文档中建议生产环境修改 `ADMIN_SEED_PASSWORD` 为更强密码
- 密码复杂度要求已统一：至少 6 位，至少包含数字、字母、符号中的两种类型
- 一期不实现强制改密（避免增加复杂度）
- 二期可加 `password_changed_at` 字段，首次登录时强制改密

### 8.3 权限粒度

**当前状态**：`inventoryPermissions.js` 定义的权限均为 `模块:操作` 级别（如 `inventory:view`），无按钮级权限。

**建议**：
- 一期保持路由级 + API 级权限控制（`requirePermission` + `meta.permission`）

### 8.4 操作日志容量管理

**风险**：长期运行后 `admin_audit_log` 表数据量增长。

**建议**：

### 8.5 多端会话管理

**当前状态**：`admin_refresh_token` 表支持多设备登录（每个 refresh_token 独立记录），登出可选择吊销单个或全部；`revokeAllAdminRefreshTokens(adminId)` 工具函数已就绪。

#### BE-1.2 新增密码复杂度校验工具函数

| 项 | 内容 |
|----|------|
| 文件 | 新建 `utils/passwordPolicy.js` |
| 逻辑 | 导出 `validatePasswordComplexity(password)` 函数：长度 ≥ 6；至少包含数字、字母、符号中的两种类型；返回 `{ valid: boolean, reason?: string }` |
| 复用 | 被 BE-2.2（新建管理员）、BE-2.3（重置密码）、BE-2.5（修改自己密码）调用 |

```javascript
// utils/passwordPolicy.js 核心逻辑
function validatePasswordComplexity(password) {
  if (!password || password.length < 6) {
    return { valid: false, reason: '密码长度至少 6 位' };
  }
  const hasDigit = /[0-9]/.test(password);
  const hasLetter = /[a-zA-Z]/.test(password);
  const hasSymbol = /[^0-9a-zA-Z]/.test(password);
  const typeCount = [hasDigit, hasLetter, hasSymbol].filter(Boolean).length;
  if (typeCount < 2) {
    return { valid: false, reason: '密码需至少包含数字、字母、符号中的两种类型' };
  }
  return { valid: true };
}
```

```typescript
// src/api/adminUser.ts
import http from './http'
import type { ApiResponse, PaginationResult } from '@/types/api'

export interface AdminUserItem {
  adminId: number
  username: string
  status: number
  roleId: number | null
  roleName: string | null
  roleCode: string | null
  lastLoginTime: string | null
  createTime: string
}

export interface CreateAdminUserPayload {
  username: string
  password: string
  roleId: number
}

export function getAdminUsers(params: {
  page?: number
  pageSize?: number
}): Promise<PaginationResult<AdminUserItem>> {
  return http.get<ApiResponse<PaginationResult<AdminUserItem>>>('/admin/admin-users', { params })
    .then(res => res.data.data)
}

export function createAdminUser(payload: CreateAdminUserPayload): Promise<AdminUserItem> {
  return http.post<ApiResponse<AdminUserItem>>('/admin/admin-users', payload)
    .then(res => res.data.data)
}

export function deleteAdminUser(id: number): Promise<void> {
  return http.delete<ApiResponse<null>>(`/admin/admin-users/${id}`).then(res => res.data.data)
}

export function updateAdminStatus(id: number, status: number): Promise<void> {
  return http.patch<ApiResponse<null>>(`/admin/admin-users/${id}/status`, { status })
    .then(res => res.data.data)
}

export function resetAdminPassword(id: number, password: string): Promise<void> {
  return http.patch<ApiResponse<null>>(`/admin/admin-users/${id}/password`, { password })
    .then(res => res.data.data)
}

export function assignAdminRole(id: number, roleId: number): Promise<void> {
  return http.patch<ApiResponse<null>>(`/admin/admin-users/${id}/role`, { roleId })
    .then(res => res.data.data)
}

export function forceLogoutAdmin(id: number): Promise<{ revokedTokenCount: number }> {
  return http.post<ApiResponse<{ revokedTokenCount: number }>>(`/admin/admin-users/${id}/force-logout`)
    .then(res => res.data.data)
}

export function changeMyPassword(oldPassword: string, newPassword: string): Promise<void> {
  return http.patch<ApiResponse<null>>('/admin/admin-users/me/password', { oldPassword, newPassword })
    .then(res => res.data.data)
}
```
