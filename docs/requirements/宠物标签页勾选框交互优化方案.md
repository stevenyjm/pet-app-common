### 1.3 当前交互问题

| 问题 | 说明 |
|------|------|
| **位置跳跃** | 两套勾选框位置不同（普通模式在右侧，联合模式在左侧），切换时视觉不连贯 |
| **状态断裂** | 进入联合模式时，原本选定的宠物没有自动勾选，用户需要重新选择 |
| **认知成本** | 用户需要适应两种不同位置的勾选框，增加理解成本 |
| **背景色混淆** | 联合模式下高亮背景色仍随勾选变化，导致视觉混乱 |

## 二、优化方案设计

### 2.1 核心思路

将勾选框统一放在左侧，通过样式变化实现模式切换：

| 模式 | 位置 | 样式 | 默认状态 |
|------|------|------|----------|
| **普通模式** | 左侧 | 圆形单选勾选框 | 仅当前宠物显示选中 |
| **联合记录模式** | 左侧 | 方形复选勾选框 | 默认勾选当前宠物 |

### 2.2 交互流程图

```
普通模式                          联合记录模式                        退出联合模式
─────────                        ──────────────                      ─────────────
☉ 豆豆 · 柯基 · 3岁 (高亮)        ☑ 豆豆 · 柯基 · 3岁 (背景不变)       ☉ 豆豆 · 柯基 · 3岁 (恢复高亮)
○ 咪咪 · 英短 · 2岁               ☐ 咪咪 · 英短 · 2岁                  ○ 咪咪 · 英短 · 2岁
○ 旺财 · 金毛 · 4岁               ☐ 旺财 · 金毛 · 4岁                  ○ 旺财 · 金毛 · 4岁
    ↓ 勾选「进行联合记录」            ↓ 用户多选操作                     ↓ 取消「进行联合记录」
☑ 豆豆 · 柯基 · 3岁              ☑ 豆豆 · 柯基 · 3岁                  ☉ 豆豆 · 柯基 · 3岁 (恢复进入前状态)
☐ 咪咪 · 英短 · 2岁              ☑ 咪咪 · 英短 · 2岁                  ○ 咪咪 · 英短 · 2岁
☐ 旺财 · 金毛 · 4岁              ☐ 旺财 · 金毛 · 4岁                  ○ 旺财 · 金毛 · 4岁
                                 (高亮背景始终不变)                     (高亮背景恢复)
```

### 2.3 优化后的状态转换

| 操作 | 状态变化 |
|------|----------|
| 进入联合模式 | 圆形 → 方形，当前宠物自动勾选，**记录当前宠物ID用于退出时恢复** |
| 退出联合模式 | 方形 → 圆形，**恢复进入联合模式前选定的宠物** |
| 点击宠物（普通模式） | 切换当前宠物，圆形勾选框移动，高亮背景跟随变化 |
| 点击宠物（联合模式） | 切换复选勾选状态，支持多选，**高亮背景不跟随变化** |

> **关键设计原则**：联合模式下的勾选操作仅影响 `selectedPetIds`（参与联合记录的宠物列表），不改变 `currentPetId`（普通模式下的当前宠物）。高亮淡绿色背景仅在普通模式下表示当前选定宠物，联合模式下背景色固定不变，避免用户混淆。

## 三、技术实现方案

### 3.1 模板结构调整

采用**两套独立勾选框**方案，分别用于普通模式和联合模式，通过 `v-if` 切换显示。两套勾选框均位于左侧同一位置，确保模式切换时位置不变。

```html
<view class="pet-vertical-item" :class="{ active: currentPetId === pet.id && !isJointMode }" @tap="isJointMode ? togglePetSelection(pet.id) : selectPet(pet.id)">
  <view v-if="!isJointMode && currentPetId === pet.id" class="pet-vertical-check">
    <text class="pet-vertical-check-icon">✓</text>
  </view>
  <view v-else-if="isJointMode" class="pet-vertical-checkbox" :class="{ checked: selectedPetIds.includes(pet.id) }">
    <text v-if="selectedPetIds.includes(pet.id)" class="pet-vertical-checkbox-icon">✓</text>
  </view>
  <view class="pet-avatar pet-avatar--vertical" :class="'pet-avatar--' + pet.avatarTheme">
    <image v-if="pet.avatarUrl" class="pet-avatar-img" :src="pet.avatarUrl" mode="aspectFill" />
    <text v-else class="pet-avatar-emoji">{{ pet.emoji }}</text>
  </view>
  <view class="pet-vertical-info">...</view>
</view>
```

> **设计说明**：普通模式下仅当前宠物显示圆形勾选框（始终为选中状态），其他宠物不显示勾选框；联合模式下所有宠物显示方形复选框，支持多选。这样既保持了普通模式的简洁性，又实现了联合模式的多选功能。

### 3.2 样式调整

两套勾选框样式独立定义，尺寸统一为 44rpx 确保布局一致：

```css
.pet-vertical-check {
  width: 44rpx;
  height: 44rpx;
  border-radius: 50%;
  background: $brand;
  display: flex;
  align-items: center;
  justify-content: center;
  flex-shrink: 0;
  margin-right: 16rpx;
}

.pet-vertical-check-icon {
  font-size: 26rpx;
  color: #fff;
  font-weight: 600;
}

.pet-vertical-checkbox {
  width: 44rpx;
  height: 44rpx;
  border-radius: 8rpx;
  border: 2rpx solid $muted;
  background: #fff;
  display: flex;
  align-items: center;
  justify-content: center;
  flex-shrink: 0;
  margin-right: 16rpx;

  &.checked {
    background: $brand;
    border-color: $brand;
  }
}

.pet-vertical-checkbox-icon {
  font-size: 26rpx;
  color: #fff;
  font-weight: 600;
}

.pet-vertical-item {
  &.active {
    background: $brand-light;
  }
}
```

> **方案选择说明**：采用两套独立勾选框方案，而非单套勾选框交叉淡入淡出方案。原因是两套方案职责分离清晰、代码简洁直观、更符合现有代码风格。虽然无法实现形状过渡动画，但小程序环境下动画收益有限，而代码可维护性的收益是长期的。两套勾选框统一放在左侧同一位置，确保模式切换时位置不变，实现核心优化目标。

### 3.3 逻辑调整

**新增数据字段**：

```javascript
data() {
  return {
    // ... 其他字段
    isJointMode: false,
    selectedPetIds: [],
    previousPetId: '',  // 进入联合模式前的当前宠物ID，用于退出时恢复
  }
},
```

**优化后的 `toggleJointMode` 方法**：

```javascript
toggleJointMode() {
  if (this.pets.length < 2) {
    uni.showToast({ title: '至少需要 2 只宠物', icon: 'none' })
    return
  }
  this.isJointMode = !this.isJointMode
  if (this.isJointMode) {
    this.previousPetId = this.currentPetId  // 保存当前宠物ID
    this.selectedPetIds = this.currentPetId ? [this.currentPetId] : []
  } else {
    if (this.previousPetId) {
      this.currentPetId = this.previousPetId  // 恢复进入联合模式前的宠物
    } else if (this.selectedPetIds.length > 0) {
      this.currentPetId = this.selectedPetIds[0]  // 降级方案：无保存状态时使用第一个勾选的宠物
    }
    this.previousPetId = ''
    this.selectedPetIds = []
  }
},
```

**点击事件调整**：

```javascript
onPetVerticalItemTap(petId) {
  if (this.isJointMode) {
    this.togglePetSelection(petId)
  } else {
    this.selectPet(petId)
  }
},
```

**状态隔离说明**：

| 状态变量 | 作用域 | 联合模式下是否变化 |
|----------|--------|-------------------|
| `currentPetId` | 普通模式下的当前宠物 | ❌ 不变化，仅在退出时恢复 |
| `selectedPetIds` | 联合模式下的参与宠物列表 | ✅ 变化，随勾选操作更新 |
| `previousPetId` | 进入联合模式前的宠物ID | ✅ 仅在进入时赋值，退出时使用 |

## 四、方案合理性评估

### 4.1 优点

| 维度 | 分析 |
|------|------|
| **交互连贯性** | 勾选框位置不变，仅样式变化，过渡更平滑 |
| **状态承接** | 进入联合模式时自动勾选当前宠物，体现"原本选定→一起参与"的关系 |
| **认知一致性** | 用户始终在同一位置操作勾选框，降低学习成本 |
| **视觉区分** | 圆形（单选）vs 方形（多选），符合平台设计规范 |
| **代码简化** | 减少条件渲染逻辑，模板结构更清晰 |

### 4.2 风险评估

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| **样式冲突** | 原有样式可能与新样式冲突 | 使用 CSS 类名隔离，保留 `.pet-vertical-checkbox` 兼容性 |
| **状态同步** | 退出联合模式时需正确恢复当前宠物 | 在 `toggleJointMode` 中处理状态同步，使用 `previousPetId` 保存和恢复 |
| **视觉混乱** | 联合模式下多个项同时高亮造成混乱 | 联合模式下取消 `.pet-vertical-item.active` 背景高亮，仅保留勾选框状态 |
| **向后兼容** | 可能影响已有的联合记录功能 | 保留原有 API 调用逻辑，仅修改 UI 交互 |

### 4.3 可行性判断

| 评估项 | 结论 |
|--------|------|
| **技术复杂度** | ⭐⭐ 低，仅需修改模板和样式 |
| **开发量** | ⭐⭐ 约 1-2 小时 |
| **风险等级** | ⭐ 低，不涉及数据结构变更 |
| **用户体验提升** | ⭐⭐⭐ 显著提升交互流畅度 |

### 5.2 测试要点

| 测试场景 | 预期结果 |
|----------|----------|
| 普通模式下点击宠物 | 圆形勾选框移动到对应宠物 |
| 勾选"进行联合记录" | 圆形变为方形，当前宠物自动勾选 |
| 联合模式下多选宠物 | 多个方形复选框被勾选 |
| 取消"进行联合记录" | 方形变为圆形，**恢复进入联合模式前选定的宠物** |
| 联合模式下取消所有勾选 | 允许取消（但点击餐食/运动会提示"请勾选至少一个宠物"） |

### 5.3 边界情况处理

| 边界情况 | 处理方式 |
|----------|----------|
| 当前无选定宠物时进入联合模式 | `selectedPetIds` 为空数组，用户需手动勾选；`previousPetId` 为空，退出时保持无选定状态 |
| 联合模式下仅勾选一只宠物 | 允许，创建单宠物联合记录（兼容单宠物场景） |
| 退出联合模式时无勾选宠物 | 通过 `previousPetId` 恢复进入前的宠物，若 `previousPetId` 为空则保持原 `currentPetId` 不变 |
| 退出联合模式时 `previousPetId` 对应的宠物已被删除 | 使用降级方案：取 `selectedPetIds[0]`；若也为空则保持原 `currentPetId` 不变 |
| 进入联合模式后用户切换了当前宠物 | `currentPetId` 不会被联合模式下的勾选操作改变，退出时恢复 `previousPetId` |

## 六、结论

**该优化方案具有合理性和可行性。**

主要理由：
1. **交互体验提升**：勾选框位置固定，从"单选"到"多选"的过渡更加自然流畅
2. **状态关系承接**：原本选定的宠物自动转为勾选状态，体现从"当前宠物"到"参与宠物"的语义延续
3. **技术成本低**：仅需调整模板结构和样式，不涉及后端 API 或数据模型变更
4. **风险可控**：修改范围仅限于 UI 层，不会影响核心业务逻辑

建议按照上述方案实施优化，提升用户在联合记录功能中的交互体验。
