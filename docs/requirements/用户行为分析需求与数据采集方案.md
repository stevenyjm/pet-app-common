# 用户行为分析需求与数据采集方案

> **文档类型**：需求分析与技术方案
> **维护仓库**：pet-app-common（公共资源目录）
> **更新日期**：2026-07-19
> **关联项目**：pet-app（小程序前端）、pet-app-backend（后端服务）

---

## 1. 概述

为了深入了解用户行为模式、优化产品体验和提升业务转化率，需要建立系统化的用户行为数据采集体系。本文档基于当前小程序前端已实现的功能，梳理了可记录的用户行为清单，并提供了数据采集的技术方案。

## 4. 行为记录实现优先级

### 4.1 优先级定义

| 优先级 | 定义 | 适用场景 |
|--------|------|----------|
| **P0** | 核心转化指标，必须实现 | 电商交易闭环、用户留存 |
| **P1** | 重要运营指标，建议实现 | 用户粘性、服务质量 |
| **P2** | 体验优化指标，按需实现 | 页面优化、性能监控 |

### 4.2 优先级排序

#### P0 - 核心转化漏斗

| 优先级 | 行为类别 | 理由 |
|--------|----------|------|
| P0 | 商品浏览→加购→下单→支付 | 电商核心转化漏斗 |
| P0 | 订单创建→支付→确认收货 | 交易闭环分析 |
| P0 | 小程序启动→页面访问 | 基础流量分析 |

#### P1 - 用户运营

| 优先级 | 行为类别 | 理由 |
|--------|----------|------|
| P1 | 宠物档案记录 | 用户粘性指标 |
| P1 | 客服咨询 | 服务质量评估 |
| P1 | 消息中心 | 消息触达效果 |
| P1 | 购物车操作 | 弃购原因分析 |

#### P2 - 体验优化

| 优先级 | 行为类别 | 理由 |
|--------|----------|------|
| P2 | 首页 Banner/资讯点击 | 内容优化参考 |
| P2 | 商品详情滚动深度 | 页面内容优化 |
| P2 | 搜索行为 | 搜索体验优化 |
| P2 | 网络请求/错误日志 | 性能监控 |

## 5. 技术方案

### 5.1 后端表设计

#### 5.1.1 通用行为记录表

建议创建通用的 `user_behavior_log` 表，替代现有的 `user_browse_log`：

```sql
CREATE TABLE user_behavior_log (
  log_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL COMMENT '用户ID，未登录时为0',
  device_id VARCHAR(64) DEFAULT NULL COMMENT '设备唯一标识，用于游客模式追踪',
  behavior_type VARCHAR(32) NOT NULL COMMENT '行为类型：page_view、click、add_to_cart、purchase...',
  module VARCHAR(32) NOT NULL COMMENT '模块：home、mall、pet、order、mine...',
  target_type VARCHAR(32) DEFAULT NULL COMMENT '目标类型：product、order、pet...',
  target_id BIGINT DEFAULT NULL COMMENT '目标ID',
  action_data JSON DEFAULT NULL COMMENT '行为附加数据',
  from_page VARCHAR(64) DEFAULT NULL COMMENT '来源页面',
  to_page VARCHAR(64) DEFAULT NULL COMMENT '目标页面',
  device_info VARCHAR(255) DEFAULT NULL COMMENT '设备信息',
  ip_address VARCHAR(64) DEFAULT NULL COMMENT 'IP地址',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_user_behavior ON user_behavior_log(user_id, behavior_type, created_at);
CREATE INDEX idx_module_time ON user_behavior_log(module, created_at);
CREATE INDEX idx_target_type ON user_behavior_log(target_type, target_id);
CREATE INDEX idx_device_id ON user_behavior_log(device_id, created_at);
```

#### 5.1.2 字段说明

| 字段 | 说明 | 示例值 |
|------|------|--------|
| `user_id` | 用户ID，未登录时为0，游客模式下使用设备标识 | 12345 |
| `device_id` | 设备唯一标识，用于游客模式下的行为追踪 | `wx_xxxxxxxxxxx` |
| `behavior_type` | 行为类型，枚举值 | `page_view`, `click`, `add_to_cart` |
| `module` | 所属模块 | `home`, `mall`, `pet`, `order`, `mine` |
| `target_type` | 行为目标类型 | `product`, `order`, `pet`, `article` |
| `target_id` | 行为目标ID | 商品ID、订单ID等 |
| `action_data` | 行为附加数据（JSON） | `{"sku_id": 1, "quantity": 2}` |
| `from_page` | 来源页面路径 | `/pages/mall/mall` |
| `to_page` | 目标页面路径 | `/pages/product/detail` |
| `device_info` | 设备信息 | `{"os": "ios", "version": "14.0"}` |

### 5.1.3 现有表迁移策略

当前后端已存在 `user_browse_log` 表，迁移策略如下：

| 策略项 | 方案 | 说明 |
|--------|------|------|
| **过渡方式** | 双写并存 | 新表上线后，旧表继续写入，同时写入新表 |
| **数据迁移** | 一次性迁移 | 在低峰期执行数据迁移脚本，将旧表数据转换为新表格式 |
| **旧表处理** | 保留1个月后废弃 | 保留旧表数据供历史查询，1个月后可归档或删除 |
| **查询兼容** | 新API统一查询 | 所有查询通过新API进行，旧API逐步废弃 |

**迁移脚本示例**：

```sql
INSERT INTO user_behavior_log (
  user_id,
  behavior_type,
  module,
  target_type,
  target_id,
  action_data,
  from_page,
  to_page,
  created_at
)
SELECT
  user_id,
  CASE action_type
    WHEN 0 THEN 'browse'
    WHEN 1 THEN 'add_to_cart'
    WHEN 2 THEN 'purchase'
  END AS behavior_type,
  'mall' AS module,
  'product' AS target_type,
  product_id AS target_id,
  JSON_OBJECT(
    'start_time', start_time,
    'end_time', end_time
  ) AS action_data,
  NULL AS from_page,
  NULL AS to_page,
  start_time AS created_at
FROM user_browse_log;
```

### 5.1.4 数据增长预估与分表策略

#### 数据增长预估

| 指标 | 预估 | 说明 |
|------|------|------|
| 日均活跃用户 | 1000-5000 | 初期阶段 |
| 日均行为记录 | 10万-50万 | 每个用户平均100-1000条行为 |
| 月增长 | 300万-1500万 | 线性增长 |
| 年数据量 | 3.6亿-18亿 | 按365天计算 |
| 单表大小 | 1亿条约50GB | 预估每条记录500字节 |

#### 分表策略（未来扩展）

当数据量达到1000万条时，建议考虑以下分表策略：

| 策略 | 方案 | 适用场景 |
|------|------|----------|
| **按时间分表** | 按月分表 `user_behavior_log_202401` | 历史数据查询为主 |
| **按用户分表** | 按 user_id 取模分表 | 用户行为追踪为主 |
| **复合分表** | 按时间+用户混合分表 | 复杂查询场景 |

**推荐分表方案**：

```sql
-- 按月分表（推荐）
CREATE TABLE user_behavior_log_202401 LIKE user_behavior_log;
CREATE TABLE user_behavior_log_202402 LIKE user_behavior_log;

-- 按用户取模分表（备选）
CREATE TABLE user_behavior_log_0 LIKE user_behavior_log;
CREATE TABLE user_behavior_log_1 LIKE user_behavior_log;
-- ... 共10个分表
```

> **注意**：当前项目处于MVP阶段，单库单表架构完全满足需求。建议在数据量达到1000万条时再考虑分表，或迁移到支持自动分片的数据库（如 CockroachDB）。

### 5.3 前端埋点方案

#### 5.3.1 埋点方式

| 类型 | 实现方式 | 适用场景 |
|------|----------|----------|
| **页面级别** | `onLoad`/`onShow` 时上报 | 页面访问、停留时长 |
| **元素级别** | 按钮/链接的 `@tap` 事件中上报 | 点击、加购、下单 |
| **时长统计** | `onHide` 时计算并上报 | 页面停留时长 |
| **批量上报** | 客户端缓存，定时发送 | 性能优化 |

#### 5.3.2 前端埋点工具封装

建议在小程序前端封装统一的埋点工具，支持游客模式：

```javascript
// utils/behaviorTracker.js
class BehaviorTracker {
  constructor() {
    this.queue = [];
    this.timer = null;
    this.batchSize = 10;
    this.batchInterval = 5000;
    this.deviceId = this.getDeviceId();
  }

  getDeviceId() {
    let deviceId = uni.getStorageSync('behavior_device_id');
    if (!deviceId) {
      deviceId = 'wx_' + Date.now().toString(36) + Math.random().toString(36).substr(2, 9);
      uni.setStorageSync('behavior_device_id', deviceId);
    }
    return deviceId;
  }

  getUserId() {
    const user = uni.getStorageSync('user_info');
    return user?.userId || user?.user_id || 0;
  }

  isGuestMode() {
    return this.getUserId() === 0;
  }

  track(event) {
    const log = {
      ...event,
      user_id: this.getUserId(),
      device_id: this.deviceId,
      created_at: new Date().toISOString()
    };

    this.queue.push(log);

    if (this.queue.length >= this.batchSize) {
      this.flush();
    } else if (!this.timer) {
      this.timer = setTimeout(() => this.flush(), this.batchInterval);
    }
  }

  async flush() {
    if (this.queue.length === 0) return;

    const logs = [...this.queue];
    this.queue = [];
    this.timer = null;

    try {
      await behaviorApi.batchLog({ logs });
    } catch (error) {
      console.error('行为日志上报失败:', error);
      this.queue = [...logs, ...this.queue];
    }
  }

  onLogin(userId) {
    if (this.queue.length > 0) {
      this.flush();
    }
  }
}

export default new BehaviorTracker();
```

#### 5.3.3 游客模式行为记录处理

小程序前端支持游客模式（guest mode），未登录用户的行为记录处理方案如下：

| 场景 | 处理方式 | 说明 |
|------|----------|------|
| **用户未登录** | 使用设备ID追踪 | `user_id` 设为 0，`device_id` 记录设备标识 |
| **用户登录后** | 追溯关联 | 将该设备ID下的行为记录与用户ID关联 |
| **游客模式限制** | 部分行为不采集 | 敏感行为（如订单操作）需登录后才能采集 |
| **数据去重** | 登录后合并 | 用户登录后，同一设备下的重复行为去重 |

**游客行为关联流程**：

```
1. 用户首次访问（未登录）
   └─ 生成设备ID，行为记录 user_id=0, device_id=xxx

2. 用户登录
   └─ 触发 onLogin 回调，上报未上报的行为
   └─ 后端执行关联：UPDATE user_behavior_log
      SET user_id = new_user_id
      WHERE device_id = xxx AND user_id = 0

3. 用户后续行为
   └─ 使用真实 user_id 上报
```

#### 5.3.4 页面级埋点示例

```javascript
// pages/mall/mall.vue
import behaviorTracker from '@/utils/behaviorTracker';

export default {
  onLoad(options) {
    behaviorTracker.track({
      behavior_type: 'page_view',
      module: 'mall',
      to_page: '/pages/mall/mall',
      action_data: { options }
    });
  },

  onHide() {
    behaviorTracker.track({
      behavior_type: 'page_leave',
      module: 'mall',
      from_page: '/pages/mall/mall',
      action_data: { stay_duration: this.stayDuration }
    });
  }
};
```

## 6. 数据安全与隐私

### 6.1 用户隐私保护

| 措施 | 说明 |
|------|------|
| **匿名化处理** | IP地址脱敏处理，不存储完整IP |
| **用户授权** | 首次上报前获取用户授权（可选） |
| **数据最小化** | 仅采集必要数据，不采集敏感信息 |
| **本地缓存加密** | 客户端缓存数据加密存储 |

### 6.2 数据存储规范

| 规范 | 说明 |
|------|------|
| **存储期限** | 行为数据保留1年，过期自动清理 |
| **访问控制** | 仅授权人员可访问行为数据分析平台 |
| **数据隔离** | 不同环境数据隔离，测试数据不进入生产 |
