## 一、需求背景

### 1.1 问题描述

当前管理端的角色权限体系存在两个核心问题：

1. **覆盖面窄**：权限码仅覆盖进销存模块（17 个权限码），未覆盖管理端其他业务模块——订单、商品、用户服务、宠物、内容、消息广播、小程序配置、仪表盘等。这些模块的路由在 [router/index.ts](../../../pet-app-admin-web/src/router/index.ts) 中**未配置 `meta.permission`**，路由守卫不拦截，任何登录用户均可访问。

2. **划分方式不合理**：现有 4 个可分配角色（仓库管理员 / 采购专员 / 财务专员 / 运营专员）按"职能"划分，部分模块存在职责重合（如批次/临期/追溯同时归属仓库、采购、财务、运营），既无法清晰区分边界，也无法满足实际运营中"按模块授权"的灵活需求。

#### 1.2.3 实际影响

- 非超管角色登录后 `GET /admin/permissions` 返回空数组（种子未落地）
- 进销存菜单对非超管完全不可见（已配置 `meta.permission` 但无权限记录）
- 订单/商品/用户服务/宠物/内容/独立菜单对**任何登录用户**都可见（未配置 `meta.permission`），违反最小权限原则
- 超管无法在前端"勾选/取消勾选"非超管角色的具体权限，只能整体分配 `role_id`

### 1.3 需求目标

1. **权限码扩展到管理端全部模块**：从 17 个扩展到 ~45 个，覆盖仪表盘、订单、商品、用户服务、宠物、内容、消息广播、小程序配置、系统等全部业务模块
2. **角色权限矩阵重构**：保留 4 个预设角色（仓库管理员 / 采购专员 / 财务专员 / 运营专员），但其权限分配方式从"按职能预设"改为"按模块细分 + 超管可勾选/取消勾选"
3. **新增超管矩阵管理界面**：超管可在前端矩阵 UI 中，按模块/权限码对任意非超管角色勾选/取消勾选权限
4. **路由权限全量覆盖**：补全所有未配置 `meta.permission` 的路由，使权限控制覆盖全模块

## 二、设计原则

### 2.1 权限码命名规范

- 格式：`模块:操作`（snake_case，与现有进销存权限码一致）
- 模块名采用单数名词：`order` / `product` / `inventory` / `user` / `pet` / `content` / `message` / `mini_app_config` / `system` 等
- 操作动词：`view`（查看）/ `edit`（编辑）/ `create`（创建）/ `delete`（删除）/ `audit`（审核）/ `ship`（发货）/ `reply`（回复）/ `send`（发送）/ `config`（配置）/ `manage`（管理）等
- 每个模块至少有一个 `view` 权限

### 2.2 角色权限分配原则

- **超管（super_admin）**：始终拥有全部权限（代码层提供，不可在前端矩阵中勾选/取消）
- **非超管角色**：权限分配由超管在前端矩阵中勾选/取消，写入 `admin_role_permission` 表
- **预设角色**：4 个预设角色仅作为"默认勾选状态"的初始值（用于新建角色或种子初始化），超管后续可自由调整
- **不再依赖"职能划分"**：矩阵的横轴是"模块/权限码"而非"职能"，避免职责重合

### 2.3 兼容性原则

- 不破坏现有 `admin_role` / `admin_role_permission` 表结构
- 保留 `ROLE_PERMISSION_MATRIX` 作为种子初始化数据
- 现有进销存 17 个权限码全部保留（避免破坏既有路由 `meta.permission`）
- 原 `log:view` 统一为 `audit_log:view`，路由从 `/inventory/operation-logs` 提升为 `/system/operation-logs`（迁移期保留旧路由兼容跳转）

## 五、数据库变更

### 5.1 新增 `admin_permission` 字典表

用于权限码元数据管理（中文名、模块归属、排序），供前端矩阵 UI 渲染。

#### 字段信息表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| permission_code | VARCHAR(64) | PK | 权限码（如 `order:ship`, `product:edit`） |
| module | VARCHAR(32) | NOT NULL | 所属模块（`dashboard`/`order`/`product`/`inventory`/`user`/`pet`/`content`/`message`/`mini_app_config`/`system`） |
| name | VARCHAR(64) | NOT NULL | 权限中文名（如 `订单发货`） |
| description | VARCHAR(255) | DEFAULT NULL | 权限描述 |

**响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "role_id": 2,
    "role_code": "warehouse_admin",
    "permissions": [
      "inventory:dashboard",
      "inventory:view",
      "inventory:inbound",
      "order:ship",
      "product:view"
    ]
  }
}
```

**业务规则**

- 不可修改 `super_admin`（role_code = 'super_admin'）的权限（返回 40304 `ROLE_NOT_EDITABLE`）
- 传入的 `permission_code` 必须存在于 `admin_permission` 字典表，否则跳过并 warning 日志
- 全量覆盖：先 DELETE 该 role_id 的所有记录，再 INSERT 新记录（事务）
- 写审计日志：`action = admin_role_permission_update`，`resource_type = admin_role`，`resource_id = role_id`，`detail_json` 记录变更前后权限码差异

|------|------|------|
| 0 | 200 | 成功 |
| 40101 | 401 | 未登录或 Token 失效 |
| 40301 | 403 | 非超管角色 |
| 40304 | 403 | 角色权限不可编辑（super_admin） |
| 40401 | 404 | 角色不存在 |
| 40001 | 400 | 请求参数错误（permissions 非数组） |
| 50001 | 500 | 服务器内部错误 |
