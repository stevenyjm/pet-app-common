# 需求分析：资讯/商品详情"相关入口"编辑功能

> **文档类型**：临时需求分析
> **文档版本**：v1.4
> **更新日期**：2026-06-27
> **需求来源**：小程序 C 端资讯详情页与商品详情页"相关入口"信息编辑能力

---

## 1. 现状分析

### 1.1 后端存储方式

资讯详情的"相关入口"数据存储在 `articles` 表的 `content_json` 字段中，采用 JSON 格式存储。

**数据结构**（对应 `pet-app-admin-web/src/types/article.ts`）：

```typescript
interface ArticleContent {
  internalLink?: {
    icon?: string      // 图标 emoji，如 "🛒"
    title?: string     // 链接标题，如 "查看推荐鲜食商品"
    desc?: string      // 链接描述，如 "犬用鲜食系列 · 商城内跳转"
    action?: Record<string, unknown>  // 跳转动作参数
  }
  externalLink?: {
    title?: string     // 外链标题，如 "阅读原文 · 专业喂养白皮书"
    url?: string       // 外部网址，如 "https://docs.zzp.com/feeding-guide"
  }
}
```

**`action` 字段支持的跳转类型**（对应 `pet-app/src/services/news.js:runArticleAction`）：

| action.type | 跳转目标 | 说明 |
|-------------|----------|------|
| `mall` | 商城 Tab | `uni.switchTab({ url: '/pages/mall/mall' })` |
| `product` | 商品详情页 | `uni.navigateTo({ url: '/pages/product/detail?id=xxx' })` |
| `order` | 订单 Tab | `uni.switchTab({ url: '/pages/order/order' })` |
| `mine` | 我的 Tab | `uni.switchTab({ url: '/pages/mine/mine' })` |

### 1.2 小程序前端显示方式

#### 1.2.1 资讯详情页（已实现）

在 `pet-app/src/pages/news/detail.vue` 中实现了"相关入口"区域的完整展示逻辑：

**条件渲染**：
```vue
<view v-if="showInternalLink || article.externalLink" class="link-section">
  <!-- 内部链接 -->
  <view v-if="showInternalLink" class="link-card link-card--internal" @tap="onInternalLink">
    <view class="link-icon link-icon--green">
      <text>{{ article.internalLink.icon || '🔗' }}</text>
    </view>
    <view class="link-info">
      <text class="link-title">{{ article.internalLink.title }}</text>
      <text class="link-desc">{{ article.internalLink.desc }}</text>
    </view>
    <text class="link-arrow">›</text>
  </view>
  <!-- 外部链接 -->
  <view v-if="article.externalLink" class="link-card link-card--external" @tap="onExternalLink">
    <view class="link-icon link-icon--blue">
      <text>🔗</text>
    </view>
    <view class="link-info">
      <text class="link-title">{{ article.externalLink.title }}</text>
      <text class="link-desc">将在小程序 web-view 中打开外部页面</text>
    </view>
    <text class="link-arrow">›</text>
  </view>
</view>
```

**交互逻辑**：
1. **内部链接**：点击触发 `onInternalLink()` → 调用 `runArticleAction()` → 根据 `action.type` 执行对应的 `uni.switchTab` 或 `uni.navigateTo`
2. **外部链接**：点击触发 `onExternalLink()` → 弹出确认弹窗 → 调用 `openExternalLink()` → 通过 web-view 页面打开外部 URL
3. **电商暂停模式**：内部链接会被 `ecommerceGuard` 屏蔽（`showInternalLink` 计算属性控制）

**UI 样式**：
- 内部链接使用绿色主题图标（`link-card--internal`）
- 外部链接使用蓝色主题图标（`link-card--external`）

#### 1.2.2 商品详情页（未实现）

经过代码分析，**商品详情页面目前没有"相关入口"功能**：

- `pet-app/src/pages/product/detail.vue` 中没有相关入口区域的代码
- 商品数据结构中也未包含 `internalLink` / `externalLink` 字段
- 商品详情页仅有主图轮播、价格、规格、简介/详情 Tab 等基础功能

### 1.3 Web 前端当前支持情况

**当前状态：部分支持**

| 功能 | 状态 | 说明 |
|------|------|------|
| 类型定义 | ✅ | `ArticleContent` 接口已包含 `internalLink`/`externalLink` |
| 预览展示 | ✅ | `ArticlePreviewPanel.vue` 已实现链接预览 |
| 表单编辑 | ❌ | `ArticleContentEditor.vue` 无专用编辑字段 |
| JSON 编辑 | ✅ | 仅能通过"JSON 高级编辑"模式手动编辑 |

**问题分析**：

`ArticleContentEditor.vue`（`pet-app-admin-web/src/components/ArticleContentEditor.vue`）仅提供了以下字段的表单编辑：
- 来源（source）
- 引用块（quote）
- 正文段落（paragraphs）
- 结尾说明（tail）
- 行内 Emoji（inlineEmoji）

缺少对 `internalLink`、`externalLink` 和 `cta` 字段的可视化表单编辑支持。运营人员必须切换到"JSON 高级编辑"模式手动编写配置，门槛高且易出错。

## 2. 需求合理性分析

### 2.1 功能价值

| 维度 | 分析 |
|------|------|
| **运营灵活性** | 资讯底部的相关入口是重要的流量引导入口，支持运营人员动态配置跳转目标，提升转化率 |
| **用户体验** | 相关入口提供了资讯内容与业务功能的关联，帮助用户快速找到相关商品或服务 |
| **内容完整性** | 当前 Web 管理端缺少可视化编辑能力，运营人员需要手动编写 JSON，门槛高且易出错 |
| **一致性** | 资讯和商品详情页都应支持相关入口，形成统一的内容运营能力 |

### 2.2 可行性评估

| 评估项 | 结论 | 依据 |
|--------|------|------|
| 后端接口（资讯） | ✅ 无需改动 | 数据已通过 `content_json` 字段存储，API 已支持读写 |
| 后端接口（商品） | ✅ 可扩展 | 商品表已有 `extra_json` 字段，可复用类似结构 |
| 小程序前端（资讯） | ✅ 已有完整实现 | 资讯详情页已有完整展示和跳转逻辑 |
| 小程序前端（商品） | ✅ 技术可行 | 可复用资讯页的 `runArticleAction` 和 `openExternalLink` 函数 |
| Web 前端（资讯） | ✅ 技术可行 | 类型定义和预览已有，仅需新增编辑表单 |
| Web 前端（商品） | ✅ 技术可行 | 商品编辑页面已有 `extra_json` 编辑能力 |
| 数据迁移 | ✅ 无需迁移 | 使用现有字段，向后兼容 |

interface ProductExtra {

### 3.3 方案三：统一链接管理（二期 · 建议降级）

**评估结论**：当前仅资讯和商品两个入口点使用相关入口，独立表 + CRUD API 的投入产出比不合理，建议采用**轻量级链接模板复用方案**，在现有结构上扩展，而非新建数据表。

**轻量级方案设计**：

**方案对比**：

| 维度 | 独立表方案（原建议） | 轻量级方案（推荐） |
|------|---------------------|-------------------|
| 后端开发量 | 高（新建表、API） | 低（复用现有字段） |
| 前端开发量 | 高（新建管理页面） | 中（扩展现有编辑器） |
| 数据一致性 | 强（统一管理） | 一般（独立配置） |
| 运营灵活性 | 高（模板复用） | 中（独立配置） |
| 投入产出比 | 低 | 高 |

**推荐方案：链接模板配置**

在 Web 前端本地维护常用链接模板，运营人员可选择模板快速填充，同时保留自定义编辑能力：

```typescript
interface LinkTemplate {
  id: string
  name: string           // 模板名称，如"商城入口"
  type: 'internal' | 'external'
  icon?: string
  title?: string
  desc?: string
  action?: { type: string; targetId?: string }
  url?: string
}
```

**预设模板示例**：

| 模板名称 | 类型 | 标题 | 描述 | 跳转类型 |
|----------|------|------|------|----------|

| 喂养指南 | 外部 | 阅读喂养科普原文 | 将在小程序 web-view 中打开 | - |

## 5. 风险与注意事项

### 5.1 电商暂停模式影响

当前小程序处于电商暂停模式（`ecommerceGuard`），内部链接跳转至商城、商品、订单等电商相关页面会被屏蔽。因此：
- 配置内部链接时需考虑当前电商状态
- 建议在编辑表单中添加电商状态提示

### 5.2 外链安全

- 外部链接需在小程序白名单域名中配置（微信小程序业务域名）
- 建议在编辑表单中添加 URL 格式校验
- 外链打开前会弹出确认弹窗，告知用户即将离开小程序

### 5.3 向后兼容性

- 当前方案完全向后兼容，未配置相关入口的资讯仍可正常显示
- JSON 格式保持一致，不影响已有数据

### 5.4 商品相关入口的特殊考量

- 商品详情页已有底部操作栏（分享、客服、购物车、二维码、数量、加购按钮），相关入口区域需合理布局
- 商品相关入口的跳转目标建议增加"资讯"类型，支持从商品跳转到相关喂养科普
