# 需求：反馈处理人 & 客服操作人显示

## 一、需求背景与目标

### 1.1 背景

在商户管理端（Admin Web）运营过程中，为了提升服务质量和可追溯性，需要明确每一条用户反馈和每一次客服对话的**责任人**。目前系统存在以下不足：

1.  **用户反馈**：虽然后端已记录处理人，但小程序（C 端）和管理端的反馈详情页均未展示处理该反馈的管理员名称，用户无法得知是谁处理了自己的问题。
2.  **客服消息**：当管理员回复用户时，会话中无法直观地看到是哪位管理员正在处理该用户的咨询，导致多人协作时容易混乱，用户体验不佳。

### 1.2 目标

1.  **反馈处理人全端展示**：
    *   **小程序端**：用户在查看自己的反馈详情时，能看到“由管理员【XXX】处理”的信息。
    *   **管理端**：管理员在查看反馈详情时，能清晰看到该反馈的处理人，形成内部记录。
2.  **客服操作人管理端标识**：
    *   **管理端**：在客服会话界面的**消息列表**中，针对**每一条**由管理员发送的消息，标识出发送该消息的管理员姓名，让客服团队内部清楚每条回复的责任人。

## 二、需求分析

### 2.1 需求一：用户反馈处理人显示

#### 2.1.1 现状分析

*   **后端**：
    *   `user_feedback` 表已包含 `processed_by` (admin_id) 和 `processed_at` 字段。
    *   `GET /admin/feedback/:id` 接口已通过关联查询返回 `processed_by_username`。
    *   **缺失**：面向小程序的 `GET /feedback/:id` 接口需确认是否返回处理人信息。
*   **管理端前端**：
    *   类型定义中已包含 `processedByName`，但详情页组件 (`FeedbackResolveDrawer.vue` 或类似) **未展示**此字段。
*   **小程序前端**：
    *   详情页 (`subpk-feedback/history.vue`) **未获取和展示**处理人信息。

#### 2.1.2 需求点

1.  **后端**：确保面向小程序的反馈详情接口返回处理人信息（`processed_by_username` 或 `processed_by` 对象）。
2.  **管理端前端**：在反馈详情展示区域（如抽屉、弹窗）新增一行，醒目标示“处理人：【XXX】”。
3.  **小程序前端**：在反馈详情页的状态区域下方，新增“处理人”信息展示，仅在状态为“已处理”时显示。

### 2.2 需求二：客服消息操作人显示

#### 2.2.1 现状分析

*   **后端**：
    *   `service_message` 表仅记录了 `sender_role` ('user' / 'admin')，**未记录**具体是哪个管理员 (`admin_user.id`) 发送的。
    *   `service_conversation` 表**没有**“当前处理人”或“最后操作人”字段。
    *   `adminServiceConversationService.js` 中的 `sendAdminMessage` 方法未记录操作人 ID。
*   **管理端前端**：
    *   `ChatPanel.vue` 会话头部仅展示用户信息，**无操作人**展示。

#### 2.2.2 需求点

1.  **后端**：
    *   **修改 `service_message` 模型**：新增 `sender_admin_id` 字段（当 `sender_role` 为 `admin` 时填入，记录管理员 ID）。
    *   **修改 Service 逻辑**：在 `sendAdminMessage` 中，将 `req.admin.id` 写入新消息的 `sender_admin_id` 字段。
    *   **修改消息查询**：在 `getConversationMessages` (获取消息列表接口) 中，对返回的每条消息，如果 `sender_role` 为 `admin`，则根据其 `sender_admin_id` 关联查询 `admin_user` 表，获取其 `username`，作为 `sender_name` 附加在消息对象中返回。
2.  **管理端前端**：
    *   在 `ChatPanel.vue` 的**消息列表渲染区域**，针对 `sender_role === 'admin'` 的消息气泡，在消息内容旁（如头像右侧、消息气泡下方或时间戳旁）显示 `sender_name`。

## 三、解决方案

### 3.1 技术方案

#### 3.1.1 后端修改方案

1.  **数据库模型 (`models/ServiceMessage.js`)**
    *   *新增字段*：`sender_admin_id` (BIGINT, NULLABLE)。
    *   *说明*：当 `sender_role` 为 'admin' 时，记录发送该消息的管理员 ID；当为 'user' 时，该字段为 NULL。

2.  **数据库迁移 (`scripts/migrate-xxxx-add-sender-admin-id.js`)**
    *   创建迁移脚本，为 `service_message` 表添加 `sender_admin_id` 列。

3.  **业务逻辑 (`services/adminServiceConversationService.js`)**
    *   *修改 `sendAdminMessage`*：在创建新消息实例时，增加 `sender_admin_id: req.admin.id`。
    *   *修改 `getConversationMessages`*：在获取消息列表后，遍历每条消息。若 `message.sender_role === 'admin'`，则根据 `message.sender_admin_id` 查询 `AdminUser` 表，获取其 `username`，并添加到消息对象的 `sender_name` 属性中。
4.  **API 规范文档**
    *   更新 `pet-app-common/docs/api-specs/` 下的客服消息 API 文档，说明消息对象中新增 `sender_name` 字段。

#### 3.1.2 前端修改方案

**管理端前端 (`pet-app-admin-web`)**

1.  **类型定义 (`types/customerService.ts`)**
    *   在 `ServiceMessage` 接口中新增 `senderName?: string`。

2.  **UI 展示 (`components/customer-service/ChatPanel.vue`)**
    *   在消息列表的模板中，针对 `v-for` 循环渲染的每条消息，判断 `message.sender_role === 'admin'`。
    *   如果是管理员消息，则在消息气泡旁边（通常是时间戳旁边或消息气泡下方）显示 `message.sender_name`。例如：
        ```vue
        <!-- 在消息时间戳旁显示发送者名称 -->
        <div class="message-time">
          {{ formatTime(message.createTime) }}
          <span v-if="message.senderRole === 'admin'" class="sender-name">
            ({{ message.senderName }})
          </span>
        </div>
        ```
    *   样式上可以使用 `el-tag` 或简单的 `span` 来区分，确保在对话气泡中比较醒目，但又不过于突兀。

**小程序前端 (`pet-app`)**

1.  **API 服务 (`src/services/feedback.js`)**
    *   确认 `getFeedbackDetail` 返回的数据中包含 `processed_by_username` 字段，并进行映射。

2.  **UI 展示 (`src/subpk-feedback/history.vue` 或详情页)**
    *   在反馈卡片或详情的状态区域，新增处理人信息展示：
        ```vue
        <view class="processed-info" v-if="feedback.status === 2 && feedback.processedByUsername">
          <text>处理人：{{ feedback.processedByUsername }}</text>
        </view>
        ```
    *   仅在反馈状态为“已处理”时显示。

## 四、影响范围

1.  **API 变更**：
    *   `GET /admin/service/conversations/:id/messages` (管理端消息列表)：响应体中每条 `message` 对象新增 `sender_name` 字段。
    *   `GET /feedback/:id` (小程序反馈详情)：响应体需确认或新增 `processed_by_username` 字段。
    *   **兼容性**：向前兼容。新字段对旧版本客户端无影响（忽略即可）。
2.  **数据库变更**：
    *   `service_message` 表结构变更，新增 `sender_admin_id` 列。需执行迁移脚本。
3.  **UI 变更**：
    *   管理端：反馈详情页、客服会话详情页新增展示元素。
    *   小程序端：反馈详情页新增展示元素。

## 五、风险与回滚方案

*   **风险**：
    *   数据库迁移失败。
    *   新字段为空导致前端显示问题（需做判空处理）。
*   **回滚方案**：
    *   代码回滚：Git 回滚即可。
    *   数据库回滚：由于是新增 nullable 字段，影响极小。如需回滚，可执行 `ALTER TABLE service_message DROP COLUMN sender_admin_id;`。前端回滚代码即可兼容。
