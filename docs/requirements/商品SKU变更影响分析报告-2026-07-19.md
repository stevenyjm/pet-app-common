# 商品信息变更/SKU变更影响分析报告

> **文档版本**: v1.0  
> **创建日期**: 2026-07-19  
> **适用范围**: 宠物生鲜电商后端系统  
> **关联模块**: 商品管理、订单管理、库存管理

---

## 1. 问题背景

在电商系统中，商品信息和SKU的变更会对历史订单、商品库存、用户购物车等多个模块产生连锁影响。本报告基于对现有代码的深入分析，识别潜在风险点并提出修复方案。

### 1.1 分析范围

| 变更类型 | 涉及字段 |
|---------|---------|
| 商品基本信息变更 | `product_name`, `thumbnail`, `intro`, `status`, `is_hidden` |
| SKU价格变更 | `price`, `original_price` |
| SKU库存变更 | `stock` |
| SKU状态变更 | `status`（上架/下架） |
| SKU规格变更 | `spec_json`, `sku_name`, `sku_image` |
| SKU删除 | 软删除（`status=0`） |

## 2. 历史订单影响分析

### 2.1 快照隔离机制（已实现保护）

系统在创建订单时采用**快照机制**，将SKU信息固化到订单明细中，确保历史订单不受后续变更影响：

| 订单明细表字段 | 快照内容 | 来源代码 |
|--------------|---------|---------|
| `sku_snapshot` | `{label, emoji, thumb_theme}` | [orderController.js#L216-L220](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/controllers/orderController.js#L216-L220) |
| `buy_price` | 购买价格 | [orderController.js#L221](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/controllers/orderController.js#L221) |
| `product_name` | 商品名称 | [orderController.js#L214](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/controllers/orderController.js#L214) |
| `product_image` | 商品图片 | [orderController.js#L215](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/controllers/orderController.js#L215) |

**结论**：已完成/已关闭订单完全不受商品/SKU变更影响，数据通过快照永久固化。

### 2.2 待支付订单风险（价格漂移风险）

**问题描述**：当管理员修改SKU价格时，待支付（pending）订单仍使用下单时的`buy_price`快照。

**风险场景**：

> 用户下单后、支付前，商户修改SKU价格（如涨价），用户仍按旧价格支付，导致实际收款与当前商品价格不一致。

**代码证据**：

```javascript
// adminProductService.js - updateSku 直接修改价格，未检查待支付订单
if (payload.price !== undefined) updates.price = payload.price;
```

**影响程度**：⚠️ 中等

### 2.3 快照信息不足（售后追溯隐患）

**问题描述**：当前`sku_snapshot`仅包含最小化信息，缺失关键的价格和规格参数。

**当前快照结构**：

```json
{
  "label": "默认规格",
  "emoji": "📦",
  "thumb_theme": "green"
}
```

**缺失信息**：

| 缺失字段 | 影响 |
|---------|------|
| `price` | 无法还原购买时的单价 |
| `original_price` | 无法还原购买时的划线价 |
| `spec_json` | 无法还原完整规格参数 |

**影响程度**：⚠️ 中等

## 3. 商品库存影响分析

### 3.1 Redis缓存失效问题（严重Bug）

**问题描述**：`adminProductService.js`中的SKU操作**未刷新Redis缓存**，导致C端展示过期数据。

**代码证据**：

```javascript
// productCacheService.js 提供了缓存失效方法但未被调用
async function invalidateSkuCache(skuId) {
  return redisClient.del(buildSkuKey(skuId));
}
```

**影响范围**：

| 操作 | 是否调用缓存失效 | 影响 |
|------|-----------------|------|
| `createSku` | ❌ | C端无法立即看到新SKU |
| `updateSku`（含stock/price/status） | ❌ | C端展示过期库存/价格 |
| `deleteSku`（软删除status=0） | ❌ | C端仍显示已删除SKU |

**风险场景**：

> 1. 商户修改SKU库存为0（下架），但Redis缓存未更新，用户仍看到有库存并下单，导致超卖
> 2. 商户修改SKU价格，用户看到过期价格，影响购买决策
> 3. 商户删除SKU，用户仍能在商品详情页看到并选择已删除的规格

**影响程度**：🔴 高

### 3.2 库存直接覆盖（无审计追踪）

**问题描述**：库存变更通过直接赋值方式修改，无流水记录，无法追溯变更原因。

**代码证据**：

```javascript
// updateSku - 直接覆盖库存值
if (payload.stock !== undefined) updates.stock = payload.stock;
```

**问题分析**：

> 库存变更无流水记录（参考进销存系统需求中规划的`inventory_flow`表），无法追溯库存变更原因（采购入库/销售出库/盘点调整）。

**影响程度**：⚠️ 中等

### 3.3 SKU软删除后的库存残留

**问题描述**：SKU软删除（`status=0`）后，库存仍保留在`product_sku.stock`字段中，可能造成统计偏差。

**代码证据**：

```javascript
// deleteSku - 仅设置status=0，库存保留
await sku.update({ status: 0 });
```

**影响程度**：🟡 低

## 4. 其他关联影响

### 4.1 card_display_sku_id失效引用

**问题描述**：当商户指定的卡片显示SKU被删除或下架时，`card_display_sku_id`字段不会自动清空。

**代码证据**：

```javascript
// adminProductService.js - deleteSku 删除SKU后未检查card_display_sku_id
await sku.update({ status: 0 });
// 未清理 product.card_display_sku_id 的无效引用
```

**影响分析**：`deriveOriginalPrice`函数会自动回退到第一个有效SKU，但`card_display_sku_id`字段仍指向无效SKU，下次查询时需重新计算，存在冗余逻辑。

**影响程度**：🟡 低

### 4.2 购物车影响

**分析结果**：购物车仅存储`sku_id`，下单时会校验SKU有效性，影响较小。

**代码证据**：

```javascript
// orderController.js - 下单校验
if (isProductInvalid(row.sku?.product, row.sku)) {
  throw new AppError(`商品「${row.sku?.product?.product_name || ''}」已失效`, ...);
}
```

**影响程度**：✅ 无风险

### 4.3 售后模块影响

**分析结果**：售后模块使用`order_id`关联订单，退款金额独立存储，不直接查询`product_sku`表。

**代码证据**：

```javascript
// AfterSales.js - 售后表仅存储订单关联和退款金额
order_id: { type: DataTypes.BIGINT, allowNull: false },
refund_amount: { type: DataTypes.DECIMAL(10, 2), allowNull: false },
```

**影响程度**：✅ 无风险

### 4.4 管理端订单服务影响

**分析结果**：管理端订单服务使用`order_detail`的快照数据（`sku_snapshot`、`buy_price`等），没有直接查询`product_sku`表获取实时数据。

**代码证据**：

```javascript
// adminOrderService.js - formatAdminOrderItem 使用快照数据
function formatAdminOrderItem(detail) {
  let snapshot = {};
  try {
    snapshot = JSON.parse(detail.sku_snapshot || '{}');
  } catch {
    snapshot = { label: detail.sku_snapshot };
  }
  return {
    ...
    price: Number(detail.buy_price),  // 使用快照价格
    ...
  };
}
```

**影响程度**：✅ 无风险

## 5. 修复方案

### 5.1 修复Redis缓存失效（优先级：高）

**方案描述**：在`adminProductService.js`的三个SKU操作函数中添加缓存失效调用。

**修改位置**：[adminProductService.js](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/services/adminProductService.js)

**修改内容**：

```javascript
// 顶部引入
const productCacheService = require('./productCacheService');

// createSku 函数末尾（约第359行后）
await productCacheService.invalidateSkuCache(sku.sku_id);

// updateSku 函数末尾（约第407行后）
await productCacheService.invalidateSkuCache(skuId);

// deleteSku 函数末尾（约第430行后）
await productCacheService.invalidateSkuCache(skuId);
```

### 5.2 增强sku_snapshot信息（优先级：中）

**方案描述**：扩展订单创建时的快照内容，包含完整的价格和规格信息。

**修改位置**：[orderController.js#L216-L220](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/controllers/orderController.js#L216-L220)

**修改内容**：

```javascript
sku_snapshot: JSON.stringify({
  label: spec.label || spec.name || row.sku.sku_name || '默认规格',
  emoji: extra.emoji || '📦',
  thumb_theme: row.sku.product.img_theme || 'green',
  price: row.sku.price,
  original_price: row.sku.original_price,
  spec_json: row.sku.spec_json,
}),
```

### 5.3 待支付订单价格变更验证（优先级：中）

**方案描述**：在`updateSku`中增加检查，当价格变更时提示存在待支付订单。

**修改位置**：[adminProductService.js#L381](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/services/adminProductService.js#L381)

**修改内容**：

```javascript
if (payload.price !== undefined && payload.price !== sku.price) {
  const { Op } = require('sequelize');
  const { OrderDetail, OrderMain } = require('../models');
  
  const pendingOrders = await OrderDetail.count({
    where: { 
      sku_id: skuId,
      order_id: { 
        [Op.in]: sequelize.literal(
          '(SELECT order_id FROM order_main WHERE order_status = 1)'
        )
      }
    }
  });
  
  if (pendingOrders > 0) {
    console.warn(`SKU ${skuId} price change affects ${pendingOrders} pending orders`);
  }
}
```

### 5.4 清理card_display_sku_id失效引用（优先级：低）

**方案描述**：当SKU被删除或下架时，检查并清理关联商品的`card_display_sku_id`引用。

**修改位置**：[adminProductService.js#L422-L428](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-backend/services/adminProductService.js#L422-L428)

**修改内容**：

```javascript
await sku.update({ status: 0 });

if (product.card_display_sku_id === skuId) {
  const activeSkus = await ProductSku.findAll({ 
    where: { product_id: productId, status: { [Op.ne]: 0 } } 
  });
  if (activeSkus.length > 0) {
    await product.update({ card_display_sku_id: activeSkus[0].sku_id });
  } else {
    await product.update({ card_display_sku_id: null });
  }
}
```

### 5.5 库存流水记录（优先级：低）

**方案描述**：按进销存系统规划，后续新增`inventory_flow`表记录库存变更。

**参考文档**：[进销存系统-多端适配性分析与实施方案.md](file:///C:/Users/22188/Desktop/宠物生鲜电商开发项目/pet-app-common/docs/requirements/进销存系统-多端适配性分析与实施方案.md)

| SKU删除(软删除) | ✅ 不受影响 | ✅ 不受影响 | ❌ 缓存过期 | ⚠️ 结算时拦截 | ⚠️ 库存残留 |
| SKU规格变更 | ✅ 不受影响 | ✅ 不受影响 | ❌ 缓存过期 | ⚠️ 规格不匹配 | - |
