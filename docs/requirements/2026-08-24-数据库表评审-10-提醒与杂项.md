## 开头：评审与决策参考的规范准则

> 以下为本次评审依据的规范准则速查，详细规则见规范母版。

### A. 必备字段

| 字段类别 | 字段名（强制） | 类型与约束 | 说明 |
|----------|---------------|------------|------|
| 主键 | `{实体}_code` | `VARCHAR(n) PRIMARY KEY`，禁止 `BIGINT AUTO_INCREMENT` | 业务主键 |
| 创建时间 | `create_time` | `DATETIME NOT NULL`（无 `DEFAULT CURRENT_TIMESTAMP`，后端推送） | 创建时间 |
| 最后修改时间 | `last_modified_time` | `DATETIME NOT NULL`（无 `DEFAULT`/`ON UPDATE`，后端推送） | 最后修改时间 |
| 逻辑删除标记 | `is_deleted` | `TINYINT NOT NULL DEFAULT 0` | 0-未删除，1-已删除 |

### B. 业务主键编码规则

| 实体 | 编码格式 | 字段类型建议 |
|------|----------|--------------|
| 用户 `user_code` | `U00000001`（前缀 `U` + 8 位数字） | `VARCHAR(16)` |
| 宠物 `pet_code` | `UP0001`（前缀 `UP` + 4 位数字） | `VARCHAR(16)` |
| 订单 `order_code` | `yyyyMMdd` + 4 位流水号（如 `202608250001`） | `VARCHAR(20)` |
| 标签编码 `tag_code` | **待用户决策**（建议 `TAG` + 序号） | `VARCHAR(32)` |
| 提醒编码 `reminder_code` | **待用户决策**（建议 `RM` + 日期 + 序号） | `VARCHAR(32)` |
| 余额编码 `balance_code` | **待用户决策**（建议 `BL` + 序号；或直接用 `user_code` 作主键，1:1） | `VARCHAR(32)` |
| 订阅编码 `subscription_code` | **待用户决策**（建议 `SUB` + 日期 + 序号） | `VARCHAR(32)` |

> 其他实体业务主键格式在实际确定数据库表字段时由用户询问决策（包括字段长度预留、并发安全方案等）。

### C. 其他已决策规则

| 规则 | 决策结果 |
|------|----------|
| 时间字段维护方式 | 后端主动推送（移除 DB 自动维护） |
| CONSTRAINT 约束 | 全量移除（引用完整性由后端校验） |
| 字段表源前缀 | 仅易混淆字段加前缀（`status`→`{entity}_status`、`name`→`{entity}_name`、`type`→`{entity}_type`、`level`→`{entity}_level`）；通用字段不加 |
| `is_deleted` 索引 | 移除单列索引；联合索引中 TINYINT 不作首列 |
| COMMENT | 表级与字段级 COMMENT 均不可省略；枚举字段标注取值映射 |
| TEXT/JSON 类型 | 避免使用；短文本用 VARCHAR(n)，数组用子表，结构化对象用扁平字段或子表；若触发分表须先向用户确认 |
| `user_id` 外键引用 | 改为 `user_code VARCHAR(16)` |

### D. 豁免表清单（提醒与杂项）

> 本模块无豁免表。4 张表均须满足必备字段与逻辑删除规范。

#### 备注说明

- 本表已标记 `@deprecated 2026-08-20`：预设标签改为小程序端内置，本表保留用于历史查询，不参与新业务。改造优先级低，但若需保留仍应按规范收敛字段
- `id` 为逻辑主键（`INTEGER AUTO_INCREMENT`），违反 D1 业务主键规则；表已有业务字段 `name`（带 UNIQUE），可考虑新增 `tag_code` 业务主键
- `name` 为易混淆字段（联表查询时无法区分表源，可能与宠物名/商品名等混淆），违反 D2 字段表源前缀规则
- `status` 为易混淆字段，违反 D2 字段表源前缀规则
- `sort` 字段名为 SQL 关键字，建议改名为 `sort_order` 以避免冲突
- `created_at` / `updated_at` 命名不符 D3 时间字段命名（应为 `create_time` / `last_modified_time`）
- 时间字段使用 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，违反 D3 维护方式规则（应后端推送）
- 主键类型 `INTEGER` 与项目其他表 `BIGINT` 不一致（虽属次要问题）

#### 备注说明

- `subscription_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则
- `user_id` 为外键引用，需改为 `user_code VARCHAR(16)`
- `order_id` 为外键引用，需改为 `order_code VARCHAR(20)`（配合 order_main 主键改造）
- `status` 为易混淆字段（联表查询时无法区分表源，可能与订单状态/宠物状态等混淆），违反 D2 字段表源前缀规则
- `extra_json` 使用 `TEXT` 类型且为 JSON 内容，违反 D6（建议扁平化或移除，待用户评估）
- 1 处 `CONSTRAINT` 外键约束（`fk_user_subscription_user`），违反 D5（应移除，引用完整性由后端校验）
- `created_at` / `updated_at` 命名与维护方式违反 D3
- `plan_code` / `plan_name` 已有明确前缀，不算易混淆，保留
- `idx_user_id_status` 联合索引中 `status` 为 TINYINT 且不在首列，符合 TINYINT 索引策略
