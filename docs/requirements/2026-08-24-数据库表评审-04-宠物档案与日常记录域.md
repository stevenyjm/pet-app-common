### C. 其他已决策规则

| 规则 | 决策结果 |
|------|----------|
| 时间字段维护方式 | 后端主动推送（移除 DB 自动维护） |
| CONSTRAINT 约束 | 全量移除（引用完整性由后端校验） |

| COMMENT | 表级与字段级 COMMENT 均不可省略；枚举字段标注取值映射 |
| TEXT/JSON 类型 | 避免使用；短文本用 VARCHAR(n)，数组用子表，结构化对象用扁平字段或子表；若触发分表须先向用户确认 |
| `pet` 与 `pet_owner` 表设计 | 用户已决策保留两表设计，不合并 |

### 第一部分：当前数据表（旧表）

#### 字段介绍

| breed | VARCHAR(64) | NULL | 品种 |

| allergens | VARCHAR(500) | NULL | 过敏原 |

| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### 建表语句

```sql
CREATE TABLE IF NOT EXISTS `pet` (
  `pet_id` BIGINT NOT NULL AUTO_INCREMENT,
  `name` VARCHAR(64) NOT NULL,
  `avatar_url` VARCHAR(255) DEFAULT NULL,
  `breed` VARCHAR(64) DEFAULT NULL,
  `gender` TINYINT DEFAULT 0 COMMENT '性别：0-未知，1-雄性，2-雌性',
  `birthday` DATE DEFAULT NULL,
  `default_owner_user_id` BIGINT NOT NULL COMMENT '默认所属用户，不可变',
  `preferences` VARCHAR(500) DEFAULT NULL,
  `medical_history` TEXT,
  `allergens` VARCHAR(500) DEFAULT NULL,
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '1-正常 0-已软删',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`pet_id`),
  KEY `idx_default_owner` (`default_owner_user_id`),
  KEY `idx_status_create` (`status`, `created_at`),
  CONSTRAINT `fk_pet_default_owner` FOREIGN KEY (`default_owner_user_id`) REFERENCES `user_account` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 备注说明

- `pet_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则；应改为 `pet_code VARCHAR(16)`，编码格式 `UP0001`
- `name` 字段名易混淆（联表查询时与 `user_profile.nickname`、商品名等无法区分），违反 D2 字段表源前缀规则，应改为 `pet_name`
- `gender` 字段名易混淆（联表时与 `user_profile.gender` 无法区分），应改为 `pet_gender`
- `status` 字段名易混淆，应改为 `pet_status`
- `default_owner_user_id` 为外键引用，需改为 `default_owner_user_code VARCHAR(16)`（引用 `user_account.user_code`）
- `medical_history` 使用 `TEXT` 类型，违反 D6（避免 TEXT）；建议改为 `VARCHAR(2000)` 或子表 `pet_medical_history`
- `allergens` 字段与子表 `pet_allergy_ingredient` 语义重复，是否保留作快照字段待评审
- `created_at` / `updated_at` 命名不符 D3 时间字段命名（应为 `create_time` / `last_modified_time`）
- 时间字段使用 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE CURRENT_TIMESTAMP`，违反 D3 维护方式规则（应后端推送）
- `idx_status_create(status, created_at)` 索引中 `status`（TINYINT）作首列，违反 D6 TINYINT 不作联合索引首列规则
- 1 处 `CONSTRAINT` 外键约束，违反 D5（应移除，引用完整性由后端校验）
- 无表级 `COMMENT`
- `name` / `avatar_url` / `breed` / `birthday` / `preferences` / `medical_history` / `allergens` 等字段缺失 `COMMENT`

```sql
CREATE TABLE IF NOT EXISTS `pet_owner` (

  `pet_id` BIGINT NOT NULL,

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 备注说明

- `pet_owner_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则
- `pet_id` / `user_id` 为外键引用，需改为 `pet_code` / `user_code`
- `status` 字段名易混淆（联表时与 `pet.pet_status`、用户状态等无法区分），违反 D2，应改为 `pet_owner_status`
- `ownership_type` 字段名虽含 `ownership` 前缀但 `type` 仍可能混淆，建议改为 `ownership_type`（保留，已有 ownership_ 前缀，合规）
- `idx_user_status(user_id, status)` 索引中 `status`（TINYINT）作次列，符合 D6（TINYINT 不作首列）；但 `user_id` 改名后索引名需更新
- 2 处 `CONSTRAINT` 外键约束，违反 D5（应移除）
- `created_at` / `updated_at` 命名与维护方式违反 D3
- 无表级 `COMMENT`
- `pet_id` / `user_id` 等字段缺失 `COMMENT`
- **表设计保留**：用户已决策 `pet` 与 `pet_owner` 不合并（`pet` 主表存宠物档案，`pet_owner` 存多用户归属关系）
