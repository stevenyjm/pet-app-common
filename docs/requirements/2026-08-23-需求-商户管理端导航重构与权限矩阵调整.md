## 一、需求背景

### 1.1 前提

商户管理端功能已基本接近稳定，在较长时间内不会进行功能的增减，最多进行功能的修改与优化。在此基础上：

1. **导航重构**：对左侧导航区进行层级精简与归类，从当前 10 个分组 + 2 个独立菜单精简为 9 项主层级
2. **订单管理合并**：合并「订单管理 / 待发货 / 售后管理」三个页面为单一「订单管理」页，采用 Tab 分栏布局
3. **UI 主题资产管理移除**：全面移除管理端 UI 主题资产配置功能，小程序端相关资源改为静态方案处理
4. **消息广播立即发送移除**：移除「立即发送广播」功能（风险高、无审核时机），消息广播统一走「预设 + 定时发布」流程；功能移除后移除消息广播页面与路由
5. **权限矩阵调整**：根据管理端实际功能盘点，清理无用权限码，并重新设计角色（增删角色 + 重新分配权限）

### 1.2 目标

1. 导航层级精简为 9 项主层级（无「其他」归档分组）
2. 订单管理页支持 Tab 分栏，待发货订单显示「去发货」，售后中订单显示「去处理」
3. UI 主题资产管理功能从管理端与后端彻底移除，小程序端改为静态内置
4. 消息广播「立即发送」功能从管理端与后端移除，广播统一走预设模板 + 定时调度
5. 权限码从 58 个缩减至 40 个（数字勘误：原"53→41"基于后端代码注释错误，经 `node -e` 核实实际为 58 个），角色从 4 个非超管角色调整为 3 个

### 2.2 功能承接关系核实

#### 2.2.1 CMS 页面（/cms）— 已被小程序工作台完全承接 ✅

- 旧页面 [views/cms/Index.vue](../../../pet-app-admin-web/src/views/cms/Index.vue) 直接调用 `/admin/cms/pages`（GET 列表、GET 单条、PUT 更新）
- 工作台 [views/workbench/CmsPublish.vue](../../../pet-app-admin-web/src/views/workbench/CmsPublish.vue) 固定 `MODULE_TYPE = 'cms_publish'`，调用 `/admin/workbench/cms_publish/*`（草稿→发布→回滚流程），并通过 `getCmsPage(type)` 加载旧 CMS 页面数据作为初始数据
- **结论**：工作台 CMS 配置发布是增强版（草稿/发布/回滚），操作同一数据源，**功能完全覆盖**旧 CMS 页面，旧页面可移除

#### 2.2.2 店铺配置（/shop-config）— 已被小程序工作台完全承接 ✅

- 旧页面 [views/shop-config/Index.vue](../../../pet-app-admin-web/src/views/shop-config/Index.vue) 直接调用 `/admin/shop-config`（GET、PUT 直接更新）
- 工作台 [views/workbench/ContentConfig.vue](../../../pet-app-admin-web/src/views/workbench/ContentConfig.vue) 固定 `MODULE_TYPE = 'content_config'`，调用 `/admin/workbench/content_config/*`（草稿→发布流程），并通过 `getShopConfig()` 加载店铺配置作为初始数据
- **结论**：工作台文案信息配置发布是增强版，操作同一 `shop_config` 数据，**功能完全覆盖**旧店铺配置页，旧页面可移除

#### 2.2.3 小程序配置（/mini-app-config）— 部分功能待移除

小程序配置包含 3 个子功能：

| 子功能 | 页面 | 后端 API | 权限码 | 处理方式 |
|-------|------|---------|--------|----------|
| 配置入口 | [Index.vue](../../../pet-app-admin-web/src/views/mini-app-config/Index.vue) | `/admin/mini-app-config`（GET） | `mini_app_config:view` | **移除**（仅作为 UI 主题资产入口，主题资产移除后无独立价值） |
| UI 主题资产 | [ThemeAssets.vue](../../../pet-app-admin-web/src/views/mini-app-config/ThemeAssets.vue) | `/admin/mini-app-config/theme-assets/*` | `mini_app_config:theme` | **移除**（全面移除功能，小程序端改静态化） |
| 文本配置 | [Texts.vue](../../../pet-app-admin-web/src/views/mini-app-config/Texts.vue) | `/admin/mini-app-config`（PUT） | `mini_app_config:edit` | **移除**（文本配置功能由小程序工作台文案信息配置发布承接） |

> **结论**：小程序配置的 3 个子功能全部移除（UI 主题资产移除 + 文本配置已被工作台承接 + 入口页失去意义），整个 `/mini-app-config` 路由树移除。

#### 2.2.4 消息广播（/messages/broadcast）— 立即发送功能待移除

消息广播页面包含两个功能：

| 子功能 | 实现位置 | 后端 API | 权限码 | 处理方式 |
|-------|---------|---------|--------|----------|
| 立即发送广播 | [Broadcast.vue](../../../pet-app-admin-web/src/views/message/Broadcast.vue) 发送 Tab | `/admin/messages/broadcast`（POST） | `message:send` | **移除**（风险高、无审核时机） |
| 广播历史查看 | [Broadcast.vue](../../../pet-app-admin-web/src/views/message/Broadcast.vue) 历史记录 Tab | `/admin/messages/jobs`（GET） | `message:view` | **移除**（广播历史查看功能随页面移除） |

> **替代方案**：消息广播统一走「预设模板（信息注册台）+ 定时调度（任务调度平台）」流程：
> - **预设模板**：[registration/PresetBroadcast.vue](../../../pet-app-admin-web/src/views/registration/PresetBroadcast.vue) 管理预设广播消息模板（CRUD），权限码 `preset_broadcast:manage`
> - **定时调度**：[task-platform/BroadcastSchedules.vue](../../../pet-app-admin-web/src/views/task-platform/BroadcastSchedules.vue) 管理广播定时任务（新增/撤销/提前执行），权限码 `broadcast_schedule:view` / `broadcast_schedule:manage`
> - **立即发送替代**：任务调度平台支持「提前执行」功能，作为紧急发送的替代方案（需先创建预设模板，再调度执行，保留审核时机）
>
> **结论**：消息广播页面整体移除，立即发送功能由「预设 + 定时调度（支持提前执行）」替代。

```
        ↓

```

> **「提前执行」作为紧急发送替代**：任务调度平台 [BroadcastSchedules.vue](../../../pet-app-admin-web/src/views/task-platform/BroadcastSchedules.vue) 支持「提前执行」功能，作为紧急发送的替代方案。流程为：先在信息注册台创建预设模板 → 在任务调度平台创建调度任务并「提前执行」，保留审核时机（预设模板可预先审核）。
>
> **「指定用户列表」能力已具备（无需新增）**：经核查，预设广播模板的指定用户能力已全链路打通：
> - **模型层**：[PresetBroadcastMessage.js](../../../pet-app-backend/models/PresetBroadcastMessage.js) 已有 `target_type`(默认 'all') + `target_value`(TEXT) 字段
> - **Service 层**：[adminPresetBroadcastService.js#L35](../../../pet-app-backend/services/adminPresetBroadcastService.js) `ALLOWED_TARGET_TYPES = ['all', 'users']`，create/update 均支持
> - **前端预设广播页**：[PresetBroadcast.vue#L294-L305](../../../pet-app-admin-web/src/views/registration/PresetBroadcast.vue) 已有「全部用户/指定用户」单选 + user_id 输入框
> - **前端调度页**：[BroadcastSchedules.vue#L349-L354](../../../pet-app-admin-web/src/views/task-platform/BroadcastSchedules.vue) 下拉选项已显示「目标：全体用户/指定用户」
> - **调度执行**：`executeBroadcastSchedule` 会读取 preset 的 `target_type` 与 `target_value`，按指定用户列表下发
>
> 因此「立即发送」移除后，「指定用户」场景由「预设模板（指定用户）+ 定时调度 / 提前执行」完整替代，**本次需求无需新增任何代码**。
