# 微信小程序代码质量检测问题诊断报告

## 一、问题概述

在微信开发工具中上传项目代码时，出现三项未通过检测项：

| 检测项 | 检测结果 | 微信要求 |
|--------|----------|----------|
| 主包 - 主包大小 | ❌ 未通过 | 主包尺寸（不包含插件）应小于 1.5 M |
| 代码压缩 - JS文件 | ❌ 未通过 | 对JS文件进行压缩 |
| 代码包 - 组件 | ❌ 未通过 | 启用组件按需注入 |

---

## 二、问题深度分析

### 2.1 主包大小问题

#### 2.1.1 当前状态

- 构建输出总大小：约 **977.94 KB**（dist/build/mp-weixin）
- vendor.js 大小：约 **85.83 KB**（包含 Vue3 运行时 + qrcode-generator）
- 页面数量：共 **28 个页面**，全部打包在主包中
- 组件数量：共 **14 个组件目录**，全部打包在主包中

#### 2.1.2 问题根因

1. **缺乏分包配置**：所有页面均配置在 `pages.json` 的 `pages` 数组中，没有使用 `subPackages` 分包机制。微信小程序规定主包（包含 TabBar 页面）不得超过 1.5MB，但当前项目将所有页面（包括非核心页面如 `news/`、`feedback/`、`reminder/` 等）都打包在主包内。

2. **第三方库冗余**：`qrcode-generator`（约 15-20KB）被打包进 vendor.js，该库仅在 `QrShareSheet` 组件中使用，属于非首屏必需资源。

3. **静态资源未优化**：`static/` 目录下的图片资源未进行压缩处理，如 `dock-bg.png`、`logo.png` 等。

4. **API 模块全量打包**：`api/` 目录下的所有接口文件（22个）被打包进主包，部分接口仅在特定页面使用。

#### 2.1.3 影响评估

| 资源类型 | 估算大小 | 是否首屏必需 |
|----------|----------|--------------|
| Vue3 运行时 | ~50 KB | 是 |
| qrcode-generator | ~20 KB | 否（仅分享功能用） |
| 页面 JS 总和 | ~150 KB | 部分否 |
| 组件 JS 总和 | ~60 KB | 部分否 |
| API 模块总和 | ~50 KB | 部分否 |
| 静态资源 | ~80 KB | 部分否 |

### 2.2 代码压缩 - JS文件问题

#### 2.2.1 当前状态

从构建输出的 `vendor.js` 分析，代码经过了基础的模块化打包（使用 ES Module），但**未启用 Terser 压缩**：

- 变量名存在较长命名（如 `stringToBytesFuncs`、`getMode`、`writeByte`）
- 代码中包含大量空格和换行符
- 没有进行死代码消除（Tree Shaking）

#### 2.2.2 问题根因

1. **Vite 配置缺失压缩插件**：`vite.config.js` 中仅配置了 `@dcloudio/vite-plugin-uni`，未添加 `terser` 或 `@rollup/plugin-terser` 压缩插件。

2. **uni-app 构建模式未启用压缩**：默认构建命令 `uni build -p mp-weixin` 可能未开启生产环境的 JS 压缩选项。

3. **缺少环境变量配置**：未设置 `NODE_ENV=production` 或 `UNI_COMPRESS=1` 等触发压缩的环境变量。

#### 2.2.3 影响评估

- JS 文件压缩率通常可达 **30%-50%**
- 当前约 350KB 的 JS 代码，压缩后可减少 **100-175KB**

### 2.3 代码包 - 组件问题

#### 2.3.1 当前状态

`pages.json` 中的 `easycom` 配置仅注册了部分组件：

```json
"easycom": {
    "autoscan": true,
    "custom": {
        "^TabPageSheet$": "@/components/tab-page-sheet/TabPageSheet.vue",
        "^PageLoading$": "@/components/page-loading/PageLoading.vue",
        "^QrShareSheet$": "@/components/qr-share-sheet/QrShareSheet.vue"
    }
}
```

但 `app.json` 中仅声明了两个组件：

```json
"usingComponents": {
    "tab-page-sheet": "/components/tab-page-sheet/TabPageSheet",
    "page-loading": "/components/page-loading/PageLoading"
}
```

#### 2.3.2 问题根因

1. **未启用微信小程序原生按需注入**：微信小程序要求在 `app.json` 或页面 JSON 中使用 `usingComponents` 声明组件，并启用 `lazyCodeLoading` 配置。

2. **easycom 自动扫描可能导致组件冗余**：`autoscan: true` 会自动扫描所有组件目录并全局注册，导致未使用的组件也被打包进主包。

3. **组件未按页面按需引用**：所有组件都通过 easycom 全局注册，而非在需要的页面中局部引用。

## 三、解决方案

### 3.1 主包大小优化方案

#### 3.1.1 配置分包加载（推荐，高优先级）

> **重要提示**：微信小程序不允许分包的 `root` 目录与主包页面路径重叠。例如 `pages/order/order` 是 TabBar 页面在主包中，则不能将 `root` 设为 `pages/order`。必须将非主包页面迁移到独立的分包根目录。

**修改文件**：`src/pages.json`

### 3.2 JS 文件压缩方案

> **重要提示**：直接在 `vite.config.js` 中添加 terser 插件可能与 uni-app 内置构建管线冲突。推荐优先通过 `manifest.json` 配置和环境变量方式启用压缩。

#### 3.2.1 通过 manifest.json 配置压缩（推荐）

**修改文件**：`src/manifest.json`

**实施步骤**：

```json
{
    "mp-weixin": {
        "setting": {
            "urlCheck": false,
            "es6": true,
            "minified": true,
            "autoAudits": true
        },
        "usingComponents": true
    }
}
```

**参数说明**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `es6` | `true` | 将 ES6 代码转为 ES5 |
| `minified` | `true` | 压缩 JS 文件 |
| `autoAudits` | `true` | 自动代码审查 |

#### 3.2.2 设置环境变量

**创建文件**：`.env.production`

```
NODE_ENV=production
UNI_COMPRESS=1
```

**修改文件**：`package.json`（可选，明确指定环境）

```json
{
    "scripts": {
        "build:mp-weixin": "cross-env NODE_ENV=production UNI_COMPRESS=1 uni build -p mp-weixin"
    }
}
```

**安装依赖**（如需使用 cross-env）：

```bash
npm install -D cross-env
```

#### 3.2.3 Vite 配置压缩（备选方案）

> **注意**：如果上述方式无效，再尝试此方案。直接添加 terser 插件可能与 uni-app 构建管线冲突。

**修改文件**：`vite.config.js`

```js
import path from 'path'
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'

export default defineConfig({
    plugins: [uni()],
    build: {
        minify: 'terser',
        terserOptions: {
            compress: {
                drop_console: true,
                drop_debugger: true,
                pure_funcs: ['console.log', 'console.debug']
            },
            mangle: {
                toplevel: true
            }
        }
    },
    css: {
        preprocessorOptions: {
            scss: {
                additionalData: '@import "@/styles/theme.scss";',
            },
        },
    },
    resolve: {
        alias: {
            '@': path.resolve(__dirname, 'src'),
        },
    },
    server: {
        host: '0.0.0.0',
        port: 3000,
        strictPort: true,
    },
})
```

**预期收益**：JS 文件体积减少 **30%-50%**，约 **100-175 KB**。

### 3.3 组件按需注入方案

#### 3.3.1 配置微信小程序按需加载

**修改文件**：`src/pages.json`

**实施步骤**：

1. 关闭 easycom 自动扫描，改为手动按需注册：

```json
{
    "easycom": {
        "autoscan": false,
        "custom": {}
    }
}
```

2. 在每个页面的 JSON 文件中按需声明组件：

**示例**：`src/pages/index/index.json`

```json
{
    "usingComponents": {
        "page-loading": "@/components/page-loading/PageLoading",
        "tab-page-sheet": "@/components/tab-page-sheet/TabPageSheet"
    }
}
```

#### 3.3.2 配置全局按需注入

**修改文件**：`src/manifest.json`

**实施步骤**：

```json
{
    "mp-weixin": {
        "setting": {
            "urlCheck": false,
            "es6": true,
            "minified": true
        },
        "usingComponents": true,
        "lazyCodeLoading": "requiredComponents"
    }
}
```

**预期收益**：未使用的组件不会被打包进主包，预计减少 **10-30 KB**。

## 六、风险提示

1. **分包路径变更**：分包配置后，页面跳转路径需要调整。非主包页面路径从 `/pages/xxx/xxx` 变更为 `/subpk-xxx/xxx`，如 `/pages/order/detail` → `/subpk-order/detail`。需检查并更新所有 `uni.navigateTo`、`uni.redirectTo`、`uni.switchTab` 等跳转代码。
2. **分包目录结构迁移**：需要将非主包页面从 `src/pages/` 迁移到独立的分包目录（如 `src/subpk-order/`），需确保文件移动后路径引用正确。
3. **动态 import 兼容性**：微信小程序基础库版本需 >= 2.11.0。
4. **组件注册遗漏**：关闭 easycom 自动扫描后，需确保所有组件都在页面 JSON 中正确注册。
5. **压缩导致的调试困难**：生产环境压缩后，错误堆栈可能难以定位，建议保留 source map。
6. **manifest.json 配置冲突**：确保 `mp-weixin.setting.minified` 设置为 `true`，与 vite 配置不冲突。
