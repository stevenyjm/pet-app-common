## 一、需求概述

商户希望对小程序端的宠物页进行 UI 重新设计，同时对宠物数据进行重构。整体页面结构由原型 v6 定义：

```
[     日期选择区    ]
[     宠物卡片区    ]
[   餐食|运动看板   ]
[心情看板]  [排便看板]
```

本次变更涉及：
1. **UI 整改**：宠物页主页面重构 + 新增今日心情详情页、排便状态详情页、日记录独立页面
2. **数据重构**：心情/排便从"每日单值"升级为"每日多条记录"、新增生理状态/卡路里目标/运动目标等数据

## 三、UI 整改方案

### 3.1 日期选择区（改造）

**现状**：横向日期条，"有记录"显示绿点。

**整改后**：
- 顶部导航：`<<  <  2026年8月  >  >>`（双左箭头=上月，单左=上周，单右=下周，双右=下月）
- 星期行：`日 一 二 三 四 今 六`（今天星期显示为"今"）
- 日期行 + 每日缩略环图（替代绿点）
- 缩略环图 = 当日 [餐食|运动看板] 同心双环图的缩略版（外环餐食达成率，内环运动达成率）
- 月份标签可点击 → 弹出日期选择器切换年月
- 日期切换逻辑沿用现有 `pet.vue` 的 prevMonth/nextMonth/prevWeek/nextWeek/onMonthPickerChange

**关键变化**：绿点 → 双环缩略图，需要每天的餐食/运动达成率数据。

### 3.2 宠物卡片区（改造 + 新增）

**现状**：横向宠物选项条（头像+名称+品种）。

**整改后**分两行：

**第一行：宠物卡片 + [+]**
- 宠物卡片：`[头像] [名称(性别)] / [种类]`，头像尺寸较大（=右侧两行信息高度）
- 名称后附性别图标（♂/♀）
- 未选中卡片：内部文案和背景为灰色系
- 点击未选中卡片 → 切换宠物；点击已选中卡片 → 查看宠物档案信息（沿用现有 `subpk-pet/info.vue`）
- [+] → 添加宠物（沿用现有 `PetAddWizard`）

**第二行：四个常驻卡片**（切换宠物时内部信息同步更新）

| 卡片 | 显示内容 | 点击行为 |
|------|----------|----------|
| 体重卡片 | 该宠物最新一次记录的体重值（默认 kg） | 记录体重（覆盖旧值） |
| 生理卡片 | 该宠物最新一次记录的生理状态（枚举值） | 记录生理状态（覆盖旧值） |
| 卡路里目标卡片 | 目标卡路里理论参考值 K0 或用户自定义 K1，最终显示值 KK | 进入目标卡路里设定页面（暂未实现） |
| 运动目标卡片 | 目标运动时长理论参考值 T0 或用户自定义 T1，最终显示值 TT | 进入目标运动时长设定页面（暂未实现） |

> 说明：
> - K0 = K(体重 W, 用户偏好参数 C1)
> - T0 = T(体重 W, 用户偏好参数 C2, 目标卡路里 KK)
> - KK = 用户自定义 K1 存在时取 K1，否则取理论值 K0
> - TT = 用户自定义 T1 存在时取 T1，否则取理论值 T0

### 3.3 餐食|运动看板（新增）

**整改后**：
- 左侧：同心双环图（外环=餐食，内环=运动），中心三段式（上=运动% / 蓝色分割线 / 下=餐食%）
- 右侧：
  - `[餐食色块] 餐食: kk / KK`
  - `[运动色块] 运动: tt / TT`
- 整面板可点击 → 进入日记录页面

**数据定义**：
- kk = 该宠物当日摄入卡路里的加权和
- tt = 该宠物当日运动时长的加权和
- KK / TT 与卡路里目标卡片 / 运动目标卡片同源

> 视觉规范与 v6 原型一致：外环橙(#FF8C42) r=54 stroke-width=14，内环青(#4ECDC4) r=37 stroke-width=12，中心分割线蓝(#4A90E2)。

### 3.4 心情看板 & 排便看板（改造）

**现状**：每日状态摘要三宫格中的一部分，每日单值。

**整改后**：独立为两个并排卡片。

**心情看板**：
- 标题行：`[😻] 今日心情`
- 内容行：水平居中对齐的今日最近 3 次记录（图标+描述，无需时间标注）
- 不足 3 条保持居中对齐；无记录显示 `---` 占位符
- 采用"变化图"视觉（竖虚线 + 底部 X 轴水平虚线），竖线高度按固定位置分配（非状态量化），最右项（最新）视觉凸显
- 点击 → 进入今日心情详情页

**排便看板**：
- 标题行：`[💩] 便便状态`
- 内容行：水平居中对齐的今日最近 3 次记录（描述，无需时间标注）
- 同样采用"变化图"视觉
- 点击 → 进入排便状态详情页

### 3.5 今日心情详情页（新增页面）

**结构**：
```
[  标题: 今日心情  ]
[  07:15 -  开心+图标  编辑|删除  ]
[  13:08 -  无聊+图标  编辑|删除  ]
[  + 添加  ]
```

- 按时间排序，最多 5 条
- 每条：时间 + 图标 + 描述 + 编辑/删除
- 添加/编辑弹出编辑框：输入或从预设值选择
- 预设值示例：开心/无聊/兴奋/低落/生气/亲昵/焦虑/困倦

### 3.6 排便状态详情页（新增页面）

**结构**：
```
[        标题: 便便状态        ]
[  07:15 -  干硬颗粒+Img缩略图  编辑|删除  ]
[  13:08 -  完美成型+Img缩略图  编辑|删除  ]
[  + 添加  ]
```

- 按时间排序，最多 5 条
- 每条：时间 + 描述 + 图片缩略图（可选）+ 编辑/删除
- 添加/编辑弹出编辑框：输入或从预设值选择，或拍摄/上传图片
- 预设值示例：干硬颗粒/偏硬/完美成型/偏软/软便/水样/带血丝/有异物

### 3.7 日记录页面（新增独立页面，参考 v7 原型）

**入口**：宠物页 [餐食|运动看板] 整面板点击。

**结构**：
- 顶部导航：返回 + 标题"日记录"
- 圆环图综合区：
  - 左栏：宠物信息纵向 4 行（头像 / 名称+性别 / 品种 / 体重）
  - 中栏：同心双环图（130×130，与宠物页看板同源，中心三段式）
  - 右栏：日期切换纵向 2 行（月日信息 / 左箭+文案+右箭）
  - 下方 Tab 数据行：餐食/运动 两个卡片（含色块+标签+数值+进度条），点击切换
- 双栏时间线区：
  - 主列（餐食或运动记录，带圆点时间线）+ 次列（另一类记录摘要）
  - Tab 切换时主次列互换
  - 底部统一橙色添加按钮
- 编辑弹层：时间 + 名称 + 卡路里(餐食)/时长(运动) + 类型预设值

> 内部功能沿用原宠物页餐食/运动的日记录功能（CRUD、模板等）。

## 四、数据重构方案

### 4.1 心情记录：每日单值 → 每日多条

**现状**：`pet_daily_status.daily_mood`（VARCHAR(32)），每天一条单值。

**重构**：新增独立表 `pet_mood_record`，支持每日多条（最多 5 条）。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| mood_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| pet_id | BIGINT | NOT NULL | 宠物ID |
| record_date | DATEONLY | NOT NULL | 记录日期 |
| record_time | TIME | NOT NULL | 记录时间（HH:mm） |
| mood_value | VARCHAR(32) | NOT NULL | 心情描述（如"开心"） |
| mood_icon | VARCHAR(16) | NULL | 心情图标（emoji） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除 |

```sql
CREATE TABLE IF NOT EXISTS `pet_mood_record` (
  `mood_id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '心情记录主键',
  `pet_id` BIGINT NOT NULL COMMENT '宠物ID',
  `record_date` DATE NOT NULL COMMENT '记录日期',
  `record_time` TIME NOT NULL COMMENT '记录时间 HH:mm',
  `mood_value` VARCHAR(32) NOT NULL COMMENT '心情描述，如开心/无聊/兴奋',
  `mood_icon` VARCHAR(16) DEFAULT NULL COMMENT '心情图标 emoji',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除 1-已删除',
  PRIMARY KEY (`mood_id`),
  KEY `idx_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_mood_record_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='宠物心情记录表（每日多条）';
```

**对 `pet_daily_status` 的影响**（决策已确认 D11）：`daily_mood` 旧字段数据迁移到 `pet_mood_record` 后废弃（标记 deprecated）。需编写迁移脚本。

### 4.3 每日健康指标表（体重 + 生理状态 + 目标卡路里 + 目标运动时长，统一表）

> **决策已确认（D1）**：体重、生理状态、目标卡路里、目标运动时长 4 项**统一建立一张新表，按日期存储**，记录历史值；C 端用户只能修改当天的值（覆盖当天值），不提供修改历史值能力。

**现状**：`pet_daily_status` 表含 daily_mood/daily_weight_kg/daily_stool_health，但无生理状态、无卡路里目标、无运动目标。

**重构**：新增表 `pet_daily_health_metric`，按 pet_id + record_date 唯一，每天一条记录，含体重、生理状态、卡路里目标、运动目标 4 项指标。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| metric_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| pet_id | BIGINT | NOT NULL | 宠物ID |
| record_date | DATEONLY | NOT NULL | 记录日期 |
| weight_kg | DECIMAL(6,2) | NULL | 体重 kg |
| physiology_status | VARCHAR(32) | NULL | 生理状态预设值文本（正常/生病/怀孕/术后/虚弱/发情期/残疾，与心情/排便存储模式一致） |
| calorie_theory_kcal | DECIMAL(8,2) | NULL | 卡路里理论参考值 K0（系统计算，本期占位） |
| calorie_custom_kcal | DECIMAL(8,2) | NULL | 卡路里用户自定义 K1 |
| exercise_theory_min | SMALLINT | NULL | 运动时长理论参考值 T0（系统计算，本期占位） |
| exercise_custom_min | SMALLINT | NULL | 运动时长用户自定义 T1（分钟） |
| user_pref_c1 | DECIMAL(6,2) | NULL | 用户偏好参数 C1（参与 K0 计算，本期占位） |
| user_pref_c2 | DECIMAL(6,2) | NULL | 用户偏好参数 C2（参与 T0 计算，本期占位） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除 |

```sql
CREATE TABLE IF NOT EXISTS `pet_daily_health_metric` (
  `metric_id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '每日健康指标主键',
  `pet_id` BIGINT NOT NULL COMMENT '宠物ID',
  `record_date` DATE NOT NULL COMMENT '记录日期',
  `weight_kg` DECIMAL(6,2) DEFAULT NULL COMMENT '体重 kg',
  `physiology_status` VARCHAR(32) DEFAULT NULL COMMENT '生理状态预设值文本（正常/生病/怀孕/术后/虚弱/发情期/残疾）',
  `calorie_theory_kcal` DECIMAL(8,2) DEFAULT NULL COMMENT '卡路里理论参考值K0（系统计算，本期占位）',
  `calorie_custom_kcal` DECIMAL(8,2) DEFAULT NULL COMMENT '卡路里用户自定义K1',
  `exercise_theory_min` SMALLINT DEFAULT NULL COMMENT '运动时长理论参考值T0（系统计算，本期占位，分钟）',
  `exercise_custom_min` SMALLINT DEFAULT NULL COMMENT '运动时长用户自定义T1（分钟）',
  `user_pref_c1` DECIMAL(6,2) DEFAULT NULL COMMENT '用户偏好参数C1（参与K0计算，本期占位）',
  `user_pref_c2` DECIMAL(6,2) DEFAULT NULL COMMENT '用户偏好参数C2（参与T0计算，本期占位）',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除 1-已删除',
  PRIMARY KEY (`metric_id`),
  UNIQUE KEY `uk_pet_date` (`pet_id`, `record_date`),
  KEY `idx_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_health_metric_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='宠物每日健康指标表（体重+生理状态+卡路里目标+运动目标，按日存储历史）';
```

**业务规则**：
- 体重卡片显示"最新一次记录的体重值"：查询 `pet_daily_health_metric` 中 `record_date <= 今天` 且 `weight_kg IS NOT NULL` 的最近一条。
- 生理卡片显示"最新一次记录的生理状态"：同上，取 `physiology_status IS NOT NULL` 的最近一条。生理状态预设值（正常/生病/怀孕/术后/虚弱/发情期/残疾）在小程序端 `constants/` 内置，与心情/排便同模式（VARCHAR 文本 + allowCreate 兜底）。
- 卡路里目标卡片显示 KK：当天记录存在 `calorie_custom_kcal` 取 K1，否则取 `calorie_theory_kcal`(K0)；当天无记录则取最近一次有值的记录。
- 运动目标卡片显示 TT：当天 `exercise_custom_min` 取 T1，否则 `exercise_theory_min`(T0)；最近回退同上。
- **覆盖语义**：C 端点击记录体重/生理/目标时，若当天已有记录则 UPDATE 当天记录对应字段，当天无记录则 INSERT；**不允许修改历史日期的记录**。
- 理论值 K0/T0 由系统在写入时计算填充（本期占位，公式后续迭代）；用户自定义 K1/T1 由用户设定页面写入（本期仅存储能力，设定页面暂未实现）。

> **决策已确认（D4）**：本期 K0=K(W,C1)、T0=T(W,C2,KK) 理论公式**仅占位**，K0/T0 留空或默认值，只实现 K1/T1 用户自定义存储 + UI 展示。公式后续迭代补充。

### 4.4 餐食卡路里加权和 kk

> **决策已确认（D5）**：kk = 当日所有餐食项卡路里**简单求和**（不加权）。

**现状**：`pet_meal_item.nutrition_json` 可能含卡路里数据（结构化营养信息），可靠性待验证。

**实现**：
- kk = Σ(当日所有 meal_item 的卡路里)
- 卡路里来源：优先从 `nutrition_json` 解析卡路里字段；若不含则该餐食项贡献 0。
- 后续若 `nutrition_json` 普遍无卡路里，再考虑餐食项新增 `calorie_kcal` 字段。

### 4.5 运动时长加权和 tt

> **决策已确认（D6）**：tt = 当日所有运动 session 的 `duration_minutes`**简单求和**（不加权）。

**现状**：`pet_exercise_session.duration_minutes`（SMALLINT），每条运动记录有时长。

**实现**：tt = Σ(当日所有 exercise_session.duration_minutes)

### 4.6 日期缩略环图数据

**现状**：`fetchRecordDates` 返回有记录的日期列表（仅日期字符串）。

**整改需求**：每日缩略环图需要每天的餐食/运动达成率（kk/KK, tt/TT）。

**方案**：新增接口或扩展现有 `getDailyRecords` 返回每天达成率（见第六节 API 设计）。

### 4.7 数据变更汇总

| 变更类型 | 对象 | 说明 |
|----------|------|------|
| 新增表 | `pet_mood_record` | 心情每日多条记录（替代 daily_mood） |
| 新增表 | `pet_stool_record` | 排便每日多条记录（含图片，替代 daily_stool_health） |
| 新增表 | `pet_daily_health_metric` | 体重+生理状态+卡路里目标+运动目标，按日统一存储历史 |
| 废弃字段 | `pet_daily_status.daily_mood` | 迁移到 pet_mood_record 后 deprecated |
| 废弃字段 | `pet_daily_status.daily_stool_health` | 迁移到 pet_stool_record 后 deprecated |
| 废弃字段 | `pet_daily_status.daily_weight_kg` | 迁移到 pet_daily_health_metric.weight_kg 后 deprecated |
| 迁移脚本 | 上述三字段数据迁移 | 旧 daily_mood→mood_record(默认 12:00)、daily_stool_health→stool_record(默认 12:00)、daily_weight_kg→health_metric |
