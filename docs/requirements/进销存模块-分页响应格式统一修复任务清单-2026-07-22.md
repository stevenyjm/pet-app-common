# 进销存模块 - 分页响应格式统一修复任务清单

> **文档版本**: v1.0  
> **创建日期**: 2026-07-22  
> **关联问题**: 入库管理页面和库存管理页面统计信息显示正确但列表条目不显示  
> **适用范围**: 宠物生鲜电商后端 + Web管理端

---

## 1. 任务概述

### 1.1 问题描述

商户反馈在商户管理端存在以下问题：
- **入库管理页面**：创建入库单后，没有条目显示，但下方统计信息显示"共1条"
- **库存管理页面**：没有库存条目显示，但下方统计信息显示"共17条"

### 1.2 根因分析

**数据结构不匹配**：后端返回分页数据时使用 `data` 字段承载数据列表，但前端类型定义和代码均期望使用 `list` 字段。

| 层级 | 返回字段 | 期望字段 | 结果 |
|-----|---------|---------|------|
| 后端 | `{ total, data: [...] }` | `{ total, list: [...] }` | `data.list` 为 `undefined` |
| 前端 | `rows.value = data.list` | `rows.value = data.list` | 表格无数据可渲染 |
| 前端 | `total.value = data.total` | `total.value = data.total` | 分页器统计正确 |

### 1.3 修复方案

采用**方案二：后端修改**，将进销存模块中所有分页服务的返回格式从 `data:` 统一改为 `list:`，与后端已有 16 个服务保持一致。

### 1.4 涉及端

| 端 | 目录 | 职责 |
|---|------|------|
| **后端** | `pet-app-backend/` | 修改 11 个分页服务的返回字段名 |
| **Web管理端** | `pet-app-admin-web/` | 无需修改，代码已适配 `list` 字段 |
| **小程序前端** | `pet-app/` | 不受影响（不调用进销存接口） |
