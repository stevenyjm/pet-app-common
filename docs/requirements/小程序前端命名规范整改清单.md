## 二、可独立修复项（纯前端）

### 2.1 🔴 P0：自定义组件 emit 原生事件名 `'tap'`

**问题描述**：`GenderIcon.vue` 组件 emit 了原生事件名 `'tap'`，在 uni-app 自定义组件场景下可能导致事件重复触发。

**涉及文件**：

| 文件 | 行号 | 当前写法 | 期望写法 |
|------|------|----------|----------|
| `src/components/gender-icon/GenderIcon.vue` | L2 | `@tap="$emit('tap')"` | `@tap="$emit('icontap')"` |
| `src/components/gender-icon/GenderIcon.vue` | L15 | emits 未声明 | 声明 `emits: ['icontap']` |

**修改详情**：

```vue
<!-- 修改前 -->
<template>
  <view class="gender-icon" :class="genderClass" @tap="$emit('tap')">

<!-- 修改后 -->
<template>
  <view class="gender-icon" :class="genderClass" @tap="$emit('icontap')">
```

```javascript
// 修改前
export default {
  name: 'GenderIcon',
  props: { ... },

// 修改后
export default {
  name: 'GenderIcon',
  emits: ['icontap'],
  props: { ... },
```

**调用方更新**：搜索项目中所有使用 `@tap` 绑定 `GenderIcon` 组件的位置，将监听事件从 `@tap` 改为 `@icontap`。

### 2.2 🟡 P1：页面层直接使用 snake_case 字段

**问题描述**：规范要求页面层只处理 camelCase 数据，snake_case 字段应由 Service 层转换。当前有 3 处在页面（`.vue`）中直接使用 `page_size` 参数调用 Service。

**涉及文件**：

| 文件 | 行号 | 当前写法 | 期望写法 |
|------|------|----------|----------|
| `src/pages/message/index.vue` | L304 | `page_size: 20` | 使用 camelCase 参数 `pageSize: 20` |
| `src/subpk-news/favorites.vue` | L106 | `page_size: this.pageSize` | 使用 camelCase 参数 `pageSize: this.pageSize` |
| `src/subpk-news/favorites.vue` | L128 | `page_size: this.pageSize` | 使用 camelCase 参数 `pageSize: this.pageSize` |

**修改说明**：Service 层内部应将 `pageSize` 自动转换为 `page_size` 发送给 API，页面层只使用 `pageSize`。需同步修改 Service 层的接口定义。

### 2.3 🟢 P2：常量文件命名（历史存量，建议保持）

**问题描述**：`error-codes.js` 使用 kebab-case 命名，规范建议 camelCase。但规范明确声明「已存在的 kebab-case 文件保持不变」。

**涉及文件**：

| 文件 | 当前命名 | 建议 |
|------|----------|------|
| `src/constants/error-codes.js` | `error-codes.js` | **保持现状**，新文件使用 camelCase |

> ⚠️ 该文件被 20+ 处 import 引用，重命名成本极高，建议保持现状。

### 2.4 🟢 P2：状态元数据命名 `statusClass` → BEM

**问题描述**：`constants/order.js` 中状态元数据使用 `statusClass`（camelCase），规范要求 BEM + kebab-case。

**涉及文件**：

| 文件 | 行号 | 当前写法 | 期望写法 |
|------|------|----------|----------|
| `src/constants/order.js` | L15-20 | `statusClass: 'status-pending'` | `statusClass: 'order-status--pending'` |

**影响范围**：以下文件引用了 `statusClass` 属性：
- `src/pages/order/order.vue` L68、L273
- `src/subpk-feedback/history.vue` L35、L111

> 💡 此项涉及样式类名变更，需同步修改所有引用处的 CSS class，且需要同步修改样式表中的 BEM 类定义。建议在统一的样式重构时一并处理。

## 三、跨项目配合项

### 3.1 🔴 P1：API 响应字段 snake_case → camelCase 整改

**问题描述**：当前三端 API 响应字段大量使用 snake_case（如 `page_size`、`created_at`、`is_favorited`），与本规范要求的 camelCase 不一致。

**当前状态**：
- API 层（`src/api/`）直接透传后端 snake_case 字段（20+ 处 JSDoc 注释使用 `page_size`、`is_read` 等 snake_case）
- Service 层（`src/services/`）部分文件有转换逻辑（如 `services/order.js` 的 `normalizeOrder`），但部分函数直接透传
- 页面层仍有少量直接使用 snake_case

**整改策略**：

| 阶段 | 负责端 | 任务 | 说明 |
|------|--------|------|------|
| 1 | **后端** | API 响应字段 snake_case → camelCase | 新增接口使用 camelCase；旧接口保持 snake_case 兼容期 |
| 2 | **后端** | 提供 `?use_camel_case=true` 查询参数切换 | 便于前端渐进式迁移 |
| 3 | **小程序前端** | Service 层统一转换 | API 层透传 → Service 层转换 → 页面层 camelCase |
| 4 | **Web 管理端** | 同步适配 | 同上策略 |

**小程序前端具体任务**：

| 文件 | 行号 | 任务 | 说明 |
|------|------|------|------|
| `src/services/order.js` | L113+ | Service 层 `fetchOrders` 返回 `pageSize` 而非 `page_size` | 已有 `normalizeOrder` 转换 |
| `src/services/message.js` | L113-127 | `fetchMessages` 中 `page_size` → `pageSize` 转换 | `const pageSize = params.page_size` |
| `src/services/serviceChat.js` | L157 | `fetchServiceMessages` 中 `page_size` → `pageSize` | `page_size: options.pageSize` |
| `src/services/feedback.js` | L137 | `fetchOrders` 中 `page_size: limit` → `pageSize: limit` | |
| `src/services/exercise-template.js` | L149 | `getExerciseTemplates` 中 `page_size: 50` → `pageSize: 50` | |
| `src/services/meal-template.js` | L347 | `getMealTemplates` 中 `page_size: 50` → `pageSize: 50` | |

> ⚠️ **此项需与后端 `pet-app-backend/.trae/rules/naming-conventions.md` 中的整改计划联动，在后端完成 snake_case → camelCase 整改后同步推进。**

## 四、合理例外（无需修改）

### 4.1 custom-tab-bar 使用 `wx.xxx` 原生 API

**说明**：`src/custom-tab-bar/index.js` 是微信原生 Component，不经 Vite/uni-app 编译，无法使用 `uni.xxx`。此为微信自定义 TabBar 的必要限制。

| 文件 | 行号 | 使用的 API | 原因 |
|------|------|-----------|------|
| `src/custom-tab-bar/index.js` | L44 | `wx.getStorageSync()` | 原生 Component 无法使用 uni API |
| `src/custom-tab-bar/index.js` | L85 | `wx.switchTab()` | 同上 |
| `src/custom-tab-bar/index.js` | L88 | `wx.reLaunch()` | 同上 |

**结论**：✓ 合理例外，无需修改。

### 4.2 utils/system.js 中 `wx.getWindowInfo` 降级

**说明**：`src/utils/system.js` 在 `uni.getWindowInfo` 不可用时降级使用 `wx.getWindowInfo`，属于兼容性适配。

| 文件 | 行号 | 使用的 API | 原因 |
|------|------|-----------|------|
| `src/utils/system.js` | L16-17 | `wx.getWindowInfo()` | uni API 不可用时的降级方案 |

**结论**：✓ 合理例外，无需修改。

### 4.3 Service 层使用 `wx.requestPayment` 注释

**说明**：`src/services/payment.js` L30 仅是 JSDoc 注释，不涉及实际调用。

**结论**：✓ 合理例外，无需修改。

### 4.4 `@tap` 在原生元素上的使用

**说明**：`@tap` 在原生 `<view>`、`<text>`、`<button>` 元素上使用是 uni-app 的标准事件绑定方式，不是自定义组件的事件名冲突。

受影响的文件（43 个 `.vue` 文件中的大量 `@tap` 绑定）均为原生元素事件，**不属于规范禁止范围**。

**结论**：✓ 合理使用，无需修改。
