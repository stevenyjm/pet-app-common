# 分析报告：小程序图片上传大小限制与反馈机制

> **创建日期**：2026-08-26
> **文档类型**：分析报告（归档待处理）
> **涉及项目**：pet-app（小程序前端）、pet-app-backend（后端服务）
> **状态**：待处理 · 待用户评审决策后推进
> **关联规则**：`multi-project.md` §2.1 新增 API 流程、§3 三端对齐检查清单

## 一、背景与目标

近期梳理小程序端涉及用户上传图片的业务场景时，需明确：

1. 当前哪些业务允许用户上传图片；
2. 后端 `/storage/upload` 接口是否具备限制图片大小的能力；
3. 当用户上传图片超出大小限制时，前端对用户的反馈与提醒机制是否完善。

本报告用于归档现状分析与改进建议，等待后续评审决策后推进实施。

## 二、小程序端图片上传业务场景梳理

小程序端共 **4 个业务场景** 涉及用户上传图片，均通过通用接口 `POST /storage/upload` 上传（宠物排便记录另走专用接口）。

| # | 业务场景 | 入口页面 | 上传用途 | category |
|---|---------|---------|---------|----------|
| 1 | 用户反馈 | `pet-app/src/subpk-feedback/index.vue` | 反馈截图 | `common` |
| 2 | 订单评价 | `pet-app/src/subpk-order/review.vue` | 评价配图 | （经通用上传，默认 `common`） |
| 3 | 宠物排便记录 | `pet-app/src/subpk-pet/stool-detail.vue` | 便便拍照 | 走专用接口 `/pets/{petId}/stool-records` |
| 4 | 在线客服聊天 | `pet-app/src/subpk-service/chat.vue` | 聊天图片 | `service` |

底层统一调用 `pet-app/src/api/storage.js` 的 `uploadStorageFile()`，由 `uni.uploadFile` 请求 `/storage/upload`。

## 三、后端接口与大小限制能力

**已支持，且已配置默认限制。** 关键实现位置：

| 关注点 | 文件位置 | 实现说明 |
|--------|---------|---------|
| 上传中间件 | `pet-app-backend/middleware/upload.js` | 使用 `multer`，`limits.fileSize = config.storage.maxFileSizeBytes`，`fileFilter` 仅允许 `image/jpeg/png/webp/gif` |
| 错误处理 | `pet-app-backend/middleware/upload.js` | 命中 `LIMIT_FILE_SIZE` 时返回"文件大小不能超过 ...MB" |
| 路由注册 | `pet-app-backend/routes/storage.js` | `POST /storage/upload` 挂载 `userOrAdminAuthMiddleware` + `uploadSingle` + `handleUploadError` |
| Controller | `pet-app-backend/controllers/storageController.js` | 校验上传文件存在，按 `req.body.category` 或默认 `common` 分类，按 admin/user 构造上传用户前缀 |
| 路径前缀 | `pet-app-backend/utils/storageService.js` | 不同 `category` 映射不同存储目录（如 `common -> uploads`、`service -> uploads/service`、`pet_cert -> pet-cert`） |
| 类型校验 | `pet-app-backend/utils/storageService.js` | `assertAllowedMimeType` 校验 MIME，仅允许 jpg/png/webp/gif |
| 配置来源 | `pet-app-backend/config/env.js` | `config.storage.maxFileSizeBytes` 来自环境变量 `OS_MAX_FILE_SIZE_BYTES`，**默认 5MB**（`5 * 1024 * 1024`） |

### 现状结论

1. **大小限制**：后端已具备限制能力，当前默认上限 **5MB**，通过环境变量 `OS_MAX_FILE_SIZE_BYTES` 调整即可，无需改代码。
2. **类型限制**：已限制为 `jpg/png/webp/gif`。
3. **数量限制**：每次仅允许上传 1 个文件（`upload.single('file')`），前端循环调用逐张上传。

## 四、前端反馈机制现状

### 4.1 通用上传错误处理（错误源头）

`pet-app/src/api/storage.js` 的 `uploadStorageFile()` 是所有业务的上传错误源头：

```javascript
if (res.statusCode < 200 || res.statusCode >= 300) {
  reject(createRequestError(body?.message || `上传失败(${res.statusCode})`, body?.code))
  return
}
```

后端在超限时返回 `文件大小不能超过 ...MB`，前端通过 `e.message` 取到该文案。

### 4.2 各业务场景的具体反馈

| 业务 | 文件位置 | 上传前提示 | 上传中反馈 | 失败提示文案 |
|------|---------|-----------|-----------|------------|
| 用户反馈 | `subpk-feedback/index.vue` L382-L415 | `最多上传 N 张图片`（仅数量检查） | `showLoading: 上传中…` | `e.message \|\| '图片上传失败'` + **从列表移除该图** |
| 订单评价 | `subpk-order/review.vue` L340-L370 | `每件商品最多 N 张图片`（仅数量检查） | `showLoading: 上传中…` | `e.message \|\| '图片上传失败'`（图片**不进列表**） |
| 客服聊天 | `subpk-service/chat.vue` L333-L358 | 无（每次1张） | `showLoading: 发送中…` | `getServiceErrorMessage(err, '图片发送失败')` |
| 宠物排便记录 | `subpk-pet/stool-detail.vue` L292-L342 | 无 | 提交时统一上传，无单独 loading | 走 `handleError`，提示较模糊 |

### 4.3 反馈方式的特点

1. **统一使用 `uni.showToast({ icon: 'none' })` 轻提示**：不带图标、3 秒后自动消失，无"重试"按钮。
2. **文案直接透传后端 message**：用户看到的是后端返回的 "文件大小不能超过 5MB"。
3. **无前置大小校验**：所有场景的 `uni.chooseImage` 都没有读取 `tempFiles[i].size` 做本地预检。
4. **加载状态统一**：上传过程中显示 `showLoading` 遮罩，阻止重复操作。
5. **失败后行为不一**：
   - 反馈页：失败图片从列表移除（用户体验较好）
   - 评价页：失败图片根本不进列表
   - 客服聊天：无图片列表概念，仅 toast
   - 便便记录：选图与提交分离，选图阶段无错误反馈

## 五、潜在改进点

| 改进方向 | 当前问题 | 建议做法 |
|---------|---------|---------|
| 前端预检大小 | 全部依赖后端报错，浪费一次网络请求 | `uni.chooseImage` success 回调里检查 `res.tempFiles[i].size`，超限直接 toast 不上传 |
| 错误提示更明显 | `icon: 'none'` 轻提示易被忽略 | 大小超限改用 `uni.showModal` 弹窗，给"重新选择"按钮 |
| 文案统一性 | 反馈用"图片上传失败"、客服用"图片发送失败"、便便用"请稍后重试" | 统一映射后端 code（如 40013）到"图片过大，请选择小于 5MB 的图片" |
| 失败后重试 | 需用户重新点击"添加图片"从头来 | 在失败的图片项上显示"重试"按钮，点击重新上传同一 localPath |
| 压缩质量可调 | `sizeType: ['compressed']` 用微信默认压缩，对大图可能仍超 5MB | 改用 `uni.compressImage` 显式指定 `compressedWidth` / `quality`，再上传前判断 |
| 业务差异化大小上限 | 所有业务共用同一上限（5MB） | 如需按业务差异化（如头像 2MB、评价 5MB），需在中间件按 `category` 分支处理 |
