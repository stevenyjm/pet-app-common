## 四、P3 — API 响应字段命名整改（✅ 已完成 · 2026-07-27）

### 4.1 问题描述

当前 TypeScript 接口定义中大量使用 **snake_case** 字段名（如 `order_id`、`created_at`、`pay_amount`、`page_size`），与命名规范要求的 **camelCase** 不一致。

此问题属于三端联动问题，经三端会议协调，采用 **HTTP 拦截器自动转换** 方案：

- **请求拦截器**：将 HTTP 查询参数（`params`）从 camelCase 自动转换为 snake_case 发送给后端
- **响应拦截器**：将后端返回的 snake_case 响应数据自动转换为 camelCase，前端代码统一使用 camelCase 访问

### 4.2 整改方案

#### 方案选型

采用 **HTTP 拦截器自动转换** 方案，优点：
1. **零侵入**：API 层和视图层代码统一使用 camelCase，无需手动转换
2. **渐进式**：后端逐步迁移时，只需调整拦截器，前端代码无需变更
3. **一致性**：所有请求/响应自动转换，避免遗漏

#### 核心实现

**新增工具函数**：`src/utils/caseConvert.ts`
- `toCamelCase<T>(obj)`：递归将对象的 snake_case 键转为 camelCase
- `toSnakeCase<T>(obj)`：递归将对象的 camelCase 键转为 snake_case
- `convertQueryParams(params)`：将查询参数从 camelCase 转为 snake_case

**HTTP 拦截器**：`src/api/http.ts`
- 请求拦截：自动将 `params` 从 camelCase 转为 snake_case
- 响应拦截：自动将响应数据从 snake_case 转为 camelCase
- 特殊处理：Blob/ArrayBuffer 响应（文件下载）跳过转换

### 4.3 已执行的整改操作

#### 类型定义整改（19 个文件，350+ 字段）

将 `src/types/` 下所有文件的 snake_case 字段转换为 camelCase：

| 文件 | 修改示例 |
|------|----------|
| `order.ts` | `order_id` → `orderId`, `created_at` → `createdAt`, `pay_amount` → `payAmount` |
| `product.ts` | `product_id` → `productId`, `category_id` → `categoryId` |
| `inventory.ts` | `warehouse_id` → `warehouseId`, `location_id` → `locationId` |
| `feedback.ts` | `feedback_id` → `feedbackId`, `resolved_at` → `resolvedAt` |
| `customerService.ts` | `conversation_id` → `conversationId`, `order_id` → `orderId` |
| `api.ts` | `page_size` → `pageSize`, `page` → `page` |
| 等其他 13 个文件 | 全量 snake_case → camelCase |

#### API 层整改（10+ 文件）

更新 `src/api/` 下所有文件的内联类型和参数构造：

- `src/api/order.ts`：`Promise<{ order_id: number }>` → `Promise<{ orderId: number }>`
- `src/api/message.ts`：`page_size` → `pageSize`
- `src/api/inventory.ts`：更新所有请求参数为 camelCase
- `src/api/product.ts`：更新所有请求参数为 camelCase
- 等其他 API 文件

#### 组件/视图层整改（44+ 文件，450+ 处变更）

更新 `src/views/` 和 `src/components/` 下所有文件的模板和脚本代码：

- 模板中：`row.order_id` → `row.orderId`, `order.created_at` → `order.createdAt`
- 脚本中：`data.page_size` → `data.pageSize`, `item.pay_amount` → `item.payAmount`
- 表单模型：`form.sku_id` → `form.skuId`, `form.batch_no` → `form.batchNo`
- el-table-column props：`prop="order_id"` → `prop="orderId"`, `row-key="user_id"` → `row-key="userId"`

#### 特别注意

**API 请求体保持 snake_case**：当构造发送给后端的 POST/PUT body 时，键名仍使用 snake_case（如 `{ sku_id: form.skuId }`），因为请求拦截器仅转换 URL 查询参数（`params`），不转换请求体。

### 4.5 保持 snake_case 的场景（合规保留）

以下场景仍使用 snake_case，属于正确做法：

| 场景 | 示例 | 原因 |
|------|------|------|
| API 请求体键 | `{ sku_id, warehouse_id, batch_no }` | 后端仍使用 snake_case 接收请求体 |
| 业务常量/枚举值 | `ORDER_STATUS = { ship: 'ship' }` | 业务语义标识，非字段名 |
| URL 查询参数键 | `route.query.user_ids` | URL 路由参数，非数据字段 |
| 本地存储键 | `localStorage.setItem('auth_token', ...)` | 浏览器存储键，非数据字段 |
| CSS 类名 | `class="order-list-panel"` | 样式类名，与数据字段无关 |
