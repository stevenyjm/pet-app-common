# 用户管理页面 · 需求分析与方案（临时）

> **文档类型**：需求分析 / 方案建议（非正式 PRD）  
> **编写日期**：2026-06-11  
> **适用项目**：`pet-app-admin-web`（追煮跑 · PC 商户管理端）  
> **关联文档**：[项目开发说明-Web前端.md](../pet-app-admin-web/docs/项目开发说明-Web前端.md) · [项目开发说明-后端.md](../pet-app-backend/docs/项目开发说明-后端.md) · [商户管理端-需求分析与方案.md](./商户管理端-需求分析与方案.md)

## 1. 需求概述

新增 **「用户管理」** 页面，用于：

1. **展示** C 端注册用户的基本信息；
2. **查询** 用户（关键词、状态、注册时间等）；
3. **导出** 用户信息（CSV，与订单/宠物导出口径一致）；
4. **多选用户**，生成 `user_id` 列表，供 **消息广播**（指定用户）使用；
5. **可选**：将现有 **「在线用户」** 页（`/stats/online`）能力合并进本页。

---

## 2. 现状与差距分析

### 2.1 已有能力（可复用）

| 能力 | 现状 | 位置 |
|------|------|------|
| 在线用户列表 | ✅ 分页展示滑动窗口内在线用户 | `GET /admin/stats/online-users` · `views/stats/Online.vue` |
| 注册/新增统计 | ✅ 仪表盘 `registered_count`、`today_new_users` | `GET /admin/stats/dashboard` |
| 消息广播（指定用户） | ✅ `target_type=users` + `user_ids[]` | `views/message/Broadcast.vue` · 当前为 **手工输入 ID 文本框** |
| 列表 + 筛选 + 导出模式 | ✅ 宠物/订单已落地 | `views/pet/List.vue` · `views/order/List.vue` |
| 用户数据表 | ✅ `user_account` + `user_profile` | 后端 Schema §4.2.1 |

### 2.2 关键缺口

| 缺口 | 说明 | 影响 |
|------|------|------|
| **无 Admin 全量用户列表 API** | 后端文档中 **不存在** `GET /admin/users`、`GET /admin/users/export` | 本需求 **必须先补后端接口**，否则前端只能展示「在线用户」子集 |
| 广播与用户选择未联动 | 广播页仅支持 textarea 粘贴 ID | 多选 → 广播需前端路由传参或 Pinia 暂存 |
| 菜单分散 | 「在线用户」在统计菜单下，与「用户管理」语义重叠 | 合并后需处理路由与菜单迁移 |

**结论**：需求在 **产品与技术层面均可行**，但属于 **前后端协同增量**；前端可独立先做 UI 骨架，**联调依赖后端新增 Admin 用户 API**。

---

## 3. 可行性评估

### 3.1 总体结论：**可行（建议分两期交付）**

| 维度 | 评估 | 说明 |
|------|------|------|
| 数据 | ✅ | `user_account`、`user_profile` 字段完整，可与 Redis 在线状态组合 |
| 后端 | 🟡 | 需新增 2 个只读接口（列表 + 导出）；工作量参考 `admin/pets`（BE-509~510） |
| 前端 | ✅ | 组件与模式成熟：`PaginatedTable`、`DateRangeFilter`、CSV 下载、表格多选 |
| 广播联动 | ✅ | 广播 API 已支持 `user_ids`；仅需改善 UX（跳转/预填） |
| 在线合并 | ✅ | 建议 Tab 或筛选，复用现有 `getOnlineUsers` + 新全量 API |
| 合规 | 🟡 | 导出含手机号需审计日志；禁止暴露 `openid` / `session_key` |

### 3.2 风险与约束

1. **在线 ≠ 全量**：`online-users` 仅含 Redis 窗口内用户（默认 300s）；不能与注册用户列表混为同一数据源。
2. **导出上限**：项目惯例单次 CSV **最多 1 万行**（订单/宠物一致）；超出需缩小筛选或二期异步导出。
3. **Redis 不可用**：在线 Tab 应保留现有 `redis_available` 告警；全量用户 Tab 不依赖 Redis。
4. **封禁用户广播**：广播 preview 仅统计 **status=1（正常）** 用户；多选时应对禁用用户给出提示（与后端 preview 对齐）。
5. **隐私字段**：管理端对手机号在订单/宠物场景已展示 **完整号码**；用户管理建议 **列表脱敏、导出/详情完整**，或统一为管理端完整展示并记审计（见 §6.3）。

## 4. 用户信息字段设计

字段来源：`user_account` + `user_profile`（后端 §4.2.1）；在线相关来自 Redis / `presence` 服务。

### 4.1 列表展示字段（推荐）

| 字段 | 来源 | 展示说明 | 优先级 |
|------|------|----------|--------|
| `user_id` | `user_account` | 主键；广播目标 ID | **P0** |
| `avatar_url` | `user_profile` | 头像（无则昵称首字） | P0 |
| `nickname` | `user_profile` | 昵称，空显示「—」 | **P0** |
| `phone` | `user_profile` | 建议列表 **138****8000**，Tooltip 或详情页完整号 | **P0** |
| `status` | `user_account` | `1` 正常 / `0` 封禁，Tag 展示 | **P0** |
| `create_time` | `user_account` | 注册时间 | **P0** |
| `last_login_time` | `user_account` | 最近登录（离线用户主要活跃指标） | P1 |
| `is_online` | 计算字段 | 仅「全部用户」视图：是否在当前在线窗口内 | P1（合并在线页时） |
| `last_seen_at` | Redis / 在线 API | 仅「当前在线」Tab 展示 | P1 |
| `pet_count` | 聚合 `pet` | 拥有宠物数，便于运营筛选 | P2 |
| `order_count` | 聚合 `order_main` | 历史订单数 | P2 |

**不建议在列表展示**：`openid`、`unionid`、`session_key`、`email` 完整明文（邮箱可详情页脱敏展示）。

### 4.2 查询 / 筛选条件（推荐）

| 参数 | 类型 | 匹配规则 | 优先级 |
|------|------|----------|--------|
| `keyword` | 文本 | `user_id`（精确/前缀）、昵称（模糊）、手机号（完整或后四位） | **P0** |
| `status` | 枚举 | `all` / `1` 正常 / `0` 封禁 | **P0** |
| `from_date` / `to_date` | 日期 | 注册时间 `create_time` 范围（YYYY-MM-DD） | **P0** |
| `online_only` | 布尔 | `true` 时等价于当前在线列表（或切 Tab） | P1 |
| `has_phone` | 布尔 | 是否已绑定手机 | P2 |
| `has_pet` | 布尔 | 是否有宠物档案 | P2 |

分页：`page` 默认 1，`page_size` 默认 20、最大 50（与现有 Admin 列表一致）。

### 4.3 导出 CSV 字段（推荐）

与列表筛选参数一致；建议列顺序：

```text
user_id,nickname,phone,status,gender,email,invite_code,inviter_user_id,invited_at,create_time,last_login_time,pet_count,order_count
```

| 列 | 说明 |
|----|------|
| `status` | 导出为 `正常` / `封禁` 或 `1`/`0`（与订单导出风格统一） |
| `gender` | `0` 未知 / `1` 男 / `2` 女 |
| `email` | **脱敏**（与 C 端 profile 一致） |
| `phone` | 管理端导出建议 **完整号码**（履约/客服场景需要；写审计） |

**不包含**：`openid`、`session_key`、微信原始凭证。

**响应约定**（对齐宠物/订单）：

- `Content-Type: text/csv; charset=utf-8`
- 响应头 `X-Export-Row-Count`
- 单次最多 **10000** 行
- `admin_audit_log`：`action=user_export`

### 4.4 用户详情（可选 P2）

路由 `/users/:id` 只读详情：基础资料 + 宠物列表入口 + 最近订单摘要 + 登录日志最近 N 条。一期可不做，列表 + 导出已满足主需求。

## 5. 与「在线用户」页合并方案

### 5.1 推荐方案：**单页双 Tab（推荐）**

```
用户管理 (/users)
├── Tab「全部用户」     → GET /admin/users（新）
└── Tab「当前在线」     → GET /admin/stats/online-users（现有）
```

**顶部公共区**（在线 Tab 或全部 Tab 均可见）：

- 当前在线人数 `online_count`
- 统计窗口 `window_seconds`
- Redis 不可用告警（复用 `Online.vue` 逻辑）

**迁移**：

- 路由：`/stats/online` → 301 重定向到 `/users?tab=online`
- 菜单：移除「在线用户」，保留「用户管理」；图标继续可用 `User`
- 仪表盘「当前在线」卡片仍链到 `/users?tab=online`

**优点**：语义统一、减少侧栏项、广播多选可与在线用户直接联动（「选中当前在线用户发广播」）。

### 5.2 备选方案：保持两页

- `/users`：全量用户管理
- `/stats/online`：仅在线监控

**缺点**：菜单重复、运营需在两个页面间切换；仅当商户明确要求独立「监控大屏」时采用。

## 6. 消息广播联动方案

### 6.1 当前广播能力

- API：`GET /admin/messages/broadcast/preview`、`POST /admin/messages/broadcast`
- 指定用户：`target_type: "users"` + `user_ids: number[]`
- 前端：`Broadcast.vue` 手工输入逗号/换行分隔 ID

### 6.2 推荐交互

| 步骤 | 行为 |
|------|------|
| 1 | 用户管理表格启用 **多选**（`el-table-column type="selection"`） |
| 2 | 工具栏显示「已选 N 人」+ **复制 ID 列表** |
| 3 | 主按钮 **「用于消息广播」** → `router.push({ path: '/messages/broadcast', query: { user_ids: ids.join(',') } })` |
| 4 | `Broadcast.vue` 挂载时读取 `route.query.user_ids`，预填 `target_type=users` 与 textarea |
| 5 | 可选：**「选择当前页全部」** / **「选择当前筛选结果」**（后者需后端支持 `user_ids` 批量 preview 或前端限制最多 500 人） |

### 6.3 业务规则

- 跳转前过滤 `status=0` 用户并 Toast 提示「已排除 N 名禁用用户」
- 广播页仍走 **preview 二次确认**（现有 FE-303），不跳过
- 从在线 Tab 多选时，ID 集合即为在线子集，与全量 Tab 行为一致

## 7. 后端 API 建议（待实现）

> 以下接口 **当前不存在**，建议作为 **BE-6xx** 任务纳入后端迭代。

### 7.1 `GET /admin/users`

**鉴权**：Admin JWT  

**Query**：§4.2 所列参数  

**响应 `list[]` 示例**：

```json
{
  "list": [
    {
      "user_id": 1001,
      "nickname": "铲屎官A",
      "avatar_url": "https://...",
      "phone": "138****8000",
      "phone_full": "13800138000",
      "status": 1,
      "gender": 0,
      "create_time": "2026-01-15T08:00:00.000Z",
      "last_login_time": "2026-06-10T12:00:00.000Z",
      "is_online": false,
      "pet_count": 2,
      "order_count": 5
    }
  ],
  "pagination": { "page": 1, "page_size": 20, "total": 1523, "has_more": true }
}
```

> `phone_full` 可选：若不想在 JSON 列表中带完整号，则仅导出 CSV 时查完整号。

**实现要点**：

- `user_account` LEFT JOIN `user_profile`
- `keyword` 手机号匹配需索引或限制长度避免全表扫（用户量上万后考虑）
- `is_online`：批量查询 Redis `online:user:{id}` 或 JOIN 在线 ZSET

### 7.2 `GET /admin/users/export`

- Query 与列表相同
- CSV 列：§4.3
- 上限 10000 行；审计 `user_export`

### 7.3 与现有 API 关系

| API | 关系 |
|-----|------|
| `GET /admin/stats/online-users` | **保留**；在线 Tab 专用；不做导出 |
| `GET /admin/stats/dashboard` | **保留**；卡片统计不变 |
| `GET /admin/messages/broadcast/preview` | **不变**；前端传入多选 ID |

## 9. 验收标准（草案）

1. 可按 **昵称 / 手机 / user_id** 搜索，按 **注册日期、账号状态** 筛选。
2. 分页列表字段不少于 §4.1 P0 列。
3. 导出 CSV 与当前筛选一致，≤1 万行，文件名含日期，成功后 Toast 行数。
4. 多选 ≥1 人后，可 **一键跳转广播** 且 ID 已预填；preview 人数与选择一致（排除禁用用户时有提示）。
5. （若合并）在线 Tab 行为与现 `Online.vue` 一致；旧路由重定向有效。
6. 导出操作写入 `admin_audit_log`（后端验收）。
7. 响应与导出 **不包含** openid / session_key。

## 10. 专业建议摘要

| 主题 | 建议 |
|------|------|
| **优先级** | P0：全量列表 + 查询 + 导出 + 多选联动广播；P1：合并在线 Tab；P2：用户详情页 |
| **后端先行** | 先定 API 契约再开发前端，避免仅用 `online-users` 冒充用户管理 |
| **菜单位置** | 建议放在 **「用户反馈 / 在线客服」** 附近，或 **「消息广播」** 上方，体现用户运营闭环 |
| **不要做的** | 一期不做封禁/解封、改资料、删号；不做 C 端 openid 展示 |
| **性能** | 用户量 &lt; 1 万：MySQL 分页足够；更大时再议 ES/缓存 |
| **文档** | 后端 §5 增补「Admin 用户管理」；Web 文档 §4 增 FE-Uxx 任务行 |
