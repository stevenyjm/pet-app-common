# 后端修复：资讯详情接口收藏状态回显

> **创建日期**：2026-07-26  
> **创建人**：yjm（前端）  
> **指派给**：后端开发  
> **优先级**：高  
> **影响范围**：资讯详情页收藏状态回显

---

## 一、问题描述

在微信小程序中，用户对某篇资讯已收藏，进入资讯详情页后：
- 底部收藏按钮始终显示**未点亮**状态（空心 ♡）
- 点击红心执行的是"添加收藏"而非"取消收藏"
- 从「我的收藏」页面点击进入详情页，同样表现异常

## 二、问题分责

| 端 | 状态 | 说明 |
|----|------|------|
| 小程序前端 | ✅ 无责 | 已登录用户请求资讯详情时，正确携带了 `Authorization: Bearer <token>` 请求头 |
| **后端** | ❌ **有责** | `/articles/:article_id` 路由未注册认证中间件，导致 token 未被解析，`req.user` 始终为 `undefined` |

## 三、根因分析

### 3.1 期望链路

```
前端请求 GET /articles/banner-1 (带 token)
    → 后端中间件解析 token → req.user.userId = 123
    → 控制器查询收藏表 (user_id=123, article_id='banner-1')
    → 返回 is_favorited: true
```

### 3.2 实际链路

```
前端请求 GET /articles/banner-1 (带 token)
    → 无中间件解析 token → req.user = undefined
    → 控制器走 else 分支，强制返回 is_favorited: false
    → 收藏按钮未点亮
```

### 3.3 代码证据

**① 后端路由缺少中间件**

文件：`pet-app-backend/routes/article.js`

```javascript
const router = express.Router();

router.get('/', asyncHandler(listArticles));
router.get('/:article_id', asyncHandler(getArticle));  // ← 无 authMiddleware
```

**② 控制器代码逻辑正确，但 userId 永远为 undefined**

文件：`pet-app-backend/controllers/articleController.js`

```javascript
async function getArticle(req, res) {
  // ...
  const userId = req.user?.userId;  // ← undefined，因为无中间件解析

  if (userId) {
    const isFavorited = await ArticleFavorite.count({
      where: { user_id: userId, article_id: articleId },
    });
    result.is_favorited = isFavorited > 0;  // ← 永远不会执行
  } else {
    result.is_favorited = false;  // ← 始终走这个分支
  }
}
```

**③ 现有认证中间件是强制认证，不适用公开接口**

文件：`pet-app-backend/middleware/auth.js`

```javascript
// authMiddleware：强制认证，无 token 返回 401
// 不适用于 /articles/:article_id（公开接口，未登录用户也可访问）
```

**④ 对比：收藏路由正确使用了强制认证中间件**

文件：`pet-app-backend/routes/articleFavorite.js`

```javascript
router.post('/', authMiddleware, asyncHandler(async (req, res) => { ... }));  // 正确
router.get('/:articleId', authMiddleware, asyncHandler(async (req, res) => { ... }));  // 正确
```

## 四、修复方案

### 4.1 新增可选认证中间件

在 `pet-app-backend/middleware/auth.js` 中新增 `optionalAuthMiddleware`：

```javascript
/**
 * 可选认证中间件
 * - 有有效 token：解析并设置 req.user，后续代码可获取 userId
 * - 无 token 或 token 无效：静默忽略，继续处理（不报错、不拦截）
 * 
 * 适用场景：公开接口需要返回个性化数据（如收藏状态、是否已点赞等）
 */
async function optionalAuthMiddleware(req, res, next) {
  const authHeader = req.headers.authorization;
  
  // 无 token，直接放行
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return next();
  }

  const token = authHeader.slice(7);
  
  try {
    const decoded = verifyAccessToken(token);
    const userId = decoded.userId || Number(decoded.sub);
    
    // 查询用户是否存在（可选，视业务需求决定是否校验）
    const account = await UserAccount.findByPk(userId);
    if (account && account.status !== 0) {
      req.user = {
        userId,
        logId: decoded.logId || null,
        openid: decoded.openid || null,
      };
    }
    // 用户不存在或已禁用，静默忽略 token，继续处理
    return next();
  } catch (error) {
    // token 过期或无效，静默忽略，继续处理
    // 不返回 401，因为这是可选认证
    return next();
  }
}
```

### 4.2 导出新增的可选中间件

在 `pet-app-backend/middleware/auth.js` 底部修改导出：

```javascript
module.exports = { authMiddleware, optionalAuthMiddleware };
```

### 4.3 在资讯详情路由中应用

修改 `pet-app-backend/routes/article.js`：

```javascript
const express = require('express');
const asyncHandler = require('../utils/asyncHandler');
const { listArticles, getArticle } = require('../controllers/articleController');
const { optionalAuthMiddleware } = require('../middleware/auth');

const router = express.Router();

router.get('/', asyncHandler(listArticles));
// 资讯详情接口：使用可选认证，已登录用户可返回收藏状态等个性化数据
router.get('/:article_id', optionalAuthMiddleware, asyncHandler(getArticle));

module.exports = router;
```

## 五、修复后的预期行为

| 场景 | 前端请求 | 中间件解析 | `req.user` | `is_favorited` | 收藏按钮状态 |
|------|----------|-----------|------------|----------------|-------------|
| 已登录用户访问**已收藏**资讯 | 带有效 token | 解析成功 | `{ userId: 123 }` | `true` | ♥ 点亮 ✅ |
| 已登录用户访问**未收藏**资讯 | 带有效 token | 解析成功 | `{ userId: 123 }` | `false` | ♡ 未点亮 ✅ |
| 已登录用户访问资讯（token 过期） | 带过期 token | 静默忽略 | `undefined` | `false` | ♡ 未点亮（正常） |
| 未登录用户访问资讯 | 不带 token | 静默放行 | `undefined` | `false` | ♡ 未点亮（正常） |

## 六、验收要点

修复完成后，请验证以下场景：

1. **收藏回显**：已收藏的资讯，进入详情页 → 收藏按钮显示红心 ♥
2. **取消收藏**：在详情页点击红心 → 取消收藏 → 按钮变为空心 ♡
3. **再次收藏**：在详情页点击空心 ♡ → 添加收藏 → 按钮变为红心 ♥
4. **跨页面一致性**：从「我的收藏」列表点击进入详情页 → 收藏按钮应显示红心 ♥
5. **未登录不受影响**：退出登录后访问资讯详情 → 页面正常显示，收藏按钮为空心 ♡
6. **资讯列表不受影响**：资讯列表 `/articles` 路由未修改，行为不变

## 七、其他公开接口复用建议

后续如果其他公开接口也需要返回个性化数据（如"是否已点赞""是否已浏览"等），可复用 `optionalAuthMiddleware`：

```javascript
// 示例：产品详情接口需要回显是否已收藏
router.get('/products/:id', optionalAuthMiddleware, asyncHandler(getProductDetail));
```

控制器中使用 `req.user?.userId` 做可选判断即可。
