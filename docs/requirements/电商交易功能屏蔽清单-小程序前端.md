## 0. 文档背景与屏蔽策略

### 0.1 产品阶段

根据产品说明文档 §1.1：MVP 已完成（电商交易闭环 + 宠物档案 + 商户管理端 + 进销存系统），**C 端电商入口临时暂停展示**（代码保留，可随时恢复），当前对外聚焦「资讯 + 宠物档案 + 客服互动」。

### 0.2 屏蔽策略

采用**整体入口暂停 + 路由守卫兜底**策略，而非对每个子功能单独屏蔽：

- 电商交易闭环代码**完整保留**（商品浏览、购物车、结算、支付、订单、售后、评价），不做删除
- 通过 Dock 配置 `mall`/`order` slot `enabled=false` 隐藏底部导航入口
- 通过 `ecommerceGuard` 路由守卫拦截直接 URL 访问
- 通过页面内条件渲染隐藏「我的」页等处的电商入口卡片
- 通过资讯/消息过滤隐藏电商相关 CTA 与消息

> ⚠️ **与 v1.0 的关键差异**：v1.0 将「订单评价」「申请售后」标注为"已屏蔽"，实际这两个功能**已完整开发**（代码保留），仅入口暂停。v2.0 修正此分类错误，并补充实际屏蔽机制与恢复步骤。

## 3. 屏蔽机制说明（三层防护）

### 3.1 第一层：Dock 配置 - 导航入口隐藏

**机制**：Dock 配置中 `mall`/`order` slot `enabled=false`，`custom-tab-bar` 的 `buildVisibleTabList()` 过滤掉这两个 Tab。

**涉及文件**：

| 文件 | 作用 |
|------|------|
| `pet-app-backend/config/dockDefaultConfig.js` | 后端默认模板：mall/order `enabled=false`（与暂停态一致） |
| `pet-app/src/config/dock.theme.default.json` | 小程序 bundled fallback：mall/order `enabled=false` |
| `pet-app/src/custom-tab-bar/index.js` | `buildVisibleTabList()` 第 122-129 行：mall/order enabled=false 时过滤 |
| `pet-app/src/utils/ecommerceGuard.js` | `isEcommerceNavEnabled()`：mall/order 须同时 `enabled!==false` 才启用 |
| `pet-app-admin-web/src/utils/dockEcommerceNav.ts` | 管理端「电商导航」总控开关：`setEcommerceNavEnabled()` 联动 mall/order |

**业务规则**（BR-2）：`mall` 与 `order` 须**同开同关**，不可单独控制。`home`/`pet`/`mine` 恒启用（BR-1）。

### 3.2 第二层：路由守卫 - 直接访问拦截

**机制**：`ecommercePageGuard` mixin 在电商页面 `onLoad`/`onShow` 时检测 `isEcommerceNavEnabled()`，若关闭则 `redirectIfEcommerceDisabled()` 重定向至首页。

**涉及文件**：

| 文件 | 作用 |
|------|------|
| `pet-app/src/utils/ecommerceGuard.js` | `redirectIfEcommerceDisabled()`：关闭时 `uni.switchTab` 跳转首页 |
| `pet-app/src/mixins/ecommercePageGuard.js` | 页面 mixin：`onLoad`/`onShow` 调用守卫 |

**覆盖页面**：见 §1.1 页面守卫覆盖明细（9 个页面）。

### 3.3 第三层：页面内条件渲染 - 散落入口隐藏

**机制**：非电商页面（如「我的」页）中散落的电商入口（收货地址卡片等），通过 `v-if="ecommerceEnabled"` 条件渲染隐藏。

**涉及文件**：

| 文件 | 作用 |
|------|------|
| `pet-app/src/pages/mine/mine.vue` | 第 169 行 `v-if="ecommerceEnabled"` 控制收货地址卡片；第 539 行 `onShow` 时更新 `ecommerceEnabled` |

### 3.4 第四层：资讯/消息过滤 - 内容入口屏蔽

**机制**：资讯详情页的电商类 CTA（商品/商城/订单跳转）、消息中心的订单类消息，在电商关闭时过滤或隐藏。

**涉及文件**：

| 文件 | 作用 |
|------|------|
| `pet-app/src/utils/ecommerceGuard.js` | `isEcommerceArticleAction()`：识别电商类资讯 CTA；`filterMessagesForEcommerce()`：过滤订单类消息；`filterMessageTabsForEcommerce()`：隐藏订单消息 Tab |
| `pet-app/src/services/news.js` | 资讯详情：电商关闭时屏蔽电商类 CTA |
| `pet-app/src/services/message.js` | 消息列表：电商关闭时过滤订单类消息 |
| `pet-app/src/subpk-news/detail.vue` | 资讯详情页：电商 CTA 守卫 |
| `pet-app/src/subpk-message/index.vue` | 消息中心：订单 Tab 守卫 |

### 3.5 环境变量强制覆盖（可选）

| 环境变量 | 作用 | 配置位置 |
|----------|------|----------|
| `VITE_ECOMMERCE_ENABLED=true` | 强制开启电商（本地联调交易闭环） | `pet-app/.env.development` |
| `VITE_ECOMMERCE_ENABLED=false` | 强制关闭电商（覆盖 Dock 配置） | `pet-app/.env.production` |

> 当前各环境未设置此变量，默认跟随 Dock `mall`+`order` enabled 状态。

## 4. 撤回 / 恢复步骤

### 4.1 标准恢复（推荐）

通过商户管理端操作，无需改代码：

1. 登录商户管理端（pet-app-admin-web）
2. 进入「小程序配置 → Dock」
3. 打开「电商导航（商城 + 订单）」总控开关
4. 点击「发布」，确认发布提示（含电商导航恢复说明）
5. C 端将在下次启动或缓存失效后拉取新配置，商城/订单 Tab 恢复显示

### 4.2 本地联调恢复

开发环境可通过环境变量强制开启：

1. 编辑 `pet-app/.env.development`
2. 添加 `VITE_ECOMMERCE_ENABLED=true`
3. 重新编译运行

### 4.3 后端默认模板恢复（可选）

若需将后端默认模板恢复为"电商开启"状态（影响商户首次配置/重置默认）：

1. 编辑 `pet-app-backend/config/dockDefaultConfig.js`
2. 将 `mall`/`order` slot 的 `enabled` 改为 `true`
3. 编辑 `pet-app/src/config/dock.theme.default.json`
4. 将 `mall`/`order` slot 的 `enabled` 改为 `true`
5. 同步更新本文档 §3.1

> ⚠️ 恢复电商导航前，请确认微信支付三件套（`WECHAT_MCH_ID`/`WECHAT_API_KEY`/`WECHAT_NOTIFY_URL`）已配置，否则支付环节将失败。

## 5. 功能限制清单（电商恢复后适用）

以下限制在电商入口暂停期间无需单独处理（用户无法进入）；电商恢复后自动生效。

### 5.1 商品浏览功能

| 功能名称 | 限制内容 | 处理方式 |
|----------|----------|----------|
| 商品搜索 | 仅支持关键词搜索 | 不显示高级搜索选项 |
| 商品筛选 | 仅支持分类筛选 | 不显示价格区间、品牌等筛选 |
| 商品排序 | 仅支持默认排序 | 不显示价格、销量等排序选项 |

### 5.2 购物车功能

| 功能名称 | 限制内容 | 处理方式 |
|----------|----------|----------|
| 购物车数量 | 最多 50 件商品 | 超过 50 件时提示用户 |
| 购物车合并 | 不支持跨店铺合并 | 每个店铺单独结算 |

### 5.3 订单功能

| 功能名称 | 限制内容 | 处理方式 |
|----------|----------|----------|
| 订单数量 | 最多显示 100 条 | 超过 100 条时提示用户 |
| 订单详情 | 仅显示基本信息 | 不显示物流轨迹、评价等 |

## 6. 变更流程

1. **提出变更**：由产品或开发团队提出功能屏蔽/限制变更需求
2. **评估影响**：评估变更对用户体验和业务流程的影响
3. **更新清单**：修改本文档，记录变更内容
4. **代码实现**：在小程序前端代码中实现屏蔽/限制逻辑
5. **测试验证**：进行功能测试，确保屏蔽/限制生效
6. **记录变更**：在本文档末尾添加变更记录

---

## 7. 注意事项

1. **用户体验**：屏蔽功能时应考虑用户体验，避免出现空白页面或错误提示
2. **兼容性**：确保屏蔽逻辑在不同版本的微信客户端中都能正常工作
3. **可恢复性**：屏蔽的功能应保留恢复的可能性，便于后续业务扩展
4. **文档同步**：变更后及时更新本文档，确保团队成员了解最新状态
5. **三端对齐**：Dock 配置变更后，确认后端 `dockDefaultConfig.js`、小程序 `dock.theme.default.json`、管理端 `dockEcommerceNav.ts` 三端一致
6. **BR-2 同开同关**：`mall` 与 `order` 必须同时启用或同时暂停，管理端已通过「电商导航」总控开关强制联动
