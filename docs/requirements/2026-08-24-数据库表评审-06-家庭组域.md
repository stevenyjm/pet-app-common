## 表 1：family_group（家庭组主表）

### 第一部分：当前数据表（旧表）

#### 字段介绍

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| family_group_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(64) | NOT NULL | 家庭组名称 |
| creator_user_id | BIGINT | NOT NULL | 创建人 user_id |
| status | TINYINT | NOT NULL, DEFAULT 1 | 1-正常 0-已解散 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 最后更新时间 |
| dissolved_at | DATETIME | NULL | 解散时间 |
| is_deleted | TINYINT | NOT NULL, DEFAULT 0 | 逻辑删除：0-未删除，1-已删除 |

#### 建表语句

```sql
CREATE TABLE IF NOT EXISTS `family_group` (
  `family_group_id` BIGINT NOT NULL AUTO_INCREMENT,
  `name` VARCHAR(64) NOT NULL,
  `creator_user_id` BIGINT NOT NULL,
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '1-正常 0-已解散',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `dissolved_at` DATETIME DEFAULT NULL,
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`family_group_id`),
  KEY `idx_creator_status` (`creator_user_id`, `status`),
  CONSTRAINT `fk_family_group_creator` FOREIGN KEY (`creator_user_id`) REFERENCES `user_account` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 备注说明

- `family_group_id` 为逻辑主键（`BIGINT AUTO_INCREMENT`），违反 D1 业务主键规则
- `name` 字段名易混淆（联表查询时与 `pet_name`、`product_name` 等无法区分），违反 D2 字段表源前缀规则，应改为 `group_name`
- `status` 字段名易混淆（联表时与 `member_status`、`group_pet_status` 等无法区分），违反 D2，应改为 `group_status`
- `creator_user_id` 为外键引用，需改为 `creator_user_code VARCHAR(16)`（引用 user_account.user_code）
- `created_at` / `updated_at` 命名与维护方式违反 D3（应为 `create_time` / `last_modified_time`，后端推送）
- `dissolved_at` 业务时间字段使用 `_at` 后缀，与新规范 `_time` 后缀不一致，是否调整为 `dissolve_time` 待评审
- 1 处 `CONSTRAINT` 外键约束，违反 D5（应移除，引用完整性由后端校验）
- 无表级 `COMMENT`
- `name` / `creator_user_id` / `dissolved_at` 等字段缺失 `COMMENT`
- **TEXT/JSON 说明**：当前 schema 中 `family_group` 未含 `tags(TEXT)` / `image_urls(TEXT)` 字段（合规）；如未来需扩展标签，应使用 `family_group_tag` 子表（已存在），不得在主表加 `TEXT` 存储标签数组；如需头像/图片 URL，应使用 `VARCHAR(n)` 单字段或独立图片子表
