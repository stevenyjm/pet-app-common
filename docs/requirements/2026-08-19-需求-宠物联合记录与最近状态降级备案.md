## 1. 文档目的

本文档针对当前已上线的「宠物档案最近状态字段」与「宠物联合日记录」两项能力进行**降级**与**备案**，并新增两项替代能力。依据商户确认结论（§2.3 Q1-Q8），本项目处于开发阶段、数据库内均为测试数据，故采取**物理删除**策略（非软降级）：

1. **降级 A — 最近状态字段物理删除**：物理删除宠物档案表 `pet` 中 9 个"最近状态"缓存字段，移除全部读写链路与三端展示/编辑 UI。
2. **降级 B — 联合记录功能物理下线**：物理下线联合记录 4 条 API 路由、控制器、服务函数；物理删除联合记录关联表；移除前端联合记录 UI。
3. **降级 C — Tab 收起/展开完全移除**：移除宠物 Tab 日记录区的收起态、FAB、滑动切换，固定为展开样式。
4. **🆕 新增 D — 快速记录弹窗**：用户完成一笔餐食/运动日记录保存后，若该用户拥有多个宠物，弹窗询问"是否为其他宠物快速添加一致的餐食/运动记录？"，提供其他宠物的勾选栏，支持批量创建**独立**记录或直接关闭结束。
5. **🆕 新增 E — 自动拉取最近一次记录填充**：用户新增餐食/运动日记录时（页面与表单刚加载完成时），自动从该宠物最近一次同类型记录（跨日期）拉取内容填充表单，并在上方展示提醒条"已自动为您拉取该宠物最近一次记录"，提醒停留 5 秒后收回。仅新增模式触发，编辑模式不触发。

> ⚠️ **关键架构变更**：因物理删除 `pet_meal_session_pet` 关联表，而该表原是 `pet_meal_session`（主表不含 `pet_id`）与宠物的唯一关联载体，故须**同步为 `pet_meal_session` 新增 `pet_id` 字段**，将宠物关联从"关联表模式"收敛为"主表直挂模式"，与 `pet_exercise_session`（已含 `pet_id`）保持一致。

本文档**仅**进行方案拟定、各阶段开发任务规划与任务清单划分，**不**包含代码变更。代码实现将在本方案评审通过后另行启动。

## 2. 需求背景与降级动因

### 2.1 现状回顾

#### 2.1.1 宠物档案"最近状态"字段

宠物档案表 `pet` 当前维护一组"最近状态"缓存字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `latest_mood` | VARCHAR(32) | 最近心情 |
| `latest_mood_update_time` | DATETIME | 最近心情更新时间 |
| `latest_weight_kg` | DECIMAL(6,2) | 最近体重（kg） |
| `latest_weight_update_time` | DATETIME | 最近体重更新时间 |
| `latest_stool_health` | VARCHAR(32) | 最近排便健康 |
| `latest_stool_update_time` | DATETIME | 最近排便健康更新时间 |
| `latest_physical_state` | VARCHAR(6) | 最近身体状态描述（限 6 字） |
| `latest_physical_state_update_time` | DATETIME | 最近身体状态更新时间 |
| `latest_record_date` | DATE | 最近一次记录日期 |

**写入路径**：`services/petService.js createPet`（L76-107）、`updatePet`（L199-236）、`syncPetLatestSnapshot`（L734-752，由 `upsertDailyRecord` 的 `sync_to_latest` 触发）、`services/adminPetService.js`（L440-443）。

**展示路径**：C 端 `src/subpk-pet/info.vue`（L199-280 档案页展示+编辑）、`src/pages/pet/pet.vue`（L450-503 每日状态 Sheet 预填充/同步开关）、`src/services/pet.js normalizePet`（L67-74 映射）/ `buildUpdatePayload`（L655-678 发送）；管理端 `src/views/pet/Detail.vue`（L144-297）、`src/views/pet/List.vue`（L224-232）、`services/adminPetService.js`（L273-283 CSV 导出）。

#### 2.1.2 宠物联合日记录功能

依据 [多宠物联合日记录需求分析.md](./多宠物联合日记录需求分析.md)，当前已上线"联合记录"能力：用户在宠物 Tab 勾选"进行联合记录"后，可在新增/编辑餐食/运动记录时选择多个参与宠物，**创建一条 session 同时关联多个宠物**。

**核心数据模型**：

| 表 | 说明 | 是否含 `pet_id` |
|----|------|----------------|
| `pet_meal_session` | 餐食会话主表 | ❌ 不含（会话本身与宠物解耦，依赖关联表） |
| `pet_meal_session_pet` | 餐食会话-宠物关联表 | ✅ 含 `session_id` + `pet_id` |
| `pet_exercise_session` | 运动会话主表 | ✅ 含 `pet_id`（主宠物） |
| `pet_exercise_session_pet` | 运动会话-宠物关联表 | ✅ 含 `session_id` + `pet_id`（附加参与宠物） |

> ⚠️ **关键约束**：`pet_meal_session` 主表**不含 `pet_id`**，餐食会话与宠物的关联**完全依赖** `pet_meal_session_pet` 关联表。即**单宠物餐食记录也会写入 `pet_meal_session_pet` 一行**（见 `services/petService.js createMealSessionWithItems` L557-563）。因此物理删除 `pet_meal_session_pet` 前，**必须先为 `pet_meal_session` 新增 `pet_id` 字段**并改造查询/写入逻辑。

**联合记录入口与链路**：C 端 `pet.vue`（L415-437 联合开关、L1431-1473 `onQuickAddRecord`/`toggleJointMode`/`togglePetSelection`）、`meal-record.vue`（L22-47 关联宠物选择区、L468-538 onLoad 解析多宠物、L905-916 联合提交）、`exercise-record.vue`（L541-569 联合提交）、`src/api/pet.js createJointDailyRecord`；后端 `routes/pet.js`（L49-64 4 条路由）、`controllers/petController.js`（L98-141）、`services/petService.js`（L1004-1129）、`models/index.js`（L249-265 关联配置）。

依据 [宠物标签页收起展开方案.md](./宠物标签页收起展开方案.md)：`pet.vue`（L410-413 收起态 FAB、L85-94 迷你条、L1321-1352 `expandPetStrip`/`collapseDrawer`/`expandDrawer`/`onTouchEnd`、state `drawerExpanded`/`petStripCollapsed`）。

### 2.2 降级动因

#### 2.2.1 最近状态字段降级动因

| # | 动因 | 说明 |
|----|------|------|
| D1 | 双份状态语义冗余 | `latest_*` 与 `daily_*`（每日状态）语义重叠，"最近状态"实为"最新一次每日状态的缓存副本"，维护两套字段易产生不一致 |
| D2 | 同步链路复杂 | `syncPetLatestSnapshot` 跨 `latest_record_date` 比较写入、C 端 `sync_to_latest` 开关、管理端同步逻辑三处入口，逻辑分散且难维护 |
| D3 | 用户认知负担 | "最近状态"与"每日状态"在 UI 上区分模糊，用户难以理解"同步至最近状态"开关的语义 |
| D4 | 真实需求是"快速填充"而非"档案缓存" | 用户编辑今日状态时希望复用最近一次数据，本质是"预填充"需求，可通过本期新增的"自动拉取最近一次记录填充"能力（🆕 E）更直接地满足 |

#### 2.2.2 联合记录功能降级动因

| # | 动因 | 说明 |
|----|------|------|
| J1 | 共享 session 模型与独立记录语义冲突 | 联合记录将多宠物挂到同一条 session，但实际场景中各宠物的食量/运动评估可能不同，共享 session 不便后续按宠细分 |
| J2 | 参与宠物选择交互复杂 | 用户需先勾选"进行联合记录"再在记录页选择参与宠物，操作链路长，使用频度低 |
| J3 | 快速记录更贴合真实诉求 | 用户真实诉求是"给多只宠物快速添加相同记录"，而非"共享一条 session"；本期新增的快速记录弹窗（🆕 D）以"独立记录 + 批量提交"形态更直接满足 |
| J4 | Tab 收起/展开增加操作成本 | 日记录区收起/展开的滑动与 FAB 按钮增加了操作步骤，固定展开可降低交互成本 |

### 2.3 商户确认结论（已确认 ✅）

| # | 确认项 | 确认结论 | 方案落点 |
|---|--------|----------|----------|
| Q1 | `pet` 表 `latest_*` 字段是否物理删除 | ✅ **物理删除** 9 个字段 | §5.1 / §6.1 |

## 3. 方案总览

### 3.1 总览

依据 Q1-Q4 确认结论（物理删除 + 测试数据可丢弃），原 Level-1（软降级）/Level-2（物理清理）两级方案**合并为本期单级方案**：

| 维度 | 本期方案 |
|------|----------|
| 最近状态字段 | 💥 物理删除 `pet.latest_*` 9 字段；移除全部读写与展示 |
| 联合记录 | 💥 物理下线 4 条路由 + 控制器 + 服务函数；💥 物理删除 2 张关联表 |
| 餐食会话主表 | 💥 `pet_meal_session` 新增 `pet_id` 字段（替代关联表） |
| Tab 收起/展开 | 🚫 完全移除，固定展开 |
| 快速记录 | 🆕 新增快速记录弹窗 + 批量独立记录 API |
| 自动拉取填充 | 🆕 新增最近一次记录 API + 表单自动填充 + 5 秒提醒条 |
| 数据库 DDL | 💥 迁移脚本 v51：删字段 + 删表 + 加字段 |
| 兼容性 | 无需兼容期（测试数据可丢弃，无线上旧版客户端依赖） |

### 3.2 边界

```
本期范围 ─────────────► 物理删除最近状态字段 + 物理下线联合记录 + Tab固定展开
                        + 快速记录弹窗 + 自动拉取填充
                        + pet_meal_session 加 pet_id（架构收敛）
```

### 5.9 新增能力详细设计

#### 5.9.1 🆕 快速记录弹窗（QuickRecordSheet）

**触发时机**：用户在 `meal-record.vue` / `exercise-record.vue` 点击保存、单宠物记录提交成功后。

**触发条件**：用户拥有宠物数 > 1（通过 `fetchPets()` 返回 `list.length` 判断）。

**UI 设计**：
- 底部弹窗（TabPageSheet 风格）；
- 标题："是否为其他宠物快速添加一致的 餐食/运动 记录？"（根据 sessionType 动态显示）；
- 中部：列出除当前宠物外的其他宠物，每行含 头像 + 名称 + checkbox（默认不勾选）；
- 底部：左侧"关闭"按钮（直接结束）、右侧"提交"按钮（为勾选宠物创建独立记录）；
- 提交后 toast 提示"已为 N 只宠物添加记录"，关闭弹窗并 `navigateBack`。

**数据流**：
1. `onSubmit` 成功 → `fetchPets()` 获取宠物列表；
2. `list.length > 1` → 实例化 `QuickRecordSheet`，传入 `currentPetId` / `sessionType` / `recordDate` / `sessionBody`；
3. 用户勾选 + 提交 → 调用 `quickBatchRecords(selectedPetIds, recordDate, sessionType, sessionBody)`；
4. 后端 `quickBatchCreateRecords` 循环 `selectedPetIds`，对每个宠物调用单宠物保存逻辑，创建**独立** session（餐食：`pet_meal_session` 直接写 `pet_id`；运动：`pet_exercise_session` 写 `pet_id`）；
5. 返回 `{ success_count, failed: [{ pet_id, reason }] }`；
6. 前端按结果 toast，关闭弹窗。

**API 请求体**（`POST /api/v1/pets/daily-records/quick-batch`）：

```json
{
  "pet_ids": [101, 102],
  "record_date": "2026-08-19",
  "session_type": "meal",
  "meal_session": {
    "slot": "早上",
    "time": "08:00",
    "status": "良好",
    "items": [{ "name": "鸡胸肉", "amount": "150g" }],
    "remark": ""
  }
}
```

**API 响应**（`code: 0`）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success_count": 2,
    "failed": []
  }
}
```

**部分失败**：某宠物已达当日餐食上限等，计入 `failed`，其余成功。

#### 5.9.2 🆕 自动拉取最近一次记录填充（AutoFillBanner）

**触发时机**：用户进入 `meal-record.vue` / `exercise-record.vue` **新增**模式（`mode !== 'edit'`），页面与表单刚加载完成时。

**不触发**：编辑模式（回显被编辑记录）；该宠物无历史记录（不填充、不显示提醒条）。

**数据流**：
1. `onLoad` 解析 `petId` 与 `mode`；
2. `bootstrap` 完成后，若 `mode !== 'edit'`，调用 `getLatestRecord(petId, 'meal' | 'exercise')`；
3. 返回非空 → 用 `mealToEditForm` / 同理映射填充 `this.form`；
4. 设置 `this.autoFillBannerVisible = true`，挂载 `AutoFillBanner`；
5. `AutoFillBanner` mounted 启动 5 秒计时器，到时设 `autoFillBannerVisible = false` 触发收回动画。

**UI 设计**：
- 表单上方插入提醒条；
- 文案："已自动为您拉取该宠物最近一次记录"；
- 背景：浅绿色（`#e8f5e9`）+ 左侧 ℹ️ 图标；
- 收回动画：高度过渡到 0 + 透明度 1→0，时长 300ms；
- 5 秒后自动收回；用户可点击 ✕ 提前关闭。

**API 请求**（`GET /api/v1/pets/:pet_id/daily-records/latest?type=meal|exercise`）：

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | BIGINT | 是 | path | 宠物 ID |
| type | string | 是 | query | `meal` 或 `exercise` |
| Authorization | string | 是 | header | Bearer token |

**成功响应**（`code: 0`，以餐食为例）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "session_id": 12345,
    "record_date": "2026-08-18",
    "period": "早上",
    "meal_time": "08:00",
    "post_meal_status": "良好",
    "nutrition_reference": null,
    "remark": "",
    "items": [
      { "food_name": "鸡胸肉", "amount": "150g", "nutrition_ref": "" }
    ]
  }
}
```

**无历史记录响应**（`code: 0`，`data: null`）：

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

**可能的错误码**

| code | 说明 |
|------|------|
| 40001 | 参数错误（`type` 非 `meal`/`exercise`） |
| 40300 | 无权访问该宠物 |
| 40400 | 宠物不存在 |
| 50001 | 服务器内部错误 |

**后端查询逻辑**（变更后，直接按主表 `pet_id` 查询）：
- 餐食：`PetMealSession.findAll({ where: { pet_id, is_deleted: 0 }, include: [{ model: PetMealItem }], order: [['record_date', 'DESC'], ['sort_order', 'DESC']], limit: 1 })`；
- 运动：`PetExerciseSession.findAll({ where: { pet_id, is_deleted: 0 }, order: [['record_date', 'DESC'], ['start_time', 'DESC']], limit: 1 })`。
