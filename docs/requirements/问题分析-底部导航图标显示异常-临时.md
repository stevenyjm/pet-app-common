# 问题分析-底部导航图标显示异常

## 问题描述

商户在 Web 管理端完成了底部导航栏图标的配置更新后，在微信小程序体验版中发现以下现象：
- **首页标签页**：底部导航区的图标仍然显示为原始静态图标（`src/static/tabbar/` 目录下的 PNG 文件）
- **其他标签页**（商城、宠物、订单、我的）：底部导航区的图标正确显示为 Web 端配置的新图标

## 状态

**已关闭**（2026-07-16）

## 根本原因确认

经过代码审查和分析，确认问题根本原因为：

### 响应式更新失效

**核心问题**：首页的 BottomDock 组件在远程配置加载完成前就已渲染，使用了 bundled default 配置显示静态图标。当远程配置异步加载完成后，原有的响应式更新机制不够可靠，导致图标未能及时刷新。

**原实现分析**：

```javascript
// 原实现：依赖 configRevision 作为响应式触发点
enabledSlots() {
  void this.configRevision  // 通过读取触发响应式更新
  return (this.dockConfig.slots ?? []).filter((slot) => slot.enabled !== false)
},
```

**问题点**：
1. 在微信小程序环境中，通过 `void this.configRevision` 触发 computed 属性更新的方式不可靠
2. 当 `subscribeDockConfig` 回调更新 `dockConfig` 对象时，Vue 的响应式系统可能未能正确检测到对象内部属性的变化
3. 其他页面正常的原因：用户切换到其他 Tab 页时，远程配置已经加载完成，新页面的 BottomDock 挂载时获取的是已更新的配置

## 解决方案

### 修改 BottomDock 组件，增强响应式更新机制

**文件**：`src/components/bottom-dock/BottomDock.vue`

**核心变更**：

1. 添加 `deep: true` watcher 监听 `dockConfig` 对象内部变化
2. 配置更新时自动重置 `bgFallback` 和 `iconFallbacks`，确保远程图标重新加载
3. 移除不再使用的 `configRevision` 状态变量

```javascript
watch: {
  dockConfig: {
    deep: true,
    handler() {
      this.bgFallback = false
      this.iconFallbacks = {}
    },
  },
},
mounted() {
  this.unsubscribeDockConfig = subscribeDockConfig((config) => {
    this.dockConfig = config
  })
},
```

**原理说明**：
- `deep: true` 选项使 Vue 能够检测到 `dockConfig` 对象内部属性的变化（如 `slots[].iconDefault`、`slots[].iconActive` 等）
- 当配置更新时，computed 属性（如 `enabledSlots`、`layoutSlots`）会自动重新计算
- 重置 `bgFallback` 和 `iconFallbacks` 确保远程图标能够重新加载，而不是继续使用之前的回退图标

## 验证结果

1. **单元测试**：`npm run test:dock-config` 全部 28 项测试通过
2. **文档更新**：`项目开发说明-小程序前端.md` 已更新至 v0.9.180，新增响应式更新机制说明
3. **运行验证**：待商户在 Web 端更新图标后，在小程序体验版中验证首页图标是否自动更新

## 风险评估

| 风险点 | 影响 | 缓解措施 |
|--------|------|----------|
| 响应式更新仍不触发 | 图标不更新 | deep watcher 已确保对象内部变化能被检测 |
| 远程配置加载失败 | 显示默认图标 | 保持 bundled default 作为兜底 |
| 域名白名单未配置 | 图标加载失败 | 在 Web 管理端提示商户配置域名 |
| 缓存过期 | 首次加载延迟 | 优化网络请求，增加加载状态提示 |
