## 一、客服消息操作人显示

### 1.1 涉及接口

| 方法 | 路径 | 说明 | 适用端 |
|------|------|------|--------|
| GET | `/admin/service/conversations/:conversationId/messages` | 管理端消息分页 | 管理端 |
| GET | `/service/conversations/:conversationId/messages` | C 端消息分页 | 小程序 |

> 两端共用后端 `services/serviceConversationService.js` 的 `queryConversationMessages` 方法，响应结构一致。

### 1.2 数据库变更

`service_message` 表新增字段：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| sender_admin_id | BIGINT | NULL, DEFAULT NULL | 管理员发送者 admin_id（仅 `sender_role='admin'` 时填入；其余角色为 NULL） |

新增索引：`idx_sender_admin_id (sender_admin_id)`

> 依据 `multi-project.md` §8.5 例外场景，`service_message` 为会话消息表，**豁免** `is_deleted` 字段；本表保留 `id` + `created_at` + `updated_at` 三类必备字段。

### 1.3 响应字段新增

消息对象（`ServiceMessage`）在原有字段基础上新增 `sender_name`：

| 字段 | 类型 | 说明 |
|------|------|------|
| message_id | number | 消息主键 |
| conversation_id | number | 所属会话 ID |
| sender_role | string | 发送者角色：`'user'` / `'admin'` / `'system'` |
| **sender_name** | **string \| null** | **发送者名称。仅当 `sender_role='admin'` 且关联到有效管理员时返回管理员 `username`；其余角色返回 `null`** |
| content_type | string | 消息内容类型：`'text'` / `'image'` |
| content | string | 消息内容 |
| related_order_id | number \| null | 关联订单 ID |
| created_at | string | 创建时间（ISO 8601） |

### 1.4 响应示例

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "message_id": 1,
        "conversation_id": 10,
        "sender_role": "user",
        "sender_name": null,
        "content_type": "text",
        "content": "请问我的订单什么时候发货？",
        "related_order_id": 1001,
        "created_at": "2026-08-19T10:00:00.000Z"
      },
      {
        "message_id": 2,
        "conversation_id": 10,
        "sender_role": "admin",
        "sender_name": "admin_alice",
        "content_type": "text",
        "content": "您好，您的订单将在今天下午发出。",
        "related_order_id": 1001,
        "created_at": "2026-08-19T10:01:00.000Z"
      }
    ],
    "pagination": {
      "page": 1,
      "page_size": 50,
      "total": null,
      "has_more": false
    }
  }

```

### 1.5 字段消费说明

| 端 | 后端字段（snake_case） | 前端字段（camelCase） | 转换链路 |
|----|----------------------|---------------------|----------|
| 管理端 | `sender_name` | `senderName` | `adminResponseKeysMiddleware` → `http.ts` 拦截器 `toCamelCase()` |
| 小程序 | `sender_name` | `senderName` | `request.js` 拦截器 `deepToCamelCase()` |

> 小程序本期不展示 `sender_name`（仅管理端展示），但字段已返回，便于后续扩展。

### 1.6 兼容性

- **向前兼容**：`sender_name` 为新增字段，旧版本客户端忽略即可。
- **null 值处理**：`sender_role` 非 `admin` 时 `sender_name` 为 `null`；`sender_role='admin'` 但管理员记录已删除时同样为 `null`，前端需做判空处理。

## 二、反馈处理人显示

### 2.1 涉及接口

| 方法 | 路径 | 说明 | 适用端 |
|------|------|------|--------|
| GET | `/feedback` | 我的反馈列表 | 小程序 |
| GET | `/feedback/:feedbackId` | 反馈详情 | 小程序 |

### 2.2 数据库变更

本次无新增数据库字段。`user_feedback` 表已包含 `processed_by` (admin_id) 字段；`models/index.js` 已建立 `UserFeedback.belongsTo(AdminUser, { foreignKey: 'processed_by', as: 'processor' })` 关联。

本次仅在查询时补充 `include: [{ model: AdminUser, as: 'processor', required: false, attributes: ['username'] }]`。

### 2.3 响应字段新增

反馈对象（`UserFeedback`）在原有字段基础上新增 `processed_by_username`：

| 字段 | 类型 | 说明 |
|------|------|------|
| feedback_id | number | 反馈主键 |
| feedback_no | string | 反馈编号 |
| type | string | 反馈类型 |
| content | string | 反馈内容 |
| status | string | 状态：`'pending'` / `'processing'` / `'resolved'` / `'closed'` |
| image_urls | string[] | 截图 URL 列表 |
| order_id | number \| null | 关联订单 ID |
| created_at | string | 创建时间（ISO 8601） |
| processed_at | string \| null | 处理时间（ISO 8601） |
| **processed_by_username** | **string \| null** | **处理人管理员 username。仅当 `status='resolved'` 且关联到有效管理员时返回非 null；其余状态返回 `null`** |
| reply | string \| null | 客服回复（仅 `resolved` 时非 null） |

### 2.5 字段消费说明

| 端 | 后端字段（snake_case） | 前端字段（camelCase） | 转换链路 |
|----|----------------------|---------------------|----------|
| 小程序 | `processed_by_username` | `processedByUsername` | `request.js` 拦截器 `deepToCamelCase()` |

> 小程序 `src/services/feedback.js` 的 `normalizeFeedbackItem` 需新增三层兼容映射：`raw.processed_by_username ?? raw.processedByUsername ?? null`（snake_case 原始 → camelCase 拦截器转换 → 旧缓存兜底）。

### 2.6 兼容性

- **向前兼容**：`processed_by_username` 为新增字段，旧版本客户端忽略即可。
- **null 值处理**：未处理反馈（`status != 'resolved'`）返回 `null`；已处理但管理员记录已删除同样返回 `null`。
