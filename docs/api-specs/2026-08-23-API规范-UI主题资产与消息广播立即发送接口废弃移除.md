# API 规范：UI 主题资产与消息广播立即发送接口废弃移除

> **创建日期**：2026-08-23
> **涉及项目**：pet-app-backend（实现）、pet-app-admin-web（消费）、pet-app（消费）
> **关联需求**：[2026-08-23-需求-商户管理端导航重构与权限矩阵调整.md](../requirements/2026-08-23-需求-商户管理端导航重构与权限矩阵调整.md) §五 §六
> **优先级**：中
> **影响范围**：后端移除 UI 主题资产管理接口（admin + C 端公开接口）、移除消息广播立即发送对外接口；管理端移除相关页面与 API 调用；小程序端主题资产改为静态内置

---

## 一、背景

基于 [2026-08-23-需求-商户管理端导航重构与权限矩阵调整.md](../requirements/2026-08-23-需求-商户管理端导航重构与权限矩阵调整.md)，本次需求涉及两类接口的废弃移除：

1. **UI 主题资产管理接口**：全面移除管理端 UI 主题资产配置功能，小程序端相关资源改为静态方案处理。后端 admin 路由与 C 端公开接口一并移除。
2. **消息广播立即发送接口**：移除「立即发送广播」功能（风险高、无审核时机），消息广播统一走「预设 + 定时发布」流程。仅移除对外 POST 路由与控制器，**保留** service 层 `createBroadcast` 函数（供 `adminBroadcastScheduleService.executeBroadcastSchedule` 定时调度与「提前执行」内部复用）。

本规范定义被废弃移除的接口清单、替代方案及迁移指引。

### 2.6 小程序端迁移指引

小程序端从「启动时动态拉取远程主题资产」改为「静态内置主题资产配置」：

| 文件 | 变更内容 |
|------|----------|
| `src/App.vue` | 移除 `bootstrapThemeAssets()` 和 `refreshThemeAssetsFromRemote()` 调用 |
| `src/stores/themeAssets.js` | 移除远程拉取逻辑，改为从本地静态文件加载默认配置 |
| `src/services/themeAssets.js` | 移除 `fetchPublicThemeAssets()` 函数；`normalizeThemeAssetsConfig()` 保留用于解析静态配置 |
| `src/constants/miniAppConfig.js` | 保留 `THEME_ASSETS_PATHS` 路径常量；新增 `DEFAULT_THEME_ASSETS_CONFIG` 静态默认配置 |

> **静态化步骤**：
> 1. 从数据库 `mini_app_config` 表导出当前已发布的 `themeAssets.config` JSON
> 2. 将该 JSON 写入小程序端 `src/constants/defaultThemeAssets.js` 作为默认配置
> 3. 小程序端 `stores/themeAssets.js` 改为从本地静态文件加载，移除远程拉取逻辑
> 4. 后端 `/mini-app-config/public` 接口一并移除

## 三、消息广播立即发送接口废弃移除

### 3.1 废弃接口清单（admin 端）

| 接口 | 方法 | 路径 | 废弃类型 | 替代方案 |
|------|------|------|----------|----------|
| 立即发送广播 | POST | `/admin/messages/broadcast` | **移除** | 预设模板 + 定时调度（支持「提前执行」） |
| 获取广播预览 | POST | `/admin/messages/broadcast/preview` | **移除** | 无（预览功能随立即发送移除） |
| 获取广播任务列表 | GET | `/admin/messages/jobs` | **移除** | 无（历史查看随页面移除） |
| 获取广播任务详情 | GET | `/admin/messages/jobs/:job_id` | **移除** | 无 |
| 获取广播接收人列表 | GET | `/admin/messages/jobs/:job_id/recipients` | **移除** | 无 |

### 3.2 关键依赖关系保留说明

> **重要**：`adminBroadcastService.createBroadcast` 函数**不能移除**。

经核查 [adminBroadcastScheduleService.js#L258](../../../pet-app-backend/services/adminBroadcastScheduleService.js) 与 [#L348](../../../pet-app-backend/services/adminBroadcastScheduleService.js)，定时调度执行与「提前执行」均**复用** `createBroadcast` 函数完成实际广播下发，并会读取预设模板的 `target_type` 与 `target_value` 按指定用户下发。

因此本次移除仅针对**对外暴露的 POST `/admin/messages/broadcast` 路由与控制器动作**，service 层函数保留。

### 3.3 后端文件移除清单

| 文件 | 移除内容 |
|------|----------|
| `routes/admin/messageRoutes.js` | 整个文件移除 |
| `controllers/adminMessagesController.js` | 整个文件移除（含 `getBroadcastPreview`、`postBroadcast`、`getBroadcastJobs`、`getBroadcastJob`、`getBroadcastRecipients`） |
| `services/adminBroadcastService.js` | **保留 `createBroadcast` 函数**（供 `adminBroadcastScheduleService.executeBroadcastSchedule` 复用）；仅移除仅供控制器调用的辅助函数（如 `getBroadcastPreview`、`getBroadcastRecipients`，如存在） |
| `routes/admin/index.js` | 移除 `messageRoutes` 注册行 |

### 3.4 权限码移除

| 权限码 | 处理方式 |
|--------|----------|
| `message:view` | 从 `ADMIN_PERMISSIONS` 常量移除 + `admin_permission` 字典表删除 |
| `message:send` | 从 `ADMIN_PERMISSIONS` 常量移除 + `admin_permission` 字典表删除 |

### 3.5 数据库变更

| 表 | 变更 |
|----|------|
| `admin_message_job` | **保留表结构与历史数据**（审计追溯，用户决策 2026-08-23 确认）；仅停止新增立即发送类型的记录（定时调度执行仍会产生记录） |
| `admin_permission` | 删除 `permission_code IN ('message:view', 'message:send')` 的 2 条记录 |
| `admin_role_permission` | 删除上述 2 个权限码对应的所有角色分配记录 |

### 3.6 替代方案：预设 + 定时调度流程

消息广播统一走以下流程：

```
Step 1: 信息注册台 → 预设广播消息模板（CRUD）
        路由：/registration/preset-broadcast
        权限：preset_broadcast:manage
        ↓
Step 2: 任务调度平台 → 消息广播定时任务管理
        路由：/task-platform/broadcast-schedules
        权限：broadcast_schedule:view / broadcast_schedule:manage
        ↓
Step 3: 定时触发或手动「提前执行」
        后端：adminBroadcastScheduleService.executeBroadcastSchedule()
        （内部复用 adminBroadcastService.createBroadcast 完成实际下发）
        ↓
Step 4: 消息写入用户消息中心（admin_message_job 表记录执行结果）
```

> **「提前执行」作为紧急发送替代**：任务调度平台支持「提前执行」功能，作为紧急发送的替代方案。流程为：先在信息注册台创建预设模板 → 在任务调度平台创建调度任务并「提前执行」，保留审核时机（预设模板可预先审核）。

> **「指定用户列表」能力已具备（无需新增）**：经核查，预设广播模板的指定用户能力已全链路打通：
> - **模型层**：`PresetBroadcastMessage.js` 已有 `target_type`(默认 'all') + `target_value`(TEXT) 字段
> - **Service 层**：`adminPresetBroadcastService.js` `ALLOWED_TARGET_TYPES = ['all', 'users']`，create/update 均支持
> - **前端预设广播页**：`PresetBroadcast.vue` 已有「全部用户/指定用户」单选 + user_id 输入框
> - **前端调度页**：`BroadcastSchedules.vue` 下拉选项已显示「目标：全体用户/指定用户」
> - **调度执行**：`executeBroadcastSchedule` 会读取 preset 的 `target_type` 与 `target_value`，按指定用户列表下发
>
> 因此「立即发送」移除后，「指定用户」场景由「预设模板（指定用户）+ 定时调度 / 提前执行」完整替代，**本次需求无需新增任何代码**。

## 四、字段命名对齐

本次接口废弃移除不涉及新增字段，沿用既有命名规范：

| 维度 | 规则 | 说明 |
|------|------|------|
| 数据库字段 | snake_case | `permission_code`/`config_key`/`is_active` 等 |
| API 响应字段 | snake_case | 废弃接口移除后不再产生响应 |
| 前端消费字段 | camelCase（拦截器转换后） | 小程序端静态配置消费 camelCase |
