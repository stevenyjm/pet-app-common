# API 规范：角色 CRUD 管理

> **创建日期**：2026-08-19
> **涉及项目**：pet-app-backend（实现）、pet-app-admin-web（消费）
> **关联需求**：[2026-08-19-需求-账户删除移除与角色CRUD管理.md](../requirements/2026-08-19-需求-账户删除移除与角色CRUD管理.md)
> **优先级**：高
> **影响范围**：后端新增 3 个角色写接口（创建/编辑/启禁），账户删除接口下线
> **关联文档**：[2026-08-18-API规范-管理员角色列表.md](./2026-08-18-API规范-管理员角色列表.md)、[2026-08-18-API规范-管理员权限矩阵.md](./2026-08-18-API规范-管理员权限矩阵.md)

## 一、背景

已完成的「管理员角色权限矩阵重构」项目实现了角色列表查询（只读）与角色权限矩阵配置。但角色的创建、编辑（名称/编码/描述）、启禁能力缺失，且当前管理员账户的「删除」功能与「禁用」语义重叠（均为 status=0 逻辑删除），存在安全风险。

本规范定义：
1. **新增 3 个角色写接口**：`POST /admin/admin-roles`（创建）、`PUT /admin/admin-roles/:role_id`（编辑）、`PATCH /admin/admin-roles/:role_id/status`（启禁）
2. **账户删除接口下线**：`DELETE /admin/admin-users/:id` 不再注册路由，前端同步移除入口

---

## 二、接口定义

所有接口鉴权：`adminAuthMiddleware` + `requireRole('super_admin')`（仅超权账户可操作）。

---

### 2.1 POST /admin/admin-roles（创建角色）

创建新的管理员角色。新角色默认 `is_active = true`，默认权限为空（`admin_role_permission` 无记录，需后续在矩阵中配置）。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|:---:|------|------|
| Authorization | string | ✅ | header | `Bearer <access_token>` |
| role_name | string | ✅ | body | 角色名称，1-64 字符 |
| role_code | string | ✅ | body | 角色编码，1-32 字符，snake_case（^[a-z][a-z0-9_]*$），全局唯一，不可为 `super_admin` |
| description | string | ❌ | body | 角色描述，≤ 255 字符 |

**请求示例**

```json
{
  "role_name": "客服主管",
  "role_code": "customer_service_lead",
  "description": "负责客服团队管理与用户反馈处理"
}
```

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "role_id": 6,
    "role_name": "客服主管",
    "role_code": "customer_service_lead",
    "description": "负责客服团队管理与用户反馈处理",
    "is_active": true,
    "created_at": "2026-08-19T10:00:00+08:00",
    "updated_at": "2026-08-19T10:00:00+08:00"
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| role_id | number | 新创建角色的主键 ID |
| role_name | string | 角色名称 |
| role_code | string | 角色编码 |
| description | string \| null | 角色描述 |
| is_active | boolean | 是否启用（默认 true） |
| created_at | string | 创建时间（ISO 8601 北京时间） |
| updated_at | string | 更新时间（ISO 8601 北京时间） |

**业务规则**

1. `role_code` 必须符合 snake_case 正则（^[a-z][a-z0-9_]*$），首字符为小写字母
2. `role_code` 不可为 `super_admin`（系统保留，种子预置）
3. `role_code` 全局唯一，违反则返回 40061 `ROLE_CODE_DUPLICATE`
4. 新角色默认 `is_active = true`
5. 不自动写入 `admin_role_permission` 记录（权限为空）
6. 写审计日志：`action = admin_role_create`，`resource_type = admin_role`，`resource_id = role_id`，`detail_json = { role_name, role_code, description }`

**错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败（必填缺失 / 长度超限 / 格式不符） |
| 40061 | 400 | 角色编码已存在（`ROLE_CODE_DUPLICATE`） |
| 40101 | 401 | 未登录或 Token 失效 |
| 40301 | 403 | 非超管角色，无权操作 |
| 50001 | 500 | 服务器内部错误 |

### 2.2 PUT /admin/admin-roles/:role_id（编辑角色）

更新已有角色的 `role_name`、`role_code`、`description`。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|:---:|------|------|
| Authorization | string | ✅ | header | `Bearer <access_token>` |
| role_id | number | ✅ | path | 角色 ID |
| role_name | string | ✅ | body | 角色名称，1-64 字符 |
| role_code | string | ✅ | body | 角色编码，1-32 字符，snake_case，唯一（排除自身） |
| description | string | ❌ | body | 角色描述，≤ 255 字符 |

**请求示例**

```json
{
  "role_name": "客户服务主管",
  "role_code": "customer_service_lead",
  "description": "负责客服团队管理、用户反馈处理与客服话术维护"
}
```

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "role_id": 6,
    "role_name": "客户服务主管",
    "role_code": "customer_service_lead",
    "description": "负责客服团队管理、用户反馈处理与客服话术维护",
    "is_active": true,
    "created_at": "2026-08-19T10:00:00+08:00",
    "updated_at": "2026-08-19T10:05:00+08:00"
  }
}
```

**业务规则**

1. 不可编辑 `super_admin` 角色（`role_code === 'super_admin'`）→ 返回 40304 `ROLE_NOT_EDITABLE`
2. 修改 `role_code` 时，唯一性校验需**排除当前角色自身**（即其他角色不可使用此编码，自身可以保持不变）
3. 修改 `role_code` 时 warning 日志（代码层多处 `requireRole('xxx')` 硬编码引用，变更可能产生隐性影响）
4. 写审计日志：`action = admin_role_update`，`detail_json = { before: {...}, after: {...}, changed_fields: [...] }`（before/after 含本次涉及的三个字段，changed_fields 列出实际变更的字段名）

**错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败 |
| 40061 | 400 | 角色编码已存在（与**其他**角色冲突） |
| 40101 | 401 | 未登录 |
| 40301 | 403 | 非超管 |
| 40304 | 403 | 角色不可编辑（`super_admin`） |
| 40424 | 404 | 角色不存在（`ADMIN_NOT_FOUND`） |
| 50001 | 500 | 服务器错误 |

### 2.3 PATCH /admin/admin-roles/:role_id/status（启用/禁用角色）

切换角色的 `is_active` 状态。禁用后该角色不再出现在「新建管理员」「分配角色」下拉选项中，但已分配此角色的管理员登录与权限不受影响。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|:---:|------|------|
| Authorization | string | ✅ | header | `Bearer <access_token>` |
| role_id | number | ✅ | path | 角色 ID |
| is_active | boolean | ✅ | body | `true` 启用，`false` 禁用 |

**请求示例**

```json
{
  "is_active": false
}
```

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "affected_admin_count": 3
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| affected_admin_count | number | 当前使用此角色且状态为正常（`admin_user.status = 1`）的管理员数量。供前端判断是否需要弹出「当前有 N 个管理员使用此角色」的二次确认提示 |

**业务规则**

1. 不可禁用 `super_admin` 角色（启用也受保护）→ 返回 40304 `ROLE_NOT_EDITABLE`
2. `affected_admin_count` 统计规则：`SELECT COUNT(*) FROM admin_user WHERE role_id = ? AND status = 1`（仅统计正常状态管理员，已禁用的不计入）
3. 禁用**不阻塞**：即便 `affected_admin_count > 0`，接口仍执行禁用（由前端 UI 做二次确认）。已分配此角色的管理员：
   - 登录、已有权限不受影响（分配记录 `admin_user.role_id` 不自动清理）
   - 仅「新建管理员」「分配角色」下拉中不再出现此角色
4. 写审计日志：
   - 禁用：`action = admin_role_disable`，`detail_json = { new_status: 0, affected_admin_count }`
   - 启用：`action = admin_role_enable`，`detail_json = { new_status: 1 }`

**错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40001 | 400 | 参数校验失败（`is_active` 非 boolean） |
| 40101 | 401 | 未登录 |
| 40301 | 403 | 非超管 |
| 40304 | 403 | 角色不可编辑（`super_admin`） |
| 40424 | 404 | 角色不存在 |
| 50001 | 500 | 服务器错误 |

---

### 2.4 DELETE /admin/admin-users/:id（下线·不再注册）

> **已下线**：本接口路由不再注册（`adminUserRoutes.js` 中注释删除），直接请求返回 404。删除功能与「禁用」语义重复（均为 `status=0` 逻辑删除），统一使用「禁用」替代。
>
> Controller 函数 `deleteAdminUser` 保留 1 个月并标注 `@deprecated`，以防需紧急回滚。

## 三、数据库表结构

涉及表 `admin_role`（已存在，无 DDL 变更）、`admin_user`（统计 `affected_admin_count` 用）、`admin_role_permission`（已存在，无 DDL 变更）、`admin_audit_log`（审计写入）。

### 3.1 admin_role（沿用·无变更）

#### 字段信息表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| role_id | BIGINT | PK, AUTO_INCREMENT | 角色主键 |
| role_name | VARCHAR(64) | NOT NULL | 角色名称（1-64 字符） |
| role_code | VARCHAR(32) | NOT NULL, UNIQUE (`uk_role_code`) | 角色编码（snake_case，全局唯一） |
| description | VARCHAR(255) | DEFAULT NULL | 角色描述（≤ 255 字符） |
| is_active | TINYINT(1) | NOT NULL, DEFAULT 1 | 是否启用：1-启用 0-禁用 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间（北京时间） |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间（北京时间） |

#### 建表语句（沿用）

```sql
CREATE TABLE IF NOT EXISTS `admin_role` (
  `role_id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '角色主键',
  `role_name` VARCHAR(64) NOT NULL COMMENT '角色名称（1-64 字符）',
  `role_code` VARCHAR(32) NOT NULL COMMENT '角色编码（snake_case，全局唯一）',
  `description` VARCHAR(255) DEFAULT NULL COMMENT '角色描述（≤ 255 字符）',
  `is_active` TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否启用：1-启用 0-禁用',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  PRIMARY KEY (`role_id`),
  UNIQUE KEY `uk_role_code` (`role_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='管理员角色表';
```

### 3.2 admin_user（沿用·仅用于统计）

仅 PATCH 接口中用于统计 `affected_admin_count`：

```sql
SELECT COUNT(*) AS affected_admin_count
FROM admin_user
WHERE role_id = ? AND status = 1;
```

## 四、字段命名对齐

| 维度 | 规则 | 遵循情况 |
|------|------|---------|
| 数据库字段 | snake_case | `role_id`/`role_name`/`role_code`/`is_active`/`created_at`/`affected_admin_count` |
| API 请求/响应字段 | snake_case | `role_id`/`role_name`/`role_code`/`is_active`/`affected_admin_count` |
| 前端消费字段 | camelCase（响应拦截器 `toCamelCase` 转换） | `roleId`/`roleName`/`roleCode`/`isActive`/`affectedAdminCount` |
| 时间字段 | ISO 8601 北京时间 +08:00 | `created_at`/`updated_at` |

## 五、与现有接口的关系

| 现有接口 | 关系 |
|----------|------|
| `GET /admin/admin-roles` | 只读列表接口，角色创建/编辑/启禁后调用此接口刷新列表 |
| `GET /admin/admin-roles/:role_id/permissions` + `PUT /admin/admin-roles/:role_id/permissions` | 权限矩阵接口，与本规范角色信息字段编辑互不干扰。**新建角色默认权限为空，创建成功后可调用权限矩阵接口配置** |
| `POST /admin/admin-users` + `PATCH /admin/admin-users/:id/role` | 分配角色时角色下拉选项需过滤 `is_active = true` 且 `role_code != 'super_admin'`。本规范 PATCH 接口禁用角色后，这两个接口的角色下拉（通过 `GET /admin/admin-roles` 的前端过滤）不再展示禁用角色 |
| `DELETE /admin/admin-users/:id` | 已下线（本规范 §2.4）。替代方案：`PATCH /admin/admin-users/:id/status` 设 status=0（禁用） |

## 六、验收清单

### 6.1 接口功能

- [ ] `POST /admin/admin-roles` 创建成功，返回 `role_id` + `is_active = true`；`role_code` 重复返回 40061；`role_code = 'super_admin'` 返回 40001/40304
- [ ] `PUT /admin/admin-roles/:role_id` 编辑成功；编辑 `role_id = 1`（`super_admin`）返回 40304；改编码与其他角色冲突返回 40061
- [ ] `PATCH /admin/admin-roles/:role_id/status` 切换成功；响应返回 `affected_admin_count`；禁用 `super_admin` 返回 40304
- [ ] `DELETE /admin/admin-users/:id` 返回 404（路由未注册）
- [ ] 所有写接口非超管调用返回 40301

### 6.2 数据一致性

- [ ] 新建角色后 `admin_role` 表插入正确记录，`admin_role_permission` **无**对应记录（权限为空）
- [ ] 编辑角色后 `updated_at` 自动更新
- [ ] 禁用角色后 `GET /admin/admin-roles` 返回 `is_active = false`，前端过滤后新建管理员下拉不出现
- [ ] 禁用有关联管理员的角色后，`admin_user.role_id` 不被修改，管理员仍可登录

### 6.3 审计日志

- [ ] 每次创建写入 `admin_role_create`，含 `detail_json` 基本信息
- [ ] 每次编辑写入 `admin_role_update`，含 before/after 差异
- [ ] 禁用写入 `admin_role_disable`，含 `affected_admin_count`；启用写入 `admin_role_enable`

### 6.4 兼容性

- [ ] `GET /admin/admin-roles` 现有调用方不受影响（新增字段未改变现有返回结构）
- [ ] `PATCH /admin/admin-users/:id/status`（禁用管理员）继续正常工作（替代原删除）
- [ ] `requirePermission` / `requireRole` 中间件不依赖 `is_active` 字段做运行时权限拦截（仅分配角色时前端下拉过滤）
