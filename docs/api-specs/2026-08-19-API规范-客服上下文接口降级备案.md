## 一、降级背景

依据 [客服功能降级与备案方案](../requirements/2026-08-19-需求-客服功能降级与备案方案.md) v1.0，本期 Level-1 决定：

1. 移除客服会话中"关联订单 / 关联商品"的上下文交互能力；
2. 将以下 4 条上下文切换 / 清除接口标记为 **Deprecated**；
3. 进入 **6 个月兼容观察期**（2026-08-19 起，预计 2027-02-19 截止）；
4. 兼容期内接口保留路由，但**不再执行写库操作**（No-Op），响应统一附加 `deprecated: true` 与 `sunset_date` 字段；
5. 兼容期结束后视情况物理下线（届时另行备案）。

## 二、Deprecated 接口清单

### 2.1 C 端接口（Bearer User JWT）

#### 2.1.1 `PUT /service/conversations/:conversation_id/active-order`

- **状态**：🚫 Deprecated（自 2026-08-19 起）
- **Level-1 行为**：No-Op（不写库，仅返回当前会话状态）
- **原语义**：切换会话活跃订单（写入 `service_conversation.active_order_id`）

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| conversation_id | number | 是 | path | 会话 ID |
| order_id | number | 是 | body | 订单 ID（Level-1 忽略不写入） |
| Authorization | string | 是 | header | Bearer User JWT |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "conversation_id": 10,
    "active_order_id": null,
    "active_product_id": null,
    "deprecated": true,
    "sunset_date": "2027-02-19"
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| conversation_id | number | 会话 ID |
| active_order_id | number \| null | 当前活跃订单 ID（Level-1 起恒为 null） |
| active_product_id | number \| null | 当前活跃商品 ID（Level-1 起恒为 null） |
| deprecated | boolean | 是否为 Deprecated 接口（恒为 true） |
| sunset_date | string | 兼容期截止日期（ISO 8601 日期，北京时间） |

#### 2.1.2 `PUT /service/conversations/:conversation_id/active-product`

- **状态**：🚫 Deprecated（自 2026-08-19 起）
- **Level-1 行为**：No-Op（不写库，仅返回当前会话状态）
- **原语义**：切换会话活跃商品（写入 `service_conversation.active_product_id`）

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| conversation_id | number | 是 | path | 会话 ID |
| product_id | number | 是 | body | 商品 ID（Level-1 忽略不写入） |
| Authorization | string | 是 | header | Bearer User JWT |

**成功响应**：结构与 §2.1.1 一致。

#### 2.1.3 `DELETE /service/conversations/:conversation_id/active-context`

- **状态**：🚫 Deprecated（自 2026-08-19 起）
- **Level-1 行为**：No-Op（不写库，仅返回当前会话状态）
- **原语义**：清空会话活跃上下文（置空 `active_order_id` 与 `active_product_id`）

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| conversation_id | number | 是 | path | 会话 ID |
| Authorization | string | 是 | header | Bearer User JWT |

**成功响应**：结构与 §2.1.1 一致。

### 2.2 管理端接口（Bearer Admin JWT）

| Authorization | string | 是 | header | Bearer Admin JWT |

```json
{
```

## 三、保留（非 Deprecated）接口的字段变更

以下接口不属 Deprecated，但其响应中的上下文字段在 Level-1 起恒返回 null：

### 3.1 `POST /service/conversations/open`（C 端）

- **状态**：✅ 保留（非 Deprecated）
- **Level-1 行为**：请求 body 中的 `order_id` / `product_id` **忽略不写入**；仅创建 / 获取会话
- **响应变更**：响应中 `active_order_id` / `active_product_id` 等字段恒为 null

### 3.2 `GET /service/conversations/current`（C 端）

- **状态**：✅ 保留
- **响应变更**：`active_order_id` / `active_order_no` / `active_product_id` / `active_order` / `active_product` 字段恒为 null（字段保留返回以兼容旧客户端）

### 3.3 `GET /service/conversations/:conversation_id/messages`（C 端 + 管理端共用）

- **状态**：✅ 保留
- **响应变更**：历史消息中 `related_order_id` 字段**保留原值**（不抹除历史数据）；Level-1 起新发送的消息 `related_order_id` 恒为 null

### 3.4 `POST /service/conversations/:conversation_id/messages`（C 端 + 管理端）

- **状态**：✅ 保留
- **行为变更**：发送消息时**不再写入** `related_order_id`（强制 NULL）

### 3.5 `GET /admin/service/conversations`（管理端列表）

- **状态**：✅ 保留
- **响应变更**：列表项中 `active_order_id` / `active_order_no` 字段恒为 null

### 3.6 `GET /admin/service/conversations/:conversation_id`（管理端详情）

- **状态**：✅ 保留
- **响应变更**：详情中 `active_order` / `active_product` / `active_order_id` / `active_product_id` 字段恒为 null

## 四、字段消费说明

| 端 | 后端字段（snake_case） | 前端字段（camelCase） | 转换链路 |
|----|----------------------|---------------------|----------|
| 管理端 | `deprecated` | `deprecated` | `adminResponseKeysMiddleware` → `http.ts` 拦截器 `toCamelCase()` |
| 管理端 | `sunset_date` | `sunsetDate` | 同上 |
| 小程序 | `deprecated` | `deprecated` | `request.js` 拦截器 `deepToCamelCase()` |
| 小程序 | `sunset_date` | `sunsetDate` | 同上 |

---

## 五、兼容性策略

| 维度 | 策略 |
|------|------|
| 数据库 | 不删字段、不删外键、不删索引，新值恒为 NULL |
| 后端 | 旧版客户端继续调用 Deprecated 路由时返回 200 + `deprecated: true`，不抛错 |
| C 端 | 旧版小程序如继续传递 `order_id` / `product_id`，后端忽略不报错；新版本不传递 |
| 管理端 | 旧版管理端如继续调用 `updateAdminServiceActiveOrder`，返回 No-Op；新版管理端不调用 |
| 历史消息 | `service_message.related_order_id` 历史非空值**保留**（不抹除）；新消息恒为 null |

---

## 六、错误码

本次降级**不新增**业务错误码。Deprecated 路由仍返回 `code: 0`，仅在响应 `data` 中附加 `deprecated: true` 与 `sunset_date` 字段。客户端如继续调用，不应触发错误。
