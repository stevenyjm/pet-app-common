## 一、变更背景

### 1.1 原规格（Schema v21 收紧状态）

| 对象 | 字段 | 约束 |
|------|------|------|
| `pet_exercise_session.location` | `VARCHAR(32)` | **NOT NULL**（1~32 字） |
| `pet_exercise_template.location` | `VARCHAR(32)` | **NOT NULL** |
| `exerciseValidator.js` `validateExerciseSessionFields` | location 空串 | **拦截**，返回 `请填写运动地点` 错误 |
| 小程序前端 `exercise-record.vue` 表单 | 运动地点标签 | **红色必填星号 `*`** |
| 小程序 `canSubmit()` | `!form.location.trim()` | **return false**（按钮禁用） |
| 小程序 `suggestTemplateName()` | location 空时 | **直接 return**（不生成模板名），结合模板名非空校验会导致按钮永久禁用 |

### 1.2 原始需求（Schema v21 实施前 MR 草稿）

- [需求分析-宠物运动记录-临时.md](../../pet-app-common/docs/requirements/需求分析-宠物运动记录-临时.md) §2.2 表结构：`location VARCHAR(255) NULL`
- §4 UI 规格 line 131：「运动地点输入（**可选**）」
- §4 流程图 568-570：「是否填写地点 → 是/否 双分支」

### 1.3 本次对齐目标

**运动地点字段统一改为「选填」**：
- DB 层采用 **NOT NULL + DEFAULT ''** 折中方案（避免三层 NULL 语义不一致，回滚最容易）
- 前后端校验放松非空拦截，空串视为合法输入
- **模板名自动生成**升级为 B1→B2→B3 三级递进，保证地点空时仍有合法候选名

## 二、数据库 Schema 变更

### 2.1 变更说明

**不改变 allowNull（保持 NOT NULL），仅新增 DEFAULT 空串 + 更新 COMMENT 字数范围。**

### 2.2 字段信息表

#### 2.2.1 `pet_exercise_session` 表

| 字段 | 类型 | 约束（变更前） | 约束（变更后） | 说明 |
|------|------|---------------|---------------|------|
| `location` | VARCHAR(32) | NOT NULL COMMENT '运动地点 1~32 字' | **NOT NULL DEFAULT '' COMMENT '运动地点 0~32 字；空串表示用户未填写（选填）'** | 选填，空串合法 |

#### 2.2.2 `pet_exercise_template` 表

| 字段 | 类型 | 约束（变更前） | 约束（变更后） | 说明 |
|------|------|---------------|---------------|------|
| `location` | VARCHAR(32) | NOT NULL（无 DEFAULT） | **NOT NULL DEFAULT ''** | 与 session 保持一致 |

### 2.3 建表语句（变更后终态）

```sql
CREATE TABLE IF NOT EXISTS `pet_exercise_session` (
  `session_id` BIGINT NOT NULL AUTO_INCREMENT,
  `pet_id` BIGINT NOT NULL COMMENT '冗余，便于按宠按日查询',
  `record_date` DATE NOT NULL COMMENT '冗余，便于按宠按日查询',
  `location` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '运动地点 0~32 字；空串表示用户未填写（选填）',
  `start_time` TIME NOT NULL COMMENT '开始时间 HH:mm',
  `duration_minutes` SMALLINT NOT NULL COMMENT '时长 1~480 分钟',
  `assessment` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '运动评估 ≤32 字',
  `ext_json` JSON DEFAULT NULL COMMENT '远期扩展',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`session_id`),
  KEY `idx_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_exercise_session_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS `pet_exercise_template` (
  `template_id` BIGINT NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `template_name` VARCHAR(16) NOT NULL,
  `location` VARCHAR(32) NOT NULL DEFAULT '' COMMENT '运动地点 0~32 字；空串表示用户未填写（选填）',
  `start_time` TIME NOT NULL COMMENT '模板默认开始时间',
  `duration_minutes` SMALLINT NOT NULL,
  `assessment` VARCHAR(32) NOT NULL DEFAULT '',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '1-启用 0-停用（软删）',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '0-未删除；1-已逻辑删除（Schema v52）',
  PRIMARY KEY (`template_id`),
  UNIQUE KEY `uk_user_active_template_name` (`user_id`, `template_name`, `status`),
  KEY `idx_user_id_status` (`user_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 2.4 生产迁移前巡检 SQL

```sql
-- 巡检是否存在空串或 NULL 脏数据
SELECT COUNT(*) AS null_count FROM pet_exercise_session WHERE location IS NULL;
SELECT COUNT(*) AS empty_count FROM pet_exercise_session WHERE location = '';
SELECT COUNT(*) AS tpl_null_count FROM pet_exercise_template WHERE location IS NULL;
SELECT COUNT(*) AS tpl_empty_count FROM pet_exercise_template WHERE location = '';

UPDATE pet_exercise_session SET location = '' WHERE location IS NULL;
UPDATE pet_exercise_template SET location = '' WHERE location IS NULL;
```

## 三、后端 API 请求/响应字段变更

### 3.1 PUT `/pets/{pet_id}/daily-records/{record_date}`（运动日记录）

#### 3.1.1 请求体 `exercise_sessions[]` 字段

| 字段 | 必填（变更前） | 必填（变更后） | 类型 | 说明 |
|------|--------------|--------------|------|------|
| `location` | ✅ 是（空串会在 `assertValidExerciseSessionBody` 拦截） | ❌ **否**（0~32 字，空串合法） | string | 运动地点 |
| `start_time` | ✅ 是 | ✅ 是 | string HH:mm | 不变 |
| `duration_minutes` | ✅ 是（≥1） | ✅ 是（≥1） | number | 不变 |
| `assessment` | 否（默认空串） | 否（默认空串） | string ≤32 字 | 不变 |

#### 3.1.2 成功响应 `exercise_sessions[]` 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `location` | string | **空串是合法值**；前端可用 `\|\|` 兜底显示（例如：`item.location \|\| '运动记录'`） |
| `preview_text` | string | **生成规则升级**：location 空 → 省略地点前缀与 ` · ` 分隔点，格式为 `{duration} 分钟`；location 非空 → 保持 `{location} · {duration} 分钟` 原格式 |

### 3.2 POST `/exercise-templates` / PUT 模板快照中的 `location`

与 3.1 对齐：选填，空串合法。

## 四、模板名自动生成策略（运动）

> 仅前端侧逻辑变更；后端 `assertExerciseTemplateNameValid` 仍保持「1~16 字 trim 后非空」强约束（**无变化**）。

### 4.1 三级递进式候选名生成（B1→B2→B3）

```
用户勾选「同时设为运动模板」且模板名输入框为空时调用 suggestTemplateName()
        │
        ▼
    B1. location 非空？
    ├─ 是：suggested = location.slice(0, 16) → 赋值 → 调用查重 API → 结束
    └─ 否：进入 B2
        │
        ▼
    B2. assessment（运动评定）非空？
    ├─ 是：suggested = (assessment + '运动').slice(0, 16) → 赋值 → 查重 → 结束
    │   例：assessment = "精神很好" → 「精神很好运动」（6字）
    │   例：assessment = "有点累了但很开心" → 「有点累了但很开心运动」（11字）
    └─ 否：进入 B3（兜底，保证永远有合法值）
        │
        ▼
    B3. (时段 + duration_minutes + 分钟运动)
        时段根据 start_time 分 5 档：
          HH >= 05 且 HH < 10 → 「晨间」
          HH >= 10 且 HH < 14 → 「午间」
          HH >= 14 且 HH < 18 → 「下午」
          HH >= 18 且 HH < 22 → 「晚间」
          其它               → 「夜间」
        拼接：时段 + duration + 分钟运动 → slice(0,16)
        例：start_time=07:30, duration=20 → 「晨间20分钟运动」（9字）
        例：start_time=21:00, duration=60 → 「晚间60分钟运动」（9字）
        例：start_time=23:15, duration=10 → 「夜间10分钟运动」（9字）
```

### 4.2 长度保证

所有分支 `slice(0, 16)` 后一定是 1~16 字：
- B1：location 空才不进，非空至少 1 字
- B2：assessment + 「运动」至少 3 字
- B3：时段 2 字 + duration 数字 1-3 字 + 「分钟运动」4 字 = 至少 7 字，最多 2+3+4=9 < 16

### 4.3 查重机制不变

自动填充后调用 `scheduleTemplateNameCheck()` → GET `/exercise-templates/name-availability`：
- `{ available: true }`：不提示，用户可直接提交
- `{ available: false, will_overwrite: true }`：显示「名称重复，将覆盖原模板」黄色警告
- 用户可继续手动编辑模板名，`canSubmit` 仍按「1~16 字 + 无校验错误」判定
