## 二、字段统一定义（DDL 模板）

```sql
-- 必备字段（统一类型与约束）
`created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
`updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
`is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除'
```

> 对 5 张豁免表（流水表）只补 `created_at` + `updated_at`，不补 `is_deleted`。

## 三、向后兼容性评估

### 3.1 新增字段的影响

- 所有新增字段均有 `DEFAULT` 值（`created_at`/`updated_at` 默认 `CURRENT_TIMESTAMP`，`is_deleted` 默认 `0`），既有数据无需回填即可查询。
- 新增字段在 `SELECT *` 中会自动返回，**可能影响 API 响应字段**，但均为新增字段（snake_case），前端消费时按需取用即可。

### 3.2 移除字段的影响（仅 `product` / `after_sales` / `article`）

3 张表移除 `is_hidden` / `hidden_at` / `hidden_by` 字段：

- **API 响应字段影响**：响应中将不再包含这三个字段；前端 / 管理端如消费了这些字段需移除展示。
- **管理端功能影响**：商户管理端对应页面（`product/List.vue` / `after-sales/Index.vue` / `article/List.vue`）的"隐藏"按钮功能需改为"删除（软删）"调用，详见第 6 批变更。
- **后端 Controller 影响**：`adminProductController.js` / `adminArticleController.js` / `adminAfterSalesController.js` 中如有"隐藏"接口（如 `POST /:id/hide`）需下线或改造为软删接口。

### 3.3 查询过滤影响

按规范 §8.3.2，所有读操作默认带 `is_deleted = 0` 过滤。本次第1批仅完成 schema 变更与 Model 定义同步；**Controller 查询层的 `is_deleted = 0` 过滤改造属于跨批次工作**，将在后续批次统一处理（避免一次性改动 23 个 Controller 的查询条件造成回归风险）。

> ⚠️ 风险提示：在 Controller 查询层改造完成前，未带 `is_deleted = 0` 过滤的查询会返回已逻辑删除的记录。建议在第 2 批之前完成对 `product` / `product_sku` / `order_detail` 等核心交易表 Controller 的查询层补齐过滤。
