## 1. 变更范围

第五档包含 **10 张表**，分为 5 小类：
- 第 5 档 · 类 1：Token 表 · 物理删除豁免（`user_refresh_token`、`admin_refresh_token`），不补 is_deleted，但需要规范化 created_at/updated_at 命名
- 第 5 档 · 类 2：审计/流水表 · 追加不删除豁免（`inventory_flow`、`payment_log`、`user_sms_log`），不补 is_deleted，但需要规范化 created_at/updated_at 命名
- 第 5 档 · 类 3：轻微不符（`after_sales_request`、`after_sales_item`、`article_category`）——created_at/updated_at 已有，is_deleted 为 BOOLEAN→TINYINT
- 第 5 档 · 类 4：纯关联表缺字段（`family_group_tag`、`pet_allergy_ingredient`）——缺 created_at/updated_at/is_deleted 三字段，补齐

## 2. 10 张表详细变更计划

| # | 表名 | 分类 | 当前字段问题 | 修复方案 | 是否补 is_deleted |

| 2 | `admin_refresh_token` | Token豁免 | `create_time DATETIME`；缺 `updated_at` | `create_time` → `created_at`（RENAME）；补 `updated_at` | ❌ 豁免（Token 表）|
| 3 | `inventory_flow` | 流水豁免 | `create_time DATETIME`；缺 `updated_at` | `create_time` → `created_at`（RENAME）；补 `updated_at` | ❌ 豁免（流水表）|
| 4 | `payment_log` | 流水豁免 | `create_time DATETIME`；缺 `updated_at` | `create_time` → `created_at`（RENAME）；补 `updated_at` | ❌ 豁免（流水表）|
| 5 | `user_sms_log` | 流水豁免 | 推测 `create_time DATETIME`；缺 `updated_at` | `create_time` → `created_at`（RENAME）；补 `updated_at` | ❌ 豁免（流水表）|

## 3. 字段定义（规范版）

```sql
`created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）'
`updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）'
`is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除'
```

## 4. 向后兼容性评估

| 变更 | 向后兼容 | 影响 |
|------|---------|------|
| Token 表 create_time→created_at + 补 updated_at | ❌ 不兼容 | 后端查询 create_time 的代码需要同步改名；新增字段不影响 |
| 流水表 create_time→created_at + 补 updated_at | ❌ 不兼容 | 同上 |
| 3 张轻微不符表 BOOLEAN→TINYINT | ✅ 基本兼容 | 需检查严格比较 `=== true/false` 的代码 |
| 2 张纯关联表补三字段 | ✅ 兼容 | 新增字段无影响 |
