## 2. 物理下线路由（联合记录）

以下 4 条路由在 Phase 1 中**物理删除**，不再注册，调用返回 404。

| # | 方法 | 路径 | 原用途 | 处置 |
|---|------|------|--------|------|
| 1 | POST | `/api/v1/pets/daily-records/joint` | 创建联合日记录 | 💥 物理下线 |
| 2 | PUT | `/api/v1/pets/daily-records/session/:session_id/participants` | 更新会话参与宠物 | 💥 物理下线 |
| 3 | GET | `/api/v1/pets/daily-records/session/:session_id` | 获取会话详情 | 💥 物理下线 |
| 4 | DELETE | `/api/v1/pets/daily-records/session/:session_id` | 删除会话 | 💥 物理下线 |

> 依据 Q2（物理下线）+ Q4（测试数据可丢弃），无兼容期，直接删除路由注册与对应控制器/服务函数。

## 3. 物理删除字段（`pet.latest_*`）

以下 9 个字段从 `pet` 表物理删除，API 响应中不再返回。

| # | 字段 | 类型 | 原用途 | 处置 |
|---|------|------|--------|------|
| 1 | `latest_mood` | VARCHAR(32) | 最近心情 | 💥 物理删除 |
| 2 | `latest_mood_update_time` | DATETIME | 最近心情更新时间 | 💥 物理删除 |
| 3 | `latest_weight_kg` | DECIMAL(6,2) | 最近体重 | 💥 物理删除 |
| 4 | `latest_weight_update_time` | DATETIME | 最近体重更新时间 | 💥 物理删除 |
| 5 | `latest_stool_health` | VARCHAR(32) | 最近排便健康 | 💥 物理删除 |
| 6 | `latest_stool_update_time` | DATETIME | 最近排便健康更新时间 | 💥 物理删除 |
| 7 | `latest_physical_state` | VARCHAR(6) | 最近身体状态 | 💥 物理删除 |
| 8 | `latest_physical_state_update_time` | DATETIME | 最近身体状态更新时间 | 💥 物理删除 |
| 9 | `latest_record_date` | DATE | 最近记录日期 | 💥 物理删除 |

### 3.1 影响的 API 响应

| API | 变更 |
|-----|------|
| `GET /api/v1/pets/:pet_id` | 响应中不再含 `latest_*` 字段 |
| `GET /api/v1/admin/pets/:id` | 响应中不再含 `latest_*` 字段 |
| `GET /api/v1/admin/pets` | 列表项不再含 `latest_mood` / `latest_physical_state` / `latest_weight_kg` |
| `GET /api/v1/admin/pets/export` | CSV 导出不再含 `latest_*` 列 |

### 3.2 影响的 API 请求

| API | 变更 |
|-----|------|
| `PUT /api/v1/pets/:pet_id` | 请求体不再接收 `latest_mood` / `latest_weight_kg` / `latest_stool_health` / `latest_physical_state` 等字段 |
| `PUT /api/v1/pets/:pet_id/daily-records/:record_date` | 请求体不再接收 `sync_to_latest` 参数 |

## 5. 🆕 新增路由

### 5.1 快速记录批量创建

| 项 | 值 |
|----|----|
| 方法 | POST |
| 路径 | `/api/v1/pets/daily-records/quick-batch` |
| 鉴权 | Bearer token（C 端用户） |
| 用途 | 为多个宠物批量创建**独立**的餐食/运动日记录 |

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_ids | BIGINT[] | 是 | body | 目标宠物ID列表（不含当前已保存的宠物） |
| record_date | string(YYYY-MM-DD) | 是 | body | 记录日期 |
| session_type | string | 是 | body | `meal` 或 `exercise` |
| meal_session | object | 条件必填 | body | `session_type=meal` 时必填，餐食会话内容 |
| exercise_session | object | 条件必填 | body | `session_type=exercise` 时必填，运动会话内容 |
| Authorization | string | 是 | header | Bearer token |

**请求示例（餐食）**

```json
{
  "pet_ids": [101, 102],
  "record_date": "2026-08-19",
  "session_type": "meal",
  "meal_session": {
    "slot": "早上",
    "time": "08:00",
    "status": "良好",
    "items": [{ "name": "鸡胸肉", "amount": "150g" }],
    "remark": ""
  }
}
```

**成功响应**（`code: 0`）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success_count": 2,
    "failed": []
  }
}
```

**部分失败响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success_count": 1,
    "failed": [
      { "pet_id": 102, "reason": "当日餐食记录已达上限" }
    ]
  }
}
```

**错误码**

| code | 说明 |
|------|------|
| 40001 | 参数错误（`pet_ids` 为空 / `session_type` 非法 / 缺少 `meal_session` 或 `exercise_session`） |
| 40300 | 无权访问某宠物 |
| 40400 | 某宠物不存在 |
| 50001 | 服务器内部错误 |

**后端逻辑**：循环 `pet_ids`，对每个宠物调用单宠物保存逻辑（`createMealSessionWithItems` / `PetExerciseSession.create`），创建**独立** session（餐食：`pet_meal_session` 直接写 `pet_id`；运动：`pet_exercise_session` 写 `pet_id`）。

### 5.2 获取最近一次记录

| 项 | 值 |
|----|----|
| 方法 | GET |
| 路径 | `/api/v1/pets/:pet_id/daily-records/latest` |
| 鉴权 | Bearer token（C 端用户） |
| 用途 | 获取该宠物最近一次餐食/运动记录（跨日期） |

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | BIGINT | 是 | path | 宠物 ID |
| type | string | 是 | query | `meal` 或 `exercise` |
| Authorization | string | 是 | header | Bearer token |

**成功响应（餐食，`code: 0`）**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "session_id": 12345,
    "record_date": "2026-08-18",
    "period": "早上",
    "meal_time": "08:00",
    "post_meal_status": "良好",
    "nutrition_reference": null,
    "remark": "",
    "items": [
      { "food_name": "鸡胸肉", "amount": "150g", "nutrition_ref": "" }
    ]
  }
}
```

**无历史记录响应（`code: 0`，`data: null`）**

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

**错误码**

| code | 说明 |
|------|------|
| 40001 | 参数错误（`type` 非 `meal`/`exercise`） |
| 40300 | 无权访问该宠物 |
| 40400 | 宠物不存在 |
| 50001 | 服务器内部错误 |

**后端查询逻辑**：
- 餐食：`PetMealSession.findAll({ where: { pet_id, is_deleted: 0 }, include: [{ model: PetMealItem }], order: [['record_date', 'DESC'], ['sort_order', 'DESC']], limit: 1 })`
- 运动：`PetExerciseSession.findAll({ where: { pet_id, is_deleted: 0 }, order: [['record_date', 'DESC'], ['start_time', 'DESC']], limit: 1 })`

## 6. 数据库 DDL 变更（迁移脚本 v51）

```sql
-- 1. pet_meal_session 新增 pet_id 字段（替代关联表）
ALTER TABLE `pet_meal_session`
  ADD COLUMN `pet_id` BIGINT NOT NULL COMMENT '宠物ID（Schema v51，替代原 pet_meal_session_pet 关联表）' AFTER `session_id`,
  ADD KEY `idx_meal_pet_date` (`pet_id`, `record_date`),
  ADD CONSTRAINT `fk_meal_session_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`) ON DELETE CASCADE;

-- 2. 物理删除 pet_meal_session_pet 关联表
DROP TABLE IF EXISTS `pet_meal_session_pet`;

-- 3. 物理删除 pet_exercise_session_pet 关联表
DROP TABLE IF EXISTS `pet_exercise_session_pet`;

-- 4. pet 表物理删除 9 个 latest_* 字段
ALTER TABLE `pet`
  DROP COLUMN `latest_mood`,
  DROP COLUMN `latest_mood_update_time`,
  DROP COLUMN `latest_weight_kg`,
  DROP COLUMN `latest_weight_update_time`,
  DROP COLUMN `latest_stool_health`,
  DROP COLUMN `latest_stool_update_time`,
  DROP COLUMN `latest_physical_state`,
  DROP COLUMN `latest_physical_state_update_time`,
  DROP COLUMN `latest_record_date`;
```
