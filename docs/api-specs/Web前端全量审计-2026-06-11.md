## 6. 业务错误码三端对照

> **权威来源**：后端 `docs/项目开发说明-后端.md` §5.19（2026-06-01 定稿 + 后续增量码）  
> **小程序**：`constants/error-codes.js` + 各 `get*ErrorMessage`（§5.16）  
> **Web**：`src/api/http.ts` 仅特殊处理 `40101`/`40002`/`40301`；其余展示 `payload.message`

### 6.1 Web 端错误处理架构

```
请求 → http 拦截器
  ├─ code === 0 → 成功
  ├─ 40101 / 40002 → refresh Token → 失败跳登录
  ├─ 40301 → 跳转 /403
  └─ 其他非 0 → ApiBusinessError(code, message) → 各页 getErrorMessage → Toast
```

**特点**：

- ✅ 与后端 envelope `{ code, message, data }` 一致  
- ✅ 401 刷新队列避免并发重复 refresh  
- ❌ 无分模块错误码 Map（与小程序策略不同）  
- ❌ 文档 §5.6 承诺的 `40401 → 返回列表` **未实现**（且后端无此码，见 §6.4）

### 6.2 Web 管理端应关注的错误码

以下码在 Web 业务流程中**可能被触发**，当前均仅 Toast 后端 `message`：

|------|------|-----------------|--------|-------------|
| **40101** | 未登录/Token 失效 | 全局 | ✅ 跳登录 | ✅ 跳登录 |

| 码表文件 | `constants/error-codes.js` | **无** |
| 分模块 Helper | `getAuthErrorMessage` 等 10+ | 仅 `getErrorMessage` |
| 401 处理 | refresh + 跳登录 | ✅ 同 |
| 403 处理 | Toast / 页面 | ✅ `/403` 路由 |
| 404 业务码 | 部分跳页/静默（40412） | 仅 Toast |
| 422 业务拒绝 | 友好文案 | 后端 message 直出 |
| 维护成本 | 高（需随 §5.19 同步） | 低（依赖后端文案） |

**审计意见**：Web 策略对 B 端内部用户可接受；建议至少为 **40422、42217、42218、40051** 增加轻量分支（关闭抽屉/刷新列表），不必复制小程序全量码表。
