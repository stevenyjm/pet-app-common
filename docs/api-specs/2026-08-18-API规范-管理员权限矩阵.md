# API 规范：管理员权限矩阵

> **创建日期**：2026-08-18
> **涉及项目**：pet-app-backend（实现）、pet-app-admin-web（消费）
> **关联需求**：[2026-08-18-需求-管理员角色权限矩阵重构.md](../requirements/2026-08-18-需求-管理员角色权限矩阵重构.md)
> **优先级**：高
> **影响范围**：后端新增 3 个超管接口；前端账户管理页新增「角色权限矩阵」对话框

## 一、背景

原角色权限体系仅覆盖进销存 17 个权限码，且按"职能"划分导致部分模块重合。本次重构将权限码扩展至 49 个覆盖管理端全部模块，划分方式改为"按模块细分 + 超管可勾选/取消勾选"。本规范定义 3 个支撑前端矩阵 UI 的新接口：

- `GET /admin/admin-permissions` —— 返回权限码全集（按模块分组，含中文名/排序），供前端矩阵渲染
- `GET /admin/admin-roles/:role_id/permissions` —— 获取某角色的当前勾选状态
- `PUT /admin/admin-roles/:role_id/permissions` —— 超管全量更新某角色权限（事务，写审计）

## 二、接口定义

### 2.1 GET /admin/admin-permissions

获取权限码全集（按模块分组），用于前端矩阵 UI 渲染。

**鉴权**

| 中间件 | 说明 |
|--------|------|
| `adminAuthMiddleware` | JWT 鉴权，解析 `req.admin.adminId` |
| `requireRole('super_admin')` | 仅 `role_code === 'super_admin'` 放行 |

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| Authorization | string | 是 | header | `Bearer <access_token>` |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "groups": [
      {
        "module": "dashboard",
        "module_name": "仪表盘",
        "permissions": [
          {
            "permission_code": "dashboard:view",
            "name": "仪表盘查看",
            "description": "查看管理端首页统计与图表",
            "sort_order": 1
          }
        ]
      },
      {
        "module": "order",
        "module_name": "订单",
        "permissions": [
          {
            "permission_code": "order:view",
            "name": "订单查看",
            "description": "订单列表、订单详情",
            "sort_order": 1
          },
          {
            "permission_code": "order:ship",
            "name": "订单发货",
            "description": "待发货订单的发货操作",
            "sort_order": 3
          }
        ]
      }
    ]
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| groups | array | 按模块分组的权限列表 |
| groups[].module | string | 模块编码（`dashboard`/`order`/`product`/`inventory`/`user`/`pet`/`content`/`message`/`mini_app_config`/`system`） |
| groups[].module_name | string | 模块中文名（如「订单」） |
| groups[].permissions | array | 该模块下的权限码列表 |
| groups[].permissions[].permission_code | string | 权限码（如 `order:ship`） |
| groups[].permissions[].name | string | 权限中文名（如「订单发货」） |
| groups[].permissions[].description | string \| null | 权限描述 |
| groups[].permissions[].sort_order | number | 同模块内排序权重（升序） |

> 前端响应拦截器 `toCamelCase` 会自动转为 camelCase（`groups`/`module`/`moduleName`/`permissions`/`permissionCode`/`sortOrder`），前端代码消费 camelCase。

**可能的错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40101 | 401 | 未登录或 Token 失效 |
| 40301 | 403 | 无权访问（非超管角色） |
| 50001 | 500 | 服务器内部错误 |

### 2.2 GET /admin/admin-roles/:role_id/permissions

获取某角色的当前权限勾选状态。

**鉴权**

| 中间件 | 说明 |
|--------|------|
| `adminAuthMiddleware` | JWT 鉴权 |
| `requireRole('super_admin')` | 仅超管放行 |

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| Authorization | string | 是 | header | `Bearer <access_token>` |
| role_id | number | 是 | path | 角色 ID |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "role_id": 2,
    "role_code": "warehouse_admin",
    "role_name": "仓库管理员",
    "permissions": [
      "dashboard:view",
      "inventory:dashboard",
      "inventory:view",
      "inventory:inbound",
      "inventory:outbound",
      "order:ship",
      "product:view"
    ]
  }
}
```

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| role_id | number | 角色 ID |
| role_code | string | 角色编码（`warehouse_admin`/`purchaser`/`finance`/`operations`/`super_admin`） |
| role_name | string | 角色中文名 |
| permissions | string[] | 该角色已勾选的权限码列表（super_admin 返回全集） |

**可能的错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40101 | 401 | 未登录或 Token 失效 |
| 40301 | 403 | 无权访问（非超管角色） |
| 40424 | 404 | 角色不存在（`ADMIN_NOT_FOUND`） |
| 50001 | 500 | 服务器内部错误 |

### 2.3 PUT /admin/admin-roles/:role_id/permissions

超管全量更新某角色的权限勾选状态（**全量覆盖**语义：先 DELETE 该 role_id 的全部记录，再 INSERT 新记录，事务包裹）。

**鉴权**

| 中间件 | 说明 |
|--------|------|
| `adminAuthMiddleware` | JWT 鉴权 |
| `requireRole('super_admin')` | 仅超管放行 |

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| Authorization | string | 是 | header | `Bearer <access_token>` |
| role_id | number | 是 | path | 角色 ID（不可为 super_admin） |
| permissions | string[] | 是 | body | 权限码全集（全量覆盖；空数组表示清空） |

**请求示例**

```json
{
  "permissions": [
    "dashboard:view",
    "inventory:dashboard",
    "inventory:view",
    "inventory:inbound",
    "order:ship",
    "product:view"
  ]
}
```

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "role_id": 2,
    "role_code": "warehouse_admin",
    "permissions": [
      "dashboard:view",
      "inventory:dashboard",
      "inventory:view",
      "inventory:inbound",
      "order:ship",
      "product:view"
    ]
  }
}
```

**业务规则**

1. 不可修改 `super_admin`（`role_code === 'super_admin'`）的权限 → 返回 40304 `ROLE_NOT_EDITABLE`
2. 传入的 `permission_code` 必须存在于 `admin_permission` 字典表；不存在者跳过并 warning 日志（不阻塞）
3. 全量覆盖：在事务中先 `DELETE FROM admin_role_permission WHERE role_id = ?`，再批量 `INSERT`
4. 写审计日志：
   - `action = admin_role_permission_update`
   - `resource_type = admin_role`
   - `resource_id = role_id`
   - `detail_json = { before: [...], after: [...], added: [...], removed: [...] }`
   - `ip_address = req.admin.ipAddress`
5. 审计日志写入失败不阻塞主流程（沿用 `writeAdminAudit` 容错策略）

**可能的错误码**

| code | HTTP | 说明 |
|------|------|------|
| 0 | 200 | 成功 |
| 40001 | 400 | 请求参数错误（`permissions` 非数组 / 含非字符串元素） |
| 40101 | 401 | 未登录或 Token 失效 |
| 40301 | 403 | 无权访问（非超管角色） |
| 40304 | 403 | 角色权限不可编辑（`super_admin`） |
| 40424 | 404 | 角色不存在（`ADMIN_NOT_FOUND`） |
| 50001 | 500 | 服务器内部错误 |

## 三、数据库表结构

涉及两张表：`admin_permission`（新增字典表）、`admin_role_permission`（已存在，无需变更）。

### 3.1 admin_permission（新增）

#### 字段信息表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| permission_code | VARCHAR(64) | PK | 权限码（如 `order:ship`, `product:edit`） |
| module | VARCHAR(32) | NOT NULL | 所属模块（`dashboard`/`order`/`product`/`inventory`/`user`/`pet`/`content`/`message`/`mini_app_config`/`system`） |
| name | VARCHAR(64) | NOT NULL | 权限中文名（如「订单发货」） |
| description | VARCHAR(255) | DEFAULT NULL | 权限描述 |
| sort_order | INT | NOT NULL, DEFAULT 0 | 排序权重（同模块内升序） |
| is_active | TINYINT(1) | NOT NULL, DEFAULT 1 | 是否启用：1-启用 0-禁用 |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间（北京时间） |
| updated_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间（北京时间） |

#### 建表语句

```sql
CREATE TABLE IF NOT EXISTS `admin_permission` (
  `permission_code` VARCHAR(64) NOT NULL COMMENT '权限码（如 order:ship, product:edit）',
  `module` VARCHAR(32) NOT NULL COMMENT '所属模块（dashboard/order/product/inventory/user/pet/content/message/mini_app_config/system）',
  `name` VARCHAR(64) NOT NULL COMMENT '权限中文名（如 订单发货）',
  `description` VARCHAR(255) DEFAULT NULL COMMENT '权限描述',
  `sort_order` INT NOT NULL DEFAULT 0 COMMENT '排序权重（同模块内升序）',
  `is_active` TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否启用：1-启用 0-禁用',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  PRIMARY KEY (`permission_code`),
  KEY `idx_module` (`module`),
  KEY `idx_sort_order` (`sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='管理员权限码字典表';
```

### 3.2 admin_role_permission（沿用，无变更）

```sql
CREATE TABLE IF NOT EXISTS `admin_role_permission` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `role_id` BIGINT NOT NULL,
  `permission_code` VARCHAR(64) NOT NULL COMMENT '权限标识（如 inventory:dashboard, order:ship）',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_role_permission` (`role_id`, `permission_code`),
  CONSTRAINT `fk_role_permission_role` FOREIGN KEY (`role_id`) REFERENCES `admin_role` (`role_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='角色权限关联表';
```

## 四、字段命名对齐

| 维度 | 规则 | 本接口遵循情况 |
|------|------|----------------|
| 数据库字段 | snake_case | `permission_code`/`module`/`sort_order`/`is_active`/`created_at` |
| API 响应字段 | snake_case | `permission_code`/`module_name`/`sort_order`/`role_id`/`role_code` |
| 前端消费字段 | camelCase（拦截器转换后） | `permissionCode`/`moduleName`/`sortOrder`/`roleId`/`roleCode` |
| 时间字段 | ISO 8601 北京时间 +08:00 | `created_at`/`updated_at` |

## 六、与现有接口的关系

| 现有接口 | 关系 |
|----------|------|
| `GET /admin/admin-roles` | 提供角色字典，本接口在其之上提供角色 × 权限的勾选状态与更新能力 |
| `GET /admin/permissions` | 返回**当前登录管理员**的权限列表（自身权限）；本接口返回**全部权限码字典**与**指定角色的勾选状态**，二者职责不同 |
| `PATCH /admin/admin-users/:id/role` | 分配用户的 `role_id`；本接口管理 `role_id` 对应的权限勾选。用户最终权限 = 所属角色的勾选权限 |
