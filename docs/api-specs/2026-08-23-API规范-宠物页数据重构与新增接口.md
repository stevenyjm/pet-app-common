## 1. 变更概览

| 变更类型 | 数量 | 说明 |
|----------|------|------|
| 🆕 新增表 | 3 张 | pet_mood_record / pet_stool_record / pet_daily_health_metric |
| 🚫 废弃字段 | 3 个 | pet_daily_status 的 daily_mood / daily_stool_health / daily_weight_kg（迁移后 deprecated） |
| 🆕 新增路由 | 13 条 | 心情 CRUD 4 + 排便 CRUD 4 + 健康指标 3 + 看板聚合 1 + 月度摘要 1 |
| 🔄 既有接口扩展 | 1 个 | getDailyRecord 响应新增 mood_records / stool_records / health_metric / daily_dashboard |
| 🆕 新增错误码 | 4 个 | 心情/排便记录不存在、记录数超限、历史记录不可修改 |

> 所有 C 端 API 响应字段使用 **snake_case**（与既有宠物接口一致）。时间字段统一北京时间 +08:00。

## 2. 新增表结构

### 2.1 pet_mood_record（心情记录表，每日多条）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| mood_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| pet_id | BIGINT | NOT NULL | 宠物ID |
| record_date | DATE | NOT NULL | 记录日期 |
| record_time | TIME | NOT NULL | 记录时间（HH:mm:ss） |
| mood_value | VARCHAR(32) | NOT NULL | 心情描述（开心/兴奋/平静/低落/饥饿/无聊/一般/焦虑/懒惰/困倦/生病/不适/性情不定） |
| mood_icon | VARCHAR(16) | NULL | 心情图标 emoji |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间（北京时间） |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间（北京时间） |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除：0-未删除 1-已删除 |

```sql
CREATE TABLE IF NOT EXISTS `pet_mood_record` (
  `mood_id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '心情记录主键',
  `pet_id` BIGINT NOT NULL COMMENT '宠物ID',
  `record_date` DATE NOT NULL COMMENT '记录日期',
  `record_time` TIME NOT NULL COMMENT '记录时间 HH:mm:ss',
  `mood_value` VARCHAR(32) NOT NULL COMMENT '心情描述，如开心/无聊/兴奋',
  `mood_icon` VARCHAR(16) DEFAULT NULL COMMENT '心情图标 emoji',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除 1-已删除',
  PRIMARY KEY (`mood_id`),
  KEY `idx_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_mood_record_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='宠物心情记录表（每日多条）';
```

> 预设值复用 `pet-app/src/constants/pet.js` 已内置的 `MOOD_OPTIONS`（13 项），支持 allowCreate 自定义输入兼容历史值。

### 2.3 pet_daily_health_metric（每日健康指标表，按日统一存储）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| metric_id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| pet_id | BIGINT | NOT NULL | 宠物ID |
| record_date | DATE | NOT NULL | 记录日期 |
| weight_kg | DECIMAL(6,2) | NULL | 体重 kg |
| physiology_status | VARCHAR(32) | NULL | 生理状态文本（正常/生病/怀孕/术后/虚弱/发情期/残疾） |
| calorie_theory_kcal | DECIMAL(8,2) | NULL | 卡路里理论参考值 K0（系统计算，本期占位） |
| calorie_custom_kcal | DECIMAL(8,2) | NULL | 卡路里用户自定义 K1 |
| exercise_theory_min | SMALLINT | NULL | 运动时长理论参考值 T0（系统计算，本期占位，分钟） |
| exercise_custom_min | SMALLINT | NULL | 运动时长用户自定义 T1（分钟） |
| user_pref_c1 | DECIMAL(6,2) | NULL | 用户偏好参数 C1（参与 K0 计算，本期占位） |
| user_pref_c2 | DECIMAL(6,2) | NULL | 用户偏好参数 C2（参与 T0 计算，本期占位） |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间（北京时间） |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间（北京时间） |
| is_deleted | TINYINT | NOT NULL DEFAULT 0 | 逻辑删除：0-未删除 1-已删除 |

```sql
CREATE TABLE IF NOT EXISTS `pet_daily_health_metric` (
  `metric_id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '每日健康指标主键',
  `pet_id` BIGINT NOT NULL COMMENT '宠物ID',
  `record_date` DATE NOT NULL COMMENT '记录日期',
  `weight_kg` DECIMAL(6,2) DEFAULT NULL COMMENT '体重 kg',
  `physiology_status` VARCHAR(32) DEFAULT NULL COMMENT '生理状态预设值文本（正常/生病/怀孕/术后/虚弱/发情期/残疾）',
  `calorie_theory_kcal` DECIMAL(8,2) DEFAULT NULL COMMENT '卡路里理论参考值K0（系统计算，本期占位）',
  `calorie_custom_kcal` DECIMAL(8,2) DEFAULT NULL COMMENT '卡路里用户自定义K1',
  `exercise_theory_min` SMALLINT DEFAULT NULL COMMENT '运动时长理论参考值T0（系统计算，本期占位，分钟）',
  `exercise_custom_min` SMALLINT DEFAULT NULL COMMENT '运动时长用户自定义T1（分钟）',
  `user_pref_c1` DECIMAL(6,2) DEFAULT NULL COMMENT '用户偏好参数C1（参与K0计算，本期占位）',
  `user_pref_c2` DECIMAL(6,2) DEFAULT NULL COMMENT '用户偏好参数C2（参与T0计算，本期占位）',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除 1-已删除',
  PRIMARY KEY (`metric_id`),
  UNIQUE KEY `uk_pet_date` (`pet_id`, `record_date`),
  KEY `idx_pet_date` (`pet_id`, `record_date`),
  CONSTRAINT `fk_health_metric_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='宠物每日健康指标表（体重+生理状态+卡路里目标+运动目标，按日存储历史）';
```

> **业务规则**：
> - 每只宠物每天一条记录（UNIQUE: pet_id + record_date）
> - C 端 PUT 仅允许 record_date = 今天，不允许修改历史
> - "最新一次记录" = `record_date <= 今天` 且对应字段 IS NOT NULL 的最近一条
> - 卡路里目标 KK = `calorie_custom_kcal`(K1) 存在取 K1，否则取 `calorie_theory_kcal`(K0)
> - 运动目标 TT = `exercise_custom_min`(T1) 存在取 T1，否则取 `exercise_theory_min`(T0)

### 4.3 每日健康指标

#### 4.3.1 GET /api/v1/pets/:pet_id/health-metrics

获取指定日健康指标。

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | BIGINT | 是 | path | 宠物ID |
| record_date | string(YYYY-MM-DD) | 是 | query | 记录日期 |
| Authorization | string | 是 | header | Bearer token |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "metric_id": 1,
    "pet_id": 101,
    "record_date": "2026-08-23",
    "weight_kg": 5.20,
    "physiology_status": "正常",
    "calorie_theory_kcal": null,
    "calorie_custom_kcal": 350.00,
    "exercise_theory_min": null,
    "exercise_custom_min": 60,
    "calorie_goal_kk": 350.00,
    "exercise_goal_tt": 60
  }
}
```

> `calorie_goal_kk` = `calorie_custom_kcal` 存在取 K1，否则取 `calorie_theory_kcal`(K0)，两者皆空为 null。
> `exercise_goal_tt` = `exercise_custom_min` 存在取 T1，否则取 `exercise_theory_min`(T0)，两者皆空为 null。
> 指定日无记录时 data 为 null。

| code | 说明 |
|------|------|
| 40001 | 参数错误 |
| 40301 | 无权访问该宠物 |
| 40410 | 宠物不存在 |
| 50001 | 服务器错误 |

## 6. 错误码定义

### 6.1 新增错误码

| code | 含义 | 触发场景 |
|------|------|----------|
| 40411 | 心情记录不存在 | PUT/DELETE mood-records 时 mood_id 不存在或已删除 |
| 40412 | 排便记录不存在 | PUT/DELETE stool-records 时 stool_id 不存在或已删除 |
| 42210 | 当日记录已达上限 | POST mood-records/stool-records 时当日已达 5 条 |
| 42211 | 不允许修改历史记录 | PUT health-metrics 时 record_date 非今天 |

> 错误码段说明：404xx 为模块专属"不存在"，422xx 为业务规则拒绝（遵循 AGENTS.md 错误码体系）。
> 40410（宠物不存在）为既有错误码复用，非本次新增。

### 6.2 响应示例

```json
{ "code": 42211, "message": "不允许修改历史日期的健康指标", "data": null }
```

```json
{ "code": 42210, "message": "当日心情记录已达 5 条上限", "data": null }
```

## 7. 数据迁移说明

### 7.1 迁移脚本

**脚本路径**：`pet-app-backend/scripts/migrations/migrate-daily-status-to-new-tables.js`

**迁移逻辑**：
1. 遍历 `pet_daily_status`（is_deleted=0）所有记录
2. `daily_mood` 非空 → 插入 `pet_mood_record`（record_time 默认 12:00:00，mood_icon 留空）
3. `daily_stool_health` 非空 → 插入 `pet_stool_record`（record_time 默认 12:00:00，image_url 留空）
4. `daily_weight_kg` 非空 → upsert `pet_daily_health_metric`（pet_id + record_date）
5. 迁移完成后，`pet_daily_status` 三个字段在 schema.sql 标记 `-- DEPRECATED`

### 7.2 验证

- 迁移后数据量核对：`SELECT COUNT(*) FROM pet_mood_record` vs 旧 `daily_mood` 非空数
- 抽样检查迁移数据正确性
- `npm run verify:db` 校验新增 3 表结构

## 8. 路由注册位置

新增路由注册在 `pet-app-backend/routes/pet.js`，注意路由顺序（带固定路径段的路由需在 `:pet_id` 通配之前）：

```javascript
// 心情记录
router.get('/:pet_id/mood-records', authMiddleware, asyncHandler(listMoodRecords));
router.post('/:pet_id/mood-records', authMiddleware, asyncHandler(createMoodRecord));
router.put('/:pet_id/mood-records/:mood_id', authMiddleware, asyncHandler(updateMoodRecord));
router.delete('/:pet_id/mood-records/:mood_id', authMiddleware, asyncHandler(deleteMoodRecord));

// 排便记录
router.get('/:pet_id/stool-records', authMiddleware, asyncHandler(listStoolRecords));
router.post('/:pet_id/stool-records', authMiddleware, asyncHandler(createStoolRecord));
router.put('/:pet_id/stool-records/:stool_id', authMiddleware, asyncHandler(updateStoolRecord));
router.delete('/:pet_id/stool-records/:stool_id', authMiddleware, asyncHandler(deleteStoolRecord));

// 健康指标
router.get('/:pet_id/health-metrics', authMiddleware, asyncHandler(getHealthMetric));
router.get('/:pet_id/health-metrics/latest', authMiddleware, asyncHandler(getLatestHealthMetric));
router.put('/:pet_id/health-metrics', authMiddleware, asyncHandler(upsertTodayHealthMetric));

// 看板聚合 + 月度摘要
router.get('/:pet_id/daily-dashboard', authMiddleware, asyncHandler(getDailyDashboard));
router.get('/:pet_id/monthly-summary', authMiddleware, asyncHandler(getMonthlySummary));
```

> `health-metrics/latest` 和 `daily-records/latest` 一样需放在通配 `:record_date` 之前避免路径冲突。
