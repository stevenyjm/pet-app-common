## 1. 变更总览

| 类别 | 说明 |
|------|------|
| 新增接口-工作台草稿/版本/发布 | `/admin/workbench/:moduleType/*` 通用草稿管理 |
| 新增表 | `workbench_draft`（草稿/版本/发布表）、`workbench_item_blocklist`（发布项禁止列表） |

## 2. 保存草稿 POST `/admin/workbench/:moduleType/draft`

创建新版本草稿。

**权限**：`workbench:manage`

**请求体（JSON）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| draft_data | object | 是 | 草稿内容（模块特定结构，见 §7） |
| remark | string | 否 | 版本备注（≤500字） |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "module_type": "product_publish",
    "version_no": 1,
    "draft_data": { "items": [] },
    "publish_status": 0,
    "published_at": null,
    "published_by": null,
    "remark": "首次草稿",
    "created_by": 1,
    "created_at": "2026-08-21T12:00:00+08:00",
    "updated_at": "2026-08-21T12:00:00+08:00"
  }
}
```

> 写审计日志 `workbench_draft_save`（含 `module_type`、`version_no`）

## 3. 查询历史记录 GET `/admin/workbench/:moduleType/drafts`

分页查询指定模块的草稿/版本列表。

**权限**：`workbench:view`

**请求参数（query）**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | number | 否 | 默认 1 |
| page_size | number | 否 | 默认 20，最大 100 |
| publish_status | number | 否 | 0-草稿；1-已发布；2-已归档；不传=全部 |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [/* formatDraft[] */],
    "total": 10,
    "page": 1,
    "page_size": 20
  }
}
```

## 6. 提交发布 POST `/admin/workbench/:moduleType/drafts/:draftId/publish`

将指定草稿版本发布，同时将当前已发布版本归档，并分发到业务表。

**权限**：`workbench:manage`

**联动逻辑**

1. 将当前 `publish_status=1` 的版本改为 `publish_status=2`（已归档）
2. 将选中草稿改为 `publish_status=1`（已发布），记录 `published_at` 和 `published_by`
3. 分发 `draft_data` 到业务表（见 §7 分发逻辑）
4. 以上步骤在事务内执行

> 写审计日志 `workbench_publish`（含 `module_type`、`version_no`）

**错误响应**

| HTTP | code | 说明 |
|------|------|------|
| 404 | 40001 | 草稿版本不存在 |
| 400 | 40001 | 该版本已发布 |

---

## 7. 回滚 POST `/admin/workbench/:moduleType/rollback`

回滚到上一个已归档版本（`publish_status=2`）。

**权限**：`workbench:manage`

**联动逻辑**

1. 当前已发布版本改为已归档
2. 上一个已归档版本改为已发布，记录 `published_at` 和 `published_by`
3. 重新分发上一个版本内容到业务表
4. 以上步骤在事务内执行

> 写审计日志 `workbench_rollback`（含 `from_version`、`to_version`）

**错误响应**

| HTTP | code | 说明 |
|------|------|------|
| 400 | 40001 | 当前无已发布版本，无法回滚 |
| 400 | 40001 | 无历史发布版本可回滚 |

## 8. 模块分发逻辑（draft_data 结构与分发）

### 8.1 商品发布 `product_publish`

**draft_data 结构**

```json
{
  "items": [
    { "product_id": 1, "product_name": "商品A", "category_id": 10, "action": "on_shelf" },
    { "product_id": 2, "product_name": "商品B", "category_id": 10, "action": "off_shelf" }
  ]
}
```

**分发逻辑**：批量更新 `Product.status`（`action=on_shelf` → `status=1`；`action=off_shelf` → `status=0`）

### 8.2 资讯发布 `article_publish`

**draft_data 结构**

```json
{
  "items": [
    { "article_id": "banner-001", "title": "横幅1", "position": "home_banner", "sort_order": 1 },
    { "article_id": "news-001", "title": "资讯1", "position": "mall_top", "sort_order": 1 }
  ]
}
```

**分发逻辑**：批量更新 `Article.position`、`Article.sort_order`、`Article.status=1`、`Article.published_at=now`

### 8.3 CMS 配置发布 `cms_publish`

**draft_data 结构**

```json
{
  "pages": [
    { "type": "about", "title": "关于我们", "content_json": { "blocks": [] } }
  ]
}
```

**分发逻辑**：`CmsPage.upsert`（以 `type` 为唯一键）

### 8.4 文案信息配置发布 `content_config`

**draft_data 结构**

```json
{
  "configs": [
    { "source": "shop_config", "config_key": "shop_name", "config_value": "宠物鲜生" },
    { "source": "mini_app_config", "config_key": "home_title", "config_value": "新鲜到家" }
  ]
}
```

**分发逻辑**：
- `source=shop_config`：`ShopConfig.upsert`（以 `config_key` 为条件）
- `source=mini_app_config`：`MiniAppConfig` 按 `config_key` 查找并更新 `config_json.text` 与 `status=published`；不存在则创建

## 11. 错误码

| HTTP | code | 常量名 | 说明 |
|------|------|--------|------|
| 409 | 40901 | `PRODUCT_WORKBENCH_PUBLISHED` | 商品已在工作台发布，软删前需二次确认 |
| 409 | 40902 | `PRODUCT_WORKBENCH_BLOCKED` | 商品已被禁止再次发布 |
| 409 | 40903 | `CATEGORY_WORKBENCH_PUBLISHED` | 商品分类已在工作台发布，软删前需二次确认 |
| 409 | 40904 | `ARTICLE_WORKBENCH_PUBLISHED` | 资讯已在工作台发布，软删前需二次确认 |
| 409 | 40905 | `ARTICLE_WORKBENCH_BLOCKED` | 资讯已被禁止再次发布 |

> 错误码 `40901`–`40905` 需三端同步：后端 `businessCodes.js`、管理端 `constants/errorCodes.ts`、小程序 `constants/errorCodes.js`。
