## 一、变更背景

### 1.1 问题描述

微信开发者工具中访问宠物页时，后端日志出现 404 错误：

```
GET /api/v1/pets/91/health-metrics/2026-08-24 → 404
businessCode: 40427（接口不存在）
```

### 1.2 根因

前后端对健康指标接口的路径风格契约不一致：

| 端 | 路径风格 | 实际请求示例 |
|----|---------|-------------|
| 前端（`pet-app/src/api/pet.js`） | **路径参数** | `GET /pets/91/health-metrics/2026-08-24` |
| 后端（`routes/pet.js`） | **query 参数** | `GET /pets/91/health-metrics?record_date=2026-08-24` |
| 原规范（2026-08-23 §4.3） | **query 参数** | 与后端一致 |

前端按项目惯例（`daily-records/:record_date` 路径参数风格）实现，但 2026-08-23 规范文档定义健康指标接口时偏离了该惯例，导致前后端不一致。

### 1.3 方案选型

| 方案 | 描述 | 评估 |
|------|------|------|
| A. 改前端 | 前端改用 query 参数 | ❌ 违背项目惯例（daily-records 等均用路径参数），且需改 3 处前端调用 |
| **B. 改后端+规范** ✅ | 规范改为路径参数风格，后端路由对齐 | ✅ 与项目惯例一致，RESTful 风格统一，前端无需改动 |

**最终选择方案 B**：更新本规范为路径参数风格，并修改后端路由 / Controller / Service 实现。

## 二、契约变更

### 2.1 变更范围

| 接口 | 原路径（query） | 新路径（path 参数） |
|------|----------------|---------------------|
| GET 指定日 | `GET /pets/:pet_id/health-metrics?record_date=YYYY-MM-DD` | `GET /pets/:pet_id/health-metrics/:record_date` |
| PUT 当日 | `PUT /pets/:pet_id/health-metrics`（body 含 record_date） | `PUT /pets/:pet_id/health-metrics/:record_date`（body 不再需要 record_date） |
| GET latest | `GET /pets/:pet_id/health-metrics/latest` | `GET /pets/:pet_id/health-metrics/latest`（不变） |

### 2.2 路径参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pet_id` | number | 是 | 宠物 ID |
| `record_date` | string | 是 | 日期，格式 `YYYY-MM-DD`（北京时间） |

### 2.3 路由注册顺序

`/latest` 必须注册在 `/:record_date` 之前，避免 `latest` 被当作 `record_date` 匹配：

```javascript
router.get('/:pet_id/health-metrics/latest', ...);      // 1. latest 在前
router.get('/:pet_id/health-metrics/:record_date', ...); // 2. 指定日
router.put('/:pet_id/health-metrics/:record_date', ...); // 3. 写入
```

## 三、接口详情

### 3.1 GET /api/v1/pets/:pet_id/health-metrics/:record_date

获取指定日期的健康指标。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | number | 是 | path | 宠物 ID |
| record_date | string | 是 | path | 日期 `YYYY-MM-DD` |
| Authorization | string | 是 | header | `Bearer <access_token>` |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "metric_id": 101,
    "pet_id": 91,
    "record_date": "2026-08-24",
    "weight_kg": 5.20,
    "physiology_status": "健康",
    "calorie_theory_kcal": 320.00,
    "calorie_custom_kcal": 350.00,
    "exercise_theory_min": 45,
    "exercise_custom_min": 60,
    "calorie_goal_kk": 350,
    "exercise_goal_tt": 60
  }
}
```

无记录时 `data` 为 `null`（不返回 404，避免前端业务流程中断）。

**响应字段说明**

| 字段 | 类型 | 说明 |
|------|------|------|
| metric_id | number | 健康指标记录 ID |
| pet_id | number | 宠物 ID |
| record_date | string | 日期（北京时间） |
| weight_kg | number \| null | 体重（kg） |
| physiology_status | string \| null | 生理状态 |
| calorie_theory_kcal | number \| null | 卡路里理论参考值 K0 |
| calorie_custom_kcal | number \| null | 卡路里自定义值 K1 |
| exercise_theory_min | number \| null | 运动理论参考值 T0（分钟） |
| exercise_custom_min | number \| null | 运动自定义值 T1（分钟） |
| calorie_goal_kk | number \| null | 最终卡路里目标 KK = K1 ?? K0 |
| exercise_goal_tt | number \| null | 最终运动目标 TT = T1 ?? T0 |

**可能的错误码**

| code | 说明 |
|------|------|
| 40001 | record_date 格式错误（非 `YYYY-MM-DD`） |
| 40301 | 无权访问该宠物 |
| 40411 | 宠物不存在 |
| 50001 | 服务器错误 |

### 3.2 GET /api/v1/pets/:pet_id/health-metrics/latest

获取最新一次有值的健康指标（跨日期回退，用于卡片展示）。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | number | 是 | path | 宠物 ID |
| Authorization | string | 是 | header | `Bearer <access_token>` |

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "latest_weight": { "weight_kg": 5.20, "record_date": "2026-08-24" },
    "latest_physiology": { "physiology_status": "健康", "record_date": "2026-08-24" },

  }
}
```

> 本接口路径与原规范一致，**无变更**，仅在本文档中保持完整说明。

### 3.3 PUT /api/v1/pets/:pet_id/health-metrics/:record_date

记录或覆盖指定日期的健康指标。

> **业务约束**：仅允许操作当天日期（北京时间）。历史日期写入返回 42231。

**请求参数**

| 参数 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| pet_id | number | 是 | path | 宠物 ID |
| record_date | string | 是 | path | 日期 `YYYY-MM-DD`（必须为当天） |
| Authorization | string | 是 | header | `Bearer <access_token>` |
| body.weight_kg | number | 否 | body | 体重（0~999.99） |
| body.physiology_status | string | 否 | body | 生理状态（≤32 字符） |
| body.calorie_custom_kcal | number | 否 | body | 自定义卡路里目标（0~999999.99） |
| body.exercise_custom_min | number | 否 | body | 自定义运动目标（0~32767 整数） |

> **变更说明**：`record_date` 不再从 body 读取，改从 path 参数读取。body 中至少传入一个可更新字段。

**成功响应**（code: 0）

```json
{
  "code": 0,
  "message": "健康指标已保存",
  "data": {
    "metric_id": 101,
    "pet_id": 91,
    "record_date": "2026-08-24",
    "weight_kg": 5.20,
    "physiology_status": "健康",
    "calorie_custom_kcal": 350.00,
    "exercise_custom_min": 60
  }
}
```

**可能的错误码**

| code | 说明 |
|------|------|
| 40001 | record_date 格式错误 / 至少传入一个可更新字段 / 数值越界 |
| 40301 | 无权修改该宠物 |
| 40411 | 宠物不存在 |
| 42231 | 不允许修改历史日期的健康指标（record_date 非今天） |
| 50001 | 服务器错误 |

## 四、后端实现清单

### 4.1 路由（`routes/pet.js`）

```javascript
// 修改前
router.get('/:pet_id/health-metrics/latest', authMiddleware, asyncHandler(getLatestHealthMetric));
router.get('/:pet_id/health-metrics', authMiddleware, asyncHandler(getHealthMetric));
router.put('/:pet_id/health-metrics', authMiddleware, asyncHandler(upsertTodayHealthMetric));

// 修改后
router.get('/:pet_id/health-metrics/latest', authMiddleware, asyncHandler(getLatestHealthMetric));
router.get('/:pet_id/health-metrics/:record_date', authMiddleware, asyncHandler(getHealthMetric));
router.put('/:pet_id/health-metrics/:record_date', authMiddleware, asyncHandler(upsertTodayHealthMetric));
```

### 4.2 Controller（`controllers/petHealthMetricController.js`）

```javascript
async function getHealthMetric(req, res) {
  const petId = Number(req.params.pet_id);
  const data = await petHealthMetricService.getMetricByDate(
    req.user.userId,
    petId,
    req.params.record_date      // ← 从 path 读取
  );
  return success(res, data);
}

async function upsertTodayHealthMetric(req, res) {
  const petId = Number(req.params.pet_id);
  const data = await petHealthMetricService.upsertTodayMetric(
    req.user.userId,
    petId,
    req.body,
    req.params.record_date      // ← 新增：从 path 读取
  );
  return success(res, data, '健康指标已保存');
}
```
