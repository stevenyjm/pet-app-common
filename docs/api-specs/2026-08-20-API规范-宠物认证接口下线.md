# API 规范 · 宠物认证接口下线

> **文档编号**：2026-08-20-API规范-宠物认证接口下线
> **创建日期**：2026-08-20（北京时间）
> **状态**：后端已实施完成（Phase 1+2+3 ✅）；前端待对接（Phase 4~5）
> **关联需求**：`pet-app-common/docs/requirements/2026-08-20-需求-宠物认证功能移除.md`
> **涉及端**：C 端小程序、管理端 Web、后端

---

## 1. 变更概述

宠物认证功能整体下线，涉及 3 个 API 接口下线、2 处响应字段移除、1 处权限码语义调整。

### 1.1 接口下线清单

| # | 端 | 方法 | 路径 | 变更 |
|---|----|------|------|------|
| 1 | C 端 | POST | `/pets/:pet_id/certification/submit` | 下线（返回 404） |
| 2 | 管理端 | GET | `/admin/pets/certification-queue` | 下线（返回 404） |
| 3 | 管理端 | PUT | `/admin/pets/:pet_id/certification` | 下线（返回 404） |

### 1.2 响应字段移除清单

| # | 接口 | 移除字段 | 原类型 | 说明 |
|---|------|----------|--------|------|
| 1 | `GET /pets/:pet_id`、`GET /pets/` | `license` | object\|null | 狗证/认证信息对象 |
| 2 | `GET /pets/:pet_id`、`GET /pets/` | `companionship` | object\|null | 陪伴时长衍生字段 |
| 3 | `GET /admin/dashboard/stats` | `pet_certified_count` | number | 已认证宠物数 |
| 4 | `GET /admin/dashboard/stats` | `pet_pending_cert_count` | number | 待认证宠物数 |

## 2. C 端接口变更

### 2.1 POST `/pets/:pet_id/certification/submit`（下线）

**变更**：接口下线，不再接受请求。路由移除后访问返回 404 Not Found。

**原接口职责**：C 端用户提交宠物认证材料（本体照片、证件照片、登记证号、领养/入籍日期），提交后认证状态变为 `pending`。

### 2.2 GET `/pets/:pet_id` 响应字段变更

**原响应**（`includeRelations=true` 时）包含：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "pet_id": 123,
    "name": "...",
    "license": {
      "license_no": "...",
      "license_type": "...",
      "cert_status": "missing|pending|rejected|approved",
      "body_photo_urls": [],
      "license_photo_url": null,
      "reject_reason": null,
      "adoption_date": "2020-03-15",
      "submitted_at": null,
      "reviewed_at": null
    },
    "companionship": {
      "adoption_date": "2020-03-15",
      "days": 1620,
      "years": 4,
      "remaining_days": 140,
      "available": true,
      "display_text": "4 年 140 天"
    }
  }
}
```

**新响应**：移除 `license` 与 `companionship` 字段。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "pet_id": 123,
    "name": "...",
    "breed": "...",
    "gender": 1,
    "birthday": "2020-01-01",
    "preferences": "",
    "medical_history": "",
    "allergens": "",
    "status": 1,
    "created_at": "...",
    "updated_at": "..."
  }
}
```

### 2.3 GET `/pets/` 响应字段变更

列表接口在 `includeRelations=true` 时同样移除 `license`/`companionship` 字段，与单条详情一致。

### 2.4 POST `/pets`（创建宠物）请求体变更

**原请求**：可携带 `license` 对象（含 `adoption_date` 等字段）。

**新请求**：不再接受 `license` 字段。如请求体包含 `license`，后端忽略该字段（不报错，向后兼容）。

```json
{
  "name": "...",
  "breed": "...",
  "gender": 1,
  "birthday": "2020-01-01"
}
```

### 2.5 PUT `/pets/:pet_id`（更新宠物）请求体变更

**原请求**：可携带 `license` 对象更新狗证信息。

**新请求**：不再接受 `license` 字段。如请求体包含 `license`，后端忽略该字段。

## 3. 管理端接口变更

### 3.1 GET `/admin/pets/certification-queue`（下线）

**变更**：接口下线，返回 404。

**原接口职责**：查询认证审核队列，支持按 `cert_status`（`all/missing/pending/rejected`）筛选，分页返回待审核宠物列表。

### 3.2 PUT `/admin/pets/:pet_id/certification`（下线）

**变更**：接口下线，返回 404。

**原接口职责**：管理员审核宠物认证（`approve`/`reject`），更新 `cert_status`、写入审核记录、发送用户通知。原权限要求 `pet:certify`。

### 3.3 GET `/admin/dashboard/stats` 响应字段变更

**原响应**包含：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "registered_count": 100,
    "today_new_users": 5,
    "today_order_count": 10,
    "today_gmv": 1200.00,
    "pending_ship_count": 3,
    "pending_after_sales_count": 1,
    "pet_certified_count": 50,
    "pet_pending_cert_count": 5,
    "pending_feedback_count": 2,
    "pending_service_count": 1
  }
}
```

**新响应**：移除 `pet_certified_count` 与 `pet_pending_cert_count`。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "registered_count": 100,
    "today_new_users": 5,
    "today_order_count": 10,
    "today_gmv": 1200.00,
    "pending_ship_count": 3,
    "pending_after_sales_count": 1,
    "pending_feedback_count": 2,
    "pending_service_count": 1
  }
}
```

### 3.4 保留的管理端宠物接口

以下接口**不受影响**，继续使用 `pet:certify` 权限（语义调整为"宠物档案管理"）：

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/admin/pets` | `pet:view` | 宠物列表（移除认证筛选） |
| GET | `/admin/pets/:pet_id` | `pet:view` | 宠物详情（移除认证区块） |
| GET | `/admin/pets/export` | `pet:view` | 宠物导出 |
| DELETE | `/admin/pets/:pet_id` | `pet:certify` | 宠物删除（权限不变） |
| PATCH | `/admin/pets/:pet_id/restore` | `pet:certify` | 宠物恢复（权限不变） |
| PUT | `/admin/pets/:pet_id/daily-records/:record_date` | `pet:certify` | 日记录编辑（权限不变） |
| GET | `/admin/pets/:pet_id/daily-records` | `pet:view` | 日记录列表 |
| GET | `/admin/pets/:pet_id/daily-records/:record_date` | `pet:view` | 日记录详情 |

## 4. 错误码变更

### 4.1 移除的业务错误码

| 错误码 | 常量名 | 原含义 |
|--------|--------|--------|
| 42210 | `PET_CERT_INCOMPLETE` | 认证材料不完整 |
| 42211 | `PET_CERT_REJECT_REASON_REQUIRED` | 拒绝审核需填写原因 |
| 42214 | `PET_CERT_LOCKED` | 认证已通过，不可重复提交 |
| 42215 | `PET_CERT_PENDING` | 认证审核中，不可重复提交 |
| 42216 | `PET_CERT_REVIEW_INVALID` | 当前状态不可审核 |

> 以上错误码从 `utils/businessCodes.js` 移除。已分配的码号不回收复用。

## 5. 权限点变更

### 5.1 `pet:certify` 权限码（保留，语义调整）

| 属性 | 变更前 | 变更后 |
|------|--------|--------|
| 权限码 | `pet:certify` | `pet:certify`（不变） |
| 名称 | 宠物认证 | 宠物档案管理 |
| 描述 | 宠物认证审核 | 宠物档案管理（删除/恢复/日记录编辑） |
| 使用路由 | `PUT /admin/pets/:id/certification`（下线） | `DELETE /admin/pets/:id`、`PATCH /admin/pets/:id/restore`、`PUT /admin/pets/:id/daily-records/:date` |
| 角色矩阵 | `operations` 角色勾选 | `operations` 角色勾选（不变） |

### 5.2 前端路由 meta.permission

管理端路由中 `meta.permission = 'pet:certify'` 的页面（宠物删除/恢复/日记录编辑入口）保持不变。

## 6. 数据库表保留说明

| 表名 | 处理方式 | 说明 |
|------|----------|------|
| `pet_license` | **保留不变** | 表结构与既有数据保留，代码侧不再 ORM 映射或读写。符合 `multi-project.md` §8.3 禁止硬删除规则 |

`pet_license` 表定义（保留不变，参考）：

```sql
CREATE TABLE IF NOT EXISTS `pet_license` (
  `license_id` BIGINT NOT NULL AUTO_INCREMENT,
  `pet_id` BIGINT NOT NULL,
  `license_no` VARCHAR(64) NOT NULL,
  `license_type` VARCHAR(32) NOT NULL,
  `valid_from` DATE DEFAULT NULL,
  `valid_to` DATE DEFAULT NULL,
  `adoption_date` DATE DEFAULT NULL COMMENT '领养/入籍日期，来源于狗证证面，陪伴时长计算基准',
  `license_status` VARCHAR(32) NOT NULL,
  `photo_url` VARCHAR(255) DEFAULT NULL,
  `cert_status` TINYINT NOT NULL DEFAULT 0 COMMENT '0-missing 1-pending 2-rejected 3-approved',
  `body_photo_urls` JSON DEFAULT NULL COMMENT '本体照片 URL 数组',
  `license_photo_url` VARCHAR(255) DEFAULT NULL COMMENT '证件照片 URL',
  `reject_reason` VARCHAR(512) DEFAULT NULL,
  `submitted_at` DATETIME DEFAULT NULL,
  `reviewed_at` DATETIME DEFAULT NULL,
  `reviewed_by` BIGINT DEFAULT NULL COMMENT '审核管理员 ID',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间（北京时间）',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间（北京时间）',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
  PRIMARY KEY (`license_id`),
  UNIQUE KEY `uk_pet_id` (`pet_id`),
  CONSTRAINT `fk_pet_license_pet` FOREIGN KEY (`pet_id`) REFERENCES `pet` (`pet_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
