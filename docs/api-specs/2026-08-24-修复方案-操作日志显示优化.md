## 二、问题一：操作时间字段为空

### 2.1 现象描述

操作日志列表中，「操作时间」列全部显示为空，无任何时间值。

### 2.2 根因分析

#### 数据流链路

```
数据库 created_at
    ↓ (Sequelize Model, 字段名: created_at)
后端 formatAuditLog() 返回 { created_at: formatDateTime(row.created_at) }
    ↓ (HTTP 拦截器 toCamelCase 转换)
前端实际收到 { createdAt: "2026-08-24 14:30:00" }
    ↓
前端类型定义 AdminAuditLog.createTime ← ❌ 字段名错误
    ↓
表格列 prop="createTime" ← ❌ 绑定了不存在的字段
    ↓
row.createTime === undefined → 显示为空
```

#### 具体定位

| 位置 | 文件 | 行号 | 当前值 | 应有值 |
|------|------|------|--------|--------|
| 前端类型定义 | `pet-app-admin-web/src/types/inventory.ts` | 192 | `createTime: string` | `createdAt: string` |
| 前端表格列绑定 | `pet-app-admin-web/src/views/inventory/OperationLogs.vue` | 157 | `prop="createTime"` | `prop="createdAt"` |

#### 结论

**这不是预取现象**。预取现象通常指时间格式化函数（如 `formatDateTime`）未执行或返回了原始 Date 对象导致前端无法解析。经排查：

- 后端 `formatAuditLog()` 函数正确调用了 `formatDateTime(row.created_at)`，返回的是格式化好的字符串
- HTTP 拦截器的 snake_case → camelCase 转换逻辑正常工作，`created_at` 正确转换为 `createdAt`
- **真正原因**：前端类型定义中使用了 `createTime`（少了一个 `d`），与拦截器转换后的 `createdAt` 不匹配，导致取值为 `undefined`

### 2.3 修复方案

仅需修改前端两个位置（后端无需变更）：

| 序号 | 文件 | 修改内容 |
|------|------|----------|
| 1 | `src/types/inventory.ts` L192 | `createTime: string` → `createdAt: string` |
| 2 | `src/views/inventory/OperationLogs.vue` L157 | `prop="createTime"` → `prop="createdAt"` |

## 三、问题二：操作描述字段显示为 JSON 字符串

### 3.1 现象描述

「操作描述」列显示为原始 JSON 字符串，例如：

- `{"username":"admin","login_method":"password"}`
- `{"role_id":6,"role_code":"commodity_admin","role_name":"..."}`
- `{"before":{"role_name":"..."},"after":{"role_name":"..."},"changed_fields":["role_name"]}`

用户无法直接理解操作含义，需手动解析 JSON。

### 3.2 根因分析

#### 数据写入

后端 `writeAdminAudit()` 将操作详情对象 `detail` 通过 `JSON.stringify()` 序列化后存入数据库 `detail_json` 字段。不同操作类型存储的 detail 结构各异：

| action 示例 | resourceType 示例 | detail 结构示例 |
|-------------|-------------------|----------------|
| `admin_login` | `auth` | `{ username, login_method }` |
| `admin_logout` | `auth` | `{ session_revoked }` |
| `admin_role_create` | `admin_role` | `{ role_name, role_code, description }` |
| `admin_role_update` | `admin_role` | `{ before, after, changed_fields }` |
| `admin_role_permission_update` | `admin_role` | `{ role_id, before[], after[], added[], removed[] }` |
| `admin_create` | `admin_user` | `{ username, role_id, role_name }` |
| `admin_disable` / `admin_enable` | `admin_user` | `{ username, new_status }` |
| `admin_reset_password` | `admin_user` | `{ target_username }` |
| `after_sales_soft_delete` | `after_sales` | `{ status }` |
| `cms_update` | `cms_page` | `{ title }` |
| `cron_task_trigger` | `cron_task` | `{ trigger_type, result_summary }` |
| `message_broadcast` | `admin_message_job` | `{ target_type, recipient_count, title }` |
| `feedback_resolve` | `feedback` | `{ feedback_id, feedback_no, type }` |

#### 数据读取链路

```
DB detail_json (TEXT, JSON 字符串)
    ↓ 后端 parseDetailJson()
后端返回 detail_json: 对象（已解析）
    ↓ HTTP 拦截器 toCamelCase
前端收到 detailJson: 对象
    ↓ 前端 getDetailText()
JSON.stringify(detail, null, 2) → 格式化 JSON 字符串 ← ❌ 直接展示给用户
```

#### 核心问题

前端 `getDetailText()` 函数（`OperationLogs.vue` L60-69）将 `detailJson` 解析后直接 `JSON.stringify()` 序列化展示，缺少将结构化数据转换为自然语言的"翻译层"。

### 3.3 自然语言转换方案

#### 方案定位

在前端建立 **操作描述翻译器**（`auditLogTranslator.ts`），根据 `action` + `resourceType` 组合，将 `detailJson` 对象转换为简洁的中文描述语句。

#### 翻译规则设计

按 `action` 分组，为每种操作设计模板化的中文描述：

##### A. 认证模块（resourceType = `auth`）

| action | 中文模板 | detail 字段映射 | 示例输出 |
|--------|---------|----------------|----------|
| `admin_login` | `「{username}」登录系统` | `username` | 「admin」登录系统 |
| `admin_login_failed` | `「{username}」登录失败：{reason}` | `username`, `reason` | 「test」登录失败：密码错误 |
| `admin_logout` | `「{username}」退出系统（{session_revoked === 'all' ? '全部会话' : '当前会话'}）` | `username`, `session_revoked` | 「admin」退出系统（全部会话） |

##### B. 角色管理（resourceType = `admin_role`）

| `admin_role_update` | `编辑角色「{before.role_name}」，修改了 {changed_fields.map(translate).join('、')}` | `before`, `after`, `changed_fields` | 编辑角色「采购」，修改了角色名称、角色描述 |

##### I. 通用降级（无法匹配以上规则时）

| 场景 | 处理策略 |
|------|---------|
| detail 为空对象 `{}` | 仅显示操作类型中文标签，如「创建」 |
| detail 有字段但无对应翻译规则 | 拼接关键字段：取 2-3 个重要字段以「、」连接显示 |
| detail 为字符串 | 直接显示字符串内容 |
| 完全未知的 action | 显示 action 原始值，tooltip 中展示完整 JSON |

#### 实现建议

##### 文件：`pet-app-admin-web/src/utils/auditLogTranslator.ts`

```
// 结构设计：
1. 维护一个 action → 翻译函数 的映射表
2. 每个翻译函数接收 (detail, row) 参数，返回中文描述字符串
3. 对未知 action 走降级逻辑
4. 导出 translateDetail(row) 函数供 OperationLogs.vue 调用
```

##### 翻译函数签名

```typescript
type DetailTranslator = (detail: Record<string, any>, row: AdminAuditLog) => string
```

##### 降级策略优先级

1. 精确匹配 `action` + `resourceType` 组合的翻译器
2. 仅匹配 `action` 的翻译器
3. 通用降级（取 detail 前 3 个 key-value 拼接）
4. 返回 action 原始值 + tooltip 展示原始 JSON

#### 字段名转换辅助

翻译过程中需将 snake_case 字段名转为中文标签，建议维护一个 `FIELD_LABELS` 映射表：

```
username → 用户名
login_method → 登录方式
role_name → 角色名称
role_code → 角色编码
changed_fields → 修改字段
before → 修改前
after → 修改后
new_status → 新状态
target_username → 目标用户
session_revoked → 会话撤销
...
```

### 8.2 Tooltip 问题根因

```
原代码：:content="getDetailTooltip(row) || getDetailText(row)"
```
