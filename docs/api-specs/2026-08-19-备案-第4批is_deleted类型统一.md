## 1. 变更范围

第四档「is_deleted 已存在，类型使用 BOOLEAN 而非 TINYINT」共 **13 张表**：

规范要求 `is_deleted TINYINT NOT NULL DEFAULT 0`，这些表使用了 `is_deleted BOOLEAN NOT NULL DEFAULT FALSE`，在 MySQL 中 BOOLEAN 实际为 TINYINT(1)，语义等价但不符合项目统一类型规范，需要统一为 `TINYINT NOT NULL DEFAULT 0`。

## 3. 修改内容

### 3.1 schema.sql 建表语句
每张表的：
```sql
`is_deleted` BOOLEAN NOT NULL DEFAULT FALSE COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
```
改为：
```sql
`is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除',
```

### 3.2 Sequelize Model 定义
每张表的 Model：
```js
    is_deleted: {
      type: DataTypes.BOOLEAN,
      allowNull: false,
      defaultValue: false,
    },
```
改为：
```js
    is_deleted: {
      type: DataTypes.TINYINT,
      allowNull: false,
      defaultValue: 0,
    },
```

### 3.3 数据库迁移脚本（v47）
使用 MODIFY COLUMN 变更类型：
```sql
ALTER TABLE `table_name` MODIFY COLUMN `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除';
```

幂等策略：
```js
async function ensureModifyColumnType(tableName, columnName) {
  // 通过 information_schema.columns 查询 COLUMN_TYPE
  // 如果已经是 TINYINT 则跳过，如果是 tinyint(1) / BOOLEAN 则 MODIFY
  const [rows] = await sequelize.query(
    `SELECT DATA_TYPE, COLUMN_TYPE FROM information_schema.columns
     WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ? AND COLUMN_NAME = ?`,
    { replacements: [dbName, tableName, columnName], type: sequelize.QueryTypes.SELECT }
  );
  if (!rows.length) return false; // 列不存在
  const type = (rows[0].DATA_TYPE || '').toLowerCase();
  const colType = (rows[0].COLUMN_TYPE || '').toLowerCase();
  if (type === 'tinyint' && colType !== 'tinyint(1)') {
    logger.debug(`[migrate:v47] ${tableName}.${columnName} already TINYINT, skip`);
    return false;
  }
  await sequelize.query(
    `ALTER TABLE \`${tableName}\` MODIFY COLUMN \`${columnName}\` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已逻辑删除'`,
    { raw: true }
  );
  logger.info(`[migrate:v47] ${tableName}.${columnName} BOOLEAN → TINYINT done`);
  return true;
}
```

### 3.4 verify-db.js
verify-db.js 中 EXPECTED_TABLES 的字段数组不改变（is_deleted 字段名不变），但需要注意类型检查的逻辑（如果 verify-db.js 有类型校验逻辑）；通常不涉及修改，除非有显式类型判断。

## 4. 向后兼容性评估

| 变更 | 向后兼容 | 影响 |
|------|---------|------|
| BOOLEAN → TINYINT（列类型变更） | ✅ 兼容（MySQL 内部 BOOLEAN 实际为 TINYINT(1)，true→1/false→0） | 读写完全不受影响；Sequelize 读 BOOLEAN 会返回 true/false，读 TINYINT 返回 0/1，但 JavaScript 中 0 === false 不恒等——需要检查前端/后端是否有严格相等 `=== true/false` 的地方 |
| Model BOOLEAN→TINYINT | ❌ 部分不兼容（严格比较时） | 后端如果有 `is_deleted === true` / `=== false` 的严格比较，改为 `=== 1` / `=== 0` 或用 truthy 判断 |

### 注意事项
- JavaScript 中 `0 === false` 为 `false`；`1 === true` 为 `false`。
- 若后端有 `if (row.is_deleted === true)` 之类的严格比较，改为 `if (row.is_deleted)` truthy 判断即可。
