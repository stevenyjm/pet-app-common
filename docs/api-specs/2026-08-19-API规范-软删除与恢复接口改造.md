## 1. 变更背景

依据数据库基础字段与逻辑删除规范（`multi-project.md` §8），product / after_sales / article 三张表已移除旧的 `is_hidden` / `hidden_at` / `hidden_by` 业务字段，统一改为 `is_deleted`（TINYINT，0-未删除，1-已逻辑删除）逻辑删除字段。

原"隐藏 / 显示"功能（基于 `is_hidden`）需改造为"软删除 / 恢复"功能（基于 `is_deleted`），API 路径由 `PATCH /:id/hide` + `PATCH /:id/show` 改为 `DELETE /:id`（软删除）+ `PATCH /:id/restore`（恢复），符合 RESTful 语义。

## 2. 变更范围

| 模块 | 表 | 原端点（去除） | 新端点 |
|------|----|----------------|--------|
| 商品 | product | `PATCH /admin/products/:id/hide`、`PATCH /admin/products/:id/show` | `DELETE /admin/products/:id`（软删除，已有端点改语义）、`PATCH /admin/products/:id/restore`（新增） |
| 售后 | after_sales | `PATCH /admin/after-sales/:id/hide`、`PATCH /admin/after-sales/:id/show` | `DELETE /admin/after-sales/:id`（新增）、`PATCH /admin/after-sales/:id/restore`（新增） |
| 资讯 | article | `PATCH /admin/articles/:id/hide`、`PATCH /admin/articles/:id/show` | `DELETE /admin/articles/:id`（软删除，已有端点改语义）、`PATCH /admin/articles/:id/restore`（新增） |

### 2.1 去除的端点（向后不兼容）

| 序号 | 方法 | 路径 | 原功能 | 替代端点 |
|------|------|------|--------|----------|
| 1 | PATCH | /admin/products/:id/hide | 隐藏商品（is_hidden=true） | DELETE /admin/products/:id |
| 2 | PATCH | /admin/products/:id/show | 显示商品（is_hidden=false） | PATCH /admin/products/:id/restore |
| 3 | PATCH | /admin/after-sales/:id/hide | 隐藏售后（is_hidden=true） | DELETE /admin/after-sales/:id |
| 4 | PATCH | /admin/after-sales/:id/show | 显示售后（is_hidden=false） | PATCH /admin/after-sales/:id/restore |
| 5 | PATCH | /admin/articles/:id/hide | 隐藏资讯（is_hidden=true） | DELETE /admin/articles/:id |
| 6 | PATCH | /admin/articles/:id/show | 显示资讯（is_hidden=false） | PATCH /admin/articles/:id/restore |

## 3. 新增 / 变更接口定义

### 3.1 商品模块

#### 3.1.1 DELETE /admin/products/:id — 软删除商品

| 项目 | 说明 |
|------|------|
| 方法 | DELETE |
| 路径 | /admin/products/:id |
| 认证 | adminAuthMiddleware |
| 权限 | PRODUCT_EDIT |
| 功能 | 逻辑删除商品（设置 `is_deleted = 1`）；不物理删除 |
| 前置校验 | 商品存在（is_deleted=0）；若已删除返回 `already_deleted: true` |
| 响应字段 | `product_id`、`deleted: true`、`already_deleted?: boolean` |
| 关联操作 | 写 admin_audit_log（action: `product_soft_delete`）；失效商品 SKU 缓存 |
| 变更说明 | 原端点已存在（`deleteProduct`），原实现设置 `is_hidden=true`，现改为设置 `is_deleted=1` |

#### 3.1.2 PATCH /admin/products/:id/restore — 恢复商品（新增）

| 项目 | 说明 |
|------|------|
| 方法 | PATCH |
| 路径 | /admin/products/:id/restore |
| 认证 | adminAuthMiddleware |
| 权限 | PRODUCT_EDIT |
| 功能 | 恢复逻辑删除的商品（设置 `is_deleted = 0`） |
| 前置校验 | 商品存在；若未删除返回 `already_restored: true` |
| 响应字段 | `product_id`、`restored: true`、`already_restored?: boolean` |
| 关联操作 | 写 admin_audit_log（action: `product_restore`）；失效商品 SKU 缓存 |

## 4. 查询过滤变更

三张表的列表查询（listProducts / listAfterSales / listArticles）默认过滤条件由 `is_hidden = false` 改为 `is_deleted = 0`：

```js
// 改造前
where.is_hidden = false;

// 改造后
where.is_deleted = 0;
```

| 模块 | 函数 | 文件 | 改造说明 |
|------|------|------|----------|
| 商品 | listProducts | services/adminProductService.js | `where.is_hidden = false` → `where.is_deleted = 0` |
| 售后 | buildWhere / listAfterSales | services/adminAfterSalesService.js | `where.is_hidden = false` → `where.is_deleted = 0` |
| 资讯 | listArticles | services/adminArticleService.js | `where.is_hidden = false` → `where.is_deleted = 0` |

> 注意：`adminProductService.js` 中 `findPendingOrdersBySkuId`（L41）和 `updateSku`（L633, L767）的 `is_hidden: false` 是查询 `OrderMain` 表的 `is_hidden` 字段，**不属于第6批范围**（order_main 属于第2批），本次**不改**。

## 5. 响应字段变更

| 原字段 | 新字段 | 类型 | 说明 |
|--------|--------|------|------|
| is_hidden | is_deleted | TINYINT | 0-未删除，1-已逻辑删除 |
| hidden_at | （移除） | — | 不再返回 |
